--- STRUCTURAL CAVEAT (the honest frame for rows 4-6) ---------------------------
Every `native.id` workload is INPUT-FREE (constant N, constant seed). So the
theoretically-correct competitor is a CONSTANT — clang SHOULD fold each to
`mov;ret`. Where it does (small N; pow via vectorize), it TIES. Where its
folder/vectorizer gives up (fold @1e9 = 0.90s; cube @1e9 = 0.16s), native's
recurrence solver still folds -> WIN. That win is real but FRAGILE: it exploits a
budget limit in clang, not an asymptotic impossibility.

The ROBUST, unbounded FTCFTW win is RUNTIME-PARAMETERIZED recurrences: `fold(N)`
with N from input. Then NO compiler can fold (N unknown) and clang must run O(N);
a closed-form / O(log N) realization is a clean asymptotic dominance for ALL N.
native.id is exit-code / string-literal only (S0), so this class is POTENTIAL, not
yet measured. Realizing it (accept a runtime arg, keep the closed-form) is the
highest-value next FTCFTW step for the surface.

CLASS E — MEASURED (idol direct-native `.out` vs clang -O3 `.out`, best-of-3 real,
serial non-foldable kernels so both run O(N); this isolates CODEGEN, not algorithm):

  multiply-bound   s=(s*1103515245+i)&R, 1e8   idol 0.11  clang 0.09  ~parity
  cheap-op         s=((s*2)+i)&R,        3e8   idol 0.34  clang 0.20  ~1.7x LOSS

So class E is NOT an "elephant" / large constant factor — that was an unmeasured
overstatement, now corrected (law.repair.class). It is MODEST and BOUNDED:
- On latency-bound code (a real multiply per iter) idol is at ~parity: the naive
  load/store + copy overhead retires in the multiply-latency shadow.
- On cheap-op code (shift/add) it is ~1.5-1.7x, and the emitted asm names the cause:
  redundant register-to-register copies (`mov x10,x16 ; mov x11,x15` per iter) — a
  missing COPY-COALESCING / register-allocation pass, plus stack reloads. NOT a
  vectorization gap (these serial kernels are unvectorizable for clang too).

So the honest ordering of MEASURED performance debt (law.repair.class):
  1. D — affine scalar-evolution: +0.40 s to a NAMED O(1) bound (row 3). Largest,
     cleanly attributed, algorithm-axis. clang has it; the direct backend does not.
  2. runtime-parameterized recurrences: converts class A from a fragile
     "clang's folder gave up" win into a ROBUST asymptotic win for all N. Requires
     the surface to accept a runtime argument (S0: exit-code/string-literal only).
  3. E — copy-coalescing / register allocation: ~1.5-1.7x on cheap-op code only,
     ~0 on latency-bound code. Real but bounded; lives in realization/codegen and
     is gated by the differential oracle.
  4. F — data-dependent array materialization (GAP-101 0-based store + byte output).
  5. G/H — memory/cache/TLB, startup/artifact/compile: UNMEASURED; need workloads.

All of D/E/codegen live in the S0 Zig backend (non-canonical bootstrap) or the
