# GAP-086 — the native worklist, root-caused: 58 bails, and the top one is an ORDERING bug

**Status:** OPEN (measured worklist) · **Filed:** 2026-08-08
**Law:** Pass 103 NO FOREIGN WAIST · `law.waist.none`

`native-census` reads **119 native / 58 bail / 177 reachable**. The 58 have never
been broken down, so "the worklist" has been a number rather than a plan. This is
the breakdown, measured by running `DUO_DNIR_TRACE=1 duo compile --backend=direct`
over every non-`compile_fail` example and taking the FIRST precheck reason.

Why it matters more than a coverage percentage: `src/codegen.zig` is **34,971
lines — 28% of the remaining Zig ledger**, and gaps/ledger measurement showed
**25,042 of them are required bootstrap C emission**. That mass is deletable only
when programs stop reaching the C emitter. Every row below is a piece of that.

## The top row is not what it looks like

`global-decl-module-path` was 12 in `lib/std` and 12 in `examples/`. Commit
`25472b4` fixed the `lib/std` half by making the site read the EMISSION RECORD
(`embedded_module_native`) instead of refusing outright — `lib/std` precheck bails
collapsed to a single `ret-type:any`.

The `examples/` half did **not** move, and the reason is the useful part:

```
lib/std/compiler/bind.duo          precheck: CLEAN (no bail)
examples/pass16_binder_proof.duo   precheck: global-decl-module-path
```

The module is native-capable. Its consumer still refuses. So the predicate is
asking *"was this module emitted native?"* at a point where **the module has not
been emitted yet** — `embedded_module_native` has no entry, the absent record
reads as "not native", and a clean module is refused for not having happened yet.

**This is an ORDERING defect, not a nativeness one.** The repair is to give the
precheck an answer that does not depend on emission having already occurred:
decide the dependency's nativeness on demand (and memoize), rather than consulting
a record that is populated later.

It must NOT be repaired by falling back to `find_module_file_for_req(..) != null`.
That is the unsound tier the original comment correctly rejected, and it is what
produced the recorded miscompile `use of undeclared identifier
duo_g_std_compiler_rewrite_C` plus four boxed-value type errors.

**All 12 are the `pass16_*` proofs** (`arm64_exec_proof`, `arm64_proof`,
`binder_proof`, `comptime_proof`, …), which bind `std.compiler.*` modules. One
ordering fix should move all twelve — the largest single native-coverage win
available, and worth roughly 12/58 of the worklist.

## Second cluster: table-exporting modules

`keyed-table-export` (3) plus `method-unresolved:push`/`split` (5) are one
underlying thing: a module whose members live in a runtime table is not
native-direct, and a method call on such a value cannot resolve statically. This
is the same subject as the standing note *"method declarations disqualify their
whole module from native"*. Eight rows, one repair.

## How to reproduce the histogram

```
for f in examples/*.duo examples/*/*.duo
    DUO_DNIR_TRACE=1 duo compile "$f" --backend=direct -o /tmp/nc.out 2>&1
```
taking the first `precheck — <reason>` per file. Skip `compile_fail`.

**Positive-control it.** An earlier pass of this measurement reported
`bail site: native` for 18 files — the coarse OUTER label, not the reason — and
that reads like a single dominant cause when it is really seventeen different
ones. If every row comes back identical, the grep is catching the wrong line.

## Falsifier

If the ordering fix lands and `native-census` does not move by ~12, then the
`pass16_*` proofs bail a second time for a different reason immediately after,
and the histogram above is only first-reason-deep. It is; that is a known limit
of taking `head -1`, and the honest reading of every row here is "first blocker",
never "only blocker".
