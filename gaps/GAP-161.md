# GAP-161 — Corpus role not machine-visible to agent retrieval

## State

Open.

## Problem

C0 says agents should learn project-owned source patterns only from
canonical Idol. But `examples/spec100/*`, `examples/metatable_class_semantics.id`,
`examples/concept_introspect.id`, and other historical/compatibility fixtures
are ordinary searchable `.id` files. Agents can learn from them without
knowing they are not canonical teaching material.

## Evidence

```
examples/spec100/ has 20+ .id files (convert.id, relation.id, nominal.id, etc.)
examples/metatable_class_semantics.id — historical ontology name
examples/concept_introspect.id — historical ontology name
```

## Required

Corpus role must be machine-visible and retrieval-aware, not just
documented. Canonical agent search should exclude:

- foreign
- compat
- history
- migration
- generated

unless explicitly requested.

If a spec100 fixture disagrees with C0, the fixture is wrong. Never
"preserve spec100 behavior" against the constitution.

## Deletion prerequisite

- Machine-readable corpus role classification (not just comments)
- Agent retrieval filters that respect classification
- spec100 fixtures marked as generated/verified projections of C0,
  not independent authority
