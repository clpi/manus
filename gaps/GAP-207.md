# GAP-207 — the uncommitted `exprIsStr` byte-face correction prints a pointer

**Status:** OPEN · **Filed:** !2026-08-21T22:40:00Z
**Priority:** P0 · **Kind:** wrong_answer
**Filed by:** claude-gap145
**Files:** src/dnir_lower.zig

**This gap is about UNCOMMITTED work in the shared working tree, not about
`HEAD`.** `HEAD` is correct. Nothing has been reverted; this records the
measurement so the holder of `src/dnir_lower.zig` sees it before committing.

## The measurement

```id
main: i64 = ()
    s = 'abc'
    print(s .. "Z")
    0
```

Subject `c27810a4`, clean `git archive HEAD` mirror, `zig build install
-Doptimize=ReleaseFast`, three runs each:

| compiler | run 1 | run 2 | run 3 | exit |
| --- | --- | --- | --- | --- |
| `HEAD` | `abcZ` | `abcZ` | `abcZ` | 0 |
| `HEAD` + the uncommitted `exprIsStr` line | `4370531440Z` | `4342023280Z` | `4372497520Z` | **0** |

Three ASLR'd pointers rendered through `%lld`. Compile 0, run 0, no diagnostic.

## Isolation

The working tree carries two uncommitted lines. **Only the `exprIsStr` one
causes this**, applied alone:

```zig
-        .quoted => true,
+        .quoted => |lit| !ast.quotedLiteralIsByteSequence(lit.quote),
```

The companion line in `concatOperandOk` — `if (expr.* == .quoted) return true;`
— is a partial mitigation. It covers a **literal** operand and does not cover a
**name bound to** a byte literal, which is the shape above.

## Mechanism

At `HEAD`, `exprIsStr` answers `.quoted => true`, so `s` enters `str_slots` and
`planConcat` emits `%s`. Correcting `exprIsStr` to the quote face takes `s` out
of `str_slots`; `concatOperandOk(s)` then falls through to `exprIsIntegral`,
which admits it, and `planConcat` emits `%lld` on a `const char*`.

The correction is right and the fall-through is what is wrong. `exprIsStr`
returning false must not mean "integral".

## Why nothing caught it

- `zig build unit-test`: unchanged, `1667 pass, 9 fail, 0 crash / 1676`,
  identical nine names.
- Compile-status sweep, 538 `examples/**/*.id`: **zero diff**.
- Output differential over all 169 examples that compile: **zero diff**.

The corpus contains **no program with a name bound to a byte literal in a
concat**. Only an output differential on a hand-written program finds this, and
that program is the missing control.

## The class

This is APPLICATION-CONSUMER-ZERO's failure mode in the shape GAP-204 already
measured: an admission rule (`concatOperandOk`) and a capability rule
(`exprIsStr` -> `str_slots` -> `planConcat`) decided in different places, so
narrowing one silently widens the other. The narrowing is correct; it needs the
third arm — a byte-sequence operand is neither text nor integral, and the
lowering has no member to carry it (`native_ir.Value` has
`void/i64/f64/str/local/temp/record` and no byte-sequence face).

Until that member exists, the lawful shape is a named refusal, not a
fall-through.

## Required control before this line is committed

`s = 'abc'; print(s .. "Z")` must either print `abcZ` or refuse by name. A suite
pass, a compile-status sweep and an example output differential are all
insufficient — measured above, all three are clean while the program prints a
pointer.
