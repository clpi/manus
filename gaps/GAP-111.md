| title | GAP-111 — CHAIN-PREFER has nothing to chain: the canonical call form fails where the denied one works |
| status | PARTIAL (2026-08-20) — sema admits canonical `xs:map(f)` via foreign-home subject-first resolution (`gate/gap-111-subject-first.sh`); postfix chains and `any`-parameter fusion remain open |
| filed | 2026-08-09 |
| law | CHAIN-PREFER · CHAIN-BREAK (owner ruling 2026-08-09) · FACE-CALL (§0.5) · §1 DENY LIST |

| section |
|---|---|
| The ruling |

> **CHAIN-PREFER**: when a value is produced only to become the semantic subject
> of exactly one following relation, canonical source forms a postfix `:` chain
> and removes the temporary binding.
>
> Postfix `:` is the only chain operator. Leading `:` is ambient-subject
> invocation, not implicit pipeline continuation.

| # | directive |
|---|---|
| 1 | with the canonical example: |

```duo
users
    :map(.score)
    :take(n)
    :filter(positive)
```

| section |
|---|---|
| What works — the mechanism |

```duo
r = n:double():bump()          -> 11
r = n                          -> 11
    :double()
    :bump()
```

| # | directive |
|---|---|
| 1 | **Postfix chaining works, one-line and multiline offside.** The chain operator is implemented and the layout rule holds. |
| 2 | That is the good half. |

| section |
|---|---|
| What fails — everything it would chain |

```
std.iter.map(xs, twice)     operation-first, on the §1 DENY LIST     ->  2
xs:map(twice)               subject-first, CANONICAL                 ->  type error
xs:take(2)                                                           ->  type error
xs:map(.s)                  field shorthand                          ->  no output
```

| # | directive |
|---|---|
| 1 | `map`, `filter` and `take` DO exist — in `lib/iter.id`, declared operation-first with every parameter `any`: |

```duo
map: any = (list: any, fn_ref: any)
filter: any = (list: any, fn_ref: any)
take: any = (list: any, n: i64)
```

| # | directive |
|---|---|
| 1 | So the pipeline vocabulary is reachable only through the spelling FACE-CALL denies (`std.iter.map(xs, f)`), and unreachable through the spelling FACE-CALL requires (`xs:map(f)`). |

| # | directive |
|---|---|
| 1 | **CHAIN-PREFER cannot be canonical because the chain has nothing chainable.** The canonical example in the ruling does not compile. |

| section |
|---|---|
| This is the fourth instance of one pattern |

| consolidation | works | canonical form | state |
|---|---|---|---|
| ambient sigil (gap[107]) | legacy prefix `@c.emit` | `@{…}`, `x@rel` | unparsed / a synonym for `.` |
| application (gap[110]) | `point{ x, y }` | `p: point = { x, y }` | breaks on read |
| ambient fields (gap[107]) | `.x` | bare `x` in a descriptor home | undeclared identifier |
| **pipeline (here)** | `std.iter.map(xs, f)` | `xs:map(f)` | type error |

| # | directive |
|---|---|
| 1 | **Across every consolidation the law asks for, the explicit or denied form works and the canonical or inferred form does not.** That is not four bugs; it is one shape, and it says the rulings describe the language's target rather than its present. |

| # | directive |
|---|---|
| 1 | Worth stating because it changes how the rulings should be read by anyone implementing them: each is a specification of work, not a description of behaviour, and a doc or website example written from the ruling will not run. |

| section |
|---|---|
| Order |

| # | directive |
|---|---|
| 1 | **`xs:map(f)` before CHAIN-PREFER.** A canonicalizer that rewrites temporaries into chains would produce source that does not compile. The subject-first reach must work first. |
| 2 | **The `any` parameters are the same blocker one level down.** `map(list: any, fn_ref: any)` forfeits every descriptor fact, so even when the call form works, fusion has nothing to fuse on and `xs:map(f):take(n)` cannot stream — which is the whole point of preferring the chain. |
| 3 | **Then CHAIN-PREFER as a canonicalizer rule**, with CHAIN-BREAK's four exceptions (multiple consumers, semantic name, effect/world boundary, operations targeting the original ambient subject) as its guard. |

| section |
|---|---|
| Do not |

| # | directive |
|---|---|
| 1 | **Do not implement CHAIN-PREFER as a formatter rewrite first.** It would delete temporaries and produce chains that fail to compile, and the failure would look like a formatter bug rather than a missing relation surface. |

| # | directive |
|---|---|
| 1 | **Do not add `map`/`filter`/`take` as new native primitives on `str` or table.** gap[106] records why: they belong to a SEQUENCE basis (`at`/`iter`/`put`/`len`) and hand-writing them per descriptor is the thing the basis measurement exists to delete. |
