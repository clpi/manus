# GAP-062 — the descent, stage by stage: what exists, what is Zig, what is absent

**Status:** OPEN (measured roadmap) · **Filed:** 2026-08-08
**Law:** Pass 103 (NO FOREIGN WAIST) · Pass 104 (the mining loop) · G9 (ledger)

Pass 103 says the path is `graph → realize → flow → lower(target) →
encode(target) → encode(elf…) → link`, all DNIR, all family edges, the ISA as
descriptors with layout facts, registers as places, the linker as graph merge.

This file measures the distance, per stage, so "graph IR completed end to end"
becomes a worklist instead of an aspiration. Measured 2026-08-08.

## The stage table

| stage | exists? | what it actually is | distance |
|---|---|---|---|
| **graph** | partial | `semantic_graph.zig` (2173 lines) + AST. Not the DNIR spine. | large |
| **realize** | **no** | No realization stage. Demand/facts are not spent anywhere as a phase. | full |
| **flow** | **no** | No `.flow` node kind. Lowering goes AST → DNIR directly. | full |
| **lower(t)** | yes, as code | `dnir_lower.zig`, 4139 lines of Zig. One target. Not edges. | rewrite |
| **encode(t)** | yes, as code | `native_backend.zig` hand-writes instruction words (`0x1e602800` etc). Not descriptors with layout facts. | rewrite |
| **encode(macho)** | yes, as code | `emitMachOArm64Object`. No elf, no pe, no wasm container. | rewrite + 3 |
| **link** | **FOREIGN** | shells out to `cc` (via `xcrun` on macOS) — `link_native_object`, main.zig:2863. | full |

## The IR itself is not a graph

`src/duo_native_ir.zig` is 294 lines of Zig struct definitions. Its op set is a
conventional linear IR of 28 opcodes:

```
const_i const_f const_str const_req load_local store_local load_field
store_field init_record load_index store_index alloc_slots load_global
binop cmp call_direct call_extern mov_arg fp_mov_arg br br_if br_if_not
ret ret_record hw_fence hw_spin hw_unary str_len
```

That is a fine linear IR and it is **not** what Pass 103 describes. Pass 103's
DNIR is *tables* — nodes with facts attached, transformed by browsable,
overridable relation edges, where `lower(arm64)(sub)` is an EDGE a user can
override and `why` can explain. Today lowering is a 4139-line Zig `switch`.

**The honest framing:** the current backend is a competent hand-written compiler
back end that happens to be called DNIR. The Pass 103 backend is a different
artifact that reuses the codec matrix. Getting from one to the other is not
refactoring; it is building the second thing while the first keeps the lights on.


The Zig ledger concentrates hard — `codegen.zig` alone is 34,780 lines, a
quarter of the total, and it is the C emitter, which Pass 103 demotes to an
*export projection*. The five largest files are 66,980 lines, 46% of the ledger:

```
codegen.zig      34780      sema.zig     13096      parser.zig    8299
native_backend    5918      main.zig      4887
```

**There is no ratchet on the zig row.** The census reports it and enforces
nothing, so the ledger can grow silently. `sh/py` and `js` have floors; the
largest row does not. That is the first thing to fix and it is cheap.

## Ordering, and why this order

1. **Ratchet the ledger.** A ceiling on the zig row that only descends. Without
   it every other item is unmeasured. Cheapest item here.
2. **`encode(arm64)` from descriptors with layout facts.** This is the stage
   Pass 103 says is *reuse* — encoding is the codec matrix pointed at silicon —
   and it is testable against an oracle assembler per instruction (G-D3).
   `zig build abi-matrix` is already a G-D3-shaped gate in miniature, so the
   precedent exists.
3. **The linker.** Shelling to `cc` is the one stage that is *foreign* rather
   than merely *Zig*. Mach-O object emission already exists, so the gap is
   relocation + section merge, not a from-scratch linker.
4. **flow + realize.** These are new construction, not translation, and they are
   what makes `lower` an edge rather than a switch.
5. **The evaluator** (Pass 104 G-D1, days-class) — needed before lowering can be
   *data* rather than *code*, because an edge that cannot be evaluated at compile
   stage is a table nobody can run.

## What must not be lost in the move

The current backend is **correct in ways that were expensive to learn**, and all
of it is encoded as gates rather than as comments: `abi-matrix` at 0
miscompiles, the corpus differential at 87 agree / 2 differ, `native-census` at
101, `audit100` green. Any replacement passes the same gates or it is not a
replacement. Three miscompilations were found tonight by exactly these gates —
f64 arguments in GP registers, dead code after a non-tail `if`, and f64 values
living in the staging registers — and a rewrite that loses those gates will
reintroduce that class silently.
