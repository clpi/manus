# GAP-054 — "cross-module record returns" is not what blocks the 5 programs

**Filed** 2026-08-08. **Status** open. **Class** MISATTRIBUTED WORKLIST ROW —
the bail sites are real, the shared cause assigned to them is not.

The native worklist grouped five programs under one heading: a cross-module
callee returns a record, the caller does not know its shape, so extend the
`req` metadata to carry return types and field layouts. Seven probes say the
five programs do not share that cause, and that the metadata extension would
move none of them.

## Group B (pass9) — the layout is not stated, and cannot be

`lib/std/wasm/decode.duo` declares **zero** record descriptors. Every
record-shaped function there is `: any` and builds anonymous table literals
inline. `decode_i32_const` alone returns four different shapes:

```duo
decode_i32_const(c): any
    d = decode_instruction(c)
    if d.status != "ok" return d end                              -- 8 fields
    if d.id != "wasm.i32.const"
        return { status = "bad_opcode", opcode = d.opcode, id = d.id } end   -- 3
    if d.immediate == nil return { status = "truncated" } end               -- 1
    return { status = "ok", opcode = d.opcode, id = d.id, imm = d.immediate } -- 4
end
```

There is no layout for a scanner to recover, and no layout for a full AST parse
to recover either — the function is genuinely polymorphic over four field sets.
P2 shows this is not a cross-module fact at all: collapse the same code into one
module and it still bails, one step earlier, at `precheck ret-type:any`.

Repairing group B means either giving these functions a single declared record
descriptor (a source change in `lib/std/wasm/decode.duo`, four call sites'
worth of shape unification, and a decision about how `status = "truncated"`
carries absent fields), or teaching the native subset a tagged union. Neither is
`req` metadata.

## Group A (pass16) — the layout is stated, and two other things block first

`lib/std/compiler/lexer.duo` does state it: `Lexer: { ... }`, and
`new(src: str, file: str): Lexer`. The metadata argument applies here. It is
still third in line.

1. **The callee never resolves.** The programs call `std.compiler.lexer.new(...)`
   — a three-level dotted path. `lowerCall`'s entire field-call body sits under
   `if (f.obj.* == .name)` (dnir_lower.zig:1991), and here `f.obj` is itself a
   `.field`. Nothing in that block runs; control falls to the `bailWith` at 2205,
   which reports the callee name `new`. That bail is "I could not resolve this
   callee", not "I could not shape this return".
2. **The `req`-alias spelling does not rescue it.** P5: binding the module to a
   name first bails earlier still, at `precheck mod-top-stmt:global_decl`.
3. **`Lexer` is an ineligible record anyway.** It has 19 fields, and two of them
   (`peeked_token: Tok`, `error_loc: Loc`) are nested records. `collectRecords`
   (dnir_lower.zig:414) takes 1..8 fields of `str`/`i64`/`f64` only. P6a and P6b
   confirm both limits reject the function *in the same module*, with no `req`
   involved.

So group A needs dotted-path callee resolution, then a record representation
that admits nesting and more than 8 fields, and only then cross-module layout
metadata. Landing step three first buys nothing observable.

## Bearing on SH-04

`src/selfhosting_matrix.zig` closes the SH-04 blocker text with "cross-module
*record* returns still have no C ABI export form". True, and P4 demonstrates it
cleanly. But the record SH-04 needs to export is the `Lexer`/`Tok` family, which
P6a/P6b disqualify on field count and nesting before the module boundary is
reached. Closing the metadata gap alone does not close SH-04.

## Repair, in the order the probes support

1. Widen `collectRecords` past 8 scalar fields and admit nested-record fields —
   this is the one that gates the most, and it is measurable in-module (P6a/P6b
   become the fixtures, and both are self-checking).
2. Resolve multi-level dotted callees in `lowerCall`, so `std.a.b.c(...)` reaches
   the same paths `a.b(...)` already does.
3. Then extend `native_req_support.Context` with return types and field layouts,
   with P4 promoted to a real fixture so the machinery has a program that fails
   without it.

Doing 3 first is what this row asked for. It would have been unfalsifiable: no
census program changes either way.

## What was NOT done

No change was landed to `src/dnir_lower.zig` or `src/native_req_support.zig`.
Native census held at 89 across the investigation, which is the honest number —
faking the layout for group B would have moved it on fabrication, and that is
the exact failure mode `CLAUDE.md` §MEASUREMENT HONESTY was written for.
