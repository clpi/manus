## Adversarial precommit bypass

The current committed firewall in `scripts/idiomgate.duo` is lexical, not
rename-invariant. This exact added-file diff exits zero with **0 findings** and
all **14/14** built-in controls green:

```duo
script = req "std.script"
command = "printf ok"
script.run(command)
whatever.system.run(command)
message = "value " .. command
print(message)
platform.net.send(socket, data)
```

The authority detector recognizes only four literal `std.*` paths. Aliasing
the same operation or changing the home spelling therefore changes the verdict,
which directly violates the authority law. The materialization detector only
recognizes `print` and `..` on the same line, so a one-use bridge binding erases
the finding without changing meaning or demand.

The claimed `scripts/canonicalitygate.duo` identity layer is absent from the
worktree, and `.githooks/pre-commit` currently runs only `idiomgate.duo` plus
the explicitly textual `semanticgate.duo` census. Commit `1a7924f` is useful
temporary pressure against four known spellings; it is not SUBJECTGATE,
WORLDGATE, VOCABGATE, or demand/materialization closure.

Required positive controls must vary the home spelling, introduce a local alias,
and insert a single-consumer bridge while preserving the same resolved relation,
subject, world, and demand. All variants must receive the same graph verdict.

## In-flight 19-control expansion is still lexical

The current dirty `scripts/idiomgate.duo` expands its built-in report from
14/14 to 19/19 controls, but the adversarial verdict does not change:

```text
renamed/aliased RG0 fixture   exit 0   findings 0
callable alias `go(command)`  exit 0   findings 0
canonical `mask = 0xFF`       exit 1   uppercase finding
```

The added `readface` recognizer keys one terminal spelling, `read`, rather than
a resolved relation identity. It can reject `arbitrary.home.read(subject)` but
has no proof that the callee is the admitted `read` relation, and the identical
authority defect under `run`, `send`, or an aliased callable remains invisible.
The expanded capital scan inspects every remaining source byte and therefore
misclassifies uppercase hexadecimal digits as identifiers.

These changes may improve lexical migration pressure after the false positive
is fixed. They are not SUBJECTGATE, WORLDGATE, VOCABGATE, or rename-invariant
semantic canonicality. A built-in control count is not evidence unless it
contains the required alias, rename, homonym, bridge, and valid-literal
adversaries and proves them by resolved identity.

The uppercase-literal regression now has a focused Duon repair in the working
tree: numeric tokens are skipped before identifier-uppercase detection, with
controls for `0xFF`, `1E9`, and `foo2Bar`. The first two now pass and the last
still fails. This repairs only the lexical regression introduced by
`cdbac4f`; the renamed/aliased RG0 fixture still exits zero with zero findings,
so the semantic closure state is unchanged.

The same review found that `scandiff` recognized `+++ b/` anywhere in an added
source line as a file header. A string containing those bytes could suppress
the line's canonicality scan and corrupt subsequent attribution. The working
tree now requires the exact diff-header prefix and positive-controls the
boundary. A line containing `"+++ b/"` plus `std.script.run` is again rejected.
This is parser integrity for the temporary lexical firewall, not evidence for
semantic identity.
