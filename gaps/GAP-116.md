# GAP-116 — the boundary failure in four lines, and 53 of 106 instruments nobody runs

**Status:** OPEN (three reconstructions removed) · **Filed:** 2026-08-09
**Law:** IR-ONE · IDENTITY-ONE · GATE-LIVE (owner audit 2026-08-09)

## 1. The boundary failure, stated by the code

The audit's P0 is that realization does not consume authoritative semantic
facts. `src/dnir_lower.zig:337` is that architecture in four lines:

```zig
pub fn lowerModuleWithGraph(alloc, mod, graph: ?*const semantic_graph.SemanticGraph) {
    var m = try lowerModule(alloc, mod);          // AST -> DNIR. graph unused.
    if (graph) |g| try applyGraphToModule(alloc, g, &m);   // graph applied AFTER
    return m;
}
```

**Lowering completes from the AST, and only then is the graph applied to the
finished module.** The graph cannot inform lowering because lowering has already
happened. Every reconstruction map in `LowerCtx` follows from this one ordering:
the lowerer must re-derive what sema knew, because at the moment it runs there
is nothing to ask.

This is the marker the audit asks for — *"the first commit where this stops
being true."* It is a four-line function, and the diff that fixes it will be
visible here first.

## 3. GATE-LIVE, measured — half the instruments are unreachable

```

NOT referenced in build.zig         53      50%
```

Fifty-three checkers, censuses and proofs exist and nothing invokes them. That is
the audit's anti-pattern exactly: *"instrument exists but nothing invokes it."*

**One of them is `ambientfoldproof`, which I wrote today** to lock the rung-3
ambient-fold fix so it could not silently regress — and never wired. I created
an unwired instrument during the session that measured unwired instruments. That
is the failure mode being self-demonstrating, and it is why GATE-LIVE has to be
structural rather than a habit:

> **GATE-LIVE**: an authoritative checker not reachable from a named aggregate
> gate is not a checker.

An unrun proof is worse than no proof, because it reads as coverage. Anyone
scanning `scripts/` sees 106 instruments and infers 106 checks.

### The repair is derivation, not wiring

Wiring 53 build steps by hand recreates the problem at the next instrument. The
audit's own suggestion is the fix — make the gate topology a graph fact:

```
check { owner, input, output, aggregate }
```

and let the build DERIVE the step list. Then an instrument that names no
aggregate is a diagnosable condition rather than a silent orphan, and the giant
hand-written host build description shrinks as a consequence.

## 4. One wording correction worth adopting

The audit sharpens "the semantic graph is authoritative for type facts" into:

> The semantic graph is the authoritative **identity/provenance substrate**;
> semantic facts attached to those identities have one authoritative source and
> are queryable at realization.

That distinction matters for the agent currently working this: the target is a
**query interface over stable identities**, not migrating every descriptor into
one literal structure. Physical storage may remain an interned table, a side
arena or a cache. **One logical authority, not one physical container** — which
also preserves the compaction freedom IR-COMPACT asks for.

## Order

Unchanged from the audit, and now with the marker in §1 as the acceptance test:

1. semantic query interface over stable identities
2. native realization receives it NON-optionally — `lowerModule` consults it
   during lowering rather than `applyGraphToModule` decorating afterwards
3. carry relation/value identity into realized instructions
4. replace `exprReturnsF64` with a descriptor query
5. ratchet the reconstruction count

Until step 2, deleting reconstruction map #1 creates map #2 — which the file's
own comment already records happening three times.

## 5. 2026-08-09 progress — the four-line failure no longer describes HEAD

The first vertical slice changes the ordering in §1:

- `lowerModuleWithGraph` now requires a graph and passes it into lowering.
- `lowerModule` constructs the graph before lowering rather than offering an
  AST-only bypass.
- function nodes carry a resolved result descriptor under their stable identity.
- DNIR asks `funcResultDescriptor` when classifying a direct call result.
- the caller-side floating, string, and boolean result maps are deleted.

The focused negative control is a zero-argument function returning `f64`. The
old map excluded it because that map coupled result class to parameter ABI slot
count; the graph query classifies its call as `.f64`. An `i64` sibling proves the
query is not a blanket float classification.

This does not close GAP-116. The graph is still lifted from syntax at this
entry point rather than consuming all post-sema facts, and DNIR still rebuilds
record-result and parameter-ABI classifications. The next safe descent is to
carry record result identity without a name-keyed map, keeping parameter
placement separate because it is a different fact.

Evidence: `zig build unit-test --summary all`, `zig build`, `zig build test`,
`zig build native-differential`, `zig build native-census`,
`zig build agent-smoke`, `zig build audit100`, and `zig build bench` pass under
the shared Duo build lock.
