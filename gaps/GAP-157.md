## Ruling

**No `std` anywhere.** Not in source spellings, not as a runtime table, not as
a migration alias, not as documentation teaching a namespace. Vocabulary reaches
through layout/home/world projection (`fs:read`, `json:encode`, `os.env[k]`,
`io:read`) — never `std.*`.

`lib/std.id` must not export a `std` binding. The `lib/` tree is filesystem
bootstrap provenance until renamed; it is not semantic authority and not a
namespace to call.

## Acceptance

1. Law projections state zero `std` without softening language.
2. `lib/std.id` exports no `std` table.
3. Agent/MCP/gate surfaces contain zero `std.` spellings at CODE position. A
   detector needle inside a `"` literal is not a reach; a gate that cannot
   name the spelling it forbids cannot enforce it.
4. The ratchet is `sh gate/admission.sh --census-only`. It lexes each line and
   charges only code-position reaches. `tools/node/dev/hostcensus` `std_dot`
   is a `.id`-only line-based trend row, not the ratchet.
5. Added-line firewall: new code-position `std.` = 0
   (`gate/admission.sh` rule B; `gate/idiom.id` and `gate/host.id` state the
   law but neither currently compiles — both refuse at DNB011 `dot__std`).

## The denominator, ruled 2026-08-23

**The code-position count is the budget.** A `std.` inside a `#` comment or a
`"` text literal resolves no home and reaches no world, so it cannot violate
`law.std.zero`. Charging it is not conservatism — it is a currency the ratchet
should not accept, because deleting 123 characters of prose bought 123 real
reaches with no gate objection.

## The ce03c7eb denominator reconciliation

Two numbers were live for one ratchet: `473` (all-position tokens minus
whole-file exemptions) and `335`/`350` (code-position sites). They are not two
estimates of one quantity; they measure different things.

Since `ee8adabf` main carries NO census at all — the position-blind one was
deleted along with `gate/std-fixtures.manifest`, and the objection recorded
against it was correct. But a quarantine on added lines cannot ratchet: it
stops growth and applies no downward pressure to the reaches already in the
tree. Both rules now ship, and they deliberately disagree about position.
The QUARANTINE charges the raw spelling at any position on an added line;
the CENSUS charges only code-position reaches.

The arithmetic, measured at `ce03c7eb`, residual zero:

```text
547  word-bounded `std.` tokens, all positions = 350 code + 114 text + 83 comment
512  ... with an identifier after the dot (the old regex's tail); the 35 it
     dropped are bare `std.` and ALL 35 sit in text or comments
473  = 512 - 39 whole-file pins over 6 gate scanners; ALL 39 are non-code
350  code-position reaches, every class
335  ... of those in files classed `canonical`

473 - 335 = 138 = 123 text/comment charged outside the pins + 15 code reaches
                  in non-canonical files (14 historical, 1 compile-fail fixture)
```

Moving to code position **lowers** the enforced number and removes headroom:
the old shape also exempted six whole files from the added-line rule, so a real
reach added to `gate/idiom.id` passed unseen. Full reconciliation, the
per-file second-blocker probe, and the hand-merge instruction for
`reconcile/shadow-clean-20260822` are in `docs/spec/std-zero-ledger.json`.
