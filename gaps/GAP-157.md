# GAP-157 — Zero std namespace elimination

**Status:** OPEN · **Filed:** 2026-08-12
**Priority:** P0 · **Kind:** architecture
**Owner:** Cursor (coordination / canonicality)

## Ruling

**No `std` anywhere.** Not in source spellings, not as a runtime table, not as
a migration alias, not as documentation teaching a namespace. Vocabulary reaches
through layout/home/world projection (`fs:read`, `json:encode`, `os.env[k]`,
`io:read`) — never `std.*`.

`lib/std.id` must not export a `std` binding. The `lib/` tree is filesystem
bootstrap provenance until renamed; it is not semantic authority and not a
namespace to call.

## Acceptance

1. Law projections state zero `std` without softening language.
2. `lib/std.id` exports no `std` table.
3. Agent/MCP/gate surfaces contain zero `std.` spellings.
4. `tools/node/dev/hostcensus` `std_dot` count ratchets monotonically down.
5. Added-line firewall: new `std.` = 0 (`idiomgate`, `gates/host`).

## Negative control

Deleting `std` from prelude: canonical homes (`fs`, `json`, `os`, `io`, …)
still resolve through layout projection.
