# GAP-213 — a literally false branch emits its comparison and its body

**Status:** OPEN · **Filed:** !2026-08-22T02:40:00Z
**Priority:** P1 · **Kind:** perf_gap
**Filed by:** claude-gap145
**Files:** src/dnir_lower.zig,src/native_backend.zig

## Measured at `0ed88cfb`

```id
main: i64 = ()
    n: i64 = 0
    if 3 > 100
        n = n + 7
    n
```

Answers `0`, correctly. `_main` is **eleven instructions**:

```
mov  x9,  #0x0
mov  x10, x9
mov  x9,  #0x7
add  x11, x10, x9      <- the dead body's arithmetic
mov  x9,  #0x3
mov  x12, #0x64
cmp  x9,  x12          <- a comparison of two literals
csel x11, x11, x10, gt
mov  x10, x11
mov  x0,  x10
ret
```

The live twin `if 3 < 100` is **also eleven instructions** — the two differ only
in the condition code. The answer is `mov x0, #0`.

## What this is and is not

It is **not** an if-conversion gap: the `csel` shows if-conversion already
fires. It is a **constant-condition** gap — nothing folds a comparison whose
two operands are literals, so neither arm is ever proven dead.

It is also not the comptime folder's job here, and that is the interesting
part: `comptime.foldRelationBody` did not fold this body at all, even though
every value in it is a literal. Whichever of the two is meant to own it, **no
producer currently answers "this condition is constant"** where realization can
read it.

## The class

This is the same shape as the rest of the session's findings, in the
performance register rather than the correctness one: a fact that plainly
exists in the program (`3 > 100` is decidable at lift) has no producer, so the
backend emits both arms because nothing told it not to.

The demand census measured the sibling cases at the same time and they are all
open: unused record fields survive (`mul x11, x0, #7919` for an unread field is
emitted), an unread application result still runs (`k: i64 = work(300000000)`
with `k` never read costs 0.0900s against a 0.0035s baseline), and an unread
interpolation still emits `malloc` plus two `snprintf`.

## Acceptance

`if <literal> <cmp> <literal>` emits neither the comparison nor the dead arm,
with a positive control that the live arm still emits and answers, and a
control that a **runtime** condition is unaffected.
