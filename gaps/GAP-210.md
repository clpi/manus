# GAP-210 — the comptime folder treats a loop body as a tail position

**Status:** CLOSED · **Filed:** !2026-08-22T01:10:00Z
**Priority:** P0 · **Kind:** wrong_answer
**Filed by:** claude-gap145
**Files:** src/comptime.zig

`comptime.Evaluator.BlockResult` conflates **"a statement's value"** with
**"the relation's answer"**. `evalBlock` early-returns on `.value`, and
`evalWhile`/`evalNumFor` early-return on a `.value` from the body block — so
**the loop exits after one iteration** and the fold publishes that as the
relation's constant.

`dnir_lower.zig:3759-3771` documents the exact opposite rule, correctly:

> A loop body is never an implicit-tail position: its last statement runs once
> per iteration, not once per call. Propagating `allow_return` here makes … the
> loop return after one pass.

Two producers of one fact — *is a loop body a tail position?* — and the fold
runs first.

## The wrong answers, measured at `ad03c0ea`

An ordinary, **terminating, effect-free** program:

```id
main: i64 = ()
    i: i64 = 0
    n: i64 = 0
    while i < 3
        n = n + i
        i = i + 1
        i
    n
```

| | exit |
| --- | --- |
| before | **1** |
| after | **3** |
| Lua oracle | 3 |

And divergence returns:

```id
main: i64 = ()
    while 1 == 1
        0
    0
```

| | behaviour |
| --- | --- |
| before | **exits 0**, `_main: mov x0,#0; ret` |
| after | never terminates, as written |

Both compile 0, run 0, no diagnostic. The same wrong constant reaches the
graph-backed C realizer (`--backend c --emit c` emits
`return idol_bits_i64(UINT64_C(0x1));`), so the defect is upstream of every
backend. `idol explain` reports `optimization_outcome_count: 0` — the erasure
has no provenance at all.

The step budget (`comptime.fold_step_limit`) **was** the intended divergence
guard. The tail-position defect defeats it: the loop leaves after one
iteration, so the budget is never reached.

## Fix

Thread `tail` through `evalBlockScoped` / `evalBlock` / `evalStmt` / `evalIf`;
`.expr_stmt` and `.call_stmt` answer only in the tail slot, using
`dnir_lower.stmtIsTailSlot`'s rule verbatim rather than re-asserting its
negation; `evalWhile` / `evalNumFor` evaluate the body with `tail = false`.

A diverging loop now exhausts the step budget, the fold **refuses**, and
ordinary lowering emits the loop.

## Why every instrument in the tree was clean

Unit suite: no movement. 524-program corpus differential on status **and**
output: zero diff. The untracked `gate/retention.sh` — see below — is
byte-identical PASS on both compilers.

Only a hand-written control finds `while i<3 { n=n+i; i=i+1; i }` answering 1,
and that control did not exist in the tree. This is the fourth instance this
session, after GAP-207, GAP-208 and GAP-209.

## The gate that should have caught it

`1b5211fd` added `gate/retention.sh`; `5566a2a0` reverted it **70 seconds
later**. It survives only as an untracked file, no gap names it, and it is not
in the P0 ledger.

It also could not have caught this, for three measured reasons:

1. It is a **ratchet**, not a correctness gate: its ledger records
   `divergent-call-retained broken` as the *expected* value, so it PASSes
   against a compiler with the bug live.
2. Its `hung` detector is `rc >= 128`, and `idol run` collapses **every** signal
   death to 128 (`main.zig:4562`, `:5075`, `:5549` — three copies of
   `.signal => std.process.exit(128)`, signal number discarded). A trapping
   program is scored as retained divergence.
3. It has **two outcome cells for at least six outcomes**: exit 0 (silent wrong
   answer) and exit 1 (named `DNB001` refusal) are both `broken`.

## What was NOT merged, and why

Divergence remains `SEMANTIC-VOCABULARY-BLOCKED`. It is not an effect —
`hang`'s application publishes `effect: {card: "none"}`, which is **true**;
`hang` has no effect, it simply never returns, and `demand.zig:433-441` already
records that folding the two changed a hang into a return once before. It is
not a trap either: a trap is observable and terminating (SIGABRT, exit 134);
divergence produces no observation ever.

The vocabulary is missing from the law, and `gaps/GAP-187.md` already names it:
`solution` in {exactly one, zero or one, one or more, zero or more,
**never returns**, **divergent**}. With this fix the compiler *detects* the
fact and lacks only the word — `hang: i64 = () / while 1==1 / 0` refuses at
`native_backend.zig:3177` with `missing: unspecified`, which is literally the
absent `never returns`.
