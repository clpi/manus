# GAP-227 — the compile stage is ruled a world and has no world fact

**Status:** OPEN · **Filed:** !2026-08-23T19:10:00Z
**Priority:** P1 · **Kind:** expressiveness_gap
**Filed by:** claude-worldstage

## The collision this gap follows from

Three faces of `@` are visible at the surface and `law.md` §5 admits exactly one
algebra for the sigil — "current-world access, injection, or world
qualification":

```
@(expr)    compile-time evaluation     confirmed live by gap[223], 128 code sites
@{ … }     world injection
@member    world access
```

`@` is one algebra ONLY IF compile-time evaluation is itself evaluation under a
world. C0 §52's table carried the row `@( … ) eval` with no account, in the same
table that binds "@ never means compiler magic and prefix directive syntax DOES
NOT EXIST" three lines below.

## The ruling, admitted

`law.stage.world` (C0 §52), with `docs/spec/law.md` §6 and `world.md` amended to
match. `@(expr)` is `apply(current world)(expr)` — the same composition
`anchor.apply` already gives `@{ … }`, one operand kind apart — and since stage
is a fact a world carries (`law.md` §6, §11), that is exactly

```
@(expr)  ==  expr@{ stage = comp }
```

The reading that `@` genuinely has two roles was considered and refused; the
grounds are recorded in C0 §52 beside the ruling.

## What is NOT executable, which is the gap

The ruling is currently PROSE. Nothing in the compiler carries it:

- `semantic_graph.WorldFact` is `{ world, home, reach, members }` — no parent,
  no fact-delta range — so `derive(W, D)` is unrepresentable and the compile
  stage cannot BE a world here. This is gap[203] closure item 1, and this gap
  is why it is worth more than one face's worth of effort: the derived-world
  fact is what gives the ruling something to be true of.
- There is no ambient-world entity to be the PARENT of a derived one. Worlds are
  published per reached host home (`os`, `io`, …); the current world of a module
  is not an entity.
- `@(expr)` publishes no world fact of any kind. Measured: `idol graph` over a
  subject whose only content is `x = @(1 + 2)` exports `"worlds":[]`.
- `expr@{ stage = comp }` does not parse. `parser.at_glued_world_face` RECOGNISES
  the shape and refuses it by name, so the recognition half already exists.

## Acceptance

1. `expr@{ stage = comp }` compiles, runs, and answers what `@(expr)` answers —
   a DIFFERENTIAL over the same subject, not two independent assertions.
2. The two spellings publish the same derived world identity, so the ruling's
   `==` is an executable equality rather than a claim.
3. `expr@{}` is `expr` (empty injection is identity) and
   `expr@{ stage = comp }@{ stage = comp }` is `expr@{ stage = comp }`
   (same-fact reinjection is idempotent), both on running programs.
4. A name absent at the compile stage is refused BY THE DERIVED WORLD'S
   no-fallthrough rule, not by a separate compile-time-constant diagnostic —
   `world.md`: "Resolution does not search `trial` and then fall back to the
   root world."
5. A delta the compiler cannot realize refuses BY NAME and says which fact is
   missing. Admitting `stage` and silently ignoring the rest is the failure mode
   this item exists to forbid.

## Why this is not a licence to build the fact and stop

A derived-world fact with no consumer that changes a realization is producer-
hollow, and this tree treats that as a refutation. The consumer is named in
acceptance 1 and it already exists: the comptime evaluator, with 128 code sites
of prior art. Build the fact THROUGH that consumer or do not build it.
