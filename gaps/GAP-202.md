## The AST-provenance clause is a global gate, and it is now executable

The acceptance line

> poisoning/removing AST provenance after graph publication leaves machine
> bytes unchanged

is not a property of scalar multiplication. It is `docs/spec/law.md` §1 ("Once
known, a fact is carried forward; downstream phases never reconstruct it from
syntax or representation") and §12 ("AST pointers, names, paths, strings, and
opcode tags are temporary bridges only") stated in a form that can FAIL. It is
therefore measured for the whole compiler rather than for one gap's operator:

    zig build sovereign        # the per-vertical census, on its own
    zig build unit-test        # the same measurement inside the merge signal

`src/poison.zig` damages a parsed tree IN PLACE after
`liftModuleWithCheckedCalls` — integer literal values, quoted bytes, every
identifier spelling, infix relation tags — without moving a node, so every
published `Node.ast_ref` stays dereferenceable. `src/sovereign.zig` realizes the
same module twice through `native_backend.emitObjectWithGraphLineage` and
compares OBJECT BYTES, not diagnostics and not exit status.

Three controls stand around the comparison, and they are the reason a verdict
means anything:

1. the undamaged object is emitted TWICE and the two byte strings must agree,
   so a difference cannot be a timestamp;
2. the damaged tree is COMPILED AS IF IT WERE THE SOURCE — a fresh `Sema`, a
   fresh graph, a fresh object — and those bytes must DIFFER, or the damage was
   invisible and the row is `vacuous`, which is not a pass. Reusing the original
   `Sema` here is too weak: sema resolves the foreign boundary before the
   damage lands, so an `@ffi("abs")` argument reads as unobservable when what
   is actually unobserved is everything sema decides;
3. `poisonModule` returns the damaged-site count and a zero refuses; a fixture
   with no site of a class reports `absent`, never a pass.

Per-vertical verdicts are pinned in `sovereign.verticals[].expect` and compared
live on every run, so they cannot decay into prose. Read them by running the
command, not from this file. Two notes the census produces are worth naming:
`damaged-source-object` means realizing from the FROZEN graph reproduced the
object of the DAMAGED PROGRAM bit for bit — the published graph contributed
nothing that class of syntax had not already decided; `refused-under-damage`
means the damage turned bytes into a diagnostic, which is a byte change.

### The determinism baseline, because byte comparison is not safe by default

A poison test on a nondeterministic artifact is not a control. `gate/byte/stable.sh`
measures where byte comparison is trustworthy in this tree, using the real CLI
in separate processes:

- **Object bytes (`--emit obj`) are stable across processes AND independent of
  the output path.** Measured over the corpus, three processes, deliberately
  different output names: identical. This is what the sovereignty gate compares.
- **Linked executable bytes are stable across processes and across DIRECTORIES,
  but NOT across output BASENAMES.** Two identical programs written to
  `aaaa.out` and `bbbb.out` differ in 52 bytes: `LC_UUID` (16 bytes, derived by
  `ld` from the output path), the ad-hoc code signature's `Identifier`, which
  IS the output basename, and the 32-byte CDHash that covers it. Same basename
  in two different directories: identical.

So: **diff objects; if you must diff executables, hold the basename fixed and
vary the directory.** That is a one-line change for any lane currently
comparing `a.out` against `b.out` and reading the signature delta as an effect.

`gate/byte/stable.sh` §4 is the positive control that keeps this honest — it
requires two different basenames to STILL differ, so the comparison cannot
silently lose the ability to see a difference at all.

Inside the sovereignty gate the same question is asked twice: the undamaged
object is emitted a second time from the same graph, and a third time from an
INDEPENDENT lift of the same source — a second parse, `Sema` and graph at
different addresses. The second form is the one that matters, because a
pointer-keyed hash iterates in an order the addresses decide and those move
between runs. Both agree for every vertical (`blocked=0`).

## Why the prototype was rejected

It introduced a scalar-specific semantic subsystem:

- `Sema.scalar_multiplications` and `scalar_multiplication_rows` were a second
  application registry;
- `SemanticGraph.scalar_multiply_relation` was a dedicated relation slot rather
  than an ordinary relation entity selected through the one application algebra;
- DNIR selected the path by consulting that dedicated slot; and
- operand realization still called `lowerExpr` on `ast_ref` provenance, so
  changing or deleting AST after graph publication could change machine output.

That violates `law.application.one`, `law.fact.producer.one`,
`law.graph.sovereignty`, and `law.ast.backedge` even though the emitted multiply
and its validation controls were individually useful.
