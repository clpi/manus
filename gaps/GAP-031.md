# GAP-031 — `tonumber` returns 0 on non-numbers instead of nil

**Status:** FIXED 2026-08-08 · **Filed:** 2026-08-07 · **Frequency:** 1
**Cited at:** `scripts/run_benchmark.duo` (`extract_times`)

(Renumbered from 029 — parallel-session collision, as with gap[030].)

## Repro

```duo
tonumber("Fibonacci(40)")   -- 0          expected nil
tonumber("Time")            -- 0          expected nil
tonumber("0.017439")        -- 0.017439   correct
```

## Why it mattered

Every "parse it and check whether it failed" idiom silently accepts garbage:

```duo
num = tonumber(word)
if num != nil          -- ALWAYS true
    use(num)           -- uses 0 for "Fibonacci(40)"
```

In the benchmark harness the first word of every timing line was accepted as
its time, recording 0. With gap[030] this produced a suite declaring C the
winner of all 40 benchmarks.

Same family as the recorded `to(f64) never fails`: Duo's string-to-number
conversions do not signal failure, so the nil check every Lua-shaped program
writes is dead code.

## FIXED 2026-08-08 — two layers, and the second one is why the first was never enough

`tonumber` was `lua_val_from_num(lua_to_num(v))`, and `lua_to_num` answers 0 for
everything it cannot read. That is the obvious half. The half that hid it:
codegen typed a `tonumber` call `.f64` in TWO places, so the destination was
declared a native `double` and the call was wrapped in `lua_to_num(...)` — a nil
returned by the helper would have been flattened to 0 before any caller could
test it. Fixing only the helper changes nothing observable.

- `src/codegen.zig` runtime string, `static inline lua_Value tonumber` — a
  number is itself; a string must be a COMPLETE numeral (leading/trailing space
  allowed, nothing else); everything else is nil. Rejects the `strtod`
  extensions Lua does not accept (`"inf"`, `"nan"`), so a numeral has to start
  with a digit or `.`.
- `src/codegen.zig` `builtin_return_type` — `tonumber` returns `.any`, not
  `.f64`.
- `src/codegen.zig` `structural_expr_type` — the `.call` arm claiming `.f64`
  for `tonumber` is gone. `tonumber(s) or d` keeps its numeric typing through
  the new `numeric_operand_type`, used only by the `and`/`or` arm, because that
  form consumes the nil on the spot.

`tonumber(s, base)` (commit 2e8b680) is untouched and still returns nil; it now
also survives the coercion that used to turn its nil into 0 — `tonumber("zz",
16)` was 0 before this fix and is nil after, without `tonumber_base` changing.

### Measured, same program, before → after

| expression | before | after |
| --- | --- | --- |
| `tonumber("abc")` | `0` (number) | `nil` |
| `tonumber(nil)` | `0` (number) | `nil` |
| `tonumber("Fibonacci(40)")` | `0` (number) | `nil` |
| `tonumber(true)` | `1` | `nil` |
| `tonumber("12abc")` | `12` | `nil` |
| `tonumber("zz", 16)` | `0` (number) | `nil` |
| `tonumber("0.017439")` | `0.017439` | `0.017439` |
| `tonumber("42")` | `42` | `42` |
| `tonumber("  12  ")` | `12` | `12` |
| `tonumber("0x1f")` | `31` | `31` |
| `tonumber(3.5)` | `3.5` | `3.5` |
| `tonumber("ff", 16)` | `255` | `255` |
| `tonumber("abc") or 99` | `0` | `99` |

And the idiom the gap is about, on a six-word list holding three numerals:
`if tonumber(w) != nil` counted **6** before and counts **3** after. A running
minimum seeded `nil` and guarded by that test returned `0` before and `1.5`
after.

The numeric surface is unchanged where it should be: `x: f64 = tonumber("42")`
is still `42`, `tonumber("0.5") + 1.0` is still `1.5`, `tonumber("7") * 6` is
still `42`, `tonumber("7") > 3` is still true. An explicit annotation is the
caller asking for a number, and it still coerces.


## Interim (historical — the gap is closed)

Check the shape before converting; `string.match` is exact:

```duo
if string.match(s, "^%-?%d+$") != nil          -- integer
if string.match(s, "^[0-9%.eE%+%-]+$") != nil  -- numeric-ish
```

## Relation to the canon

Epoch 2 denies `tonumber(`; the canonical form is `if n = s:to(i64)` — a
binding condition whose failure is *observable*, making it a value the caller
must consume (B-14 OBLIGATION) rather than a sentinel that reads as data. That
is the real fix; the shape check is the interim until it lands.
