## Closure counterexample

Commit `f43565a` validates `front`, `after`, the individually named files, and
`duofiles`, but does not validate `all`. Both the unclassified-syntax and
runtime-boxing censuses consume `all` through a pipeline that suppresses
`git grep` errors and lets `wc` return success.

Changing only that pathspec in a temporary copy proves the remaining failure:

```text
all = "'src/no-such-*.zig'"

./zig-out/bin/duo run /tmp/semanticgate-badall.id
exit 0
(semanticgate, count, unclassified, syntax, 0, cap=0)
(semanticgate, census, migratable, runtime.boxed, 0, cap=1271, ...)
(semanticgate, pass, ...)
```

The tracked baseline is 1271 `lua_Value` lines. A nonexistent source therefore
looks like complete removal and passes. Closure requires every census to return
both command status and count, or an exact positive control for every consumed
source. `2>/dev/null | wc -l` is not authoritative evidence.
