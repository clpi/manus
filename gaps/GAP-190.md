# GAP-190 — recovery continuation and condition-restart algebra

**Status:** OPEN · **Filed:** !2026-08-18T16:30:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/effect.id, src/control.id

Unify exception handling, algebraic effect handlers, Common Lisp conditions/restarts,
and Scheme continuations into a first-class recovery algebra. A failure or abnormal
condition application publishes condition facts and establishes an enumerated set
of admissible recovery relations/continuations, decoupling failure signaling from
recovery policy.

## Current measured boundary

Errors and effects are modeled as basic failure exits or trapped branches without
dynamically established recovery protocols.

**Crossed:**

- Effect facts exist in `src/effect.zig`.
- Control branches and alternative relations operational.

**Still missing:**

- `Condition` identity carrying diagnostic and state facts.
- `Restart` relation set: dynamically established recovery continuations.
- Continuation facts:
  - Invocation cardinality ($0$, $1$, $\ge 1$)
  - Escaping vs non-escaping lifetime
  - Dynamic-wind resource extents crossed
- Multi-tier realization:
  - Known static recovery -> inlined branch / zero unwinding overhead
  - Non-escaping one-shot restart -> local jump
  - Escaping restart -> stack frame / movable continuation
  - Interactive / compiler restart -> agent, debugger, or user dialogue (e.g. "missing proof: insert guard, profile, copy, or refuse")

## Required order

1. Specify condition/restart relations and continuation facts in C0.
2. Formalize continuation usage and escape lattices.
3. Lower non-escaping recovery to direct machine branches.
4. Implement interactive restart dialogue for compiler fact acquisition.
5. Prove zero overhead for statically resolved recovery paths.

## Closure acceptance

Close when conditions and restarts are first-class semantic objects that inline to
direct branches when recovery is known statically and provide rich interactive
restarts during compilation and development.
