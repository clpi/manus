# GAP-017 — a lexer error aborted the process — CLOSED 2026-08-07

**Status:** CLOSED · **Filed:** 2026-08-07 · **Closed:** 2026-08-07
**Sites:** `lib/std/compiler/lexer.id` `_fail` (the fix, cites this gap)

## The defect

`lib/std/compiler/lexer.id` raised `error("UnterminatedString")` and friends at
ten sites. That killed the whole run, so one bad file truncated any corpus walk
and silently shrank the denominator — `scripts/parser_corpus_coverage.id` had to
skip `lib/std/os/linux.id` visibly rather than absorb the loss.

It also made SH-03 production dispatch impossible: routing the compiler through
this lexer would have turned every malformed source into a bare abort with no
location, instead of a diagnostic.

```
$ duo run walk.id
error: UnterminatedString
rc=1            # process dead, before the first print
```

## The fix

`Lexer` already carried `has_error: bool` and `error_loc: Loc` — initialized and
never set, designed for this and abandoned. A rejection now uses them, plus an
`error_code` mirroring `src/lexer.zig`'s `LexError` order:

    1 UnterminatedString  2 UnterminatedLongString  3 InvalidEscape
    4 UnexpectedChar

`_fail(self, code)` records the FIRST error (later ones are consequences, and
reporting the last points at the wrong place) and each site returns a benign
value — `""` for the string readers, an EOF token for `next_tok`, so the caller's
loop terminates.

The exports surface it as a negative return, offset by 100 so it cannot collide
with `-1` (buffer too small): `-101 … -104`. `duo_lexer_error_line` gives the
location on the cold path.

```
unterminated string: reached EOF after 4 tokens
stray bytes: reached EOF after 8 tokens
unterminated long: reached EOF after 4 tokens
SURVIVED ALL          rc=0
```

## Verification

- `src/duo_lexer_dispatch.zig` maps the codes to `lexer.LexError`; two
  regression tests assert `UnterminatedString` / `UnterminatedLongString` are
  *catchable errors*, and one asserts the rejection carries its line.
- Corpus unaffected: parser coverage stays 255/255, selfhost proofs 12/12.

## Follow-on

`scripts/parser_corpus_coverage.id` skips `lib/std/os/linux.id` because of this
gap. That skip can now be removed and the denominator grown — not done here, so
the ratchet moves in a change of its own.
