## Fix direction

| # | directive |
|---|---|
| 1 | The fix is in **sema**, not in either backend: `i64 / i64` must have type `i64`. |
| 2 | Both backends are then consistent with B-4 and with each other, and the C emitter stops needing a double at all. |

| # | directive |
|---|---|
| 1 | **Blast radius is real: 439 tracked `.id` files contain a `/`.** Any file currently relying on `/` yielding a float — `(a + b) / 2` used as a float, ratio computations on integer inputs — changes meaning. |
| 2 | That is a corpus migration with a mechanical repair (`to(f64)(a) / to(f64)(b)`, or make one operand a float literal), and it must be measured before it is done, not after. |

| # | directive |
|---|---|
| 1 | Do NOT "fix" this by teaching the C backend to print the double as an integer. |
| 2 | That preserves the type error and makes the two backends agree on the wrong answer, which is strictly worse than disagreeing. |
