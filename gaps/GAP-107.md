# GAP-107 — canonical compiler source lacks a graph-owned export projection

**Status:** OPEN · **Filed:** 2026-08-09
**Priority:** P0 · **Kind:** expressiveness_gap
**Files:** docs/spec/constitution.md,lib/std/compiler/lexer.id,lib/std/compiler/host.id,lib/std/token/classify.id,src/directives.zig,src/codegen.zig,src/native_backend.zig,src/native_req_support.zig,src/duo_lexer_bridge.zig,src/duo_lexer_dispatch.zig,tools/lsp/src/server.id

## Current law

C0 has already resolved the source and semantic model:

- `@` denotes an anchor; prefix directive syntax does not exist;
- leading colon is the ambient-subject application face, bare dot is invalid,
  and dot after a written subject is static named projection;
- relation identity is graph-owned and independent of source path, package,
  link symbol, target, and source face;
- a foreign operation retains symbol, origin, lawset, ABI, effects, ownership,
  uncertainty, world requirements, and provenance as facts; and
- physical ABI follows call-graph demand and realization rather than becoming a
  second semantic callable identity.

Prefix export directives are therefore migration syntax. They are not an
Idsem relation, a compiler namespace, or permanent foreign interface design.

## Executed blocker

The historical compiler source still uses `@c.export` and
`@comp.c.export` to make seed-callable symbols. The production lexer alone has
seven such sites, and the host shim supplies two more. The generated C lexer
linked by the seed depends on those exports, so deleting the spellings before a
replacement lands would remove the only executed Idsem-owned lexer boundary.
Plain `@export` is the same unresolved prefix-export family for native and Wasm
entry visibility; it is not a separate canonical relation.

Host consumers deepen the dependency:

- the parser and directive registry recognize the prefix forms;
- code generation and the native backend select visibility and symbol names
  from host attribute records;
- native module discovery scans source text to recover export names;
- the host bridge's handwritten six-entry lexer manifest omits the
  production-consumed error-line export and has already drifted from source;
- generated token classification and several bootstrap modules use the same
  path; and
- LSP completion still advertises the retired source face.

This does not make the directive semantic authority. It proves that canonical
`.id` compiler source lacks the physical projection required to replace it.

## Required owner seam

The semantic graph owner must publish the exact callable and foreign facts
already known for each exported realization:

- relation and callable graph entity;
- foreign symbol and origin;
- lawset and witnessed equivalence where a native relation is involved;
- linkage, visibility, calling convention, target, and observable ABI demand;
- world, effects, ownership, failure, and uncertainty where applicable; and
- source-to-graph provenance without source path or directive spelling in
  semantic identity.

The realization owner must consume those facts to derive C, native-object, and
Wasm export tables and machine/link behavior. A compact generated manifest is
allowed as a physical projection. It must not become a runtime registry, a
second identity catalog, a textual source scan, or another opcode/ABI ontology.

The self-host/frontend owner can then compile canonical `.id` source through
that projection and remove prefix recognition. It must not invent a local
bootstrap export registry or another directive spelling.

## Required controls

1. Perturbing the graph-owned export fact changes or breaks the real production
   symbol, proving that the canonical producer executes.
2. Removing that fact fails closed; host source scanning and default visibility
   do not reconstruct it.
3. Moving an implementation between packages or source paths preserves native
   relation and application identity.
4. Changing only foreign symbol, linkage, target, or ABI changes the matching
   realization/provenance facts without minting another native relation.
5. One semantic callable may retain several lawful realized ABI faces when
   different callers demand them.
6. C, direct native, Wasm, object metadata, LSP, MCP, diagnostics, and evidence
   agree on shared semantic identity and facts while retaining lawful
   target-specific projections.
7. Sealed output contains no runtime catalog, source path, directive spelling,
   or unnecessary adapter.
8. Canonical `.id` contains no `@export`, `@c.export`,
   `@comp.c.export`, or other prefix export directive.

## Deletion gate

Close this gap only when:

- executed canonical `.id` compiler source produces the production graph-owned
  export facts;
- generated-C regeneration and direct-native/object/Wasm paths derive their
  target- and demand-specific projections from those same facts;
- production perturbation and ABI/symbol differentials pass;
- parser/directive recognition, source-text export scans, host attribute
  authority, meta-module aliases, and LSP completion for `@export`,
  `@c.export`, and `@comp.c.export` are deleted; and
- the historical lexer/token/compiler source using those forms is semantically
  migrated and deleted, with no host fallback.

Until the graph and realization interfaces exist, this is
`OWNER-BLOCKED` on those exact projections and `IMPLEMENTATION-BLOCKED` for the
self-host owner. Extending the prefix mechanism is not an admissible repair.
