# GAP-032 — `x:to(i64)` does not compile in a typed position; `to(i64)(x)` does

**Status:** open · **Filed:** 2026-08-07 · **Frequency:** 2 sites in this diff
**Blocks:** LAW-CALL — the canon's *canonical* face is the broken one
**Sites:** `scripts/census/identifiers.duo` (`distinct`, `occurrences`)

## The defect

LAW-CALL is unambiguous: *subject-first when the subject is in hand.* Epoch 2
§0.7 repeats it (`to(str)(x)` inside string-building is denied in favour of the
receiver form), and §4's repair table sends `tonumber` to `if n = s:to(i64)`.

Measured, the receiver face does not compile when its result must satisfy a
declared numeric return:

```duo
count(cmd: str): i64
    out = std.script.chomp(std.script.capture(cmd))
    out:to(i64)
end
```
```
/tmp/duo_x.c:7790:12: error: returning 'lua_Value' from a function with
    incompatible result type 'int64_t' (aka 'long long')
    return ({
        lua_Value __self = out;
        lua_Value __fn = lua_table_get_str_lit(__self, "to", …);
        lua_invoke(__fn, 2, __argv);
    });
```

`x:to(T)` lowers to a **boxed dynamic dispatch** — a table lookup of the member
`"to"` followed by `lua_invoke` returning `lua_Value`. It never reaches a native
`i64`. The section face lowers correctly:

```duo
    to(i64)(out)      -- compiles, returns a native i64
```

So the two faces the canon calls *one edge* are not one edge: one is a static
conversion, the other a boxed member call.

## Second defect, same repro

Chaining the receiver face directly onto a call makes the compiler take the
**preceding binding** as the body's result:

```duo
count(cmd: str): i64
    r = root()
    c = "grep … {r} …"
    std.script.chomp(std.script.capture(c)):to(i64)
end
```
```
identifiers.duo:33:11: error: return type mismatch: expected 'i64', got 'str'
   |     c = "grep … {r} …"
   |         ^
```

The diagnostic points at the `c = …` line — the tail expression was not
recognized as the tail at all. Binding the intermediate makes it unambiguous.
Note this pushes the source *toward* a TMP-1 violation, same shape as gap[29].

## Why it matters

This is not a missing feature but an **inverted** one: the face the canon denies
works, and the face it mandates does not. An agent following LAW-CALL literally
writes the broken form, and the failure surfaces as a C type error naming
`lua_Value`, far from the rule it violated. Same class as the LV-4 and STR-1
episodes — canonical spelling, wrong output.

`to(str)` in the receiver face **does** work (`(42):to(str)` is a live row in
`scripts/census/modes.duo`, P86-C2), so this is specific to conversions whose
result must be a native scalar, not to the receiver face in general. That
narrowness is what makes it easy to miss.

## The fix

`x:to(T)` should lower to the same static conversion as `to(T)(x)` when `T` is a
primitive descriptor, rather than to a member lookup on the receiver. The
existing `to(str)` receiver path shows the projection already exists for one
direction.
