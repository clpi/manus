# GAP-115 — test evidence is corruptible by concurrent sessions, so gate results are not facts

**Status:** OPEN (P0, evidence integrity) · **Filed:** 2026-08-09
**Law:** §3 MEASUREMENT HONESTY · "one fact, one authority, explicit provenance"
(owner ruling 2026-08-09 §28)

## The ruling

> Current smoke-test evidence has been corrupted by concurrent sessions sharing
> mutable artifacts such as logs/cache state. For an agent-native compiler, each
> agent run should receive a unique run ID, private temp directory, private
> mutable logs, private mutable cache namespace, isolated generated artifacts.
> Only immutable/content-addressed cache data should be shared freely.
>
> **A test result whose evidence can be overwritten by another agent is not an
> authoritative fact.**

## The evidence, all from one day

**1. Two independent agents saw `agent-smoke` report a failure the program does
not have.** One traced its cause: `/tmp/as.log` was being written by a
concurrent session in the main checkout, so its first result was another tree's.
It re-ran into a private log and got a different answer.

**2. The failure I measured does not reproduce.** `agent-smoke` reports
`std_metaprogramming_modules_smoke` FAIL; run directly the program exits **0**
and prints `RESULT std_meta_modules ok`.

**3. `zig build test` MUTATES A TRACKED FILE.** Two separate agents reported
`tools/lsp/src/server.id` modified as a side effect of running the gate — the
lsp-gate regenerates the legend and the committed copy is stale. Both reverted it
rather than sweep it. **A test that edits the repository is a shared mutable
artifact inside version control**, and it makes `git status` unreliable as a
signal of what an agent changed.

**4. The `.zig-cache` is shared across every worktree**, so a concurrent rebuild
can land under a running gate.

**5. I propagated a stale gate fact into five agent briefs.** I told each that
`agent-smoke` is red at `explain: FAIL` and not to chase it. By the time they
ran, `explain` PASSED and the failure had moved. One agent reported this
correctly and I did not believe it until I re-ran.

## Why this is P0 rather than an annoyance

**It silently inverts conclusions.** Item 5 is the worst: five agents were told
to ignore a red gate that had gone green, so any of them who saw a NEW failure
had been pre-instructed to attribute it to the known baseline. That is a
manufactured false negative, distributed.

And it defeats the session's own method. Every real finding today came from
perturbing one input and diffing against the general path — a discipline that
assumes the measurement apparatus is stable. When the apparatus is shared and
mutable, "I changed X and the gate changed" is not evidence.

## What is owed, in order

1. **Private logs, mechanically.** No gate may write a fixed path under `/tmp`.
   A run ID in the path is sufficient and costs nothing.
2. **Stop tests mutating tracked files.** The offending in-tree LSP generator
   and tracked output were deleted on 2026-08-17. The general rule remains: a
   gate may compare generated output in a private build directory, never repair
   a tracked source while measuring it.
3. **A private cache namespace per worktree**, or an explicit statement that the
   cache is content-addressed and therefore safe. Today it is neither documented
   nor namespaced.
4. **Gate results carry provenance** — which tree, which commit, which run ID —
   so a result can be attributed rather than assumed.

## The rule that follows, and it is cheap

**Re-measure before citing a gate's state, and never carry a known-failing fact
across a session boundary.** Both of my errors above came from treating a
measured fact as durable. In a tree with four concurrent sessions, a gate result
is true for a moment, not for a day.
