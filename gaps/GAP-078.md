# GAP-078 — two role taxonomies now live in `tools/lsp/`, and they disagree on H-1

**Opened** 2026-08-08 · **Status** OPEN · **Owner** unassigned — this is a RULING,
not a repair, and neither of the two implementations may resolve it alone.

## What is true right now

Two independent role implementations landed in this tree on the same day, both
citing CLAUDE.md §0d/§0g, and they do not agree:

| | `docs/spec/roles.md` + `scripts/role_scan.duo` + `fixtures/highlight/*.roles.duo` | `tools/lsp/src/highlight.duo` + `fixtures/highlight/duon,mixed,roles,surface` |
|---|---|---|
| closed count | **17** named, §4 shows the arithmetic and calls H-2's 18 underspecified | **18**, per commit 442cc8a "H-2 holds at 18 — the discriminator is hue, not the count" |
| ordinary binding | `name`, and §3 calls it "the largest hole" — UNHUED, not counted | `place`, blue, heavy at the declaration |
| string literal | `literal` | `text` |
| the §0g fine splits | 13 UNHUED roles (`bind`, `levelparen`, `comma`, …), outside the closed set | `cards` — refinements WITHIN the 18, plus a `layout` role |
| **`:` copula vs invoke** | **grammar.md R1** — a call group is present or it is not | **spacing** — §0d's "copula SPACED, invoke TIGHT" |
| unresolved candidates | emits `ambiguous`, counted, never a token | no `ambiguous` member |

## The line where they give different answers

`fixtures/highlight/copula.duo` line 3:

```
count:u32
```

It is TIGHT and it has NO call group. R1 says **copula**; spacing says
**invoke**. `fixtures/highlight/copula.roles.duo` — hand-written — says
`copula`, and `docs/spec/roles.md` §5.1 carries the argument in full:

> R1 is the parse rule and is total. §0d is a statement about what canonical
> layout emits, and it is a *corollary* on canonical input, not the decider.

`highlight.duo`'s own header takes the other side and says so out loud:

> `:` by LAYOUT … Because the renderer is normative, spacing is a FACT ABOUT
> THE GRAPH that survives into the byte stream.

Both arguments are serious. Neither is a mistake. **One of them is law and the
other is a finding, and nothing in the tree says which.**

## Why it cannot be left

§0d: "`highlights.scm` and the LSP legend are GENERATED from the graph service
— hand edits are an H-1 drift finding." There are now two generators for one
legend. Whichever a front end picks, the other convicts it, and both corpora
are golden. G-TOTAL's coverage and ambiguity numbers are not comparable across
them: 17-with-`ambiguous` and 18-without measure different things.

## What the LSP does today, stated so it is not mistaken for a ruling

`tools/lsp/src/server.duo` serves `textDocument/semanticTokens` with a legend
GENERATED by `tools/lsp/legend.duo` from **`docs/spec/roles.md` §2 + §3**, and
its scanner decides `:` by **R1**. That was written before `highlight.duo`
landed, and it was anchored to `docs/spec/` because that is where the tracked
spec lives — not because the question was settled. `zig build lsp-gate` asserts
the token stream for `copula.duo` byte for byte against the hand-written
sidecar, so the LSP is currently CONVICTABLE by one corpus and silent about the
other.

## What closes this

A ruling in `CLAUDE.md` that names, for the record:

1. the count — 17 or 18 — and, if 18, the eighteenth member by name;
2. the decider for `:` — R1 or spacing — and what happens to `count:u32`;
3. whether the §0g fine splits are roles, cards, or modifiers;
4. which of `fixtures/highlight/*.roles.duo` and `fixtures/highlight/duon/**`
   is the golden corpus, or how both are.

Then ONE generator survives, the other's front end regenerates from it, and
both gates assert against the same corpus. Until then any G-TOTAL percentage
published from either side should carry which taxonomy produced it.

## Falsifier

If a later commit reports a G-TOTAL coverage number without naming its
taxonomy, or if `role-scan` and the LSP's own census are compared to each other
as if they measured the same quantity, this gap was closed by forgetting rather
than by ruling.

## RULING 2026-08-08 — both questions were already decided; this is the mapping

**Owner: resolved. An agent may now execute this mechanically. Do not reopen
either question; implement the table.**

### Q1 — `:` copula vs invoke. **R1 WINS. `roles.md` is right.**

Already ruled in `CLAUDE.md` §0d: *"grammar.md R1 decides the `:` role; §0d's
spacing sentence only RENDERS it."* `docs/spec/grammar.md` is NORMATIVE (Pass
108). §0d's sentence — "canonical layout makes L1 lexical" — is a statement
about what the formatter EMITS on canonical input, which is a corollary, not a
decider. `count:u32` is a **copula**.

`highlight.duo`'s counter-argument ("the renderer is normative, so spacing is a
fact about the graph that survives into the byte stream") is serious and it is
still WRONG, for a reason worth keeping: spacing survives into the byte stream
only for input the formatter has already touched. A role function that is total
must answer for input it has NOT touched — hand-typed, mid-edit, pasted, or
foreign. R1 answers there; spacing does not. **Totality is what breaks the tie.**

### Q2 — 17 vs 18. **NEITHER IS LAW. The count was never the ruling.**

Already corrected in `CLAUDE.md` §0d: the rendered spec states H-2 as *"the role
set is closed"* — **with no number**. "18" was a summary artifact of mine and I
adjudicated on it once before catching it. The RULING is CLOSURE: finite,
enumerated, total. The COUNT is a BINDING and is checked against what the
renderer needs.

So the 17/18 disagreement is **not a conflict to resolve** — it is two correct
enumerations of different working sets. `roles.md` §4's arithmetic showing H-2's
18 is underspecified was RIGHT. Stop defending a number in both files.

### Q3 — `name` vs `place`, and this is the one that matters

`roles.md` calls the ordinary-binding role `name` and leaves it **UNHUED**,
counting it as a hole. `highlight.duo` calls it `place`, blue, heavy at
definition. **H-6 makes the role function TOTAL**, and an unhued role cannot
satisfy a total function — that is exactly why one implementation measured 20%
coverage and the other 100%.

**The hue is required; the spelling is not.** Take `place` (it is what the
spec's own renderer calls it, and a binding IS a place in dnir), hue it blue,
heavy at definition.

### The mechanical mapping — apply, do not relitigate

| question | winner | loser becomes |
|---|---|---|
| `:` copula/invoke | `roles.md` — **R1** | `highlight.duo`'s spacing decider is a FINDING; delete it |
| closed count | **neither** — closure is the law | both files stop asserting a number |
| ordinary binding | `highlight.duo` — **`place`, blue, heavy** | `roles.md` §3's "largest hole" is CLOSED; rewrite it as closed |
| string literal | `roles.md` — **`literal`** | a spelling difference only; no argument either way, so take the tracked spec |
| §0g fine splits | `highlight.duo` — **cards within roles** | but see below: Pass 118 §4 names SPACE WALK its own ROLE, so cards are not universal |
| `ambiguous` | `roles.md` — **keep it** | G-TOTAL requires ambiguity=0 to be COUNTED, not absent; a taxonomy with no way to say "two candidates" cannot report the number the gate needs |

**Pass 118 §4 overrides the card reading where it speaks:** SPACE WALK
(`to[str]`) is its own ROLE, descriptor-tinted. Braces (matching stack), comma
(stratify), unit `*`, dnir `=`/`->` stay CARDS. Where the law names a role, take
the law; the hue discriminator governs only where it is silent.

### Acceptance — the fix is not done until all four hold

1. ONE taxonomy module. The other is deleted, not left beside it.
2. `count:u32` resolves **copula** in both corpora, proven by value at the byte.
3. Coverage 100%, ambiguity 0, **provenance 100%** — three numbers, all three
   reported. Specificity reported separately (Pass 118): a token whose card
   cannot beat its lexical class is a finding.
4. Positive-controlled: corrupt the decider and prove the gate goes red.
