# GAP-135 — Reader proof adds broken Zig semantic reconstruction instead of Duon authority

**Status:** OPEN · **Filed:** !2026-08-09T23:08:09Z
**Priority:** P0 · **Kind:** native_lowering_gap
**Filed by:** codex-root-shc-audit-20260809
**Files:** src/codegen.zig,examples/spec100/read.id,lib/compiler/reader.id

Current dirty proof is not landable: check passes; C run emits invalid `})__read()` plus undeclared `compiler`; direct refuses `method-unresolved:copy`. The new codegen map derives relation result descriptors by reparsing dependency AST and indexing textual home|descriptor|method|arity. It is not resolved graph identity and increases Zig semantic ownership. Closure must originate in canonical Duon semantic authority, feed both C bootstrap and direct realization without reconstruction, and prove chained record/string/i64 subject relations. Do not repair by expanding the Zig cache.

definition and result descriptor into direct lowering through the shared graph.

## Architectural regression

This does not merely miss a future graph facility. Commits `747ae09` and
`088461f` already established `SemanticGraph.funcResultDescriptor` and deleted
the floating, string, and boolean caller-side result reconstruction maps from
DNIR lowering. The dirty `subject_relation_results` map recreates that retired
architecture in the C backend:

```text
dependency source
  -> parser AST rescan in codegen
  -> result type resolution in codegen
  -> home|descriptor|method|arity string key
  -> native precheck classification
```

The key is not a definition, relation, subject, descriptor, or graph identity.
Aliases, overload constraints, imported descriptors, and distinct homonymous
definitions are therefore outside its proof. The cache also leaves emission
and precheck with different answers, which is exactly why the proof passes
`check` and fails in both realization paths.

## Required closure

1. Keep `lib/compiler/reader.id` as the semantic owner only if `compiler` is
   an admitted home and the source is current canonical Duon.
2. Resolve each subject application to one relation definition identity before
   realization. Attach its exact result descriptor to that identity in the
   shared semantic graph.
3. Make both bootstrap C projection and direct realization consume that same
   identity and descriptor non-optionally. Neither backend may rescan an AST or
   infer the relation from a textual home/name tuple.
4. Prove direct execution by value for record -> record -> i64 and record ->
   record -> str -> len chains, plus alias, overload, homonym, and unresolved
   negative controls.
5. Prove readable graph, DNIR, and machine provenance point to the same relation
   and value identities and that the typed path contains no boxed runtime.
6. Delete `subject_relation_results`, `noteSubjectRelationResults`,
   `knownSubjectHome`, `knownSubjectDescriptor`, and
   `knownSubjectRelationType` rather than expanding them.

Any temporary Zig wiring is admissible only as a non-semantic pointer/query
bridge to already-produced Duon authority, with step 6 as its immediate deletion
trigger. A larger Zig cache is negative SHC progress even if it makes this one
fixture run.
