# GAP-088 — the constructor ladder's first rung does not lower, and syntax cannot fix it

**Status:** OPEN · **Filed:** 2026-08-08
**Severity:** ROOT BLOCKER. Upstream of gap[082] scaling, gap[087], §41's
canonical form, and the entire constructor ladder.
**Law:** CLAUDE.md §0.4 CONSTRUCTOR LADDER · Pass 100 §6, §15.1 · `law.canon.performance`

## Measured 2026-08-08

| form | source | result |
|---|---|---|
| `p: point = { x = 3.0, y = 4.0 }` | typed binding + bare table | **WORKS** — prints 3 |
| `point{ 3.0, 4.0 }` | **spec §15.1's own example** | **FAILS** |

```
error: call to undeclared function 'point'
```

`point{ … }` lowers to a CALL to `point`, and nothing declares it. The
constructor ladder's rung (a) — `desc{…}`, the form §0.4 makes canonical while
BANNING `.new`/`.create`/`make_*`/`init` — **is not implemented**. The banned
alternatives are banned and the canonical form does not exist.

Exactly one construction path works, and it is the one nothing in the spec
writes.

## SYNTAX DOES NOT UNBLOCK THIS, and that is the finding

The question asked was whether minimal `.` or `@` syntax opens this up. It does
not, and inventing some would be the mistake A2 exists to prevent.

**The working form already needs no new syntax.** `p: point = { … }` is a typed
binding plus a bare table — two forms that already existed, composed. So:

- the SEMANTICS exist. A descriptor-shaped table with typed fields lowers
  natively today; that is what the working row proves.
- what is missing is only the NAMED CONSTRUCTOR PATH.
- `@{…}` is *already* in the grammar (Pass 108 `construct ::= "{" …`) and
  already means enclosing-descriptor construction. It parses. It does not lower.
  Adding syntax beside a form that already parses and fails to lower would add a
  second spelling for one missing lowering.

NNS says: *if a proposed repair needs new surface, you have not yet found the
existing form it is hiding.* Here the existing form IS found. **The repair is
that `point{…}` and `@{…}` must lower to what `p: point = {…}` already lowers
to.** That is a codegen repair, and no surface change is licensed.

## Why this is the root blocker

- **gap[082]** reported "a user descriptor cannot be attached to a value" and
  named it the thing capping the conversion algebra at N=4. Measured here, the
  cause is narrower and deeper: construction never worked, so there was never a
  value to attach.
- **gap[087]** found descriptor construction with a case field failing for BOTH
  the dotted and bare spellings. Same cause. It is not a dot question.
- **§41's canonical SELF-ZERO form** is `point{ x = x * k, y = y * k }` — rung
  (a). It cannot be written today.
- **The constructor ladder** (§0.4) has four rungs. Rung (a) does not lower,
  rung (c) `from(mode)` does not exist (recorded previously), and rungs (b) and
  (d) both produce values that rung (a) would have to construct.

## Already known, and that is its own finding

`duo-constructor-ladder-state` records: *"Pass 86 `from(mode)` does not exist and
`desc{...}` is broken; do NOT repair the 24 `from_*` sites in lib/std, the
target form won't compile."*

So this was measured before and written down, and the tree has been legislating
`desc{…}` as canonical ever since — including in a constitution that cannot be
migrated to it. A known-broken canonical form is worse than an unknown one: it
teaches every reader a spelling that fails.

## Fix

`point{ … }` lowers exactly as `p: point = { … }` lowers. The named path
resolves the descriptor, then emits the same shape the typed binding emits.
`@{…}` resolves the enclosing descriptor and does the same.

Fixture asserts BY VALUE, and asserts the two forms agree:

```
p: point = { x = 3.0, y = 4.0 }     -- works today
q = point{ x = 3.0, y = 4.0 }       -- must equal p field for field
r = point{ 3.0, 4.0 }               -- positional, §15.1
```

on BOTH backends. A construction that compiles and produces a zeroed record is
this tree's known failure mode — `tostring(d)` once reported `d=table` for a
decoder returning an EMPTY table, and a bisect built on that was wrong. Assert
field contents, never that it built.

## Do not

Do not add syntax. Do not repair the `from_*` sites. Do not migrate the
constitution to `point{…}` until this lands — `law.canon.performance` forbids a
canonical form that lowers worse than the one it replaces, and right now it does
not lower at all.
