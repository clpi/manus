| section |
|---|---|
| Fix |

| # | directive |
|---|---|
| 1 | **Sema accepts an initializer whose REPRESENTATION matches the nominal's underlying descriptor**, for the canonical spellings. |
| 2 | That is `law.nominal` stated as a rule: `feet` and `f64` share a representation and differ in identity, so `d: feet = 3.0` is well-typed and `d: feet = m` where `m: meters` is NOT. |

| # | directive |
|---|---|
| 1 | NNS: no new surface. `feet: f64` already parses; only the binding rule is missing. |

| # | directive |
|---|---|
| 1 | Fixture asserts BY VALUE on BOTH backends that: |

```
d: feet = 3.0        prints
feet and meters      remain DISTINCT — assigning one to the other DIAGNOSES
```

| # | directive |
|---|---|
| 1 | The second half is what makes it nominal rather than a rename, and a fixture that only checks the first would pass against a compiler that erased the identity entirely. |

| section |
|---|---|
| Do not |

| # | directive |
|---|---|
| 1 | **Do not use `type`.** It is on the §1 deny list; that it is the only spelling which compiles is a finding about the tree, not a licence. |
