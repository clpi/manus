# GAP-137 — SHC-01 DNIR application identity remains optional and fail-open

**Status:** OPEN · **Filed:** !2026-08-10T01:08:39Z
**Priority:** P0 · **Kind:** backend
**Filed by:** codex-root
**Files:** src/sema.zig,src/semantic_graph.zig,src/dnir_lower.zig,src/native_backend.zig

The current bootstrap bridge adds optional relation, application, and result
hashes to DNIR for a subset of checked subject calls. It does not close SHC-01.
The relation is not the selected callable identity, ordinary and uncovered calls
can still lower without it, callee text continues to select the implementation,
and public object emission carries no queryable machine lineage. Call labels,
operand descriptors, constants, world, return-pack shape, witness, provenance,
and meaning/content/incarnation identity are also absent. Repair must begin with
the Duon-owned application facts, then carry the same selected identity through
a fail-closed lowering and public machine projection without a name/op
translation table.

## 2026-08-10 Duon owner slice

`lib/compiler/application.duo` now names the complete structural boundary before
another host projection is attempted. Argument and return packs retain value,
label, position, descriptor, constant, and provenance identities. Its
application shape retains the relation, subject, argument and result packs,
descriptor facts, world, effects, witness, provenance, and demand. It does not
declare a smaller projection that could drop those facts. The type checker
admits this structural owner but does not create or observe graph identities.

`zig build shc-application` type-checks the schema and is reachable from
`agent-smoke`. It deliberately excludes the historical example corpus and any
direct run that writes a shared basename-derived artifact. The build wiring is
an authority-false Zig projection whose deletion gate is GAP-116's Duon-owned
derived aggregate.

This is the semantic owner, not production closure. Current Sema and DNIR still
omit pack identities and keep application lineage optional, and machine
selection still uses callee text. GAP-137 remains OPEN until graph-minted facts
replace those paths and survive the public object boundary.

## 2026-08-10 rejected prototype

A nine-path Zig prototype added 739 lines and removed 195 while projecting a
checked application through Sema, the semantic graph, DNIR, regions, and ARM64
byte ranges. Two independent reviews rejected it before commit. The prototype:

- used a store-local relation family rather than the selected callable identity;
- made the DNIR application reference optional and allowed production fallback;
- lost labels, operand descriptors, constants, world, and return-pack shape;
- continued to select calls, transforms, and machine branches by callee text;
- discarded lineage at the public object boundary; and
- added host semantic machinery without a Duon owner or deletion trigger.

A real current-source unit run remained at the known baseline, 1165 of 1168,
but that is only regression evidence and does not establish the semantic
contract. The prototype was rolled back. This gap remains open. The next slice
must establish the Duon-owned application/fact representation first, then add
only the smallest fail-closed, deletable Zig projection needed to carry the
same identity through realization.

## 2026-08-10 merge review of the replacement projection

The next in-flight projection was reviewed at `db48178` while its five source
files remained claimed and uncommitted. It improves one prior defect: a checked
plain call whose relation edge is missing now refuses with
`checked-application-identity`. It remains blocked from merge for four concrete
reasons:

1. `StableId` is still only a Wyhash `u64`. `id_index` keeps the first occupant
   of a collision, and DNIR stores only that hash. This is neither reversible
   canonical identity nor the required meaning/content/incarnation triple.
2. Application demand is copied from `call_shape.return_consumption`, an AST
   face. It is not produced by checked semantic demand and therefore cannot be
   called authoritative downstream.
3. Fail-closed coverage is incomplete. Static field/module calls, string
   primitives, hardware intrinsics, and other special call paths can emit
   `call_direct` without querying `checkedApplication`. Native validation only
   validates instructions that already carry `Instr.application`; it accepts
   an additional untracked call instruction.
4. The out-of-line projection contains only one result descriptor and ordered
   value hashes. It omits argument/result pack identities, labels, positions as
   facts, operand descriptors, constants, world, effects, witness, and
   provenance already owned by `lib/compiler/application.duo`. Public
   application-to-instruction and machine-byte lineage is separately required
   by C0 and still has no Duon owner.

The patch adds substantially more host semantic surface than it removes. Do
not merge it by weakening the four requirements or by relabeling the hash and
AST consumption as canonical facts. The smallest admissible bridge must make
every realized application fail closed, carry exact graph-minted identities,
and have an explicit deletion path into the Duon owner.
