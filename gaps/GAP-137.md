# GAP-137 — SHC-01 DNIR application identity remains optional and fail-open

**Status:** OPEN · **Filed:** !2026-08-10T01:08:39Z
**Priority:** P0 · **Kind:** backend
**Filed by:** codex-root
**Files:** src/sema.zig,src/semantic_graph.zig,src/dnir_lower.zig,src/native_backend.zig

The current bootstrap bridge adds optional relation, application, and result
hashes to DNIR for a subset of checked subject calls. It does not close SHC-01.
The relation is not the selected callable identity, ordinary and uncovered calls
can still lower without it, callee text continues to select the implementation,
and public object emission carries no queryable machine lineage. Call labels,
operand descriptors, constants, world, return-pack shape, witness, provenance,
and meaning/content/incarnation identity are also absent. Repair must begin with
the Idol-owned application facts, then carry the same selected identity through
a fail-closed lowering and public machine projection without a name/op
translation table.

## 2026-08-10 Idol owner slice

`lib/compiler/application.id` now names the complete structural boundary before
another host projection is attempted. Argument and return packs retain value,
label, position, descriptor, constant, and provenance identities. Its
application shape retains the relation, subject, argument and result packs,
descriptor facts, world, effects, witness, provenance, and demand. It does not
declare a smaller projection that could drop those facts. The type checker
admits this structural owner but does not create or observe graph identities.

`zig build shc-application` type-checks the schema and is reachable from
`agent-smoke`. It deliberately excludes the historical example corpus and any
direct run that writes a shared basename-derived artifact. The build wiring is
an authority-false Zig projection whose deletion gate is GAP-116's Idol-owned
derived aggregate.

This is the semantic owner, not production closure. Current Sema and DNIR still
omit pack identities and keep application lineage optional, and machine
selection still uses callee text. GAP-137 remains OPEN until graph-minted facts
replace those paths and survive the public object boundary.

## 2026-08-10 rejected prototype

A nine-path Zig prototype added 739 lines and removed 195 while projecting a
checked application through Sema, the semantic graph, DNIR, regions, and ARM64
byte ranges. Two independent reviews rejected it before commit. The prototype:

- used a store-local relation family rather than the selected callable identity;
- made the DNIR application reference optional and allowed production fallback;
- lost labels, operand descriptors, constants, world, and return-pack shape;
- continued to select calls, transforms, and machine branches by callee text;
- discarded lineage at the public object boundary; and
- added host semantic machinery without an Idol owner or deletion trigger.

A real current-source unit run remained at the known baseline, 1165 of 1168,
but that is only regression evidence and does not establish the semantic
contract. The prototype was rolled back. This gap remains open. The next slice
must establish the Idol-owned application/fact representation first, then add
only the smallest fail-closed, deletable Zig projection needed to carry the
same identity through realization.

## 2026-08-10 merge review of the replacement projection

The next in-flight projection was reviewed at `db48178` while its five source
files remained claimed and uncommitted. It improves one prior defect: a checked
plain call whose relation edge is missing now refuses with
`checked-application-identity`. It remains blocked from merge for four concrete
reasons:

1. `StableId` is still only a Wyhash `u64`. `id_index` keeps the first occupant
   of a collision, and DNIR stores only that hash. This is neither reversible
   canonical identity nor the required meaning/content/incarnation triple.
2. Application demand is copied from `call_shape.return_consumption`, an AST
   face. It is not produced by checked semantic demand and therefore cannot be
   called authoritative downstream.
3. Fail-closed coverage is incomplete. Static field/module calls, string
   primitives, hardware intrinsics, and other special call paths can emit
   `call_direct` without querying `checkedApplication`. Native validation only
   validates instructions that already carry `Instr.application`; it accepts
   an additional untracked call instruction.
4. The out-of-line projection contains only one result descriptor and ordered
   value hashes. It omits argument/result pack identities, labels, positions as
   facts, operand descriptors, constants, world, effects, witness, and
   provenance already owned by `lib/compiler/application.id`. Public
   application-to-instruction and machine-byte lineage is separately required
   by C0 and still has no Idol owner.

The patch adds substantially more host semantic surface than it removes. Do
not merge it by weakening the four requirements or by relabeling the hash and
AST consumption as canonical facts. The smallest admissible bridge must make
every realized application fail closed, carry exact graph-minted identities,
and have an explicit deletion path into the Idol owner.

## 2026-08-10 exact-handle projection review

The in-flight replacement at `3b4b05a` plus the shared dirty graph/backend
paths closes important parts of the rejected prototype. `StableId`,
`stable_id`, and `id_index` are removed; exact graph `NodeId` coordinates now
reach checked DNIR applications, regions, ARM64 instruction ranges, and the
lineage-bearing Mach-O object projection. A lease rejects coordinates from a
replacement graph at the same allocator address. Checked call selection is
validated relation-first and fails closed when required relation, application,
value, subject, descriptor, realization range, or graph-incarnation facts are
missing or inconsistent.

This is not transformation-lineage closure. `SemanticGraph.addShapeTransformApp`
and `attachCallTransforms` create exact graph transform nodes, then separately
call `transform_engine.logProvenance` with only shape/input/output hashes.
`transform_engine.ProvenanceEntry`, its snapshot, JSON output, and proof log
retain no graph transform, application, input value, output value, or graph
incarnation coordinate. The proof subject is also synthesized text. Deleting
fingerprints therefore preserves semantic selection but does not preserve the
existing transformation explanation. The checked native path currently refuses
any application instruction whose operation is no longer `call_direct`; that is
honest fail-closed behavior, not proof that constant folding or another
transformation preserves application lineage.

The graph-incarnation safety also has a measured physical cost that must remain
bounded. An ignored compile-time size probe on this exact dirty tree reported:

```text
Lease 8, SemanticGraph 208, Node 464, Edge 12
DNIR Module 112, DNIR Instr 304, Region 88, Region Node 192 bytes
```

The lease adds one pointer-sized field to each coordinate-bearing module,
region, machine output, and object projection, one lazy page-allocator anchor
per leased graph, and a retain/release pair per region. Region collections are
currently constructed and freed as one slice, so per-region lease cloning is
not yet justified by an escaping-region control. Do not call the compiler-state
effect preserved until a compile-latency/peak-state comparison is recorded or
the lease is lifted to the narrowest shared owner. Exact incarnation safety is
required; duplicated proof storage is not.

Remaining admission gates for this slice:

- graph transform node and exact input/output/application identities survive
  transformation proof and machine/object lineage without a hash standing in;
- a transformed checked application retains its original occurrence and result
  lineage instead of being refused or logged only by fingerprint;
- public production object emission exposes the exact lineage projection, not
  only private tests;
- the lease/state delta is measured and either justified or reduced; and
- the host projection names its executed canonical `.id` replacement and
  deletion gate. Until then GAP-137 remains OPEN.

## 2026-08-10 ONE-ID admission supersedes the exact-handle approval

The exact-handle direction above is no longer admissible as an endpoint under
the owner ONE-ID ruling. On local `f1cda68` with the shared graph/backend work
dirty, an exact source census reports 194 `NodeId`, 15 `NodeKind`, six
`EdgeKind`, and five `SemanticId` references under `src/*.zig`. One remaining
`StableId` occurrence is a stale relation comment. These are not merely private
array offsets: `NodeId` crosses semantic graph, graph query, DNIR, region,
native backend, machine lineage, and object projection APIs; `NodeKind` and
`EdgeKind` are exported as tool/query vocabulary; region scheduling exposes a
second `NodeKind`; and `pass26_semantic_operation.SemanticId` is another native
semantic registry.

The new graph lease also crosses DNIR, region, native output, and object
boundaries as a separate incarnation proof wrapper. It is directionally safer
than allocator-address continuity, but it preserves another public identity
concept instead of projecting one resident `id` plus facts from the exact graph
owner. The previously measured 464-byte graph `Node`, 192-byte region `Node`,
and per-consumer lease fields are compiler-state evidence against calling this
conceptual split physically closed.

The surrounding identity roots remain merge blockers even though they are not
all introduced by this dirty slice:

- The former `pass26_descriptor_intern.Registry` mapped one 64-bit semantic
  fingerprint directly to an intern slot and treated a hit as established
  equivalence. This owner, its declaration hash, and its graph/JSON identity
  projections are now deleted. Descriptor lifecycle, recursion, and completion
  remain facts produced directly during graph lift.
- `persistent_semantic_state` indexes reusable artifacts by a textual
  `entity_id` and permits reuse after fingerprint/version/target comparisons;
  it has no exact graph correspondence fact.
- transform provenance remains a separate text/fingerprint log rather than a
  transformation id and exact input/output/application facts in the same
  universe.

Therefore the current dirty graph/backend projection must not merge as
identity closure. The replacement gate is not another wrapper rename. The
graph owner must expose one compact resident `id`; semantic categories and
relationships must be facts/relations about that id; any physical row or tag
must remain private and derived; DNIR/region/machine consumers must carry that
same id without minting their own identity or kind vocabulary; and hash/intern
candidates must either be verified by exact authoritative facts or fail closed.
The combined unit gate passing does not override this architectural rejection.

## 2026-08-11 descriptor identity owner deletion

Descriptor alias lift no longer constructs a fingerprint registry or publishes
semantic fingerprint, declaration fingerprint, or intern-slot fields. These
values had no production consumer below graph lift and therefore represented
state and identity vocabulary without capability. The graph still publishes
descriptor lifecycle state, recursion classification, completion, shape,
provenance, knowledge, and stage.

The forced-collision control is deletion: descriptor meaning and graph facts no
longer query a descriptor fingerprint at all. This removes one identity root
but does not close GAP-137; application facts, transformation lineage,
realization correspondence, and machine/object lineage remain open.

## 2026-08-11 unwitnessed region rewrite refusal

The graph-backed region path now declines constant fusion and dead-constant
pruning until the graph owns the rewrite law, exact input and output ids,
application, witness, provenance, and selected realization lineage. The
physical discovery and rewrite routines remain candidate algorithms, but they
cannot mutate production DNIR from coordinates and dependencies alone.

A direct-native control over `x = 10; y = 32; x + y` returned 42 before and
after and produced a 33,512-byte Mach-O in both cases. Declining the unwitnessed
fold changes `main` from three instructions to seven; one compile observation
was 93 ms before and 85 ms after, which is not a benchmark. Restoring the
three-instruction realization is an explicit repair gate: publish and retain
the exact graph rewrite facts through machine and object lineage, then select
the fold from those facts. A local DNIR witness or coordinate record is not a
substitute.

## 2026-08-10 mechanical `NodeId` rename is not ONE-ID closure

The latest dirty projection replaces many `semantic_graph.NodeId` spellings
with `semantic_graph.id`, but preserves the split ontology and must not merge in
that form:

- `semantic_graph` still publicly exports `NodeKind` and `EdgeKind`, stores a
  kind on each 464-byte `Node`, and exposes name-plus-kind query selection.
- region realization still publicly exports its own `NodeKind` and stores
  `relation_id`, `application_id`, `value_id`, and `subject_id` fields beside a
  region `id`. These are qualification-bearing identity fields, not facts named
  `relation`, `application`, `value`, and `subject` over one id.
- functions continue to expose `semantic_identity` and `func_identity`; DNIR,
  regions, native output, and object validation carry `semantic_graph.Lease` as
  a public incarnation wrapper.
- tests and diagnostics still teach application identity, function identity,
  node identity, graph identity, identity counts, and identity collisions as
  separate layer concepts.
- name-and-kind lookup, AST pointer maps, source fingerprints, and the separate
  hash-only transformation log remain downstream reconstruction paths.

The useful part of the dirty work is retained: dense integer coordinates,
explicit subject/application/result facts, missing-argument fail-closed checks,
and resident-graph lifetime validation are real obligations. Correct them in
place rather than discarding the work, but factor them through one `id` and
facts. Private storage may keep compact tags and indices; public consumers may
not observe a node/kind/lease identity vocabulary. A spelling-only rename that
leaves those public concepts intact fails the negative control.

## 2026-08-10 direct-to-C fail-open boundary

Current `main` still treats every direct-backend refusal as permission to enter
generated-C realization in `auto` mode. `src/main.zig` catches the result of
`emitObjectForExecutableWithGraph` at the direct executable seam and continues
to `CodeGen.emit_module`. The producer does not expose enough semantic facts for
that decision: `native_backend.Error.UnsupportedProgram` currently represents
both a lawful physical subset refusal and invalid or incomplete meaning such as
missing application lineage, an orphan subject, partial realization lineage,
an unwitnessed transform, a graph mismatch, and unknown machine lineage.

The consumer must not classify those cases by matching `refusalNote()` text or
by adding a second backend-local taxonomy. The realization producer must expose
an authoritative outcome over the same id/fact universe which establishes one
of these facts:

- meaning is resolved and a generated-C realization is witnessed equivalent
  for the demanded semantics; or
- semantic facts, correspondence, witness, or lineage are invalid, incomplete,
  or unknown and compilation must diagnose before any alternative backend.

Until that fact crosses the interface, `auto` fallback is `OWNER-BLOCKED` and
cannot be made fail-closed truthfully in `src/main.zig` alone. Preserve and
correct the current graph/backend work rather than discarding it, but do not let
its generic error bucket authorize another semantic interpretation.

Required negative controls:

- remove or corrupt one required relation, application, subject, result,
  witness, or lineage fact and prove `auto` exits diagnostically before C
  emission;
- make direct machine realization physically unavailable while keeping meaning
  complete and prove C is considered only when exact equivalence and lineage
  are witnessed; and
- vary the diagnostic text and prove realization selection is unchanged.

## 2026-08-10 semantic graph preservation gate

ONE-ID strengthens the semantic graph; it does not replace the graph with
pipeline-local records. The target remains one universe of ids, facts, and
relations with specialized physical storage. Binding, descriptor composition,
subject, application packs, value flow, dependencies, worlds, effects, stages,
transformations, provenance, demand, realization, invalidation, foreign lift,
tool queries, and source-to-object lineage must remain directly queryable.

Preserve the useful parts of the current dirty projection: exact resident ids,
ambiguity refusing instead of first-name selection, checked application facts,
and application-to-machine ranges. Correct these parts in place rather than
discarding them. The current projection is still blocked because it retains a
public giant optional `Node`, `NodeKind`, `EdgeKind`, a second region `NodeKind`
and edge vocabulary, `semantic_identity`/`func_identity`, and qualification-
bearing `relation_id`/`application_id`/`value_id`/`subject_id` fields.

The physical replacement is compact graph storage, not a generic fact map:

- dense resident ids;
- specialized dense or sparse fact columns;
- packed relation, pack, provenance, and dependency ranges;
- compact derived indexes for applications and other frequent queries; and
- private lifetime/context enforcement that cannot become semantic identity.

The last requirement is currently regressed by the dirty diff. It removes graph
ownership checks from DNIR, regions, machine lineage, and object lineage while
bare `u32` ids still cross those boundaries. Removing a public lease wrapper is
correct only when ownership moves into one private shared graph context or
structural lifetime makes cross-universe mixing impossible. Preserve the
negative control: equal numeric ids from two resident graphs must never satisfy
each other's facts or lineage.

Capability-preservation admission must answer from the one universe, without
text/hash reconstruction: relation, subject, argument/result packs,
descriptors, transformation inputs/outputs, world/effects, demand, lawful and
selected realization, machine/object ranges, provenance, dependencies,
invalidation, tooling navigation, and proved cross-build correspondence. If
removing a node/kind wrapper makes any answer harder, the migration is not yet
the graph-native replacement required here.

Current dirty-slice review adds four concrete closure requirements:

- one graph-owned packed application query must retain ordered arguments and
  results plus world, effects, demand, witness, transformation, provenance, and
  selected realization; the current region/native tuple retains only relation,
  application, one result, subject, descriptor, and caller;
- every semantic direct call requires those facts even when the graph reports
  zero checked applications; an empty application census cannot authorize an
  identity-free `call_direct` or callee-text selection;
- transformation and realization joins consume exact ids and facts rather than
  region-local transform kinds, textual `subject_entity`, or package-prefixed
  record names; and
- refusal evidence belongs to the per-compilation outcome, not process-global
  mutable location/note buffers which concurrent compilations can overwrite.

Retain the sound allocation-failure cleanup, ambiguity refusal, packed argument
range algorithm, exact-once application validation, unwitnessed-transform
refusal, and machine byte ranges. These are obligations to move behind the one
graph fact interface, not work to delete.

## Algorithmic convergence gate

Closing the object graph is not permission to recreate a conventional pass
pipeline. The final graph owner must expose three reusable mechanisms from the
same ids, facts, relations, dependencies, witnesses, and provenance:

1. a sparse monotone consequence worklist whose fact families supply lattices,
   with SCC condensation and exact invalidation so unchanged facts do not pay
   for repeated whole-graph scans;
2. bounded persistent witnessed equivalence attached to the semantic graph,
   never a second e-graph IR, with growth controlled by demand, profile,
   expected gain, reuse, compile work, and peak state; and
3. demand/profile/cost-budgeted realization extraction, where layout,
   outlining, allocation/scheduling, and verified local synthesis are physical
   candidate strategies rather than semantic operation vocabularies.

Specialized columns, packed adjacency and pack ranges, bitsets, arenas, and
derived indexes are the physical substrate. Memory and observable effects use
graph-owned version/dependency facts rather than repeated alias walks or a
parallel MemorySSA ontology. Module and foreign-unit summaries are exact
projections that permit selective subgraph import; they never mint module-local
semantic identity.

This does not authorize implementing these engines in Zig ahead of the current
authority boundary. First make the complete application/fact query
authoritative and remove AST reconstruction below resolution. Then transfer
the engines into canonical `.id` in compiler-B dependency order. Any temporary
host edit must delete more semantic authority in the same slice.

Required controls eventually prove that changing the physical graph layout,
forcing every accelerator hash to collide, changing region partitions, or
removing an equivalence index preserves semantic query answers. Fact
perturbation must enqueue only exact dependents, and every extracted machine
choice must retain its equivalence witness and source-to-object lineage.
