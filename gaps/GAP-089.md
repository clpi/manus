# GAP-089 — a test that duplicates what it guards can never fail

**Status:** the instance is FIXED; the CLASS is open · **Filed:** 2026-08-08
**Law:** §3 MEASUREMENT HONESTY · `law.idiom.total`

`tests/test_hash.zig` was deleted today. The deletion is recorded only in a
concurrent session's merge commit (`3b5bad3`, which swept my staged removal), so
the reasoning is written here instead — the reasoning is the reusable part.

## The instance

The file's own header stated the defect without noticing it:

> *"The algorithm is duplicated here because `calc_lua_hash` is private to
> `codegen.zig`; these tests guard against accidental changes to the algorithm."*

A copy of an implementation cannot detect a change to that implementation.
Change `codegen.zig` and this file goes on asserting its own copy, green
forever. It was also **unreachable** — `build.zig` references `tests/` exactly
zero times (positive control: it references `src/` twenty times, so the grep
worked) — so it had never run at all.

Two independent reasons it could not fail. The real coverage exists and is live:
`zig build hash-agreement` ("compile-time vs runtime string hash must agree")
runs and exits 0. Verified BEFORE deleting, not assumed.

## The class, which is what this file is for

A test is not coverage because it exists. It is coverage when it can FAIL for
the reason it claims. Two ways today's tree violated that, both found by
measurement rather than reading:

1. **Duplicated subject.** The test re-implements the thing under test. It
   asserts self-consistency and calls it a guard.
2. **Unwired.** Nothing runs it. `tests/test_ast.zig` was the same shape and was
   removed earlier today; `tests/` is now empty and gone.

The same session removed **176 unit tests** (1341 -> 1165) that were apparatus
asserting apparatus agreed with itself, and the compiler lost no coverage. That
is the same class at scale.

## The check that would catch it

Any test asserting behaviour of a private implementation must either exercise it
through its real entry point, or be deleted in favour of a gate that does. And
every `*_tests.zig` should be reachable from a build step — an unreachable test
file is a finding, not an inventory item.

Worth a scan: for each test file, (a) is it reachable from a `b.step`, and
(b) does it import the module it claims to test, or re-declare it? Both are
mechanical. Neither is measured today.

## Falsifier

If a scan finds zero unreachable or self-duplicating test files, positive-control
it before believing the zero — this repository produced four confident zeros in
one day (zsh not word-splitting `$FILES`, `cat` collapsing 56 filenames into one
argument, `git rm` aborting wholesale, and `cmd | tail; echo $?` measuring
`tail`). Every one of them read as good news.
