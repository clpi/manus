### `defaults` / `world-launch` — the assertion was not merely unchecked, it was WRONG

Both refused unless `IDOL_BUILD_MODE` said `ReleaseFast`. Nothing in either ever
looked at the binary. `gate/all.sh` cannot set that variable honestly, so both
were red under it — and the moment it was set by hand they passed **against a
compiler that is not ReleaseFast**:

```
zig-out/bin/idol            18,404,520 bytes  sha256 6833c8dc…  41,294 debug symbol records
clean -Doptimize=ReleaseFast 6,295,908 bytes  sha256 4217c3d0…       0
idol-native bin/idol @HEAD   6,479,200 bytes  sha256 b78fc0b7…       0   ("Vendor reproducible ReleaseFast compiler")
```

`IDOL_BUILD_MODE=ReleaseFast sh gate/defaults.sh` PASSED on the 18 MB binary and
printed `build_mode=ReleaseFast compiler_sha256=6833c8dc…` into the evidence
plane. The gate was not failing to check a fact; it was **manufacturing a false
one**.

`tools/node/dev/build-mode` derives it instead. `build.zig` sets
`.strip = optimize == .fast`, so for artifacts of this build.zig *zero debug
symbol records ⟺ ReleaseFast* — a biconditional read out of the artifact, which
no caller can supply and which persists nothing. It agrees with the tree's own
witnessed ReleaseFast artifact and rejects the 18 MB one. `IDOL_BUILD_MODE` is
deleted from all three gates and from `build.zig`.
