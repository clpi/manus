# GAP-126 — Typed semantic facts cross a dynamic dispatch boundary

**Status:** OPEN · **Filed:** !2026-08-09T21:08:57Z
**Priority:** P0 · **Kind:** native_lowering_gap
**Filed by:** codex_semantic_normalization_continue
**Files:** scripts/canon.id,scripts/semanticgate.id,src/codegen.zig

A typed Duon verdict relation returning str caused native lowering to infer shared state-table string fields as raw C char pointers, then pass them directly where lua_Value is required. scripts/semanticgate.id compiled before the typed relation was added; adding the relation produced repeated lua_table_set_raw_lit incompatible char pointer diagnostics. GAP-124 uses exact scalar state interning in scripts/canon.id so no Zig workaround is added. Repair must preserve typed native strings and correctly box only at a genuinely dynamic table boundary, then enable structured native canonical findings.

The in-flight RG0 graph gate exposes the same defect more directly across typed
relation results. After the shared compiler binary changed, this exact command:

```text
DUOGATEDIFF=/tmp/rg0adversary.diff timeout 40 ./zig-out/bin/duo run scripts/idiomgate.id
```

failed in generated C while assigning `lua_Value` results to all three of:

- the typed record returned by `parser.app` / `graph.application`;
- the `i64` relation identity returned by `foreign.identity`;
- the typed application fact consumed by the gate.

The generated calls performed dynamic member lookup and `lua_invoke`, then used
that boxed result where the declared native record or scalar was required. This
violates the typed-path no-boxing law before canonicality can produce a verdict.
It also proves a gate result is not reproducible unless its compiler binary/tree
provenance is fixed; the same dirty source compiled earlier in the session before
another build replaced `zig-out/bin/duo`.

Closure is one general relation-resolution repair: a resolved cross-module typed
relation call lowers directly to its native result representation, while only a
genuinely dynamic application may return `lua_Value`. Positive controls must
cover typed string, scalar, and record results across module boundaries. Do not
add an RG0-specific opcode, boxing bridge, name recognizer, or Zig-only semantic
owner. Any temporary bootstrap edit must unlock the Duon relation path and carry
an explicit deletion target.
