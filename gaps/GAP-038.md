# GAP-038 — an unknown method on a sealed descriptor returns nil, silently

**Status:** open · **Severity:** silent wrong values · **Filed:** 2026-08-07
**Violates:** §IX STD-2 — "sealed-miss diagnostics carry curated repairs"
**Sites:** `scripts/census/contract.duo` (P94-7, P94-12)

## The defect

Calling a method that does not exist on `str` yields `nil`, with no diagnostic:

```duo
main(): void
    s = "hi"
    print(s:trim())          -- nil   (a §IX-listed method)
    print(s:bogusmethod())   -- nil   (a typo)
    print(s:upper())         -- HI    (a method that exists)
end
```

A real-but-unimplemented method and a misspelling are **indistinguishable**, and
both are indistinguishable from a method that legitimately returned nil.

## Why this is worse than a missing feature

§IX makes a specific promise about exactly this situation:

> `std.string` is an unresolved binding — a structural error; **sealed-miss
> diagnostics carry curated repairs**: `match → scan`, `gsub → replace/rebuild`,
> `format → interpolation`, `sub → s[i, j]`.

Those curated repairs **can never fire**, because there is no miss detection to
hang them on. The dispatch maps a known name to a `lua_str_*` runtime function
and falls through to nil for everything else. The whole repair-diagnostic
mechanism §IX describes is downstream of a check that does not exist.

`str` is a **sealed** descriptor — its surface is closed and known at compile
time — so this is the one case where a miss is provably a mistake. There is no
open-world argument for returning nil here.

## Measured surface

Working today: `len` `lower` `upper` `sub` `char` `format` `rep` `reverse`
`byte` `find` `match` `gsub` `gmatch` `split` `starts_with` `ends_with`.

Silently nil: `trim`, and every §IX name not in that list — `starts` `ends`
`replace` `chars` `graphemes` `has` `to`. Note the list also still carries
`match`/`gsub`/`gmatch`, which §VIII.1 marks structurally dead, and
`starts_with`/`ends_with`, which are Pass 91 interior-`_` violations. The
implemented surface and the canonical surface disagree in both directions.

## The fix

Diagnose the miss. For a receiver whose shape is known to be `str`, an
unresolved method is a compile error naming the curated repair where one exists:

```
error: `str` has no member `trim`
  help: no repair registered; the string surface is `split trim starts ends
        find replace take until join chars bytes graphemes to has`
error: `str` has no member `gsub`
  help: gsub → s:replace(lit) or rebuild
```

That turns §IX's repair table from documentation into behaviour. Implementing
`trim` itself is a separate, smaller question — the diagnostic matters more,
because it converts an entire class of silent nils into located errors.
