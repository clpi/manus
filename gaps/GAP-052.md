| title | GAP-052 — an empty string literal inside an attribute argument breaks the parser |

| # | directive |
|---|---|
| 1 | **Filed** 2026-08-08. **Status** open. **Blocks** 6 corpus files outright. |

| section |
|---|---|
| Minimal repro, isolated to one character |

```duo
@comp.define.derive("A", generate(m) -> str
    acc = ""          -- <- this
    acc
end)
main: i64 = ()  0 end
```

| # | directive |
|---|---|
| 1 | acc = "" -> error: attribute arguments cannot be recovered from this token stream (parse failed: UnexpectedToken) acc = "x" -> 0 errors |

| # | directive |
|---|---|
| 1 | An empty string literal ANYWHERE ELSE is fine — `main: i64 = () a = "" #a end` checks clean. |
| 2 | It only fails inside an attribute's argument span. |

| section |
|---|---|
| Mechanism |

| # | directive |
|---|---|
| 1 | `parse_attribute_args` (src/parser.zig:1087) recovers the argument text by POINTER ARITHMETIC against the source buffer, and guards it: |

| # | directive |
|---|---|
| 1 | if (srcOffsetOf(src, first_tok.text) == null) { ...refuse... } |

| # | directive |
|---|---|
| 1 | fn srcOffsetOf(src, text) ?usize { const p = @intFromPtr(text.ptr); if (p < base or p + text.len > base + src.len) return null; ... } |

| # | directive |
|---|---|
| 1 | An empty string literal's `text` is a ZERO-LENGTH slice. |
| 2 | Zig gives no guarantee that an empty slice's `.ptr` is meaningful, so the bounds test fails and the whole attribute is refused. |
| 3 | The guard is doing its job; the input is a token whose text has no address. |

| 1 | Make the lexer emit an empty string literal's `text` as a zero-length slice POINTING AT its source position, so the offset is recoverable, rather than a detached empty slice. |

| 1 | The alternative — special-casing length 0 in `parse_attribute_args` — cannot work: without a valid pointer there is no offset to compute, and the span start is exactly what the function needs. |
