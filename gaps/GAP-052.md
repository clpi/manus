# GAP-052 — an empty string literal inside an attribute argument breaks the parser

**Filed** 2026-08-08. **Status** open. **Blocks** 6 corpus files outright.

## Minimal repro, isolated to one character

```duo
@comp.define.derive("A", generate(m) -> str
    acc = ""          -- <- this
    acc
end)
main(): i64  0 end
```

    acc = ""    ->  error: attribute arguments cannot be recovered from this
                    token stream  (parse failed: UnexpectedToken)
    acc = "x"   ->  0 errors

An empty string literal ANYWHERE ELSE is fine — `main(): i64  a = ""  #a end`
checks clean. It only fails inside an attribute's argument span.

## Mechanism

`parse_attribute_args` (src/parser.zig:1087) recovers the argument text by
POINTER ARITHMETIC against the source buffer, and guards it:

    if (srcOffsetOf(src, first_tok.text) == null) { ...refuse... }

    fn srcOffsetOf(src, text) ?usize {
        const p = @intFromPtr(text.ptr);
        if (p < base or p + text.len > base + src.len) return null;
        ...
    }

An empty string literal's `text` is a ZERO-LENGTH slice. Zig gives no guarantee
that an empty slice's `.ptr` is meaningful, so the bounds test fails and the
whole attribute is refused. The guard is doing its job; the input is a token
whose text has no address.

## Affected files (all fail before any semantic pass)

    meta_omni_showcase · meta_infinity_showcase · meta_burst_showcase
    meta_transcend_showcase · exponential_codegen_showcase
    derive_map_bundle_showcase

The omni/transcend/infinity/hyper derive family therefore has NO live corpus
exercise — a whole meta surface is unreachable, and the six files look like
"examples that happen to fail" rather than one parser defect.

## Repair

Make the lexer emit an empty string literal's `text` as a zero-length slice
POINTING AT its source position, so the offset is recoverable, rather than a
detached empty slice. That is where the address exists; every consumer
downstream then works unchanged.

The alternative — special-casing length 0 in `parse_attribute_args` — cannot
work: without a valid pointer there is no offset to compute, and the span start
is exactly what the function needs.
