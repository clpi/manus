# GAP-097 — nominal descriptors land; the declaration spelling and the physical switches are the debt

**Status:** MECHANISM LANDED, THREE HOLES OPEN · **Filed:** 2026-08-09
**Law:** `law.nominal` (constitution §46) · `law.host.projection` ·
`law.canon.performance` (§42) · A2 NNS-FIRST · A3 ONE EDGE
**Closes the blocker recorded in:** `gaps/GAP-082.md` ("WHAT BLOCKS SCALING")

## What was measured, and what changed

gap[082] ended with the finding that the algebra had outrun its substrate:

> **A user descriptor cannot be attached to a value.** `d: feet = 3.0` is
> rejected by sema … the trie can only be reached when the call site SPELLS the
> source descriptor, or when the source is a primitive.

| | before | after |
|---|---|---|
| `d: feet = 3.0` | `error: type mismatch … declared as 'feet', but initializer has type 'f64'` | **compiles** |
| what `d` lowers to | — | **`double d = 3e0;`** |
| `d:to(inch)` with `feet -> inch` UNDECLARED | no source descriptor exists to look up | **`shrink(grow((double)(d)))`**, witnessed |
| `d: feet = x` where `x: f64` | *(unreachable — the annotation was already refused)* | **DIAGNOSES** |
| `y: f64 = d` | *(same)* | **DIAGNOSES** |
| box / wrapper / tag / retain on a `feet` | — | **none**, gated by `zig build nominal-zero-cost` |

`examples/spec100/nominal.duo` prints **914436** — 3 feet as 36 inches through a
hub composition nobody declared, plus 914400 micron through an authored edge.
Neither number is reachable by a degenerate answer: a `feet` that silently
became a plain `f64` finds no edge and fails to compile, and a hop that
collapsed to 0 prints 36 or 914400.

## How, and why it is small

**No new type and no new grammar (A2).** A named descriptor already resolved to
`ResolvedType.@"struct"{ .name = "feet" }`; that node already carried the
identity and already flowed through every switch in the compiler. What was
missing was the REPRESENTATION FACT beside it, and that is the whole addition —
`types.nominal_reprs`, one map. Because `ResolvedType` gained no variant, no
lowering path grew an arm it could get wrong, which is what makes the
zero-overhead claim provable rather than hoped for: `feet` and `f64` answer
`c_type` with the same six characters.

**Nominality is the ABSENCE of a rule.** `eql` already compares `.@"struct"` by
name, so `feet` ≠ `f64` for free. The work runs the other way — the PHYSICAL
queries (`is_integer`, `is_float`, `c_type`, the drop ladder) now read through
the identity to the representation, while the SEMANTIC ones keep seeing two
descriptors.

**One derivation (A3).** Nominal names are registered in
`AliasRegistry.collect`, the single place Sema and CodeGen already share, so the
two cannot disagree about which names are nominal. That is deliberate: the
`k == .eof` defect (parser and sema each holding a fact about one token, and the
facts disagreeing) is the failure mode this shape avoids repeating.

**CDR is why the literal is admitted.** `d: feet = 3.0` passes and `d: feet = x`
does not, and that is not a weakening. A bare numeral carries no descriptor of
its own — §0g says so directly — which is why `n: u8 = 3` is a u8. The contract
names the literal; nothing is coerced, because there was nothing there to
coerce. A value that ALREADY carries a descriptor is a different question and
gets a different answer.

## Hole 1 — the canonical declaration spelling does not declare

§46 writes the descriptor as `feet: f64`. Measured: that parses as a BINDING
with no initializer, not as a descriptor.

`src/parser.zig` mints an `alias_def` from `name: type` only when the type is a
RECORD (`if (typ == .record and … != .assign)`, around line 4252). A scalar
target falls through to `local_decl`. So the form under test is `type feet =
f64`, the spelling already in the tree at `lib/std/compiler/source.duo:19`.

**This is the third instance of the pattern gap[081] and gap[087] named** — the
law prescribing a spelling the compiler cannot produce. It is the cheapest of
the three to close (one lookahead arm), and it was left alone here only because
the parser was owned by another session at the time.

The collision to decide when it is closed: `feet: f64` at module scope currently
means "a place of type f64 with no initializer". Both readings are defensible
and the parser is the one place that may choose between them — deciding it in
sema would recreate exactly the two-subsystems-one-token defect above.

## Hole 2 — every physical switch listing `.@"struct"` as boxed is a cost site

Two were found by the fixture, and only because the emitted C refused to build:

- `populate_record_aliases` folded `feet` to `f64` and threw the name away, so
  nothing downstream could tell them apart.
- `codegen_needs_arc` emitted `duo_retain((void*)(d))` on a `double`. Clang
  caught it. **Had `feet` been nominal over `str`, that retain would have
  COMPILED** and every `feet` binding would have paid a refcount forever.

Both are fixed. The GAP is that there is no enumeration of the rest. The audit
is mechanical — every `switch` on a resolved type whose `.@"struct"` arm answers
"boxed", "owned", "not native" or "lua_Value" — and it should become a gate
rather than a fixture that happens to trip one. `zig build nominal-zero-cost`
catches these only for the shapes its fixture exercises; a nominal over `str`,
over `bool`, in a record field, as a parameter, as a return type, and across a
`req` boundary are all unexercised.

## Hole 3 — the nominal rule reaches BINDINGS only

`type_annotation_accepts_init` refuses the representation shortcut everywhere it
is called, but the CDR literal exception is wired at the local-declaration site
only, because that is the only place the initializer EXPRESSION is in hand.
Consequences, all unproven either way today:

- a function parameter annotated `feet` called with a literal;
- a record field of type `feet`;
- a return contract of `feet` returning a literal;
- a nominal descriptor crossing a module boundary, where the registry is keyed
  by TEXT and two modules may spell different descriptors the same way.

The last one is the serious one and it is the same debt `law.relation.debt`
already records against `src/relation.zig`: **string identities**. Stable
semantic ids retire both at once.

## Deletion contract

`types.nominal_reprs` is a process-global map keyed by text, and both halves of
that are bootstrap debt, recorded at the moment the mechanism became useful
rather than discovered later:

```
authority = false
projects  = descriptor
bootstrap = true
deletion  = when a descriptor is an ordinary graph node carrying its
            representation as a FACT, and identities are stable semantic ids
```

## Hole 2, one instance found and fixed after filing — and it SEGFAULTED

`print("{d}")` on a `feet` emitted `printf("%s\n", d)` against a `double`.

That is not a wrong number. It is exit 139 at runtime with `ok compile`
reported, from a format selector whose descriptor arm assumed boxed — the same
shape as the `duo_retain` bug, one switch over. gap[093] measured the identical
site one step earlier as SILENT NO-OUTPUT, before a nominal descriptor could
reach the emitter at all.

Fixed (`emit_print_call` reads `nominalReprOf` first) and gated: the zero-cost
gate now compiles a program printing a nominal over `f64` and a nominal over
`i64` and asserts `2.5 41` by value.

**It does not weaken hole 2 — it is hole 2's third instance in one session, and
the count is the finding.** Three physical switches, three separate discoveries,
none of them by an enumeration. Two of the three (`codegen_needs_arc`, this one)
produced a build that reported success. The audit is still owed.

Also confirmed while testing this, and NOT caused by nominal descriptors:
`print` on a plain `f64` disagrees between backends — `3` under `--backend=c`,
`3.000000` under `--backend=direct`. gap[093] records it. Until the two agree,
no float-printing fixture can convict either backend, which is why the fixture
here prints an `i64` total and the render row asserts `2.5` rather than a
round-trip.
