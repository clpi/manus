## Executable plan (four coordinated pieces, all located)

| # | directive |
|---|---|
| 1 | Written out because the mapping is done and the next agent should not re-derive it. |

1. **`collectModuleConsts` (`dnir_lower.zig:492`) must collect POSITIONAL fields.**
   It handles `n = <int>`, `n = <quoted>` and `.named` table fields today; the
   field loop does `switch (fld) { .named => |x| x, else => continue }`, so
   `{ "a", "b", "c" }` is skipped entirely. Emit `n.1`, `n.2`, … into `strs`
   (or `ints`), keyed exactly as `lowerDynamicIndex` already spells them
   (`"{s}.{d}"`), and record `n.len`.

2. **`lowerDynamicIndex` (`:6186`) must fall back to module consts.**
   It resolves the length via `ctx.locals.get("{s}.len")` then
   `ctx.table_lens`, and each element via `ctx.locals.get("{s}.{d}")`. Both are
   locals-only, so a module-level table resolves nothing. It needs a
   module-const path for both.

3. **The result slot must be marked as text.**
   `:6205` does `if (ctx.str_tables.contains(table_name)) try
   ctx.str_slots.put(…)`, and `str_tables` is populated only by `noteStrTable`,
   which returns early without a `ctx.body`. A module-level table needs the same
   verdict reached another way — and it must keep `tableUseInBlock`'s safety, or
   a table that is written, rebound, shadowed or passed on will be assumed
   constant when it is not.

4. **The precheck must stop refusing.**
   `module_materializes_table` (`codegen.zig:3721`) refuses first, so pieces 1–3
   are unreachable until it admits the shape. It must admit ONLY what pieces 1–3
   actually implement — widening it ahead of them is the nondeterministic
   corruption recorded above.

| 2 | 1–3 before 4 is dead code that changes nothing. |
| 3 | They land together or not at all. |

| 1 | **Acceptance:** `strs = { "alpha", "beta", "gamma" }` with a runtime index must print `beta`, deterministically, across repeated runs — and the same program with a written or rebound table must still refuse. |

## One cause of the safety failure, located

| # | directive |
|---|---|
| 1 | `module_has_keyed_write` (`codegen.zig:3775`) only recognises a STRING-keyed write. |
| 2 | Its `.index` arm is: |

```zig
.index => |ix| {
    if (ix.obj.* == .name and ix.key.* == .quoted and
        std.mem.eql(u8, ix.obj.name.ident, name)) return true;
},
```

| # | directive |
|---|---|
| 1 | `ix.key.* == .quoted` means `t["k"] = v` is caught and `t[1] = v` is not. |
| 2 | The function was written for the `M = {}` / `M.x = 1` keyed-table hazard, where the key is always a name, so an integer-indexed write was never in its remit. |

| # | directive |
|---|---|
| 1 | That is exactly how the first negative control walked through: `strs[1] = "changed"` is an integer index, so the precheck saw no keyed write, admitted the table, and the recorded elements were the ORIGINAL three. |

| # | directive |
|---|---|
| 1 | Measured on the reverted tree, this is NOT a live wrong answer today: a positional INT table with an index write prints the updated value (`nums = { 10, 20, 30 }; nums[1] = 99` prints 99 across runs). |
| 2 | The int path handles the mutation downstream. |
| 3 | It is the text path — which does not exist — that would have consumed a stale constant. |

| # | directive |
|---|---|
| 1 | So closure needs the verdict to account for integer-indexed writes AND for the marking to stay consistent when a table is mutated. |
| 2 | Those are two defects, not one, and only the first is a missing condition; the second is a design question about what a mutated table's elements are allowed to be assumed to hold. |

## Why every shortcut failed: admission and capability are decided in different passes

| # | directive |
|---|---|
| 1 | The sharpest statement of this gap, and it explains all three dead ends at once. |

| # | directive |
|---|---|
| 1 | `module_materializes_table` (`codegen.zig`) decides ADMISSION — may this module take the native-scalar path. `collectModuleConsts` / `lowerDynamicIndex` (`dnir_lower.zig`) decide CAPABILITY — can this exact binding actually be lowered. |
| 2 | They run in different passes over different state and share no fact. |

| # | directive |
|---|---|
| 1 | So admission can say yes where capability says no, and the read falls through to something that emits a pointer. |
| 2 | That is the corruption, and it is why the FIRST experiment reproduced it with the precheck widened ALONE, before any recording existed to be wrong. |

| # | directive |
|---|---|
| 1 | It also clears the safety machinery of blame. `targetWrites` (`dnir_lower.zig:5547`) handles `.index` correctly — it recurses through `ix.obj` to the name — so `tableUseInBlock` returns `.opaque_use` for `strs[1] = "changed"` and the collection records NOTHING, exactly as intended. |
| 2 | The guard worked. |
| 3 | The admission in the other file did not consult it. |

| # | directive |
|---|---|
| 1 | That reframes closure. |
| 2 | It is not "add the missing condition" and not "connect the paths": |

| # | directive |
|---|---|
| 1 | **the precheck must apply the same predicate the lowering will apply, or the two must be derived from one shared fact.** Any admission rule maintained separately from the capability rule can drift, and the drift is silent because the failure is a pointer rather than a refusal. |

| # | directive |
|---|---|
| 1 | Which is why: |

- widening the precheck alone corrupts — admission moved, capability did not;
- adding the recording underneath did not help — admission still does not
  consult it, so the shapes the recording REFUSES are still admitted;
- tightening the shared write census regresses — it is the only fact both
  passes read, so tightening it moves both, including the int path that was
  already correct.
