| section |
|---|---|
| Where the resolution lives, and why not in the parser |

| # | directive |
|---|---|
| 1 | The dotted form is resolved in `parse_anchor_case` — the parser knows the position (it just consumed `==`) and knows the cases, because it declared them. |
| 2 | The bare form cannot be: deciding it requires knowing whether the spelling is also a LEXICAL BINDING, which is scope, which is sema. |
| 3 | So the resolver is in `Sema.check_binop`, and it hands codegen the SAME `field` node the parser hands it for the dotted form. |
| 4 | A3 ONE EDGE holds — nothing downstream learns that a bare name was written, which is what makes this a canonicalization rather than a second lowering path, and it is why `law.canon.performance` (§42) is satisfied by construction rather than by measurement. |

| # | directive |
|---|---|
| 1 | **Ordering was the whole correctness argument.** `check_expr` on an unbound name IMPLICITLY DEFINES it as an `any` local in duo mode. |
| 2 | A resolver running after the operands were checked would find every bare case already bound and would fire `law.shadow` on all of them — blaming the reader for the checker's own side effect. |
| 3 | The resolver therefore runs BEFORE either operand is checked. |

| 1 | Neither is about cases, and both had to land first: |

| # | directive |
|---|---|
| 1 | **A descriptor name in a WALK had no type.** `token.kind.eof` reported `any`, because `token` is an `alias_def` and not a scope binding, so `check_expr` took the implicit-local arm. The whole walk lost its type and `k` had no case-set to be a case of. Recovered in the `.field` arm only — a descriptor name in VALUE position is APPLY-ONE's question (§43) and is answered by the call path; `x.y` where `x` names a descriptor has exactly one reading. |
| 2 | **An implicit local discarded its value's type.** `check_assign_target` binds an undeclared duo-mode name as `any`, so `k = token.kind.eof` produced a `k` with no case-set. Narrowed here to case-sets only. |

| # | directive |
