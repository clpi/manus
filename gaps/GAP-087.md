# GAP-087 — §41's bare-identity case parses but does not resolve

**Status:** OPEN · **Filed:** 2026-08-08
**Law:** `law.selfzero` (§41) · `law.subtract` (§40) · `resolution.rule`
**Blocks:** the entire §40/§41 leading-dot retirement — 231 "free" sites and 36
SELF-ZERO sites alike

## The defect

§41 rules that bare identity replaces the leading dot:

```duo
law{ kind = invariant }      -- canonical
law{ kind = .invariant }     -- retirement debt
```

and §40 obligation 1 was recorded as *satisfied by construction* because both
forms **parse**. Measured by value, that was the wrong test — parsing is not
resolving.

| form | result |
|---|---|
| dotted case in comparison — `k = .circle`, `k == .circle` | **compiles** |
| **bare case in comparison** — `k = circle`, `k == circle` | **FAILS** |
| dotted case in construction — `{ kind = .circle }` | FAILS |
| bare case in construction — `{ kind = circle }` | FAILS |

```
error: use of undeclared identifier 'circle'
```

The bare form lowers to an undeclared identifier. It is not resolved against the
case-set at all — the parser accepts the name and nothing binds it.

## Why obligation 1 was mis-recorded, and the lesson

§40 requires five proofs before any deletion. Obligation 1 is *"every semantic
role has a strictly SIMPLER EXISTING spelling"*, and I recorded it satisfied
because `duo check` accepted `kind = invariant`.

**`duo check` accepting a form is not the form working.** This tree has the
identical trap on record twice already — `duo-ambient-std-string-nil` ("a
resolving ambient path is not a working one") and `duo-mod1-unwrap-hazards`
("`duo check` passes on the broken result"). I hit it a third time, in the file
that legislates against it.

Obligation 2 (deterministic resolution) and obligation 3 (canonical lowering no
worse) both FAIL for the bare form. Obligation 3 fails maximally: the canonical
form does not lower at all while the retirement-debt form does.

## Same shape as gap[081], and that is now a pattern

gap[081]: canonical orientation `x:to(i64)` does not compile in either face
while the noncanonical `to(i64)(x)` does — so 1647 sites chose the working form.

gap[087]: canonical bare case does not resolve while the dotted form does — so
every site in the tree uses the dotted form.

**Twice now the law has prescribed a spelling the compiler cannot produce**, and
in both cases the corpus is not evidence of bad taste but of authors writing
what works. The rule this establishes:

> A retirement obligation is not satisfied by the replacement PARSING. It is
> satisfied by the replacement RESOLVING AND LOWERING, proven by value, on both
> backends.

That belongs in §40's obligation list and is the durable output of this gap.

## Construction is separately broken

Note both construction rows fail — dotted AND bare. `a: shape = { kind = .circle }`
does not compile either. So descriptor construction with a case field is broken
independently of the dot question, and any migration would have hit that wall
regardless. Worth its own narrowing; not the same defect.

## Fix, in order

1. **Bare identity resolves against the expected descriptor's case-set.**
   §41's `resolution.rule` states the mechanism: *bare identity + semantic demand
   + available homes → one identity, or a diagnostic.* The demand here is the
   field's declared case-set. Fixture asserts the VALUE — that `k == circle` is
   true and `k == square` is false, since a case that resolves to nothing
   compares equal to nothing and would pass a weaker test.
2. **The shadowing diagnostic** (`law.shadow`) lands with it, not after: a local
   `circle` in scope must diagnose rather than silently win.
3. **Then** the 231 free sites migrate, canonicalizer-driven with the §18
   witness.
4. Narrow the construction failure separately.

## Do not migrate anything until 1 lands

The 231 sites currently use the only form that works. Rewriting them to a form
that does not resolve would replace a working tree with a broken one — which is
precisely what §40's five obligations exist to prevent, and what this gap
demonstrates they catch when actually run.
