## The three sources

1. **BUILD PATH.** The binary embeds the absolute path of the object files in
   the build cache, four times:

   ```
   …/cachea/o/b5bf2d18a015dc368107212924ab7e6e/duo_lexer_tokenize.o
   …/cachea/o/4b2e057e2b788d3bd54845de6e3556ae/duo_zcu.o
   ```

| # | directive |
|---|---|
| 1 | These are `N_OSO` debug stab records in `__LINKEDIT`. |
| 2 | The build is therefore reproducible only from the directory it was made in. **A same-path rebuild can never see this**, which is why the gate builds in two different directories on purpose. |

2. **TIMESTAMP.** The same `N_OSO` records carry the object file's mtime in
   `n_value`. Two builds seconds apart differ there: the residue bytes decode
   as a Unix timestamp differing by the wall-clock gap between the builds.

3. **LC_UUID.** The linker's UUID is not derived from the content alone
   (`D698B86E-…` vs `D2C6BE87-…`). 16 bytes.

| # | directive |
|---|---|
| 1 | The 159 signature bytes are **consequential, not a fourth source**: the ad-hoc code signature hashes everything above it, so it cannot match while anything else differs. |
| 2 | Fixing 1–3 removes it. |

## The finding that narrows the work

| # | directive |
|---|---|
| 1 | **Code and data are byte-identical.** Zero differing bytes below `__LINKEDIT` once LC_UUID is set aside. |
| 2 | Two independent compiles of this compiler emit the same machine code and the same data; only the Mach-O wrapper disagrees. |
| 3 | That is a much smaller problem than "the build is nondeterministic", and it is the difference between a codegen investigation and three link-step flags. |

## Why the existing gate did not catch it

| # | directive |
|---|---|
| 1 | `zig build reproducibility-smoke` (`scripts/reproducibility_smoke.id`) has reported PASS for this tree. |
| 2 | It deletes `zig-out` and rebuilds **into the same cache**. |
| 3 | A warm cache does not recompile — it copies the artifact it already has, and two copies of one file are identical no matter how nondeterministic the toolchain is. |
| 4 | It also builds at the same path both times, so it is blind to source 1 by construction. |
| 5 | It is not wrong, it is narrow; it stays wired as the cheap smoke, and `build-determinism` is the U2 anchor. |

## What must happen, in order

1. **Strip or normalise the debug stabs** — `-fno-...`/`--strip-debug`-class
   handling for the release artifact, or `OSO` prefix rewriting. Sources 1 and
   2 die together, since both live in the same records.
2. **Make LC_UUID content-derived** (or zero it for release artifacts).
3. **Then lower `DETERMINISM_ARTIFACT_FLOOR` to 0** in the same commit. The gate
   prints that instruction on any run that comes in under budget.
4. **Cross-machine reproducibility is a further claim** and is NOT tested here:
   this gate proves same-machine, different-directory identity only. U2 as
   written is stronger.
