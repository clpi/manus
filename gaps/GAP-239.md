# GAP-239 — the wasm runtime (`tools/wasm/src/engine.id`) has no direct-native realization

**Status:** OPEN · **Filed:** !2026-08-25T00:00:00Z
**Priority:** P0 · **Kind:** architecture_and_performance_gap
**Filed by:** omp-wasm
**Files:** tools/wasm/src/engine.id, tools/wasm/src/wasm/jit_arm64.id, lib/jit.id, lib/bit.id, src/codegen.zig, src/dnir_lower.zig, src/native_backend.zig, build.zig

## The defect

The compiler's wasm **emitter** (`src/wasm_backend.zig`) is live and pinned
(`gate/wasm.sh`: 182/221 direct-lowerable subjects byte-identical to AArch64).
The wasm **runtime** — the interpreter+JIT that would compete with
wart/wasmtime — is not. `tools/wasm/src/engine.id` has **no direct-native
realization**, so there is no buildable binary to time, and every
"faster than wart/wasmtime" claim is unmeasurable at this head.

Measured at `clpi/idol` `7ca8276d` with a fresh `zig-out/bin/idol` (never the
stale tracked `out/bin/idol`):

```sh
./zig-out/bin/idol compile tools/wasm/src/engine.id --backend=direct --emit exe -o /tmp/wasm-engine
# -> DNB001 ... runtime-global:mem ... bail site: native-scalar precheck — runtime-global:mem
```

`zig build wasm-test` is additionally gated on `WART_ORACLE_REPO` (pinned
`ca2b0b9c`), unconfigured on this host, so the sole admission path cannot run
here either.

## The blocker chain, enumerated (each measured, not inferred)

The engine's dependency surface, counted from source:

| family | count | direct-native status |
|---|---:|---|
| `mem.alloc/free/zero/addr/read_byte/read_i64/write_byte/write_i64` | ~778 | **admitted** (`dnir_lower` + `codegen` precheck) |
| `mem.load(T)(p)` / `mem.store(T)(p,v)` | 22 | **NOT admitted** — first refusal |
| `jitm.*` (`req "jit"` → `lib/jit.id`) | 299 | **NOT admitted** — `req` → `DNB011 unresolved-application-facts` |
| `@comp.c.emit` (inside `lib/jit.id`, `lib/bit.id`) | — | **NOT admitted** — `statement-not-lowered:directive` |
| `math.floor/ceil/sqrt/random/randomseed/tointeger` | 19 | partial: `sqrt/sin/cos/fabs/floor/ceil` admitted; `random/randomseed/tointeger` not |
| `os.clock/time` | 14 | `os.exit` admitted; `os.clock`/`os.time` deliberately not (semantic swap risk) |
| `string.byte/char/len/sub` | 34 | `byte/char/len/sub` admitted |
| `io.open/stderr/stdin/stdout` | 40 | `io.open` admitted; `io.stderr`/`io.stdin`/`io.stdout` not |
| `to(f64)/to(i64)/to(int)/to(str)` | 55 | `to(str)`/`to(f64)`/`to(i64)` admitted; `to(int)` not |

The first refusal is `mem.load(f64)(fb)` / `mem.store(f64)(fb, v)` — the typed
pointer load/store the engine uses ~22× for float bitcast. The direct-native
precheck's `ok_mem` list (`src/codegen.zig:5757`) admits
`alloc/free/read_byte/read_i64/write_byte/write_i64/zero/addr` but **not**
`load`/`store`. The C backend lowers both (`maybe_emit_mem_call`); the direct
backend does not.

## Why this is not a one-line fix

1. **`mem.load(T)`/`mem.store(T)` need an f64 load/store in DNIR.** The
   existing `load_index`/`store_index` op carries `.ty == .i64` (scaled 8-byte
   word) or byte semantics; there is no `.f64`/`.f32` arm, and
   `native_backend.zig` emits no `ldr d`/`str d` for these ops. The engine's
   float path is the *only* consumer, and it is the whole reason the runtime
   exists (wasm f32/f64 arithmetic).

2. **The JIT substrate is foreign-realization debt.** `lib/jit.id` is
   `@comp.c.emit` (mmap/mprotect/dlsym/icache) and `req "jit"` fails with
   `DNB011 unresolved-application-facts` — the GAP-201 graph-fact gap, not a
   lowering gap. `lib/bit.id` (`f64_to_bits`/`f64_from_bits`) is the same
   `@comp.bit.bitcast` primitive, also unrealizable direct-native.

3. **The JIT is arm64-only.** `tools/wasm/src/wasm/` holds `jit_arm64.id` and
   no `jit_x64.id`; `lib/jit.id`'s `idoljitarch()` returns `"x86_64"` but the
   engine's `jit_is_arm64` accepts only `arm64`/`aarch64`, so x86-64/Linux
   falls back to the interpreter. "Across the board on all platforms" is not
   reachable from the current tree.

4. **The engine is SOURCE-ZERO debt** by its own README/CLAUDE.md: a
   standalone interpreter with private opcode/stack machinery, not the
   shared-graph architecture the law requires. It is behavioral evidence, not
   the target.

## The honest performance boundary

`docs/wart-arm64-cell.md` already measured the shape on Apple silicon: wart
wins startup/short workloads, **loses** hot steady-state to Cranelift (1.23×
cycles) and loses the large-module cell 7.3×. GAP-130 records the engine's own
`hot_big` row at ~17% behind wasmtime in generated code. "Waaaaay faster than
wart and wasmtime across the board" is contradicted by the tree's own evidence
and barred by `AUTHORITY.json` (`unmeasured_is_not_pass: true`,
`exact_head_evidence_required: true`).

## Required order

1. Admit `mem.load(T)(p)` / `mem.store(T)(p,v)` in the direct-native precheck
   and `dnir_lower`, with an f64/f32 `load_index`/`store_index` arm in
   `native_backend.zig` (`ldr d`/`str d`). This is the first refusal and the
   smallest slice.
2. Land the foreign-realization owner for `lib/jit.id`/`lib/bit.id`
   (GAP-201), or migrate the engine's bitcast sites to a graph-owned
   reinterpretation fact.
3. Only then is there a buildable runtime to time — and only then can any
   wart/wasmtime comparison be measured rather than asserted.

## Negative controls

- `mem.load(f64)(fb)` in a two-line program refuses `runtime-global:mem`
  (measured above).
- `req "jit"` in a two-line program refuses `DNB011 unresolved-application-facts`
  (measured above).
- `@comp.c.emit("1")` refuses `statement-not-lowered:directive` (measured above).
