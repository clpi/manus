# GAP-027 — `if 0` does not take its branch, contradicting B-2

**Status:** open — **needs a ruling, not a patch** · **Filed:** 2026-08-07
**Blocks:** Pass 81 §3, the non-family the registry calls STRUCTURAL
**Sites:** `scripts/census/family.duo` (NF-1, with NF-2/NF-3 as controls)

## The defect

Pass 81 §3 lists truthiness first among the deliberate non-families, and gives
the reason:

```
truthiness      false/nil falsy, forever (B-2). Overridable truthiness makes
                every binding condition unreadable at a distance. STRUCTURAL.
```

"false/nil falsy" is exhaustive as written: those two, and nothing else.
Measured, **zero is also falsy**.

## Minimal repro

```duo
main(): void
    if 0
        print("zero-truthy")
    end
    if 1
        print("one-truthy")
    end
    if ""
        print("emptystr-truthy")
    end
    if false
        print("false-truthy")
    end
    print("control")
end
```

```
one-truthy
emptystr-truthy
control
```

`0` prints nothing. The three controls all behave as B-2 describes — `1` and `""`
are truthy, `false` is falsy — so the harness is sound and the reading is
unambiguous.

## Why this is a ruling and not a bug

Two readings are defensible and they lead to opposite patches, so this is filed
rather than fixed.

1. **The compiler is wrong.** Duo is a Lua superset; Lua's `0` is truthy; B-2
   says exactly that; the conditional lowering has acquired a C/Python-shaped
   zero test. Fix the lowering.
2. **B-2 is narrower than it reads.** Duo deliberately diverges from Lua here,
   and "false/nil falsy" was written as shorthand for the *hookability* claim
   (no descriptor may redefine truthiness) rather than as an exhaustive list of
   falsy values. Fix the wording.

Reading 2 is not a stretch — §3's stated *reason* is about overridability and
readability at a distance, and a falsy zero is neither overridable nor unreadable.
But reading 1 is what the text says, and the text is canon.

Note what is **not** in question: truthiness is not hookable either way. No
descriptor can redefine it today, because no descriptor can declare any family
member at all (`GAP-035`). The non-family ruling holds; only its enumeration of
falsy values is in dispute.

## Until it is ruled

The census asserts the rule **as written**, so `NF-1` reads MISSING and the row
is visible on every run. Do not "fix" the row by changing what it asserts — that
would make the divergence invisible again, which is precisely what the
non-family rows exist to prevent.

In .duo source, write the comparison you mean: `if n != 0`, not `if n`. That is
correct under both readings.
