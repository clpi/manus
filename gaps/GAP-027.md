# GAP-027 — a function parameter does not shadow a global of the same name

**Status:** open · **Filed:** 2026-08-07 · **Severity:** silent wrong data
**Violates:** LAW-SCOPE — "assignment targets the nearest existing binding";
lexical scope is the whole mechanism worlds are built on

## The defect

A parameter whose name matches a module-level `global` is IGNORED. The function
body reads the global instead.

```duo
global g: i64 = 99

a(g: i64): i64
    g
end

main(): i64
    print("a(1) = " .. to(str)(a(1)))
    0
end
```

    a(1) = 99          -- the GLOBAL. The argument is discarded.

The generated C names it outright — the body emits `duo_g_g`, the global's
symbol, with the parameter never read.

## Why this is worse than it looks

**Same-typed collisions are SILENT.** `i64` global against `i64` parameter
produces `int64_t` against `int64_t`, so the C compiler has nothing to object
to and the program runs, returning the wrong number forever.

The loud case is an accident of typing: a `str` parameter against a
`req`-bound module global fails only because `lua_Value` will not pass as
`const char*`:

```
error: returning 'lua_Value' from a function with incompatible result type 'const char *'
    return duo_g_s;
```

So the bug announces itself only when the two happen to have incompatible C
representations. Every scalar collision is invisible.

## How it surfaced

`scripts/run_benchmark.duo` — the Duo port of the benchmark suite, which
`RL-14` names as `run_benchmark.sh`'s replacement — does not compile:

```duo
global s = req "std.script"

trim(s: str): str
    if string.sub(s, -1) == "\n" return string.sub(s, 1, #s - 1) end
    s
end
```

`trim`'s parameter `s` collides with the module global `s`, so the body
compiles against `std.script` and the C compiler rejects it. The port has been
sitting unbuildable; RL-14 was recorded as "one line from done" on the strength
of the file existing.

## The fix

Parameters must be entered into scope BEFORE global resolution, so a body
resolves `g` to the parameter. The resolution ladder already specifies
"lexical shadow" as rung 1 — this is that rung not being applied to parameters.

Regression fixtures, both needed since one of them is the silent case:

    a(g: i64): i64 g end        with global g = 99  =>  a(1) must be 1
    b(s: str): str s end        with global s = <module>  =>  must compile

## Interim

Rename the parameter at any colliding site. Detection is mechanical: for each
file, intersect its `global` names with every parameter name in it.
