| section |

| ROOT CAUSE 2026-08-09 — INSTRUMENTED, and larger than the filing |

| # | directive |
|---|---|
| 1 | Following gap[098]'s peel rule and gap[100]'s hard-won lesson: *do not implement a mechanism you have not observed.* The emitted C answers it in one read. |

```duo
main: i64 = ()
    code: i64 = 0
    work = "/tmp/x"
    if work != ""
        std.script.run("exit 7")
    code
```

```c
static inline int64_t duo_entry_main() {
    int64_t code = 0;
    const char* work = "/tmp/x";
    if ((strcmp(work, "") != 0)) {
        return std_script__run("exit 7");   /* <- the defect */
    }
    return code;                            /* <- unreachable */
}
```

| # | directive |
|---|---|
| 1 | **The `if` block is in STATEMENT position, and the C backend compiled its final expression as a `return` from the enclosing function.** §0.7 says a body's value is its final expression's, *and demand alone materializes* — the if-block's value is not demanded here, so it must be discarded. |
| 2 | It is not. |
| 3 | Everything the filing observed follows from this one line. |

| section |
|---|---|
| The defect |

| # | directive |
|---|---|
| 1 | A `main` whose last *statement before the returned expression* is a side-effecting call through `std.script.run` exits with THAT CALL'S status, not with the value `main` returns. |
| 2 | Reduced from the real case: |

```
main: i64 = ()
    code: i64 = 1
    …
    if work != ""
        sh("rm -rf {work}")      -- cleanup, status 0
    end
    code                          -- 1
end
```

| # | directive |
|---|---|
| 1 | `code` is 1 at that point — a `print` immediately above the `if` confirms it — and the process exits **0**. |
| 2 | Deleting the `if` block makes the same program exit 1. |
| 3 | Writing `return code` instead of the bare `code` does NOT help; the status is lost either way. |
| 4 | Binding the call's result does: |

```
    if work != ""
        swept: i64 = sh("rm -rf {work}")
    end
    code
```

| # | directive |
|---|---|
| 1 | That exits 1. |
| 2 | So the trigger is a bare call in statement position near the tail of `main`, not the return form. |
