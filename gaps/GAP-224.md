# GAP-224 — the declaration freeze's advertised door is a spelling C0 forbids

**Status:** OPEN
**Priority:** P1 · **Kind:** evidence_gap
**Filed by:** claude-coordinator
**Files:** gate/vocab-extract.awk,gate/vocabulary.sh,gate/idiom.id

## The defect

`gate/vocabulary.sh` is a fail-closed declaration freeze: it refuses every
newly declared non-private module-scope identity, and says "no word-list edit
can waive this". Its only escape is a leading underscore
(`gate/vocab-extract.awk:12`, "PUBLIC is `name does not begin with _`"), and
`gate/idiom.id:931` refuses that spelling by name.

Measured — the extractor and the parser are both the subject, so run both:

    printf '+brk(text: str, from: i64)\n'    | awk -v MODE=diff -f gate/vocab-extract.awk
    -> relation	brk                              REFUSED by the freeze
    printf '+brk = (text: str, from: i64)\n' | awk -v MODE=diff -f gate/vocab-extract.awk
    -> relation	brk                              REFUSED by the freeze

**Every parameterised declaration form the language has is classified and
refused.** The freeze is closed, not open, on real declarations.

## The one lawful door: the zero-parameter relation

    printf '+check(): i64\n' | awk -v MODE=diff -f gate/vocab-extract.awk
    -> (nothing)

`check(): i64` compiles, runs, composes, carries no underscore, and is not
classified — the extractor's two parenthesised patterns both require a `:`
INSIDE the parens, which an empty parameter list cannot have. It is a genuine
canonical form on its own merits, not a spelling chosen to slip past a regex.

Its price is real: every parameter becomes duplication at each call site.
`lib/compiler/token.id` was already paying it before this gap was filed
("a shared `pick(row, kind)` is a new module-scope relation and cannot be
committed; a nested binding can").

## Two corrections to this gap, both mine

**First filing** claimed the underscore was the only door and the freeze was
deadlocked. False — the zero-parameter relation is a lawful door.

**Second filing** claimed the freeze fails open on the canonical definition
form `name(...) = (...)`. Also false, and worse because it was asserted from
an extractor result without checking the parser:

    pick(row, kind) = (row)       error: expected expression, got '='   rc=1
    add(a: i64, b: i64) = a + b   error: expected expression, got '='   rc=1

**That string is not a declaration form in Idol at all.** The extractor misses
it because it is not a declaration, not because it is the canonical one. There
is no fail-open on any form the language accepts.

The remaining true finding is narrow and unchanged: `vocab-extract.awk`
advertises a private marker that C0 forbids (`underscore = false`,
`constitution.md:235`; "native underscore identifiers are zero", :5565), where
`law.md` is silent on identifier spelling and C0 therefore governs.
`gate/idiom.id` projects C0 correctly; the advertised door is the unlawful
half. But it is not the only door, and nothing fails open.

## Acceptance

1. `gate/vocab-extract.awk` stops advertising a C0-forbidden spelling as the
   definition of private. A control: the zero-parameter relation stays
   admissible and every parameterised form stays refused, so the repair does
   not open the freeze.
2. The `_`-prefixed declarations admitted under the old door are enumerated
   by a runner and given a migration disposition.
3. `gate/idiom.id` is unchanged, or changed only in a direction C0 licenses.
4. Whatever population figures this repair needs are produced by an executable
   enumerator. No count is written into this file: the commands above are the
   authority, and `sh gate/vocabulary.sh --base <rev>` is the verdict.
