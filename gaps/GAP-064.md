## Confirmed, reproduced independently of the probe that found them

### A compile-time constant that provably does not fit is silently truncated

```duo
main(): i64
    x: u8 = 300
    print(x)
    return 0
end
```

```
duo check    exit 0        no diagnostic
prints       44            300 & 0xff
```

Same shape, same result:

```
x: i8  = 200      →  -56     check exit 0
x: u16 = 70000    →  4464    check exit 0
```

This is the worst version of the defect because **the value is a literal**. There
is no analysis to do, no fact to infer, no flow to be sensitive to: 300 does not
fit in `u8`, at the point of writing, always. It is not a missed optimization or
an undecidable refinement — it is a constant the checker looked at and accepted.

State 1 (proven) is false — it is not correct. State 2 (runtime-checked) is
false — nothing checks. State 3 (diagnostic) is false — exit 0, no message.

### Integer division by zero returns the IEEE +inf bit pattern

```duo
a: i64 = 7
b: i64 = 0
print(a / b)          →  9218868437227405312
```

`9218868437227405312` is `0x7FF0000000000000` — the bit pattern of `+inf`
reinterpreted as an integer. So `i64 / i64` is going through a floating-point
path and then having its bits read back as an integer.

Pass 100 B-4 says division is operand-selected and `i64/i64` truncates. It does
not say what `7/0` does, which is itself the finding: the numerics page owes a
row here, and whatever it says, the current answer is not a defensible one.
`error.divzero` routed, or a fault per Pass 107 §3, or a documented trap — any
of the three is a decision. An `+inf` bit pattern is what happens when nobody
decided.

## Why this matters more than the count

Five instances in roughly twenty probes is a density, not a list. The probes
were not adversarial — they were written to illustrate a document. The honest
inference is that the real count is higher and that nothing in the current gate
set looks for this class: `audit100` is lexical, the differential compares two
backends against each other (and both can be wrong together, as the truncation
cases are), and `abi-matrix` covers call shapes.

**What would find them:** a range/edge-case grid in the same spirit as
`abi-matrix` — every scalar descriptor × {below min, min, max, above max,
zero divisor} × {literal, computed} — judged against a decided table in
`docs/spec/numerics.md`. That table is owed anyway; making it executable is the
cheap part.
