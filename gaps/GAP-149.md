# GAP-149 — numeric source faces lack one compositional descriptor fact owner

**Status:** OPEN · **Filed:** !2026-08-10T14:08:19Z
**Priority:** P0 · **Kind:** expressiveness_gap
**Filed by:** codex-root-application-authority-20260810
**Files:** docs/spec/numerics.md,docs/spec/constitution.md,src/types.zig,src/sema.zig,src/semantic_graph.zig

Primitive-zero ruling supersedes docs/spec/numerics.md's irreducible scalar-descriptor table. Current ResolvedType tags encode i8..u64/f32/f64/vector faces as host enum cases; semantic_graph interns them as separate type_node identities. No admitted graph fact owner currently exposes numeric domain plus observable width/range/sign/format/overflow/rounding facts, and bare literal inference eagerly defaults to i64/f64 before all demand is applied. Session 1 will stop minting fixed-width primitive descriptor identities, retain ResolvedType only as migration fact on values/applications, publish descriptor identity unknown unless an exact declaration-owned descriptor exists, and keep source faces unchanged. Closure requires C0/numeric authority reconciliation plus a compact graph-owned numeric fact projection and contextual literal demand evidence; do not invent helper vocabulary locally.

## Crossed

The compositional fact owner exists and is `ResolvedType.numericFacts` /
`NumericFacts.acceptsSource` / `acceptsDescriptor` in `src/types.zig`. No
consumer reconstructs integral/real membership, width, sign, or range from a
`ResolvedType` tag: `is_integer`, `is_float`, `literalOutOfRange`,
`numericDemandAcceptsLiteral`, and descriptor acceptance all read the facts.
Descriptor acceptance composes through `option` and `result` from the same
single derivation rather than a per-wrapper rule.

`numericAcceptsDescriptor` is the SOLE owner of the law.nominal acceptance
refusal. It was a `sema` consumer's guard, which read only the OUTER descriptor
and therefore refused `d: feet = x` while ADMITTING `d: ?feet = x` and
`d: result[feet, str] = x` — a nominal descriptor accepting a plain value of its
own representation, which is the exact failure the guard's own comment named.
The physics/identity split is the point and is pinned by a control: a nominal
descriptor still DELEGATES `numericFacts` (so `d:floor()`, `narrowFit`, ARC, and
rendering keep working) and WITHHOLDS acceptance.

Reachability is bounded at the unit surface: `idol check` cannot yet parse a
nominal descriptor name in annotation position ("expected type, got 'name'"),
which is grammar-role debt in `GAP-134`/`GAP-145`, not numeric-fact debt. Run

    zig build unit-test

and read the `types:` and `sema:` numeric/nominal cases. State the command, not
the count.

`narrowFit` — the value a semantic write to a place LEAVES BEHIND — is now
DERIVED from `numericFacts` rather than tabulated beside it. Its tag switch was
a fourth statement of width and signedness, and a table cannot compose: `c_type`
delegates a nominal descriptor to its representation, so a place over a
nominal-over-`i32` reached the C emitter as `int32_t` and truncated while
`dnir_lower`, `native_backend` and `comptime` got no fit at all and kept the
full 64-bit ring. That is the same two-realizations-of-one-fact defect
`narrowFit`'s own comment records against itself, arriving through a wrapper the
table could not see. `lanes` is why width alone cannot decide (`v8i32` carries
width 32 and is not a narrow scalar place), and `i64`/`u64` stay absent so no
program on the register-width path gains an instruction. Every non-nominal answer
is pinned equal to the retired table by a control; the machine path cannot be
measured on a host where the direct backend refuses at DNB004.

The ANNOTATION FACE of that write projection is now derived from the same
facts. `types.narrowIntOfType` — the projection `dnir_lower` and `comptime` use
to learn a declared place's width from an `ast.TypeExpr` — was a hand-written
roster of six spellings, which is a second statement of which widths are narrow
and a fifth statement of width and signedness. It is now
`descriptorNamed(name)` → physical representation → `narrowFit`, so the only
question it asks is the one `numericFacts` already owns.

`descriptorNamed` derives the roster of scalar SPELLINGS from the roster of
scalar IDENTITIES: a payload-free `ResolvedType` identity is its own source
face, so `std.meta.stringToEnum` over the union's own tag names replaces the
list, and a payload-carrying identity is refused because its source spelling is
a composition. A control iterates the union's `field_names`/`field_types`
rather than a list, so a scalar identity added to the union cannot be one the
annotation face silently does not know.

The repair this closes was opened by the `narrowFit` derivation above:
`narrowFit` composes through a nominal descriptor and the name roster could not
see one, so a place declared `p: tick = ...` over a nominal-over-`i32` reached
`codegen` as `int32_t` and truncated while `dnir_lower` and `comptime` were
handed no width at all and kept the full 64-bit ring — the same
two-realizations-of-one-fact defect, arriving one seam earlier through the AST
annotation. Every non-nominal answer is pinned equal to the retired roster by a
control, on both the six spellings it listed and the spellings it declined, so
no program on the scalar annotation path can gain or lose a truncation. Run

    zig build test

and read `types: the annotation face of the write projection is derived from
the same facts`. The pre-existing red aggregate in that step is unchanged by
this slice; compare the summary line before and after rather than trusting a
count here. The machine path still cannot be measured on a host where the
direct backend refuses at DNB004.

The SOURCE FACE of `numericFacts` is now derived from the same owner too.
`ast.TypeExpr.is_numeric`, `is_integer` and `is_float` were three further name
rosters — three more statements of which spellings are numeric, integral and
real, beside the one owner in `types.zig` — and each answered a fact the union
already owns. They are now one query, `ast.TypeExpr.scalarFacts`, which reads
`descriptorNamed(name)` → `numericFacts` and filters exactly the two things a
scalar SOURCE spelling is not: a nominal descriptor (which delegates its facts
on purpose but is not a numeric spelling) and a vector identity (`v4f64`, a
numeric fact owner whose bare word the roster also never listed). This is the
same derivation `narrowIntOfType` already uses, applied to the read face after
the write face. A roster cannot compose: a scalar spelling added to the
`ResolvedType` union is one the switches silently did not know. A control pins
the derived face equal to the retired roster on all ten scalar spellings it
listed AND on the vector, nominal, and non-numeric spellings it declined, so no
consumer of the AST numeric predicates can gain or lose an answer. Run

    zig build unit-test

and read `TypeExpr numeric face: derived equals retired roster, declines
vectors and nominals`. Compare the summary line before and after: the
pre-existing red aggregate is unchanged and one new passing control is added.

Still open, and unchanged by the above: fixed-width primitive descriptor
identities are still minted as host enum cases and interned by
`semantic_graph` as separate `type_node` identities; `codegen.mem_type_from_name`
and `abi_specialize` remain two more name rosters at the realization face; bare
literal inference still defaults before all demand is applied; the graph does
not own the numeric fact projection; `docs/spec/numerics.md` and C0 are not
reconciled.
