Primitive-zero ruling supersedes docs/spec/numerics.md's irreducible scalar-descriptor table. Current ResolvedType tags encode i8..u64/f32/f64/vector faces as host enum cases; semantic_graph interns them as separate type_node identities. No admitted graph fact owner currently exposes numeric domain plus observable width/range/sign/format/overflow/rounding facts, and bare literal inference eagerly defaults to i64/f64 before all demand is applied. Session 1 will stop minting fixed-width primitive descriptor identities, retain ResolvedType only as migration fact on values/applications, publish descriptor identity unknown unless an exact declaration-owned descriptor exists, and keep source faces unchanged. Closure requires C0/numeric authority reconciliation plus a compact graph-owned numeric fact projection and contextual literal demand evidence; do not invent helper vocabulary locally.

## Crossed

The compositional fact owner exists and is `ResolvedType.numericFacts` /
`NumericFacts.acceptsSource` / `acceptsDescriptor` in `src/types.zig`. No
consumer reconstructs integral/real membership, width, sign, or range from a
`ResolvedType` tag: `is_integer`, `is_float`, `literalOutOfRange`,
`numericDemandAcceptsLiteral`, and descriptor acceptance all read the facts.
Descriptor acceptance composes through `option` and `result` from the same
single derivation rather than a per-wrapper rule.

`numericAcceptsDescriptor` is the SOLE owner of the law.nominal acceptance
refusal. It was a `sema` consumer's guard, which read only the OUTER descriptor
and therefore refused `d: feet = x` while ADMITTING `d: ?feet = x` and
`d: result[feet, str] = x` — a nominal descriptor accepting a plain value of its
own representation, which is the exact failure the guard's own comment named.
The physics/identity split is the point and is pinned by a control: a nominal
descriptor still DELEGATES `numericFacts` (so `d:floor()`, `narrowFit`, ARC, and
rendering keep working) and WITHHOLDS acceptance.

Reachability is bounded at the unit surface: `idol check` cannot yet parse a
nominal descriptor name in annotation position ("expected type, got 'name'"),
which is grammar-role debt in `GAP-134`/`GAP-145`, not numeric-fact debt. Run

    zig build unit-test

and read the `types:` and `sema:` numeric/nominal cases. State the command, not
the count.

`narrowFit` — the value a semantic write to a place LEAVES BEHIND — is now
DERIVED from `numericFacts` rather than tabulated beside it. Its tag switch was
a fourth statement of width and signedness, and a table cannot compose: `c_type`
delegates a nominal descriptor to its representation, so a place over a
nominal-over-`i32` reached the C emitter as `int32_t` and truncated while
`dnir_lower`, `native_backend` and `comptime` got no fit at all and kept the
full 64-bit ring. That is the same two-realizations-of-one-fact defect
`narrowFit`'s own comment records against itself, arriving through a wrapper the
table could not see. `lanes` is why width alone cannot decide (`v8i32` carries
width 32 and is not a narrow scalar place), and `i64`/`u64` stay absent so no
program on the register-width path gains an instruction. Every non-nominal answer
is pinned equal to the retired table by a control; the machine path cannot be
measured on a host where the direct backend refuses at DNB004.

The ANNOTATION FACE of that write projection is now derived from the same

## The realization face of the scalar roster

The REALIZATION FACE is now derived from the same owner, and the blocker this
gap recorded against it was measured FALSE. This section stated that
`abi_specialize`'s `isNativeScalarLabel` "cannot read this owner today —
`abi_specialize.zig` is SEMA and `types.zig` is IR, so the edge is one
`gate/layering.sh` L1 refuses." That is not what the firewall says.
`gate/layering.rules` forbids `IR SEMA`, not `SEMA IR`; the direction rule
exists to stop a lower layer re-deriving meaning from a higher one, and reading
a decided answer from IR is the shape it is FOR. Twelve SEMA units already
import `types.zig`. The claim was inherited from the rule's name rather than
read off its manifest, and it parked a slice for one session behind a firewall
that was never pointed at it. Run

    sh gate/layering.sh --static-only

and compare the `L1 --` line across the slice: one more distinct import edge,
the same forbidden count, the same baseline pin. A new admitted edge does not
appear in the forbidden set at all, which is the whole content of "admitted".

The roster itself was a SIXTH statement of which identities are scalar and of
their widths, and it stood at the foreign ingress seam that decides whether a C
record has a native layout and whether a parameter is passed by value or by
pointer. It is now `types.abiDescriptorNamed` — `descriptorNamed(name)` →
`scalarRepr`, minus `str`. The subtraction is not a roster entry: `str` is a
managed reference (`const char*`), so its ABI is a POINTER, which is already the
next question `passByForParam` asks. Every identity the retired roster declined
is now declined BY A FACT rather than by absence: `void`, `nil` and `never` are
not values passed in a register, `any` is boxed and opaque, the vector
identities span several registers, and a nominal descriptor is an identity
rather than a representation. `double` and `float` stay explicit for the reason
`memSpellingOf`'s three legacy spellings do — they are C's words for `f64` and
`f32`, they are not `ResolvedType` identities, and no owner can derive them.

The face projects the DESCRIPTOR, not a boolean, so the seam that decides
pass-by can read the facts it is deciding from; a roster could only ever answer
yes or no, and the width the ABI actually needs was one it could not carry.

A control pins the derived face equal to the retired roster on every label it
listed AND every label it declined — the eleven scalar identities, the two C
spellings, `str`, the non-representational identities, the vectors, the
payload-carrying words, the legacy and foreign spellings, the empty name, both
pointer spellings and an unknown — and iterates the union's own tags rather than
a list, so a scalar identity added to the union cannot be one the ABI face
silently does not know. Run

    zig build unit-test

and read `types: the realization face of the scalar roster is derived from the
same facts`. Compare the summary line before and after: the pre-existing red
aggregate is unchanged and one new passing control is added. Planting the `str`
widening in `abiDescriptorNamed` was checked to fail this control closed.
