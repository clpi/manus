## The authority

| 1 | Owner ruling, verbatim: |

> "Any should never be explicit since a non specified type is by default
> compiler inferred any or void based on demand. Any should be an edge (a
> method) of any iterable injected algebraically."

| # | directive |
|---|---|
| 1 | Decomposed: |

1. **An explicit `any` in TYPE position is non-canonical.** The absence of an
   annotation already means compiler-inferred, and demand decides any-vs-void.
   This is SOURCE-INFER-ONE (`law.infer.one`) applied to one word: no source
   spelling survives merely to restate a fact the compiler recovers uniquely.
   `law.any.descriptor.zero` (C0 §112, enforced over gaps by
   `tools/node/dev/gapc0` and over agent surfaces by `gate/agentlaw.sh`)
   already states the annotation-position ban as law; this gap gives the
   population its ratchet and its migration owner.
   The compiler already implements the default — `src/sema.zig`
   `check_func_body`: a `.inferred` parameter gets `.any`, an `.inferred`
   result gets `.any`; the GAP-060 void-demand inference is the void half.
2. **The word `any` belongs to the RELATION vocabulary** — `xs:any(pred)`, the
   existential edge on an iterable, resolved as an ordinary subject-first
   relation (COLLECTION-RELATION-ONE, `src/collection_relation.zig`), injected
   algebraically: no namespace, no trait, no iterator protocol object.

|---|---|
| 1 | The compiler's internal `.any` lattice member is realization/checker state, not source vocabulary, and is out of scope. |

## Residue — exactly where the edge stops

1. **Subject narrowing.** Only an `.array`-descriptor subject reaches the edge
   (`xs: [3]i64 = {…}`). An unannotated table literal subject types as a
   table, `checkCollectionRelation` declines (a record has no element
   descriptor), and the application falls to ordinary subject-first
   resolution.
2. **Lib shadowing of the fallen-through name.** Ordinary resolution then
   finds the operation-first declarations `lib/iter.id:27 any: bool = (list,
   fn_ref)` and `lib/meta.id:433 any: bool = (t, pred)` and refuses:
   "ambiguous subject-first relation 'any': 2 admissible declarations".
   `lib/contracts.id:79` and `lib/ml/tensor.id:457` also declare `any`.
   These are the retired operation-first face of the exact edge the ruling
   names, with zero tracked callers (`git grep` finds no `any(`,
   `iter.any`, or `.any` application site; `lib/meta.id:954 M.any = any` is an
   export row). Deleting/renaming them is follow-on wave work under this gap —
   they are the reason a table-literal `xs:any(p)` reads as ambiguity today.
3. **`is_typed` is a spelling-derived observable.** Removing `x: any` flips
   `fb.is_typed` (src/sema.zig `check_func_body`) from true to false, and
   realization may branch on it. The sample wave verified per file that check
   and realize outcomes are unchanged; every future wave must do the same
   until the bit derives from facts rather than spelling.

## Acceptance

1. **(a) DONE — ratchet.** `gate/any.sh` pins the type-position population
   (occurrence-level, comment-stripped, relation face excluded; both counting
   directions proven by in-gate controls; subjects via `gate/subject.sh`,
   zero-subjects fails per GAP-201). Growth fails; the pin may only be
   lowered with the migration that earned it.
2. **(b) partially DONE — the edge is complete and pinned** for `.array`
   subjects on the C path, executed by `examples/any_relation_smoke.id`.
   Remaining: the residue above — table-literal subjects reach the edge, and
   the shadowing lib `any` declarations are deleted or renamed so the fallen-
   through name stops reading as ambiguity. Sibling questions (`all`,
   `count`, …) are new rows with lowering in the same change, per the roster
   test.
3. **(c) method proven — full migration is follow-on waves.** Each removed
   annotation must be inference-recoverable: `idol check` green before and
   after, realizer outcome unchanged, and by-value answers unchanged where an
   execution path exists. Removing `: any` where inference recovers something
   else (value bindings today) is a semantic change and REFUSES.
4. **(d) refusal at zero.** When the population reaches zero, `.id` mode
   refuses type-position `any` outright (parser/sema diagnostic naming this
   gap), and the gate's pin parks at 0 as the known-and-closed record.
