# GAP-177 — change and delta as first-class semantic relations

**Status:** OPEN · **Filed:** !2026-08-18T14:55:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, docs/law.change.delta, src/sema.zig, src/dnir_lower.zig

Make `Δinput → Δoutput` an ordinary property of relations. Subsume
incremental compilation, reactive programming, database view maintenance,
streaming, build systems, and automatic differentiation under one change
algebra.

## Current measured boundary

`law.change.delta` is specified but not implemented. Incremental compilation
exists as compiler state, not as a semantic algebra. AD and reactive execution
are not yet modeled as change propagation.

**Crossed:**

- `law.change.delta` is documented in C0.
- Self-adjusting computation and incremental algorithms are cited as prior art.

**Still missing:**

- `Δf(x, Δx) = Δy` for every relation `f`.
- Dependency delta, demand derivative, and minimum affected application
  frontier as graph facts.
- Integration with incremental compilation, build systems, reactive systems,
  streaming, database views, and agents.
- Automatic differentiation as a special case: `∂output/∂input` is a change
  quotient.
- Bidirectional projection (lenses/incremental relational lenses) so that
  `view = project(source)` and `Δview` can be propagated back to `Δsource`.

## Required order

1. Define `change` as a semantic relation: `f(x) = y` implies `Δf(x, Δx) = Δy`.
2. Add graph facts for dependency, demand derivative, and affected frontier.
3. Implement delta propagation through the same graph engine that evaluates
   forward semantics.
4. Show that incremental compilation and AD are realizations of the same
   change relation with different observers.
5. Generalize to bidirectional projections: `source → view` and `Δview → Δsource`.

## Closure acceptance

Close when a single change algebra powers incremental compilation, reactive
execution, database views, streaming, build systems, and AD; and when a changed
input causes only the minimum affected application frontier to recompute.
