## Strengthened target — dominance contract

`law.project.ftcftw` is now subsumed by the **dominance** contract
(`docs/spec/law.md` §98–§101; C0 `law.ftcftw.dominance`, `law.optimization.open`,
`law.cost.closure`, `law.algorithm.realization`, `law.optimization.validated`).
The admissible claim is no longer "meet or beat C on the exercised path" but
**verified Pareto dominance over the best known semantically equivalent
implementation, reaching the physical lower bound wherever dominance is
impossible**, with three valid per-dimension outcomes (win · optimal-at-lower-
bound · loss-with-named-debt) and no vanity scalar or aggregate that hides a
specific open loss.

This gap remains the **aggregate-evidence-presence** rung. The dominance
mechanics it must eventually carry — the cost vector, the per-application
cost-debt graph fact (`actual − lower_bound`), competitor-binary and
hardware-in-the-loop discovery oracles, and the acceptance inequality — are the
realization/evidence obligation tracked with GAP-169 (machine-code realization)
and GAP-151 (semantic lineage / optimization-demand projection). At S0 none of
it is measured: the FTCFTW ledger self-reports **NOT PROVEN** and the aggregate
is red. Contract presence is not a performance result (`law.profile.evidence`).

### First executed per-kernel dominance data point (2026-08-13)

Subject revision `2d3f1e7f` (== HEAD), Apple M4 arm64, clang 21 `-O3` reference.
Artifact: `evidence/recurrence.txt` (kernel source, commands, disasm, timings).

Three kernels were compiled by both the direct-native emitter and `--backend=c`,
run, and timed (best-of-5 warm USER seconds). All three machine-code path pairs
**agree** on the observation, satisfying the differential oracle
(`law.oracle.bounded`).

```text
kernel                          direct   clang -O3   outcome
A nonlinear recurrence (5e8)    0.98 s   0.97 s      parity  -> bound
B 4 nonlinear LCG lanes (3e8)   0.30 s   0.30 s      parity  -> bound
C 8 affine accumulators (4e8)   0.40 s   0.00 s      LOSS    -> open
```

**law.repair.class CORRECTION.** The prior version of this row recorded kernel A
as a "~8% LOSS (~21 instr/iter)" caused by "loop-invariant 64-bit constant not
hoisted (~13 of ~21 loop instructions are mov/movk chains) / no madd." Re-read
from the emitted binary at the SAME subject revision, that is **false**:
constant-LICM already works — A's hot loop is 12 instructions with C1/C2/bound/1
all hoisted to the prologue — and A is at PARITY with clang. The false loss is
withdrawn. See `evidence/recurrence.txt` (rewritten) and `evidence/frontier.txt`.

Corrected reading:
- A and B are at the shared multiply lower bound (latency / port throughput).
  NEITHER backend can close-form the nonlinear i64-wrapping recurrence, so both
  are pinned to the same floor → `bound`. The residual instruction-count delta
  (madd fusion + copy coalescing) is real but **not time-observable** in the
  multiply shadow (12-vs-4 instr ⇒ 0% wall-clock).
- C is the one genuine loss: every accumulator is affine, so the program's sole
  observation (a compile-time-constant exit code) is closed-form in **O(1)**.
  clang's scalar evolution folds the loop to that constant (inner loop has zero
  adds → 0.00 s); the direct backend runs all 4e8 iterations. `status=open`,
  `cause=missing-scalar-evolution` (graph/demand ALGORITHM axis, NOT a peephole),
  `lowerbound=O(1)`. This does not apply to A/B (nonlinear, unclosable) — which
  is exactly why A/B are at parity and C is not.

This is the graph-**E** debt schema formalized in GAP-172; the status enum
`{win, bound, open, unknownbound}` and the "no aggregate hides a loss" rule are
owned by `law.cost.closure`. Verification machinery (FTC-010) now exists: a
hang-proof differential oracle (compile-only + `gtimeout`; corpus baseline
agree=52/diverge=4-pre-existing/skip=7) gates any codegen change.
