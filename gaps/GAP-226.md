| The wall is one cause and it holds 74% of the population |

| # | directive |
|---|---|
| 1 | `host-relation-no-entity` and `host-relation-name-declared-in-home` are the same sentence: **the relation this application names has no relation entity in the graph, because nothing declares it.** `print`, `s:len()`, `s:sub(a,b)`, `b:byte()`, `x:floor()`, `s:gsub(a,b)`, `type(v)`, `assert(c)` are answered from `subject_home`'s closed home enum and `native_bootstrap`'s face list. |
| 2 | A spelling roster is the producer, so there is no id for `publishApplication` to point at, and every downstream fact — effect, demand, trap, completion, witness, realization — has nowhere to attach. `gate/coverage.sh` names the same thing from the other side: `relation.identity`, 514 sites, rival authority `spelling comparison`, the largest rival in that table. |

| 1 | The four counts are not stored anywhere that can decay. |
| 2 | This is the loop that produced them; run it rather than citing them: |

```sh
ok=0; missapp=0; other=0; n=0
for f in examples/*.id; do
    n=$((n + 1))
    if ./zig-out/bin/idol compile "$f" --backend=c --emit=c -o /tmp/x.c >/tmp/e.txt 2>&1; then
        ok=$((ok + 1))
    elif grep -q missing-application-id /tmp/e.txt; then
        missapp=$((missapp + 1))
    else
        other=$((other + 1))
    fi
done
printf 'examples=%s c-backend-ok=%s missing-application-id=%s other=%s\n' \
    "$n" "$ok" "$missapp" "$other"
```
