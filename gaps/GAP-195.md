- Context dimensions as FACTS on existing kinds — `stage` = world fact availability, `target` = target facts in world, `revision` = provenance, `place` = realization placement, `sample`/`precision`/`observer` = demand, `time`/`configuration` = world facts. No `context` kind.

- Context dimensions: time, stage, target, revision, place, sample, precision,
  observer, configuration.
- Specialization as partial determination of context.

## Required order

1. Express each context dimension as facts on existing kinds (world/demand/realization/provenance); amend C0 only if a dimension is PROVEN inexpressible there.
2. Make `world`, `stage`, `target`, `place` dimensions of context.
3. Implement eduction as an evaluation strategy — `demand(id, world, quotient)` propagates demand backward, computes only demanded coordinates, memoizes; a scheduler, not semantic ontology.
4. Make compilation demand-driven: `artifact(main, arm64)` induces only the
   demanded semantic sub-graph.
5. Use context-indexed values for incremental, staged, and specialized builds.
