# GAP-033 — a void tail call leaks into the return value on the native backend

**Filed** 2026-08-07. **Status** FIXED 2026-08-07 (`dnir_lower.isVoidTailCall`). **Blocks** 5 programs in `examples/`
(`mandelbrot`, `bench_simd_matmul`, `test_sql`, `pass38_semantic_access_g6`,
`pass57_primitive_descriptor_values`) plus the general shape.

## What

DEMAND (rule 3) makes the last expression of a block its result. So in

```
main(): i64
    m: i64 = 2
    if m == 2
        print(" ")
    end
    0
end
```

the `print(" ")` is the if-body block's **tail expression**, not a statement.
That is correct per the canon — the body's value simply isn't consumed here,
because the `if` sits in statement position.

The native backend does not lower it that way. It leaves the call's result as
the block's value and it leaks into the enclosing function's return:

```
              direct        C backend
  no else     exit 59       exit 0
  with else   exit 224      exit 0
```

59 and 224 are not a computed wrong answer, they are whatever was in the
register — the value was never defined.

## Why it is not just a precheck row

`native_scalar_precheck` currently refuses these modules, so the bug is not
reachable today: the tail is checked with `expr_is_native_scalar`, which
rejects `print` as a runtime global, and the module falls back to the C
backend, which is correct. The identical call one nesting level out is
admitted — `.call_stmt` at the top of a function, or in a `while` body, goes
through `call_stmt_is_native_scalar`, which has an explicit `print` arm. So one
construct gets two answers depending on how deep it sits.

**Widening the precheck was tried and reverted 2026-08-07.** Routing the tail
through `call_stmt_is_native_scalar` (a strict superset — it delegates to
`expr_is_native_scalar` for everything that is not a call) makes all five
programs compile natively, and produces the wrong binaries above. That is the
trade the ledger forbids: it exchanges a correct C-backend fallback for a
silently wrong native one.

The reverted diff is recorded in the comment at the `block_is_native_scalar`
tail check, so the next person to look at that line finds the measurement
rather than repeating it.

## The fix — landed

`tryEmitTailDemandReturn` now detects a void tail call and lowers it with
`.discard` consumption, reporting "no return" so the branch falls through
instead of emitting `ret <undefined register>`. The precheck widening is back
alongside it, so the gate and the lowering agree. Measured after: both repros
exit 0 and print the same bytes as the C backend.

`isVoidTailCall` is syntactic (`print` only) because `LowerCtx` carries no type
map. The general rule wants the callee's declared return type, which is the
same work that would let user `: void` functions lower here too — and that is
the NEXT blocker for these programs: `mandelbrot` and `test_sql` now bail at
`lowerModule` because `render(): void` is not an eligible function, so the
module's function count does not match.

## Original diagnosis

Belongs in the backend, not the gate: a tail-position call whose value is
discarded — the block is in statement position, or the callee's result type is
void — must lower as a discarded statement, leaving the block's value
undefined-but-unused rather than propagating the call's register. Once
`dnir_lower` / `native_backend` do that, the precheck widening above is the
one-line change that lands the five programs.

## Repro

```
duo compile --backend=direct x.duo -o /tmp/d.bin; /tmp/d.bin; echo $?   # 59
duo compile --backend=c      x.duo -o /tmp/c.bin; /tmp/c.bin; echo $?   # 0
```

with the precheck widened. Without the widening, `--backend=direct` reports
`bail site: native-scalar precheck — runtime-global-call:print`.
