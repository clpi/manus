# GAP-120 — File boundaries lack durable semantic concept identity

**Status:** OPEN · **Filed:** !2026-08-09T20:08:31Z
**Priority:** P1 · **Kind:** expressiveness_gap
**Filed by:** codex_semantic_normalization
**Files:** src/semantic_graph.zig,docs/spec/constitution.md

C0 law.file.one now requires each file to be the durable home of one semantic concept across ownership, docs, tests, transforms and generated projections. The live graph and MCP can inventory paths but do not yet attach or validate a durable concept identity, so utility buckets and unrelated declaration bundles cannot be rejected semantically. Implement from the persistent graph/manifest, not filename regexes; expose the same structured finding through compiler, LSP, MCP and generated docs.

## 2026-09-02 — the adjudicator refuses the utility bucket (this worktree)

The demand join and the stated refusal shape landed on the graph, produced from
the same persistent graph as the identity — never from a filename regex. Slice:

- `ConceptFact.shared_demand_count` (`src/semantic_graph.zig`): how many
  distinct caller relations drive two or more RESOLVED applications onto this
  module's relations, gathered while `publishConceptIdentities` already holds
  the applications (`law.fact.producer.one`: one producer, counted not
  decided). A caller that applies the same relation twice counts once.
- `ConceptRefusal` — module, reason enum (`no_shared_demand` today; a future
  reason joins the enum, not a second column), and the exact applied cohort
  (`split_start`/`split_len` into the packed `concept_split` column), in graph
  id order. `publishConceptRefusals` runs AFTER the identities it reads; it
  refuses exactly when two or more relations are applied from elsewhere and
  no caller drives two of them — the gap's "relation cohort sharing no
  demand". A module with fewer than two applied relations, or with a shared
  caller, is NOT refused.
- `conceptRefusal` / `conceptRefusalSplit` answer only from the refusal
  column; a damaged row answers null, never a re-derivation (test-enforced:
  removing the row index loses the refusal).
- JSON schema 16 -> 17: `refusals[]` (module, reason, split) plus
  `shared_demand` on every `concepts[]` row, so compiler, MCP and docs
  readers answer the same structured finding. `writeJson` re-verifies every
  refusal row and its cohort before writing; damage refuses the export.

## 2026-09-01 — concept identity landed on the graph (aa48675c3)

The graph now ATTACHES a durable concept identity per file boundary, produced
from the persistent graph and never from a filename regex. Slice:

- `ConceptFact` (`src/semantic_graph.zig`): identity = the module's dotted
  home (`self.home` for the root, the node's `foreign_home` for a reached
  partition — the same `homeOfPath` derivation the definer made); composition
  = the graph's own census over that home (relations declared inside it,
  descriptor shapes it owns, applications resolved onto its relations via
  `ApplicationFact.target`).
- One producer, `publishConceptIdentities`, runs at the END of checked lift
  (`law.fact.producer.one`). A graph lifted without the checked pipeline has
  no rows and `conceptIdentity` refuses to synthesize one; damaging the row
  index cannot recover an identity from the path (test-enforced).
- Structured finding exposed through the compiler's graph export: JSON
  schema version 15 -> 16, `concepts[]` plus a `concept` face on each module
  node, so compiler, MCP and tooling readers answer the same fact. LSP and
  generated docs still consume `writeJson` indirectly; a dedicated LSP
  surface and doc generation remain OPEN below.
