# GAP-117 — Canonical callable result-demand face requires deleted end token

**Status:** CLOSED · **Filed:** !2026-08-09T20:08:02Z · **Closed:** !2026-08-10T04:11:01Z
**Priority:** P0 · **Kind:** expressiveness_gap
**Filed by:** codex_semantic_normalization
**Files:** src/parser.zig,docs/spec/constitution.md,scripts/semanticgate.id

The production parser now recognizes result demand on the binding before a
parenthesized callable and lowers it through the existing function record. The
space after the copula distinguishes `name: descriptor = (...)` from the tight
receiver face `subject:relation(...)`; no new token or callable subsystem was
introduced.

Evidence:

- `examples/spec100/result.id` is canonical Duon: one-word identifiers,
  offside body, no result suffix, no `end`, no `std`, and no bridge binding.
- The semantic gate executes that fixture by value and requires output `42`.
- Parser unit coverage proves both builtin and named result descriptors.
- `zig build unit-test --summary all` moved from 4 failures to the same 3
  unrelated baseline failures; both new parser tests pass.
- Commit `06cf5c5` is pushed on `canonical-to-relation`.

The remaining typed-record boxing and cross-module initialization failures are
separate lowering obligations; GAP-121 owns the module boundary. They are not a
reason to retain the deleted callable-result suffix.
