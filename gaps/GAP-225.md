# GAP-225 — `effect: none` is published about relations whose body writes module state

**Status:** CLOSED · **Closed:** !2026-08-23T00:00:00Z
**Priority:** P0 · **Kind:** wrong_answer
**Files:** src/semantic_graph.zig,src/comptime.zig,src/dnir_lower.zig,gate/speculation.sh,gate/effect.sh,examples/place/mutate.id

## It was LIVE, not latent, and the section below is wrong about that

This gap filed the hazard as latent — refused in front of every consumer by
lineage and shape in `native_backend` — and recommended fixing mutation before
termination on that reading. The ordering was right. The latency was not.

`comptime.foldRelationBody` is a consumer with no lineage rule and no shape
rule in front of it. It reads `effect == .none` through
`graph_query.effectFreeCalleeClosure` and replaces a zero-operand relation's
whole body with its value. Measured on `--backend=direct`, source path fixed,
whole program:

    ring = 0
    bump: i64 = ()      probe: i64 = ()
      ring = ring + 1     bump()
      ring                bump()
                          ring
    print(probe())      ->  0        and the answer is 2

Three independent arms agree on 2: `IDOL_EFFECT_SEVER=1`, giving `probe` one
parameter so the fold's `params.len == 0` gate declines, and the generated
store. The read side is the same defect with the write left in place —
`lure()` whose whole body is `peek()` folded to the module initializer where
the program answers 1, because the fold binds every module-scope initializer
it can evaluate and a binding something WRITES does not hold its initializer.

`examples/place/mutate.id` pins both, by value, and `IDOL_MUTATION_SEVER=1`
reproduces the wrong answer on demand.

## What landed

**The lift.** `liftBindingsInStmts` walks in two sweeps — bind this scope, then
descend into callables — so a relation body is no longer lifted against
however much of the module happened to be declared above it. A bare-name
assignment whose name the module binds and this body does not is recorded as a
`SemanticGraph.Write` naming the exact binding entity; a body that DECLARES the
name keeps its own. `_pos` in `lib/compiler/comptime.id` collapses from seven
entities to one:

    zig-out/bin/idol graph lib/compiler/comptime.id | jq -r '[.nodes[]|select(.name=="_pos")|{id,kind,scope,line}]'

**The column.** `publishApplicationMutations` closes those writes over the call
graph and publishes `mutation: unknown | none | one(binding) | many(bindings)`
keyed by the application — `Draw`'s key, and NOT a `Draw`: a module binding is
not an injected world and confers no ambient authority, so world draw, binding
mutation and the effect consequence stay three columns. Both `writes` and
`mutations` are in the graph export (schema v13).

**The consequence.** `publishApplicationEffects` gains a sixth ground from that
column: mutation blocks AND grounds at the binding written, so the card names
the observation rather than shrugging. `comptime.foldRelationBody` stops
binding a module initializer whose binding something writes.

**The reconstruction, deleted.** `dnir_lower.moduleFunctionsAssignName` /
`stmtsAssignName` walked every relation body with their own shadow rule to
answer the same question; they are gone and the storage decision asks
`graph.moduleBindingWritten`. Every `--emit asm` output over `examples` and
`lib` — 244 modules — is byte-identical across that swap.

## The defect

`publishApplicationEffects` blocks a relation on five grounds: a C linkage
origin, a `.capture` edge, a static `.member` read, an unresolved application
candidate, and a callee already blocked. A write to a **module-scope `global`**
is none of the five, and it cannot become one by accident: the lift mints a
FRESH scope-local entity for `_pos = _pos + 1` inside a relation instead of an
edge to the module binding it names.

Measured — the graph is the subject, so read it:

    zig-out/bin/idol graph lib/compiler/comptime.id \
      | jq -r '(reduce .nodes[] as $n ({}; .[$n.id|tostring]=$n.name)) as $nm
               | [.applications[] | {rel: $nm[.relation|tostring], card: .effect.card}]
               | group_by(.rel) | map({rel:.[0].rel, cards:(map(.card)|unique)})'

Every relation in that module publishes `effect: none`, `_reset` among them —
and `_reset`'s entire body is three assignments to module-scope `global`s. The
module's own header says "Cursor state is module-level: folding is not
reentrant". The graph says it observes nothing.

    zig-out/bin/idol graph lib/compiler/comptime.id \
      | jq -r '[.nodes[]|select(.name=="_pos")|{id,kind,scope,line}]'

returns one entity of kind `local` at `scope: 0` (the `global`) and one MORE,
of the same kind and spelling, per relation that assigns it — with no edge
relating any of them. Compare that list against the relations the source scan
finds writing `_pos`:

    awk -f gate/speculation.awk lib/compiler/comptime.id | awk -F'\t' '$2=="_pos"'

The graph therefore cannot tell a write to the module binding from a fresh
local of the same spelling, and `publishApplicationEffects` reads the second.

No count is written into this file. The population is enumerated, floored and
reported by a runner:

    sh gate/speculation.sh

## Why it is a wrong answer and not a missing one

`Card` exists so that `unknown != none != one`. `.none` is a POSITIVE claim —
"no observation is reachable" — and `graph_query`'s header states the
consequence plainly: "If that pass ever promotes something observable, this
reads it as pure." A relation that advances a parser cursor is observable to
every later relation that reads the cursor. The honest card for it is
`unknown`, or a `one` naming the module binding it writes. It is neither.

The pass's own comment makes the claim explicitly: "A cycle none of whose
members is blocked performs no observable action however long it runs." That
is false for a cycle that mutates a module-scope binding, and the mutually
recursive descent in `lib/compiler/comptime.id` is exactly such a cycle.

## Why it has not miscompiled yet

Independent refusals stand in front of every consumer that would act on it, and
none of them is a fact:

1. `native_backend.ifConvArmChainAdmissible` refuses an arm containing a call
   on the ground `no-termination-fact`, before it can reach mutation;
2. it refuses any arm operation carrying graph lineage on the ground
   `arm-op-lineage`, because a collapsed window emits no realization row; and
3. `ifConvArmOpAdmissibleTwoSided` admits only single-cycle integer ALU work,
   so a `call_direct` is refused by SHAPE whether or not it carries lineage.

`gate/speculation.sh` measures which of these fire, and measures that a real
termination producer would unblock nothing:

    sh gate/speculation.sh

So the hazard is latent, and it is latent for reasons that a lane trying to
make termination measurable would be told to delete.

## The sequencing this gap exists to fix

The obvious reading of the `no-termination-fact` spelling is "publish a
termination fact, then remove the lineage rule, then the transform fires". Run
in that order it is a miscompile: the FIRST admission test on an arm is
`armInstrEffectAdmissible`, which reads `effect == .none and authority ==
.none`, and both of the surviving sites — `left = left + _term()` against
`left = left - _term()` in `_addsub`, and the `<<`/`>>` pair in `_shift` —
would then speculate a recursive-descent step that advances `_pos` in both
arms.

**Mutation before termination.** Termination is refuted as a next step by
measurement (`gate/speculation.sh`); mutation is not, because it has a live
consumer today in `graph_query.effectFreeClosure` and a second in
`native_backend`.

## Acceptance

1. A write to a module-scope binding is a graph fact keyed by the application
   or the binding — not a field on `ApplicationFact`, per `law.md` §20-21 and
   the `Draw` precedent — with `unknown`/`none`/`one(binding)` cardinality and
   no boolean anywhere.
2. `publishApplicationEffects` stops publishing `.none` about a relation that
   reaches such a write, and the `effect` census in `gate/effect.sh` records
   the movement: some `none` becomes `unknown` or `one`, and `one` does not
   fall.
3. The lift relates an assignment to a module-scope `global` to the module
   binding it names, so the six shadow `_pos` entities collapse to reads and
   writes of one. A control: a genuine shadowing local of the same spelling
   stays a distinct entity.
4. `gate/speculation.sh` keeps passing, and its `...publishing effect none`
   row reaches zero by the fact being fixed rather than by the corpus losing
   its witness — the runner refuses the second by flooring the population and
   by naming the witness module it cannot lose silently.

## C0 alignment

- **constitutional owners:** application · relation · binding · place · effect · world · witness
- **kind delta:** 0
- **registry delta:** 0
- **source syntax delta:** 0
- **semantic invariant:** a relation that writes a module-scope binding is not unobservable; `effect: none` is a proof of unobservability and may not be published where the only evidence is that the pass has no name for the write.
- **physical mechanism:** the mutation column is an ordinary sparse graph fact keyed by application, read by the same consumers that read `effect`; no new registry and no boolean.
- **prerequisites:** none. `gate/speculation.sh` is the measurement; GAP-202 and the termination fact are DOWNSTREAM of this and refuted as next steps by it.
- **foreign implication:** a foreign body already blocks on linkage origin; this adds nothing there and must not weaken it.
- **world implication:** a module binding is not an injected world and must not be modelled as one — `Draw` answers "which world does this occurrence reach", and the answer here is a binding, not a world.
- **projection implication:** none.
- **demand implication:** erasing an application whose only work is a module-scope write is a demand decision that this fact finally makes answerable; today it is answerable and wrong.
- **realization implication:** if-conversion, whole-relation folding, CSE and hoisting all read `effect == .none` and all become sound about mutation at once.
- **evidence:** `sh gate/speculation.sh`; the two `idol graph | jq` commands above; `gate/effect.sh` census movement.
- **deletion witness:** the shadow module-binding entities minted per assignment, and any consumer reading `effect == .none` as a mutation proof.
