# GAP-048 — `duo fmt` deletes every comment in the file, in place

**Status:** open · **Filed:** 2026-08-08 · **Frequency:** 1 (found the hard way)
**Cited at:** `scripts/capability_table.duo` (`_measure`), `src/pretty.zig`.

(Took 048 after checking `gaps/` here and in every sibling under
`.claude/worktrees/`; 039–047 were already filed.)

## What happens

`duo fmt <file>` rewrites `<file>` in place and the rewrite does not carry
comments. Reproduced by value:

```
cp examples/native_differential/native_only/arm64_encoder.duo /tmp/ae.duo
duo fmt /tmp/ae.duo
diff examples/native_differential/native_only/arm64_encoder.duo /tmp/ae.duo
  1,20c1,2
  < -- expect: 5
  < -- SH-11 step: ARM64 instruction encoding written in Duo, compiled to native
  ...
```

A 20-line header — including the `-- expect: 5` line the `native_only/`
differential contract is built on — became two lines. The formatter is a
comment shredder with a side effect on disk.

## How it was found, which is the part worth keeping

`scripts/capability_table.duo` measures a `parsed` rung by asking whether the
front end accepts a source, and the cheapest way to ask that is to run the
formatter. The first version ran it on the fixture itself.

One run reformatted all 68 files in `examples/native_differential/`. That:

- stripped the `-- expect: N` header from all 13 `native_only/` fixtures, so
  `scripts/native_differential.duo` then reported *"native_only file has no
  '-- expect: N' header"* for every one of them;
- broke 13 fixtures outright, dropping agreement from 59 to 46;
- emptied the `described` rung, 16 → 0.

The table then reported those numbers **confidently**, and they were nearly
written into `docs/spec/pass100.md` §22 as the repository's status — a
measurement publishing the damage it had just done as a finding about the thing
it damaged. It was caught only because `git status` showed 68 modified files
in a commit that should have touched three.

The rule this earns, and it generalises past this bug:

> **A measurement must not be able to write to what it measures.**

`capability_table.duo` now copies each fixture into `/tmp` and formats the copy.

## Two claims this retires

Both were briefly believed on the strength of the corrupted run, and neither is
true:

- *"0 of 68 differential fixtures carry any comment."* The real number is
  **16 of 68**. The zero was measured after `fmt` had removed them.
- *"All 13 `native_only/` fixtures are missing their `-- expect:` header, which
  is why native-differential is red."* They all have one. `native-differential`
  is red for an unrelated and much smaller reason: four fixtures
  (`canon3_descriptor_enum`, `canon4_descriptor_in_record`, `tokenizer`,
  `tokenizer_selfscan`) that the **C** backend cannot compile.

## Fix

Two separable pieces:

1. The formatter must round-trip comments. Until it does, `duo fmt` is unsafe
   on any file whose comments carry contract (`-- expect:`, `-- gap[nn]`, every
   header in `lib/std`).
2. `duo fmt` should refuse to overwrite, or offer a check mode (`--check` /
   stdout), so that asking "does this parse?" is not a destructive act.

Interim: never run `duo fmt` on a tracked file without reading `git diff`
afterwards.
