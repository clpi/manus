| 1 | `scripts/capability_table.id` measures a `parsed` rung by asking whether the front end accepts a source, and the cheapest way to ask that is to run the formatter. |

| 1 | One run reformatted all 68 files in `examples/native_differential/`. |

| # | directive |

| section |
|---|---|
| Two claims this retires |

| # | directive |
|---|---|
| 1 | Both were briefly believed on the strength of the corrupted run, and neither is true: |

| # | directive |
|---|---|
| 1 | *"0 of 68 differential fixtures carry any comment."* The real number is **16 of 68**. The zero was measured after `fmt` had removed them. |
| 2 | *"All 13 `native_only/` fixtures are missing their `-- expect:` header, which is why native-differential is red."* They all have one. `native-differential` is red for an unrelated and much smaller reason: four fixtures (`canon3_descriptor_enum`, `canon4_descriptor_in_record`, `tokenizer`, `tokenizer_selfscan`) that the **C** backend cannot compile. |

| section |
|---|---|
| Fix |

| # | directive |
|---|---|
| 1 | Two separable pieces: |

| # | directive |
|---|---|
| 1 | The formatter must round-trip comments. Until it does, `duo fmt` is unsafe on any file whose comments carry contract (`-- expect:`, `-- gap[nn]`, every header in `lib/std`). |
| 2 | `duo fmt` should refuse to overwrite, or offer a check mode (`--check` / stdout), so that asking "does this parse?" is not a destructive act. |

| # | directive |
|---|---|
| 1 | Interim: never run `duo fmt` on a tracked file without reading `git diff` afterwards. |
