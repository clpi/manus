## The `text` shape, and why its pins are shaped the way they are

Its reached partition converts text (`"21":to(i64)` → `duo_str_to_i64` in
`idol_str_runtime.o`); its entry only does arithmetic and needs no runtime. Its
call boundary is deliberately `duo`'s — one i64 in, one i64 out — so the only
variable between the two shapes is the reached need, and a failure cannot be
argument lowering wearing a link-line costume.

The roster's third column became a comma-separated pin list, and `!name` inverts
a pin to require ABSENCE. `duo`, `trio` and `fan` each carry
`!duo_str_to_i64`, because a compiler that materialized all three bootstrap units
on every link line would satisfy `text` without ever having read a `need`.
Control N3 proves both pin directions actually refuse, against the positive
control's image, so the pins are not decoration. And the ratchet proves the
COLUMN is not decoration either: which direction each row must take, and which
relation its reach pin may name, are both derived from the sources its own
`materialize` arm wrote, so the roster cannot quietly stop requiring what makes
the presence pin mean anything, nor aim the reach pin at a symbol the entry
already defines.

## Superseded observations

The sections below are the filing rationale and the acceptance it set. They

## The hole

`land/homeclosure-20260823` closed the case where a direct-native build reached
a partition and emitted no object for it. Each reached partition is now parsed,
lowered and emitted, content-addressed, and put on the link line.

What is NOT carried across is each reached artifact's `need` list.
`emitObjectWithGraphLineageObserved` returns an artifact whose `need` names the
bootstrap objects that artifact references; the recursive realization keeps the
BYTES and drops the needs, and `directLinkInputs` is then handed the ENTRY
artifact's needs alone. An entry that needs no bootstrap runtime, reaching a
partition that does, links without it.

Measured, an entry reaching `lib/token/grammarrole.id`:

    _idol_<…>_token_grammarrole__roleprecedence   DEFINED  (was the GAP-134
                                                           undefined symbol)
    _duo_str_sub                                  UNDEFINED, referenced from
                                                  the reached partition's own
                                                  object

## Why it is P1 and not P0

It fails LOUDLY, at the linker, by symbol name. It is not the class this
repository treats as worst — a wrong answer under exit 0 — and it is one layer
past the hole `land/homeclosure` actually closed.

## Why it was not already a gap

It was recorded, but only inside `gate/crosspartition.sh`, under a heading that
says so plainly: "WHAT THIS GATE DELIBERATELY DOES NOT COVER, and why saying so
here". That paragraph also explains why every subject in that gate is
arithmetic — so the gate measures the reach and not this second gap — and ends
"When the needs of reached partitions join the link line, the honest edit is a
fourth shape whose reached partition needs the string runtime."

That is an honest scope boundary and it did its job: review of #155 found this
from the code, and the gate comment is what confirmed it was known rather than
missed. But a limitation that lives only in the instrument is not on any
obligation list, and `gaps/` is where the obligation belongs. Filing it does not
change the code; it stops the boundary from being visible only to whoever opens
that gate.
