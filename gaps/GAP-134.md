## Review round, rebased onto `debad1df`

### The proof gate was proving the wrong pair agree — and the fix landed elsewhere

The first version of this gate joined the editor grammar to the compiler
through `src/lexer.zig`'s `spelling()` switch. That is the HOST DIFFERENTIAL
ORACLE, not the production authority: had `lib/compiler/lexer.id` changed an
operator spelling without the oracle following, the gate would have reported
AGREEMENT while the production compiler and the editor actually disagreed. A
gate that can be green while the thing it guards is broken is worse than no
gate. The finding was correct.

The repair landed on main from the `GAP-145` lane while this one was in review:
`lib/compiler/token.id` now publishes the source spelling per producer slot and
`TokenKind.spelling()` is one field read off the generated row. Two host tables
— a 60-arm switch and `token_semantic.keywords` — stopped being producers.

This gate therefore reads `src/grammar_role_table.zig`: one row per producer
slot carrying identity, spelling, infix face, precedence and associativity
TOGETHER, so no join can pair one identity's spelling with another's binding
power, and `src/lexer.zig` answers out of the same row. Reading a generated
`.zig` file is an act of reading the owner precisely because
`gate/grammar-projection.sh` regenerates privately and fails unless the tracked
bytes are identical.

the correction. But the door is not the one `GAP-224` describes.

**`name(...) = (...)` is not Idol.** All four spellings of it are refused by
the parser, not merely unseen by the classifier:

```text
pick(row, kind) = (row)        error: expected expression, got '='
pick(row, kind) = row          error: expected expression, got '='
add(a: i64, b: i64) = a + b    error: expected expression, got '='
add(a, b) = a + b              error: expected expression, got '='
```

`gate/vocab-extract.awk` misses that string because it is not a declaration
form, not because it is the canonical one. The four forms that DO compile and
run are all classified and therefore all refused:

| form | compiles | classifier |
|---|---|---|
| `brk(text: str, from: i64)` | runs | `relation` — refused |
| `brk(text: str, from: i64): i64` | runs | `relation` — refused |
| `brk = (text: str, from: i64)` | runs | `relation` — refused |
| `brk: i64 = (text: str, from: i64)` | runs | `relation` — refused |
| `brk(text, from)` | check fails | free |
| `brk(text, from): i64` | `DNB001 param-type:inferred` | free |

**The real door is the ZERO-PARAMETER relation.** `check(): i64` compiles,
runs, composes with other zero-parameter relations, carries no underscore, and
is not classified — the classifier's two parenthesised patterns both require a
`:` INSIDE the parens, which a zero-parameter list cannot have. It is a real
canonical form on its own merits, not a spelling chosen to slip past a regex.

So `gate/treesitter/agreement.id` is now six zero-parameter relations —
`editor`, `joined`, `keys`, `loose`, `stale`, `held`, `rows`, `check` — and the
parameterised primitives (substring search, line walk, field split, numeric
scan) are written out where they are used. `lib/compiler/token.id` `zigrow`
carries the same duplication for the same reason. The two owner facts this lane
added, `roledemand` and `roleopensline`, took the same shape: `demand(): str`
and `lead(): str` return one character per producer slot, and the generated
Idol projection carries them as the same two zero-parameter relations rather
than as a column-1 table plus an accessor.

## Production parser boundary observed 2026-08-10

The production lexer now supplies token content, token identity, and exact
source spans from Idol. The next host decision for canonical callable bindings
is still `src/parser.zig:scan_func_header_signal`: it walks the token stream and
locally reconstructs parameter, operator, body-start, and compatibility roles.

Moving that recognizer verbatim into `lib/compiler/parser.id` would not
close this gap. It would create a fourth grammar authority. A rejected scratch
candidate demonstrated the failure shape directly: mutable save/scan/restore,
punctuation and keyword comparisons through token text, and a handwritten
expression-start list. None of that candidate entered the working tree.

The authoritative inputs currently stop one level too early:

- historical `lib/compiler/token.id` carries numeric token identities but
  no canonical grammar-role projection;
- `lib/token/classify.id` is a generated lexical classifier only;
- `src/token_semantic.zig` is host-owned keyword metadata and does not expose
  parameter, expression-start, prefix, postfix, precedence, associativity, or
  canonical/compatibility grammar facts; and
- `docs/spec/grammar.md` is normative prose and explicitly says the parser is
  not generated from it.

The minimum interface required by the next SHC parser slice is therefore:

1. a machine-readable canonical Idol token/case identity projection;
2. grammar-derived roles for parameter slots, callable body starts, prefix and
   postfix positions, precedence, associativity, and compatibility status;
3. an immutable token view over the production Idol token pack so lookahead is
   observation rather than save/mutate/restore; and
4. a compact generated lookup representation suitable for the parser hot path.

Only after those facts exist can the production parser replace one host
recognition decision without reconstructing grammar from token text or
introducing a bootstrap parser taxonomy.

## Fail-closed lexer prerequisite

The direct production lexer route no longer treats allocation or record-buffer
failure as permission to resume the host scanner. Every route failure now
propagates, and partially allocated route storage is released. A focused
control exercises the production routing function with a failing allocator,
and the common test aggregator imports that control. This closes the hidden
fallback at the routing seam; it does not close this gap. Code-generation
callers still convert route errors into declined embed or optimization paths,
so production-wide failure propagation remains an adjacent realization-owned
deletion gate.

The next parser slice remains `IMPLEMENTATION-BLOCKED` on the same two upstream
facts: the generated grammar-role projection and an immutable view over the
production token pack. `GAP-145` must first or jointly distinguish current text,
bytes, compatibility literal/comment, shebang, and reserved-token identities.
Hand-authoring those roles in the parser would recreate the authority this gap
exists to remove.

New production parser fixtures use canonical `.id`. Historical `.id` remains
source-family provenance only and cannot select a grammar or semantic result.
The generated role projection must also preserve current delimiter authority:
parentheses identify ordinary application/grouping, braces structured packs
and descriptor application/homes, brackets computed projection, dot static
projection, and colon only its admitted descriptor/subject/home roles. These

identity bits.
