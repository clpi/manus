# GAP-134 - SHC grammar authority is not a generatable canonical artifact

**Status:** OPEN - **Filed:** !2026-08-09T23:08:57Z
**Priority:** P0 - **Kind:** expressiveness_gap
**Filed by:** codex-root-shc-audit
**Files:** docs/spec/grammar.md,docs/spec/constitution.md,lib/compiler/parser.id,scripts/treesitter_emit.id

C0 section 33 requires SHC slice 2 to consume the GENERATED constitutional
grammar. The current normative grammar cannot generate a parser:

- its opening says the parser is generated while section 6 says it is not;
- productions contain literal ellipses (`... per precedence`, `fn-slot...`);
- C0 records an unresolved contradiction (`primary drops .name;
  docs/spec/grammar.md and c0 must agree`); and
- the existing historical compiler parser/proof implements the migration
  `end`/`do`/`fun`/`local`/`type`/directive/semicolon s-expression grammar.

`scripts/treesitter_emit.id` explicitly says its structural productions are
not generated from the normative EBNF. It emits hand-authored registries,
retains an authored legacy residue, uses direct `io.open` plus `std.os`
environment/exit capability APIs, and cannot emit the offside scanner. It is a
useful partial editor projection, not the constitutional grammar authority or
an SHC parser generator.

Closure requires one complete machine-readable canonical Idol grammar
authority, generated human grammar and parser projections, a
positive/negative/fuzz differential, and zero handwritten semantic parsing
authority. Do not add Zig, another Markdown parser, or another generated-C
stage around the historical parser.

## Production parser boundary observed 2026-08-10

The production lexer now supplies token content, token identity, and exact
source spans from Idol. The next host decision for canonical callable bindings
is still `src/parser.zig:scan_func_header_signal`: it walks the token stream and
locally reconstructs parameter, operator, body-start, and compatibility roles.

Moving that recognizer verbatim into `lib/compiler/parser.id` would not
close this gap. It would create a fourth grammar authority. A rejected scratch
candidate demonstrated the failure shape directly: mutable save/scan/restore,
punctuation and keyword comparisons through token text, and a handwritten
expression-start list. None of that candidate entered the working tree.

The authoritative inputs currently stop one level too early:

- historical `lib/compiler/token.id` carries numeric token identities but
  no canonical grammar-role projection;
- `lib/token/classify.id` is a generated lexical classifier only;
- `src/token_semantic.zig` is host-owned keyword metadata and does not expose
  parameter, expression-start, prefix, postfix, precedence, associativity, or
  canonical/compatibility grammar facts; and
- `docs/spec/grammar.md` is normative prose and explicitly says the parser is
  not generated from it.

The minimum interface required by the next SHC parser slice is therefore:

1. a machine-readable canonical Idol token/case identity projection;
2. grammar-derived roles for parameter slots, callable body starts, prefix and
   postfix positions, precedence, associativity, and compatibility status;
3. an immutable token view over the production Idol token pack so lookahead is
   observation rather than save/mutate/restore; and
4. a compact generated lookup representation suitable for the parser hot path.

Only after those facts exist can the production parser replace one host
recognition decision without reconstructing grammar from token text or
introducing a bootstrap parser taxonomy.

## Fail-closed lexer prerequisite

The direct production lexer route no longer treats allocation or record-buffer
failure as permission to resume the host scanner. Every route failure now
propagates, and partially allocated route storage is released. A focused
control exercises the production routing function with a failing allocator,
and the common test aggregator imports that control. This closes the hidden
fallback at the routing seam; it does not close this gap. Code-generation
callers still convert route errors into declined embed or optimization paths,
so production-wide failure propagation remains an adjacent realization-owned
deletion gate.

The next parser slice remains `IMPLEMENTATION-BLOCKED` on the same two upstream
facts: the generated grammar-role projection and an immutable view over the
production token pack. `GAP-145` must first or jointly distinguish current text,
bytes, compatibility literal/comment, shebang, and reserved-token identities.
Hand-authoring those roles in the parser would recreate the authority this gap
exists to remove.

New production parser fixtures use canonical `.id`. Historical `.id` remains
source-family provenance only and cannot select a grammar or semantic result.
The generated role projection must also preserve current delimiter authority:
parentheses identify ordinary application/grouping, braces structured packs
and descriptor application/homes, brackets computed projection, dot static
projection, and colon only its admitted descriptor/subject/home roles. These
faces remain syntax provenance after resolution and contribute zero semantic
identity bits.

## Current evidence (2026-08-13)

`src/grammar_roles.zig` has one row per `TokenKind` (ROLECOUNT 114, KINDEOF
109), including shebang/comment trivia, quoted identities, `body_start`, and
infix associativity. `lib/token/grammarrole.id` is regenerated from that
table. Parser consumers now observe roles rather than handwritten token
lists for expression-start, callable-body start, infix-in-header,
literal/quoted kinds, prefix unary, match-pattern start (`pattern` /
`canStartPattern` / generated `rolepattern`), parenless call args,
table field continuation, and primitive descriptor identities
(`isDescriptor` — host `isTypeKeyword` and `typeKeywordName` deleted;
type-primary and type-name expression arms observe the role). Adding a
quoted, descriptor, or pattern identity updates the role table, not those
parser switches. Host `is_keyword_token(text)` is deleted — keywords are
token identities; a `.name` is never a keyword.
The immutable token view remains observation over the production pack.
This is **not** parser SHC and **not** closure:
`docs/spec/grammar.md` still does not generate the parser.
Header recognition is one `headerSignal` over the producer token pack
(`parse_module` / `scan_func_header_signal` call `route()` when the pack
is missing). The host save/scan/restore snapshot walk is deleted. That is
not parser SHC and not a port of the host recognizer into `parser.id`. Pratt `infix_prec` now takes left/right from generated
`precedence`/`assoc`
(comparisons are `nonassoc`, so `a < b < c` stays non-associative). The
parser still maps kinds to `BinOp` — that is AST realization, not a
second precedence table.

`zig test src/grammar_roles.zig -fno-emit-bin` covers identity-not-spelling
and trivia-not-expression-start. Generated `rolebodystart` exists. The
production parser still owns remaining recognition.

**GRAMMAR-ONE (`law.grammar.one`):** exactly one executable grammar-fact
owner. Canonical Idol grammar facts are the authority. Generated Zig/C
tables are a bridge. `grammar.md` and Tree-sitter are human/editor
projections from that owner. `src/grammar_roles.zig` is the **current
transitional** host table and has a deletion condition once Idol owns the
facts. Do not add `lib/compiler/grammar.id` until it *replaces* the Zig
table as the one executable owner. Parser-local `BinOp` maps remain
reconstruction debt. Tree-sitter, LSP, MCP, and formatter must consume the
same owner — never a parallel grammar.

Required adversarial controls for closure:

- token spelling changes do not affect role lookup when token identity is held;
- token identity changes do affect recognition when spelling is held;
- canonical and compatibility faces remain distinct facts;
- adding an admitted expression-start case changes the grammar owner and its
  generated projection, not parser consumers; and
- punctuation and hot-path category recognition perform no text search.

## ONE-PRODUCER ruling (`law.grammar.one`)

Exactly one executable grammar-fact owner must produce every grammar role,
precedence, and associativity fact. Current transitional owner:

```text
src/grammar_roles.zig  (host executable table — bridge, law.bridge.death)
    → lib/token/grammarrole.id (generated projection)
    → parser / Pratt observation
```

Forbidden parallel authorities:

- C0 prose alone (`docs/spec/grammar.md` without generation),
- a future `lib/compiler/grammar.id` that coexists with the Zig table,
- parser-local `BinOp` / token-text / spelling-category maps,
- Tree-sitter hand-authored grammar as a second normative source.

Destination (one producer):

```text
canonical Idol grammar facts (single owner)
    → generated Zig/C role tables
    → grammar.md (human projection)
    → Tree-sitter (editor projection, mechanically verified)
```

When an Idol grammar-fact owner lands, it **replaces** `grammar_roles.zig` as
the one executable owner; the Zig table becomes generated bridge only until
deleted. Do not add `grammar.id` beside the Zig table — migrate ownership.
