# GAP-134 - SHC grammar authority is not a generatable canonical artifact

**Status:** OPEN - **Filed:** !2026-08-09T23:08:57Z
**Priority:** P0 - **Kind:** expressiveness_gap
**Filed by:** codex-root-shc-audit
**Files:** docs/spec/grammar.md,docs/spec/constitution.md,lib/compiler/parser.id,scripts/treesitter_emit.id

C0 section 33 requires SHC slice 2 to consume the GENERATED constitutional
grammar. The current normative grammar cannot generate a parser:

- its opening says the parser is generated while section 6 says it is not;
- productions contain literal ellipses (`... per precedence`, `fn-slot...`);
- C0 records an unresolved contradiction (`primary drops .name;
  docs/spec/grammar.md and c0 must agree`); and
- the existing historical compiler parser/proof implements the migration
  `end`/`do`/`fun`/`local`/`type`/directive/semicolon s-expression grammar.

`scripts/treesitter_emit.id` explicitly says its structural productions are
not generated from the normative EBNF. It emits hand-authored registries,
retains an authored legacy residue, uses direct `io.open` plus `std.os`
environment/exit capability APIs, and cannot emit the offside scanner. It is a
useful partial editor projection, not the constitutional grammar authority or
an SHC parser generator.

Closure requires one complete machine-readable canonical Idol grammar
authority, generated human grammar and parser projections, a
positive/negative/fuzz differential, and zero handwritten semantic parsing
authority. Do not add Zig, another Markdown parser, or another generated-C
stage around the historical parser.

## Production parser boundary observed 2026-08-10

The production lexer now supplies token content, token identity, and exact
source spans from Idol. The next host decision for canonical callable bindings
is still `src/parser.zig:scan_func_header_signal`: it walks the token stream and
locally reconstructs parameter, operator, body-start, and compatibility roles.

Moving that recognizer verbatim into `lib/compiler/parser.id` would not
close this gap. It would create a fourth grammar authority. A rejected scratch
candidate demonstrated the failure shape directly: mutable save/scan/restore,
punctuation and keyword comparisons through token text, and a handwritten
expression-start list. None of that candidate entered the working tree.

The authoritative inputs currently stop one level too early:

- historical `lib/compiler/token.id` carries numeric token identities but
  no canonical grammar-role projection;
- `lib/token/classify.id` is a generated lexical classifier only;
- `src/token_semantic.zig` is host-owned keyword metadata and does not expose
  parameter, expression-start, prefix, postfix, precedence, associativity, or
  canonical/compatibility grammar facts; and
- `docs/spec/grammar.md` is normative prose and explicitly says the parser is
  not generated from it.

The minimum interface required by the next SHC parser slice is therefore:

1. a machine-readable canonical Idol token/case identity projection;
2. grammar-derived roles for parameter slots, callable body starts, prefix and
   postfix positions, precedence, associativity, and compatibility status;
3. an immutable token view over the production Idol token pack so lookahead is
   observation rather than save/mutate/restore; and
4. a compact generated lookup representation suitable for the parser hot path.

Only after those facts exist can the production parser replace one host
recognition decision without reconstructing grammar from token text or
introducing a bootstrap parser taxonomy.

## Fail-closed lexer prerequisite

The direct production lexer route no longer treats allocation or record-buffer
failure as permission to resume the host scanner. Every route failure now
propagates, and partially allocated route storage is released. A focused
control exercises the production routing function with a failing allocator,
and the common test aggregator imports that control. This closes the hidden
fallback at the routing seam; it does not close this gap. Code-generation
callers still convert route errors into declined embed or optimization paths,
so production-wide failure propagation remains an adjacent realization-owned
deletion gate.

The next parser slice remains `IMPLEMENTATION-BLOCKED` on the same two upstream
facts: the generated grammar-role projection and an immutable view over the
production token pack. `GAP-145` must first or jointly distinguish current text,
bytes, compatibility literal/comment, shebang, and reserved-token identities.
Hand-authoring those roles in the parser would recreate the authority this gap
exists to remove.

New production parser fixtures use canonical `.id`. Historical `.id` remains
source-family provenance only and cannot select a grammar or semantic result.
The generated role projection must also preserve current delimiter authority:
parentheses identify ordinary application/grouping, braces structured packs
and descriptor application/homes, brackets computed projection, dot static
projection, and colon only its admitted descriptor/subject/home roles. These
faces remain syntax provenance after resolution and contribute zero semantic
identity bits.

The immutable token view remains observation over the production pack.
This is **not** parser SHC and **not** closure:

(`parse_module` / `scan_func_header_signal` call `route()` when the pack

`precedence`/`assoc`

`zig test src/grammar_roles.zig -fno-emit-bin` covers identity-not-spelling

**GRAMMAR-ONE (`law.grammar.one`):** exactly one executable grammar-fact
owner. Canonical Idol grammar facts are the authority. Generated Zig/C
tables are a bridge. `grammar.md` and Tree-sitter are human/editor
projections from that owner. `src/grammar_roles.zig` is the **current
transitional** host table and has a deletion condition once Idol owns the
facts. Do not add `lib/compiler/grammar.id` until it *replaces* the Zig
table as the one executable owner. Parser-local `BinOp` maps remain
reconstruction debt. Tree-sitter, LSP, MCP, and formatter must consume the
same owner — never a parallel grammar.

Required adversarial controls for closure:

- token spelling changes do not affect role lookup when token identity is held;
- token identity changes do affect recognition when spelling is held;
- canonical and compatibility faces remain distinct facts;
- adding an admitted expression-start case changes the grammar owner and its
  generated projection, not parser consumers; and
- punctuation and hot-path category recognition perform no text search.

## ONE-PRODUCER ruling (`law.grammar.one`)

Exactly one executable grammar-fact owner must produce every grammar role,
precedence, and associativity fact. Current transitional owner:

```text
src/grammar_roles.zig  (host executable table — bridge, law.bridge.death)
    → lib/token/grammarrole.id (generated projection)
    → parser / Pratt observation
```

Forbidden parallel authorities:

- C0 prose alone (`docs/spec/grammar.md` without generation),
- a future `lib/compiler/grammar.id` that coexists with the Zig table,
- parser-local `BinOp` / token-text / spelling-category maps,
- Tree-sitter hand-authored grammar as a second normative source.

Destination (one producer):

```text
canonical Idol grammar facts (single owner)
    → generated Zig/C role tables
    → grammar.md (human projection)
    → Tree-sitter (editor projection, mechanically verified)
```

When an Idol grammar-fact owner lands, it **replaces** `grammar_roles.zig` as
the one executable owner; the Zig table becomes generated bridge only until
deleted. Do not add `grammar.id` beside the Zig table — migrate ownership.

## Supreme-law surface obligations observed 2026-08-13 (docs/spec/law.md)

`docs/spec/law.md` is now the SUPREME one-page law and C0 (`syntax.anchor`,
`access`, `able` in §5–§6) has been reconciled to it. The **law is closed**; the
**compiler frontend implementation is IMPLEMENTATION-BLOCKED** behind this gap
(grammar roles) and GAP-145 (lexical identity). Do not canonize a workaround —
mark blocked and implement the recognizer/resolver behind the one grammar-fact
owner:

- **`@` = the current world + projection/injection/interjection algebra
  (`law.md` §4 and the World+projection add-on; C0 `law.projection.algebra`,
  `law.injection.authority`).** Grammar/resolver must recognize the world faces:
  bare `@` (current-world value), `@member` world access (`@target`, `@env`) —
  `@` is itself the accessor, so `@.member` and `@:member` are INVALID — postfix
  `thing@world` / `thing@` qualification, `@{ k = v }`
  **injection** (derive a NEW closed world with exact fact deltas), `thing@{ k = v }`
  **interjection** (`thing@(@{ k = v })` — evaluate a subtree under an injected
  world), `@member = v` ambient **mutation** (place), `@(` eval. A prefix `@`
  directive namespace (`@comp`/`@host`/`@runtime`/`@c`/`@emit`/`@asm`) is not a
  world and is refused. `gate/idiom.id` `sigil` (`law.anchor.one`) already admits
  every world face lexically; the resolver must: (a) resolve `@` against the
  enclosing world table without minting a new identity merely because a world was
  qualified; (b) form injection as a closed world (`project(inject(w,k=v),k)=v`;
  untouched facts equal `project(w,q)`) with NO runtime parent-world fallback,
  duplicate-member-in-literal an error, empty injection = identity; (c) thread the
  qualified world through the evaluated subtree's unresolved ambient dependencies
  with **no runtime world object** (world object 0 / lookup 0 / dispatch 0 when
  statically known); (d) keep injected authority a real witness — never
  authorization magic (`@{ authority = true }` grants nothing); (e) capture the
  smallest exact world fact in closures, not the whole world. `.` must resolve to
  exactly one static structural step — never dispatch/search/fallback; computed
  keys use application `table(key)`.
- **`table(key)` is the one access algebra (`law.md` §6–§7).** Ordinary access is
  application; `table[key]` is legacy/foreign-compat computed-key debt migratable
  to `table(key)`, and `:get`/`get(t,k)` are noncanonical. Resolver decides
  value / place / applicable-value with no get-first/call-first/table-first
  precedence; incomparable applications are an ambiguity error. Place face is
  `table(key) = value` with no setter ontology.
- **`able(...)` inference (`law.md` §9).** `able(eq)` / `able(read)` /
  `able(to(str))` is the one explicit protocol/requirement boundary; it is
  normally INFERRED from use/demand and spelled only at a real boundary. Static
  satisfaction keeps runtime protocol object / dictionary / vtable = 0 and grants
  no authority. This is resolver + demand work, not a trait subsystem.
- **Descriptor sigil retired — `@{}` is injection only (`law.injection.only`;
  GAP-110 AT-APPLY reconciled).** A descriptor is an ordinary table `{ … }` whose
  values are descriptor constraints; `point = { x: f64, y: f64 }` is canonical and
  `point = @{ x: f64, y: f64 }` is retired. **IMPLEMENTATION-BLOCKED:** the host
  frontend still parses descriptor literals only as `@{ … }` and REJECTS the plain
  form (measured 2026-08-13 on `zig-out/bin/idol check`: `point = { x: f64, y: f64 }`
  → `write \`}\` at this token edge … got \`:\` here`). The grammar/resolver must
  admit a colon-typed field pack under braces as a descriptor and reserve `@{ … }`
  exclusively for world injection. Until then the following canonical/negative
  corpus specimens keep the retired `@{}`-descriptor form (do not rewrite — they
  would fail `idol check`): `examples/projection/descriptor.id`,
  `examples/pack/apply.id`, `examples/compile_fail/apply_one_label.id`. The
  `examples/native_differential/*` `@{}`-descriptor occurrences are the FOREIGN
  differential-oracle corpus (frozen legacy-equivalent inputs) and are out of
  scope for canonical migration.
- **AT-ONE accessor gate — `@` is the accessor, `@.member`/`@:member` retired
  (`law.at.one`; `law.md` §4).** `@` alone is the current world, `@member`
  accesses a static world member, `@member.child` is one world access then one
  ordinary static projection, `@member = v` mutates a member place. `@.member`
  and `@:member` are INVALID (`@` already accesses; `@.`/`@:` steal `.`/`:`), and
  `value@relation` anchoring is permanently retired — relation orientation is the
  colon face `value:relation` only. `gate/idiom.id` `sigil` now rejects `@.`/`@:`
  and admits `@member` world access on added lines; the grammar/resolver must
  make `@member` a world-access application fact, never a `@.` projection step.
- **Retired-anchor corpus — `examples/anchor/*` (`value@relation` / `@`-receiver
  / `@:`). IMPLEMENTATION-BLOCKED.** `examples/anchor/bare.id` (`()@:len()`,
  `self`) and `examples/anchor/move.id` (`p@x`, `b@inner@x`, `X@rel` "move the
  anchor") embody the fully-superseded anchor model where `@` was the call
  receiver and postfix `@` carried a *relation*. Under `law.at.one` `@` is the
  current world and postfix `@` carries a *world*, so these fixtures are
  semantically dead, but the host frontend still parses the old anchor and the
  highlight/role corpus (`scripts/highlight.id`, `fixtures/highlight/anchor.roles.id`)
  consumes them. Do not rewrite line-by-line — the fixtures' entire premise
  (anchor = receiver) is retired, not merely misspelled. They must be retired as
  a corpus together with the grammar-role migration, then their `expect:` values
  and highlight fixtures rebuilt against the world-accessor grammar. Same corpus:
  `examples/compile_fail/anchor_infix_at.id` and the diagnostic prose quoting it
  in `docs/spec/diagnostics.md` (§ "the good ones") still teach `X@rel` "moves
  the anchor and retrieves" — a retired `value@relation` form. The prose
  accurately documents the fixture's current output, so it is corrected only when
  the fixture is retired, not before.
- **APPLICATION-ONE + WORLD-CLOSED (`law.application.one`, `law.world.closed`;
  `law.md` §6–§7).** Every `value(args)` is ONE application algebra — `f(x)`,
  `table(key)`, `descriptor(value)`, `world(key)`, `closure(x)`, `foreign(x)` are
  the same semantic question, with no function-call / table-lookup / accessor /
  indexing / method-call / operator / conversion / protocol-invocation kingdom.
  The resolver may use only applied-value identity, operand identities/facts,
  operand-pack shape, result demand, descriptor/table/relation facts, current
  world, authority/witness facts, stage, control-flow refinements, and known
  metatable facts; it MUST NOT use callee spelling, file path, source category,
  AST node kind, "looks-like-a-function/table", declaration/registry order, or
  nearest-namespace fallback. It emits exactly one application fact (applied id;
  relation id only when semantically meaningful; subject id only when oriented;
  operand/result packs; descriptor/effect/authority/witness/stage/demand/
  provenance); the ladder collects facts → enumerates lawful applications →
  eliminates impossible candidates → projects implied relation/descriptor/
  conversion/`able`/witness/world-fact/result-pack/stage → publishes exactly one,
  rejects zero, and **fails AMBIGUITY (fail-closed)** on >1 incomparable candidate
  BEFORE any realization. Non-negotiables the recognizer/resolver/lowering owe:
  (a) `table(key)` value-vs-place is chosen by **demand**, not a distinct
  operation — `table(key) = value` is the place face with no setter ontology and
  no `get`/`set`/`call` relation minted for uniformity; (b) `.` is one static
  structural projection (recognition provenance) and `:` is source subject
  orientation only — after resolution there is **no `method_call`/`member_call`
  graph or DNIR kind**; (c) currying is not automatic — `add(1)(2)` is ordinary
  chained application, and partial application specializes only where the
  relation/application descriptor admits it or a callable returns a callable; (d)
  metatable / `__call` resolve **once** into an exact application fact — the
  backend never runs try-function-else-table-else-`__call` priority code (sealed
  metatable → dispatch 0; still-dynamic metatable → runtime dispatch only because
  semantic alternatives remain); (e) operators and conversion are application
  sugar — `a + b` resolves to the arithmetic relation application, `value:to(str)`
  is explicit only when the target is not inferable, and **lowering consumes the
  complete resolved application and never reconstructs a fact from spelling, AST,
  host types, or table/function category**; (f) WORLD-CLOSED — a derived `@{ k =
  v }` world holds its inherited facts at formation, and resolution under it uses
  its closed fact set with **no runtime parent-/nearest-/reachable-world
  fallback** even when the physical form structurally shares. **IMPLEMENTATION-
  BLOCKED (realization/graph lanes):** the host frontend still carries distinct
  `.call` and `.method_call` AST node kinds with separate lowering paths (measured
  2026-08-13: `src/dnir_lower.zig` routes `.method_call` through `lowerSubjectCall`
  and matches `.call, .method_call` as separate arms; `src/parser.zig` produces the
  `method_call` node). These are recognition-stage provenance and must converge to
  one resolved-application lowering with cost falling monotonically with knowledge
  (dynamic table+key → generic lookup; known shape+exact key → direct offset;
  sealed → scalar replacement; constant → no table at runtime); the graph/DNIR
  must not retain a `method_call` identity.

Each of these must land as exact graph facts (world membership, application
relation/subject/place, protocol-requirement witness) — never as source-text
reconstruction, a directive zoo, or a runtime protocol object.
