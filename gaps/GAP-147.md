# GAP-147 — test gate deadlocks when child output fills an undrained pipe

**Status:** OPEN · **Filed:** !2026-08-10T12:08:39Z
**Priority:** P0 · **Kind:** regression
**Filed by:** codex-root-audit-20260810
**Files:** src/main.zig,lib/proc.id,scripts/run_compile_fail_tests.id

A serialized `zig build test` was stuck for more than nine minutes in the
compile-fail step. Process evidence was exact:

- `run_compile_fail_tests.out` had finished its work and was blocked at process
  exit inside `__write_nocancel`, flushing stdout into a full 16 KiB pipe;
- its parent `duo` was blocked in `process.Child.wait`;
- the build maker was waiting for that parent; and
- every serialized build and benchmark queued behind the occupied lock.

The process chain completed as soon as the outer agent session resumed draining
its command output. That makes the demonstrated defect an evidence-transport
deadlock across the gate, lock runner, and agent transport; it does not yet
prove which one layer must own the repair.

Closure requires a control whose child writes more than the transport capacity
before exiting, while the caller deliberately delays observation. The gate must
finish, retain bounded diagnostic output, and preserve the actual child status.
Stdout and stderr must be drained concurrently wherever a layer owns pipes;
inherited output must have an actively drained outer sink. Do not repair this by
discarding evidence, increasing pipe size, weakening serialization, or relying
on frequent polling by an agent.

**Current classification:** OWNER-BLOCKED on the same execution-world outcome
as GAP-146 and GAP-119. A passing unmerged flood control established that active
drainage plus bounded retained output removes the transport deadlock, but its
implementation depended on new project-owned `.id` matcher loops, bookkeeping
completion state, and process-root glue. Source-purity admission rejected that
carrier. The producer must expose a per-request diagnostic stream, truncation
fact, child outcome case, and cleanup obligation. Lock and MCP consumers may
project those facts but may not rediscover them from encoded output.
