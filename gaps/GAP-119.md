# GAP-119 — Process execution lacks subject and world semantic vocabulary

**Status:** OPEN · **Filed:** !2026-08-09T20:08:39Z
**Priority:** P0 · **Kind:** expressiveness_gap
**Filed by:** codex_semantic_normalization
**Files:** lib/std/proc.duo,lib/std/script.duo,scripts/semanticgate.duo

The semantic architecture gate must currently use `std.proc.capture(command)` repeatedly because the live standard vocabulary exposes process execution as a namespace call returning a string, not as a command subject relation under an explicit process world with structured stdout, status, stderr, provenance and failure. The gate classifies and ratchets this bootstrap debt; do not disguise it with a module alias. GAP-117 prevents factoring the repeated calls behind a canonically typed result-demand helper.

The live `lib/std/script.duo` graph exposed 53 public callables. They span at
least seven independent semantic authorities:

1. process execution and capture;
2. environment observation and update;
3. filesystem observation and mutation;
4. path projection;
5. build locking and run provenance;
6. argument observation and JSON loading;
7. string trimming and output.

`std.script` is therefore both a forbidden capability namespace and a miniature
junk drawer. Renaming it, importing it under a shorter binding, or dividing it
into `std.proc`, `std.fs`, and `std.env` preserves the architecture defect.

## Closure order

1. Admit process specifications, structured process results, process-world
   requirements, and shell interpretation as distinct facts. A command string
   is not automatically a process specification.
2. Admit environment presence semantics under the environment world through
   GAP-118. Preserve absent, present empty, and present nonempty.
3. Map filesystem and path operations to subject relations and filesystem
   worlds. Prefer atomic state relations over observe-then-mutate pairs.
4. Move build locking and provenance to their actual semantic owners; neither
   belongs to process vocabulary.
5. Keep pure trimming, path projection, JSON, and formatting as value relations
   with no world authority.
6. Migrate consumers by resolved relation identity, not text replacement. An
   alias or renamed home must carry the same debt until the forbidden definition
   is unreachable.
7. Delete `lib/std/script.duo` and its import projection. The target count is
   zero definitions, zero direct calls, and zero aliases.

Until the first five families have admitted relations and world/case facts,
their state is `SEMANTIC-VOCABULARY-BLOCKED`. Do not create `execute`, `command`,
`process.run`, or another plausible public spelling merely to make this gap's
counts move.
