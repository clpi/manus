# GAP-189 — automatic collection data-structure synthesis from algebraic facts

**Status:** OPEN · **Filed:** !2026-08-18T16:25:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/collection.id, src/table_facts.zig

Programmers should express high-level mathematical collection semantics (sets, maps,
multisets, relations) while the compiler automatically selects the physical data
structure from algebraic facts (domain bounds, membership queries, density, uniqueness,
mutation patterns, inclusion relations). This realizes the 1970s SETL optimization
thesis within Idol's HPLS representation candidate space.

## Current measured boundary

Tables are the sole collection abstraction, currently realizing as fixed struct,
`.rodata` data constant, or heap table based on local size and escape heuristics.

**Crossed:**

- Table shape facts and collapse to constant `.rodata` data active in `native.id`.
- Extent and immutability facts inferred in `table_facts.zig`.

**Still missing:**

- Algebraic collection fact family: `membership`, `uniqueness`, `order`,
  `multiplicity`, `inclusion` ($A \subseteq B$), `density`, `key_value_dependency`,
  `update_pattern`.
- Automatic synthesis and realization mapping:
  - Bounded small integer domain ($0..63$) -> `bitset` / register mask
  - Immutable key set known -> `perfect hash` / direct index
  - Append-only ordered scan -> `dense vector`
  - Sparse integer domain -> `sparse set` / `bitmap`
  - Repeated subset containment query -> `bitset hierarchy` / `index`
  - Key relation monotone -> `sorted vector` / `B-tree`
  - Membership existence query only -> `Bloom filter` + exact fallback
  - Single element demanded -> `0` collection materialization (erased)

## Required order

1. Define algebraic collection descriptors in C0.
2. Implement fact extractor for collection operations (inclusion, access pattern, density).
3. Wire candidate generator $\mathcal{E}(\text{collection})$ to algebraic fact domain.
4. Integrate microarchitectural cost model for collection representations.
5. Benchmark against manual C++ / Rust container selections.

## Closure acceptance

Close when a program declaring high-level mathematical set/map semantics automatically
materializes as a bitset, perfect hash, or sparse vector without manual data structure
annotations, beating hand-specialized implementations.
