# GAP-209 — a module binding written by anything but a top-level literal is read stale inside every relation

**Status:** OPEN · **Filed:** !2026-08-22T00:20:00Z
**Priority:** P0 · **Kind:** wrong_answer
**Filed by:** claude-gap145
**Files:** src/dnir_lower.zig

A module-scope binding whose value is established by **anything other than a
top-level integer-literal assignment** is folded to its *declared initializer*
inside every relation body. Compile 0, run 0, no diagnostic.

## Reproduction — verified on `fc93fba6`, Debug and ReleaseFast alike

```id
s: i64 = 0
k: i64 = 41
peek: i64 = ()
    s + 1
s = k + 1
print(s)        # 42
print(peek())   # 1   -- Lua oracle says 43
```

```lua
local s = 0
local k = 41
local function peek() return s + 1 end
s = k + 1
print(s)        -- 42
print(peek())   -- 43
```

Measured side by side, `.id` and `.lua` twins diffed line for line:

| | `print(s)` | `print(peek())` |
| --- | --- | --- |
| idol | 42 | **1** |
| lua (oracle) | 42 | **43** |

Second shape, a loop-established value:

```id
s: i64 = 0
i: i64 = 1
peek: i64 = ()
    s + 1
while i <= 4
    s = s + i
    i = i + 1
print(s)        # 10   correct
print(peek())   # 1    -- oracle says 11
```

## Mechanism

`dnir_lower.collectModuleConsts` (`src/dnir_lower.zig:563`) walks **top-level
module statements only** and records `name -> int` whenever `intLiteralStep`
succeeds. `s: i64 = 0` records 0.

- The later `s = k + 1` is **not an int literal**, so it never overwrites the
  recorded 0.
- The `while`-body write is **nested**, so the walk never sees it.

`collectModuleGlobals` (`:419`) would grant bss storage instead, but only when
`moduleFunctionsAssignName` — that is, when a **function** assigns the name.
Here the assignment is at module scope, so no storage is granted either.

`peek` therefore folds `s` to the stale `0` and answers `1`.

`s = 41` would work, but only by accident: it *is* an int literal, so the walk
overwrites the record.

## The class

Same shape as GAP-204, GAP-207 and GAP-208: a fact is reconstructed by an AST
walk that models a narrower program than the language admits, and the
reconstruction is consulted by a consumer that has no way to know the walk did
not cover its case. Here the walk covers exactly one statement form and the
language admits four.

`ModuleConsts` is the collapsed module-scope authority GAP-145 already names.
This is a second wrong answer from it, after the `global j = "abc"` reads
recorded during the same session (empty, `(null)Z`, and `0` for a value that is
plainly `"abc"`).

## Required control

The oracle differential is the control, and no cheaper one is sufficient:

- `zig build unit-test` is clean on both shapes.
- The 538-file `examples/**/*.id` compile-status sweep is clean.
- The output differential over the examples that compile is clean.

The corpus contains no module binding established by a non-literal expression
and then read from a relation. As in GAP-207, only a hand-written program with
a language oracle finds this.

## Measured: invalidating the const map alone MOVES the wrong answer

An invalidation was built and measured, not merely proposed. `assignCountInStmts`
counts every assignment to a name across top-level statements, every nested
block and every relation body, honouring `stmtsAssignName`'s shadowing rule; a
recorded constant is dropped unless the module writes the name exactly as many
times as the recording statement itself accounts for.

It fires correctly and **the answer does not change**:

| | before | with invalidation | oracle |
| --- | --- | --- | --- |
| `s = k + 1` shape | `42 1` | `42 1` | `42 43` |
| `while` shape | `10 1` | `10 1` | `10 11` |

`peek` still emits `mov x9, #0x0`. With the constant dropped, the read resolves
through module **storage** instead — and `collectModuleGlobals` grants a bss
word only when `moduleFunctionsAssignName`, which is false for a module-scope
write, so the initializer is skipped and the read loads zero.

**There are two producers of "the value of a module binding", and they answer
the same stale value by different routes.** That is the same shape the gap
already records for `global j = "abc"`: `print(j)` empty, `print(j .. "Z")`
giving `(null)Z`, `print(j:len())` giving `0`.

So the const-map invalidation is **necessary and not sufficient**, and landing
it alone would exchange a stale constant for an uninitialized word — a
different wrong answer, not a fix. It is recorded here rather than shipped.

## Acceptance, revised

Both readers must move together:

1. `collectModuleConsts` refuses a name the module later writes — measured, the
   predicate above.
2. `collectModuleGlobals` grants storage for a module-scope write, not only a
   write from a relation body, **and** publishes the declared initializer
   instead of skipping it.

A prior attempt at (2) alone was measured elsewhere in this session to turn
seven corpus programs from running into named refusals, because it conflates
*foldable* with *resident*. The two facts are different: **written after
binding** kills folding; **observed across frames** forces storage. Landing
either half alone moves the defect.

## Related operational leak

Every `idol compile` on the direct-exe path writes
`/tmp/duo_<stem>_<hash>_<pid>_native.o` (`src/main.zig:5038`) and **never
deletes it**. Tens of thousands accumulated during this session and the boot
disk reached 100%, corrupting one differential run. A physical index with no
deletion condition.
