# GAP-024 — weak references have no family and cannot get one before E2

**Status:** open — **deliberately unruled** · **Filed:** 2026-08-07
**Blocks:** nothing today · **Gated on:** the memory decision (E2 bridge)
**Sites:** `docs/plans/pass81_family_registry.md` §4, last row of the Lua rosetta

## The hole

Pass 81 §1 states the completeness principle: every customization point is a
family row or a listed non-family, and **there is no third state**. The sweep
that produced the registry found exactly one point that is neither, and this file
is it.

Lua's `__mode` — weak keys, weak values, ephemerons — has no Duo ruling. The
shape of the eventual answer is visible: weakness is a **`ref`-strength fact on
places** (§2.2 `place` supplies the storage edge, §2.4 `ref`/`deref` supplies the
strength vocabulary), so it is very likely a fact rather than a family. But
"likely a fact" is not a ruling, and the reason it cannot be one yet is
substantive rather than procedural: weak-reference semantics are only meaningful
relative to a reclamation model, and Duo has not made the memory decision (E2).

Ruling it a family now would invent a protocol point that the memory model might
delete. Ruling it a non-family now would refuse hookability for a mechanism whose
mechanism does not exist. Both are the failure mode Pass 64 rule 2 names —
inventing rather than reporting.

## What is recorded, so the eventual ruling is cheap

- **Where it will live if it is a fact:** `ref`-strength on places, alongside the
  `at()`/`volatile` facts that already select MMIO place realizations (§2.2).
- **What it must cover:** weak keys, weak values, and ephemerons (weak key with a
  value that keeps the key alive) — the third is the one that most designs miss,
  and it constrains the answer more than the first two.
- **What it must not become:** a `__mode` field, or any string-valued mode
  selector. §1's "no `__` name ever" is not negotiable, and a mode string is a
  hookability point wearing a data field.
- **Who decides:** E2. This gap is a pointer at that bridge, not a proposal.

## Why it is filed rather than left implicit

An unruled point that nobody wrote down is indistinguishable from a point nobody
thought about. §1's own gate — "a new customization point must arrive as a family
row or a non-family row in this table, there is nowhere else for it to live" —
would otherwise be satisfied by silence. This file is the third state, made
explicit and dated so the completeness claim stays honest.
