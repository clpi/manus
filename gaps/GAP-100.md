# GAP-100 — `os` is a capability surface being used as an ordinary table, and the ratchet measures a quarter of it

**Status:** OPEN · **Filed:** 2026-08-09
**Law:** §0h STD IS THE PRELUDE GRAPH · §0e `std@{ ambient = false }` (RED IN CI)
· RECOGNITION (worlds are the only capability namespaces) · LAW-ONE
**Answers the owner question:** *"should `os` be used like any ordinary table?"*
— **No. It is the one thing that must not be.**

## The ruling first

An ordinary table is a **value**: inert, and holding it confers nothing. `os` is
not that. Every name on it is an **authority** — read the clock, read the
environment, spawn a process, delete a file, tear the process down. Spelling
authority as a table means any code anywhere takes it without anyone granting
it, which is exactly what `std@{ ambient = false }` forbids and what
RECOGNITION means by *worlds are the only capability namespaces*.

So the correct shape is not `os.remove(p)` reached ambiently, but a **world
receiver** the caller was handed and could have been refused. The op keeps its
name; what changes is that the authority arrives as an operand instead of being
in scope.

This also answers it structurally: `os` cannot be a table because a table is
**enumerable and inert**, and the CALLABLE unifies function and table on the
ENUMERABILITY axis. A capability is neither.

## The ratchet measures a quarter of the surface

`zig build capability-scan` reports **278 ambient sites across 53 of 260
modules** and PASSes at budget. That number is **lib/std only**. The 461 sites
in `tools/`, `scripts/`, `examples/` and `ext/` are not counted by anything.

So the scan is not wrong, it is **scoped**, and the scope is not stated where
the number is read. A budget that covers 25% of the reach it names will report
PASS while the ungated 75% grows without limit. **The denominator belongs in the
output**, next to the number.

The scan is honest about the deeper half, and this is worth quoting because it
is the actual blocker:

> `0 of 6 classes are enforced` — every row above is COUNTED, and the budget is
> the only pressure on it.

`std@{ ambient = false }` is an ANCHOR WITH NO ENFORCEMENT. Until `duo check`
refuses an ambient reach, every count is advisory.

## `std.os` is a module tree wrapping the ambient table

`lib/std/os.duo` does not mediate the authority — it **re-exports it**:

```duo
remove(path: str): bool
    os.remove(path)          -- the ambient table, one layer down
end
```

Which produces three violations stacked on one file:

1. **it is a module tree** — `std.os`, `std.os.linux`, `std.os.process`,
   `std.os.signal`, against §0h's *no module tree, no import*;
2. **it duplicates `std.fs`** — `remove`, `rename`, `mkdir` are defined in BOTH,
   so there are two answers to one question and they were not the same answer:
   gap[075] found `remove` reporting success for a path it had not removed, and
   the identical bug sat in both files;
3. **the vocabulary is wrong** — `read_file`, `write_file`, `mkdir_all` are
   LAW-ONE violations; the qualifier is a LEVEL or a HOME, never an underscore.

## Structure: 260 modules, 147 of them nested

```
depth 1   113 modules
depth 2   143 modules      <- a tree, which §0h says std does not have
depth 3     4 modules
underscore declarations in lib/std      2244
```

**Retirement is not about unused modules.** Measured: only 4 of 260 have zero
consumers outside `lib/std`, and one of those four is a FALSE POSITIVE —
`compiler.host` is invoked by `build.zig` as a compile target to generate
`src/duo_lexer_tokenize.c`, not referenced as `std.compiler.host`. Recorded as
method: **a reference-count retirement metric misses generators and entry
points, and will confidently propose deleting the thing that builds the lexer.**

The genuine candidates are small: `ffi_gen` (251 lines), `schema_gen` (204),
`meta.hierarchy` (57) — and two of the three names are themselves LAW-ONE
violations, which is the tell.

## The retirement plan, in dependency order

Each rung is separately shippable and each has a gate. Nothing here needs new
grammar.

1. **State the denominator.** `capability-scan` prints its scope beside its
   number, and grows a second row for the tree outside `lib/std`. One line of
   output; it converts a false PASS into a true one. **Do this first — every
   later rung is measured by it.**
2. **Collapse the duplicate surface.** `remove`/`rename`/`mkdir` live in ONE
   place. `std.fs` is the survivor (it has `exists` and `copy`; `std.os` has
   neither), `std.os`'s copies are deprecation-only. Gate: the fixture that
   already exists, `scripts/fs_remove_proof.duo`, which asserts both directions
   by value.
3. **Retire `req`.** 399 sites, and the 233 `req "std.x"` lines in `lib/std.duo`
   are the registry that makes the tree look like a tree. §0h: std is ambient by
   PINNED EPOCH, operand-reachable, no import. This is the rung that deletes the
   module tree rather than renaming it, so it is the one that matters.
4. **`os` becomes a world receiver.** The op names stay; the authority arrives
   as an operand. 620 sites is large but mechanical, and rung 1 makes the
   progress legible.
5. **Then enforcement**: `duo check` REFUSES an ambient reach. Until this, U1 is
   a count. After it, the remaining rows convert or diagnose.
6. **Vocabulary last, because it is the largest and the least load-bearing**:
   2244 underscore declarations. It cannot go first — renaming a surface that is
   about to be retired is wasted work, and rungs 2-4 delete a share of them.

## Do not

**Do not retire a module because its reference count is zero.** The count found
`compiler.host`, which builds the lexer the compiler links. Any retirement
proposal must show the module is unreachable from build steps and documented
commands, not merely unreferenced by `std.`.

**Do not close rung 4 by renaming `os` to a world and keeping ambient reach.**
That converts the spelling and not the property. The test is whether a caller
could have been REFUSED — if nothing can refuse it, it is still ambient.

## RUNG 2 ATTEMPTED 2026-08-09 — and it found a THIRD copy of the gap[075] bug

Collapsing the duplicate surface onto the better implementation was tried and
**reverted**. Recorded because the attempt produced a finding worth more than
the rung.

`std.fs.mkdir` forks a shell to make one directory:

```duo
os.execute("mkdir '" .. string.gsub(path, "'", "'\\''") .. "' 2>/dev/null")
```

Two costs, not one: fork+exec is ~1000x a syscall, and it takes **proc-class
authority to do an fs-class job** — so the capability scan counts it in the
wrong class, and the quoting exists to defend against an injection surface the
call never needed to be exposed to. `std.os.mkdir` has the syscall
(`@c.emit("mkdir(path, 0777) == 0")`), so the duplicate surface was simply
keeping the worse half reachable. That is a clean rung-2 story.

**It does not work.** Measured, contract held fixed across the swap:

```
shell version    made=true   exists=true   badparent=false
syscall version  made=false  exists=true   badparent=false
```

The directory IS created and the function answers **false**. `path` is a boxed
value and `mkdir(2)` wants `const char*`, so the `== 0` comparison is against a
return the caller never gets to trust. `@c.emit("mkdir(lua_to_str(path), …))`
fails to compile at all.

**So `std.os.mkdir` — the "better" implementation — carries the same
silent-wrong-answer class as gap[075], and has presumably carried it the whole
time.** Three sites now: `fs.remove`, `fs.rename` (fixed), `os.mkdir` (open).
The duplicate surface did not merely duplicate an op, it duplicated a *defect
pattern*: **a wrapper that reports success it did not verify.**

Reverted rather than shipped: the shell version is slow and over-privileged but
ANSWERS CORRECTLY, and trading a correct slow answer for a fast wrong one is the
§3 failure mode exactly.

**Rung 2 is therefore blocked on a rung 0 nobody had named:** every one of these
wrappers needs its return value verified by value before any of them can be
collapsed, because the collapse picks a survivor and picking the broken one
ships the bug to every caller of both. `scripts/fs_remove_proof.duo` is the
model — assert the filesystem state, never the wrapper's word for it. The same
fixture is owed for `mkdir`, `mkdir_all` and `copy`, none of which has one.

## RUNG 3 MEASURED 2026-08-09 — `req` cannot be deleted, because ambient std is a HAND-MAINTAINED registry that fails SILENTLY

`req` is 398 sites, **376 of them `req "std.*"`**, and 233 of those are the
registry inside `lib/std.duo` itself. So the module tree §0h denies is
constructed by one file, by hand.

The rewrite is mechanical and it does work — proven by value, not by compiling:

```
scripts/assert_no_ansi_reports.duo
  global s = req "std.script"   ->   s = std.script
  baseline  "ANSI escape sequence leaked in --no-color pretty"
  ambient   "ANSI escape sequence leaked in --no-color pretty"   IDENTICAL
```

**And then it does not.** `scripts/symbol_proof.duo`:

```
  sym = req "std.compiler.symbol"   ->   sym = std.compiler.symbol
  baseline  "symbol proof: PASS — 13 rows, every duon name owns its C symbol"
  ambient   (nothing — compiles clean, runs, prints NOTHING)
```

The cause is exact. `lib/std.duo` registers:

```duo
std.compiler = {
    source = req "std.compiler.source",
    token  = req "std.compiler.token",
    lexer  = req "std.compiler.lexer"
}
```

**`symbol` is not in it.** So `std.compiler.symbol` is a missing member, reads
`nil`, and every call through it silently does nothing. No diagnostic, exit 0.

This is the same shape as the `std.string.byte` finding — *a resolving ambient
path is not a working one* — and it is why rung 3 is not a `perl -pi` away:

- **`req` is currently the only RELIABLE path.** It loads the file. Ambient
  works only where a human remembered to add a line to `lib/std.duo`.
- **The registry is incomplete by construction** and nothing measures the gap.
  `symbol.duo` was added this session and never registered; no gate noticed.
- **The failure is SILENT**, which is the worst property a migration blocker can
  have: a mechanical sweep would convert 376 sites, the tree would compile, the
  gates would stay green, and an unknown share of programs would quietly stop
  doing their work.

## What rung 3 actually needs, in order

1. **A registry-completeness gate first.** Every `lib/std/**/*.duo` must be
   reachable by its ambient path, asserted BY VALUE (call something and check
   the answer, never check for non-nil). Until that is green, no sweep.
2. **Then make ambient reach DERIVED rather than hand-written** — the registry
   is a graph fact (`std` is the prelude graph, operand-reachable), so a file
   existing should be what makes it reachable. Hand-maintaining 233 lines is the
   defect that produced the hole.
3. **Only then rewrite the 376 sites**, in batches, each verified by value.
4. `std` in a nil-reaching position should DIAGNOSE, not read nil. That is B-12
   applied to the prelude: structural nil is unwritten.

**Do not sweep `req` before step 1.** The conversion is silent when it is wrong,
so the sweep would be indistinguishable from success.

## RUNG 3 BLOCKER ISOLATED 2026-08-09 — ambient resolves the TABLE and not its MEMBERS

Registering the module was necessary and not sufficient. With
`std.compiler.symbol` present in `lib/std.duo`, the two paths still disagree —
same module, same function, same argument:

```duo
sym = req "std.compiler.symbol"      print(sym.root("foo"))  -> duo_fn_foo
s   = std.compiler.symbol            print(s.root("foo"))    -> (nothing)
```

`s` is not nil — `print("a") · s = std.compiler.symbol · print("b")` prints both
`a` and `b`, so the path resolves and the table exists. **Its members read
nil.** Nothing diagnoses; the call returns nothing and execution continues.

This is the `std.string.byte` shape exactly — *a resolving ambient path is not a
working one* — and it matches the known "file-as-scope binding still open" half
of module embedding: a table-exporting module now `req`s correctly, and the
ambient projection of the same file does not bind its exports.

**So rung 3 has a precise, single blocker rather than a vague risk:**

> ambient member binding. Until `std.x.y.z()` calls the same function `req
> "std.x.y"` then `.z()` calls, `req` is the only path that works, and the 376
> sites cannot move.

The two-line repro above is the whole test. It needs no fixture harness and it
is the gate: when it prints `duo_fn_foo` from both spellings, the sweep is safe
and mechanical. Until then a sweep converts 376 sites into silent no-ops that
compile clean and exit 0.

**Cost note measured in passing:** registering 11 modules took a trivial
program's compile from 0.9s to 34s, because the registry is eagerly `req`'d as
one graph. That is an argument for rung 3's real repair — reachability derived
from the file existing, resolved on demand — and against growing the
hand-written registry any further. **Do not close the remaining 19 holes by
adding 19 more lines.**
