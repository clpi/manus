# GAP-160 — lib/std result/errors/check/property may be conventional subsystems

## State

Open.

## Problem

`lib/result.id` (276 lines), `lib/errors.id` (94 lines),
`lib/check.id` (335 lines), and `lib/property.id` (278 lines)
exist as standard library surfaces. They may create conventional
subsystems (Result wrapper, errors API, validation API, property API)
where ordinary result packs + union/failure obligations + descriptor
facts + shape/reflection suffice.

## Evidence

```
lib/result.id: 276 lines
lib/errors.id: 94 lines
lib/check.id: 335 lines
lib/property.id: 278 lines
```

## Required audit

For each file, determine whether it creates:

- Result wrapper / ok-error object / success flag / boxed failure
  where ordinary result packs + union/failure obligations suffice
- Errors API where failure is already a graph fact
- Validation API where descriptor facts and constraints suffice
- Property API where reflection/descriptor facts suffice

Do not automatically delete if foreign compatibility requires it.
Classify each as: canonical, migration, foreign, or invalid.
