# GAP-170 — Exact observation model (OBSERVATION-MINIMUM)

**Status:** OPEN · **Priority:** P1 · **Kind:** language design / semantics
**Owner:** Cursor (canonicality / design authority) · consumers: Codex (graph), Poolside (realization)

## Obligation

Define the exact observation model: the behavior every realization must preserve.
Law: `docs/spec/law.md` §103 OBSERVATION-MINIMUM; C0 `law.observation.minimum`
(`why = law.physical.open`). A realization must preserve only what the program's
semantics actually make observable; everything else is free to change under
`law.physical.open`.

This is the single highest-leverage remaining language-design work. FTCFTW power
is proportional to how precisely Idol defines what is and is not observable —
**every accidental observable is a permanent optimization barrier**. The physical
realization space of GAP-169 is only as large as this model allows.

## Deepest framing (OBSERVATION-ONE / BOUNDARY-ONE)

`law.observation.one` (`docs/spec/law.md` §104) is deeper than OBSERVATION-MINIMUM:
a program *is* a set of required observable relationships among inputs, worlds,
effects, outcomes, and outputs — not a sequence of steps. If written intermediate
bindings/applications disappear entirely, that is ideal. This model must also fix:

- **Semantic vs physical time** — `A` happens-before `B` requires no wall-clock
  duration; execution duration and scheduling are not observable unless the
  program observes a clock/deadline world fact (reading a clock is an effect).
- **Allowed outcome sets** — concurrency, unordered iteration, and randomized
  algorithms admit a set of valid outcomes; the optimizer may realize any of them
  unless world/demand constrains it. Determinism/reproducibility are world demands.
- **World-dependent observability** — a security world may make timing, cache
  access, and addresses observable (constant-time/oblivious realization); an
  ordinary world does not. The observable set is a world fact, not a global constant.
- **`none` representation** — physical nonexistence is a first-class realization
  state; the default optimization question is whether any required observation
  depends on an entity's physical existence.
- **BOUNDARY-ONE** (`law.observation.one` folds it; §105) — representation is free
  except at irreversible boundaries (foreign ABI, file format, network protocol,
  shared memory, observable pointer, volatile/device, authority, debugger address);
  foreign representation has finite extent (exactly the foreign application) and
  never infects the whole program; serialization/parsing are projection/inverse
  projection under a descriptor; endian/alignment are boundary facts.

## What must be classified (observable vs realization)

For each behavior, decide: is it a preserved semantic observation, or a free
realization choice? Default conservative (observable) only where a proof is
absent; narrow later, never widen silently.

Presumptively **non-observable** (realization choices) unless a fact makes them
observable:

- allocation identity, address, and existence of a place;
- table/record/array physical layout (AoS/SoA/split/scalarized/frozen);
- iteration order over unordered collections;
- exact instruction schedule and micro-architectural timing;
- intermediate strings and temporaries in a fused pipeline;
- physical representation, width, and encoding of a value;
- device (CPU/GPU/NPU/core class) and storage tier;
- thread placement, memory tier, and page size;
- whether a pure result is recomputed, memoized, or precomputed.

Presumptively **observable** (must be preserved) unless proven otherwise:

- values and value relations demanded by the program;
- ordering the program's semantics actually fix (e.g. declared-ordered maps);
- observable effects, their authority, and their externally-visible order;
- error/trap semantics the program can catch or that escape a boundary;
- floating-point results **except** where a precision/error demand permits
  approximation (GAP-169 precision class);
- foreign-ABI-visible representation at a real boundary;
- concurrency observations at genuine sharing/atomicity points.

## Dependencies and interactions

- **Effects/authority** — observable effect ordering is fixed by the effect and
  world model, not by realization (`law.cost.explain`, `law.world.closed`).
- **Precision** — approximation is legal only when a descriptor/demand explicitly
  permits an error bound (GAP-169 § precision proportional to demand).
- **Ordering** — unordered table semantics free iteration order; declared order
  is observable. The line must be a graph fact, not source spelling.
- **Concurrency** — the memory/observation model at sharing points bounds
  transaction/optimistic-concurrency/lock-shape realization (GAP-169).

## Floor (2026-08-13)

**IMPLEMENTATION-BLOCKED at S0.** No compiler B; no graph-level observation
facts exist. The model is currently specified only as law prose. No realization
may claim a non-observable freedom until the graph can carry the corresponding
observation fact and the resolver can prove non-observability
(`law.optimization.validated` — the search may be experimental, the accepted
result may not be semantically speculative).

## Deletion conditions

1. The graph carries an explicit observation classification for each behavior
   class above, producible per application/place, with provenance.
2. Every GAP-169 realization freedom (layout, order, device, tier, precision,
   memoization, zero-copy) is gated by a proven non-observation fact from this
   model, not by a heuristic.
3. A positive control: a program that *does* observe one of the presumptively
   non-observable behaviors (e.g. captures allocation identity or fixes order)
   blocks the corresponding realization, and the gate proves it.
4. No accidental observable remains that blocks a lawful realization without a
   named semantic reason.

## Observation + obligation + hyperproperties (2026-08-13)

The observation model is one side of semantics; **obligation** is the co-equal
other (`docs/spec/law.md` §109 OBLIGATION-ONE, C0 `law.obligation.one`). The
graph fact set this GAP must carry therefore includes, per application/place:

- **positive obligations** — respond, commit durable state, deadline, ordering,
  release resource, availability-under-fault, authority boundary;
- **negative obligations** — no network / allocation / secret-dependent timing /
  write-after-cancel / duplicate external effect / persistent state / data
  leaving a region (the strongest optimization enablers: a proven `cannot`
  deletes whole mechanisms);
- **temporal** — `eventually A`, `A until B`, `never C after D`, `within
  deadline`, `at most once`; **safety vs liveness** kept distinct;
- **progress model** (wait/lock/obstruction-free, eventual, best-effort) and
  **fairness** observability as world facts (never globally promised);
- **causality** (`B because of A`) distinct from order; **counterfactual** facts
  for speculation/rollback/deopt; **noninterference** as a relation between
  executions.

Critically, equivalence is **not** single-trace: determinism, noninterference,
serializability, linearizability, and observational consistency are
**hyperproperties** over *sets* of executions. The equivalence checker (GAP-171)
must preserve demanded hyperproperties, not only per-trace observations — a
single-trace oracle is an unsound acceptance criterion for these worlds.
