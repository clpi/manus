# GAP-234 — the `__*` intrinsic namespace is 129 relations with no relation entity

**Status:** OPEN · **Filed:** !2026-08-25T07:30:00Z
**Priority:** P1 · **Kind:** expressiveness_gap
**Filed by:** claude-reconcile

## Why this gap exists at all

`gaps/GAP-226.md` excludes compile-time directives by name — "`comptime-directive`
(353) is `@comp.*`, whose applications are compile-time and whose relation
entities are **a separate owner's**." `gaps/GAP-233.md` repeats the exclusion.

That owner does not exist. Measured:

    cd gaps && grep -il 'comptime|intrinsic|metaprog|@comp\.' *.md   # 25 files, none owns it
    grep -rln 'comptime-directive' gaps/ gate/   # gaps/GAP-226.md, gate/application.sh only

Two gaps route this population to a third that was never filed. This is that
gap.

## What the population is

`@comp.c.emit(x)` is rewritten by the PARSER into an ordinary call node with a
`.name` callee spelled `__emit` — `src/parser.zig:7404-7407`, via
`meta_module.resolveBuiltin`. The rewrite is skipped under `self.formatting`
(`src/parser.zig:7382`), which is the proof it is a parse-time desugar and not a
semantic identity.

    src/meta_module.zig:80      `builtins`, 234 rows -> 129 distinct `__*` internals
    src/legacy_directives.zig:15-43   25 legacy flat/underscore ingress rows
    src/meta_dispatch.zig:63-98       34 combinator dispatch rows
    src/sema.zig:1710                 blanket admission: startsWith "__" -> true

63 subjects in `examples/` refuse the C realizer on one of 30 distinct `__*`
faces — the largest family in `gaps/GAP-233.md`'s split, and 66 once the three
`simd.v4f64` subjects are moved here from the non-callable family.

## They are lifted as call nodes, and the only phase that consumed them is gone

There is no pre-graph expansion. `src/macro_expand.zig` contains one `__`
occurrence and it is a gensym suffix. The comptime evaluator expands
combinators only when a host hook is installed (`src/comptime.zig:766-769`), and
`grep -n meta_hook src/*.zig` finds exactly one production installer:
`src/codegen.zig:802 .meta_hook = comptimeMetaHook`.

`--backend=c` never constructs that CodeGen. `src/main.zig:6042-6046` says so in
its own comment — the branch "returns before constructing the retired AST/Lua
CodeGen". So the entire consumption surface (`src/codegen.zig:17232` `__emit`,
`:17254` `__c_call`, `:17320` `__static_assert`, `:17410` `__comptimefor`,
`:17550` `__type_name`, `:19646`, `:22389`) is unreachable on the graph path.

They then reach `OccurrenceBridge` as `.call` nodes with no application fact and
refuse. **No fact can be published for them**: `recordApplicationInHome`
(`src/sema.zig:1342-1358`) requires a `*const ast.FuncDecl`, and
`src/sema.zig:1706-1710` states the design outright — these names are
"recognised in the call handler by name, never declared in scope".

**This is a capability regression across backends, not a static gap.** The
intrinsics WORK on the retired emitter and are unreachable on the graph path;
the migration deleted the consumer without minting the replacement. `idol check`
accepts all 63 subjects and the only host-portable realizer refuses them.

## Law rules them relations, so the refusal is correct

`docs/spec/law.md:265-267` (§9): "There is one application algebra.
Function-like, subject-oriented, generic, **builtin**, foreign, and transformed
calls are **applications of exact relation/value identities**." `builtin` is
named; there is no exemption for a `__`-spelled callee.

`docs/spec/law.md:219-222` (§6) removes the escape hatch: "an operation whose
whole content is 'do this at compile time' is an ordinary relation applied under
a stage-delta world". `law.stage.world` (`docs/spec/constitution.md:2794`):
"`@comp.*` `@meta.*` `@compiler.*` carry no capability the stage world lacks".
`law.at.one` (`:2817`) denies the prefix-directive plane outright.

So the lawful outcome is NOT "comptime should have consumed them" — that is the
retired second control plane. It is that they are relations and need relation
entities. The refusal is the law being enforced; only its ATTRIBUTION is wrong,
which is `gaps/GAP-233.md`'s subject.

## Four faces have no implementation anywhere

`__schema` (`src/meta_module.zig:263`), `__run` (`:273`), `__pipeline` (`:265`),
`__fieldsmap` (`:193`) appear in that file and nowhere else:

    grep -rn '__schema\|__pipeline\|__fieldsmap' src/*.zig | grep -v meta_module.zig
    # (empty)

Seven subjects refuse on them. They parse, pass the blanket `__` admission, and
are consumed by nobody. These are dead spellings and should be DELETED rather
than given relation entities — they are inflating the ledger's denominator.

## The destination is already assigned

`docs/spec/directive-ledger.json` inventories every `@comp.*` form at a code
position — `code_occurrences 790, distinct_forms 101, files 132` — and each form
already carries a `disposition`: `relation` 55, `transformation` 23, `foreign` 9,
`stage` 7, `evidence` 6, `target` 1. `@comp.c.emit` is `foreign`; `@comp.map` is
`relation`, rationale "the directive face adds nothing law.infer.one does not
already recover".

`gate/directive.sh` is the ratchet: "This gate does not delete that plane —
migration is per-form semantic work recorded in
docs/spec/directive-ledger.json. It stops the plane GROWING."

A ledger plus a ratchet is a containment instrument, not an owner with
acceptance. That is the hole this gap fills.

## Acceptance item 1 is NOT a four-row deletion — measured

The obvious edit — delete the alias rows for `__schema`, `__run`, `__pipeline`,
`__fieldsmap` — was attempted and stopped by the parser's miss path. When
`resolveBuiltin` returns null, `parse_at_form` does not refuse: it falls
through `at_builtin_internal_name` and then mints

    return self.new_expr(.{ .macro_call = .{ .name = first.text, ... } });

so a deleted spelling does not become "unknown directive"; it becomes a
`.macro_call` node routed into the macro-expansion path. Measured over the
corpus, the public spellings behind these four internals appear in 22 files
(`comp.pipeline` 11, `comp.run` 4, `comp.fields.map` 4, `comp.schema` 2,
`meta.fields.map` 1) — the seven refusing subjects are only the ones that
reach the realizer today. Deleting the rows would silently reroute all 22
through `.macro_call`, which is a semantic change wearing a cleanup's clothes.

So item 1 decomposes, in order:

1a. The parser's miss path refuses `@comp.*`/`@meta.*` spellings BY NAME in
    `.id` mode — the same shape the `@constexpr` arm already has — instead of
    minting a `.macro_call`. Only then is a deleted row a truthful refusal.
1b. The four rows are deleted, and `src/meta_module.zig`'s resolver test drops
    its `__fieldsmap` assertion.
1c. The 22 files are migrated or their forms get owners per the ledger's
    dispositions, so the refusal count moves for a reason the census can name.

## Acceptance

1. Items 1a-1c above, in that order — 1a is the guard that makes 1b safe.
2. Per-disposition, not per-face: the 55 `relation` forms become ordinary
   relations applied under `expr@{ stage = compile }` (GAP-227's world), and the
   9 `foreign` forms become foreign origin/ABI facts — which
   `src/directives.zig:59-65` already anticipates ("The operations behind them
   are foreign origin/ABI realizations awaiting an owning graph fact").
3. `gate/realize/census.sh` shows the `__*` faces leaving the refusal histogram
   as each disposition lands, rather than a count pinned here.
4. Explicitly disjoint from GAP-226 (43 host-relation subjects) and sequenced
   after GAP-233 (the note split), so the two families stop being read as one.
