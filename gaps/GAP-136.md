# GAP-136 — relation identity gate accepts untracked C-only noncanonical evidence

**Status:** OPEN · **Filed:** !2026-08-10T00:08:10Z
**Priority:** P0 · **Kind:** script
**Filed by:** codex-root-shc-audit-20260810
**Files:** gaps/GAP-103.md,scripts/relationid.id,examples/spec100/relation_store.id

A named relation identity gate can report closure from an untracked fixture that the canonical diff gate rejects and direct native cannot realize. Closure must fail closed unless every fixture is tracked, current-canonical, and exercises the authoritative Idsem semantic relation through direct realization. Keep the stable store-unit result, but do not count C/default runner output or Zig-source scans as SHC/source authority. No new Zig; repair the Idsem gate/evidence topology and source semantic path.

## Reproduction

The gate names an untracked file as evidence:

```text
$ git ls-files --error-unmatch examples/spec100/relation_store.id
error: pathspec 'examples/spec100/relation_store.id' did not match any file(s) known to git
```

The file is not landable under the repository's first commit chokepoint. An
added-file diff fails `scripts/idiomgate.id` with eight `LAW-ONE` findings for
the `eq_*` identifiers. It also contains the retired callable-result suffix and
an imperative iteration face where the relation identity being proved should
remain visible.

The default bootstrap path nevertheless accepts and runs it:

```text
$ ./zig-out/bin/duo check examples/spec100/relation_store.id
$ ./zig-out/bin/duo run examples/spec100/relation_store.id
16
```

The direct path does not:

```text
$ ./zig-out/bin/duo run --backend=direct examples/spec100/relation_store.id
error: direct backend refused native lowering at native-scalar precheck — assign-target
```

`scripts/relationid.id` calls default `duo run` for both fixtures, reaches
processes through the retiring `std.script` namespace, and scans
`src/relation.zig` with host text tools. Its green result is useful bootstrap
evidence for the existing relation store. It is not evidence that canonical
Idsem source can name the identity, that the semantic graph owns it, or that the
direct realization consumes it.

The deleted pass-era extractor once recorded that `relation_store` was visible
from a parallel session but uncommitted. It is not current evidence. A gate must
never derive a released claim from session-private work merely because it is
visible in the shared worktree.

## Required separation

Keep the current store result classified narrowly:

```text
store unit semantics       proven in bootstrap implementation
source reachability        open under GAP-103
canonical corpus evidence  absent
semantic graph authority   absent
direct realization         refused
SHC evidence               absent
```

The bootstrap store now also refuses a pair when two lawful two-hop routes
exist, regardless of declaration order. This closes the store-level ambiguity
fail-open only. It does not provide the missing relation-level composition law,
graph identity, canonical source reachability, witness identity, or direct
realization required below.

Do not weaken or delete the stable identity tests merely because their host is
temporary. They become an oracle until an equivalent Idsem-owned proof exists.
What must stop is promoting their result into a stronger claim.

## Closure

1. Every proof fixture is tracked in the commit whose gate names it.
2. The exact added-file canonicality check passes before the fixture can
   contribute a row.
3. The fixture names an admitted semantic relation identity from canonical
   Idsem source; it does not create a second operation family in gate code.
4. The semantic graph retains that same identity and direct realization
   consumes it without text reconstruction.
5. Direct native executes the value proof and reports lineage from source
   relation to realized operation.
6. C/bootstrap output may remain a differential oracle, but it is a separately
   labelled row and cannot satisfy direct or SHC closure.
7. The proof runner and result model are Idsem-owned. No new Zig gate or runner
   is added. Existing Zig inspection is temporary oracle evidence with an
   explicit deletion condition: remove it when the Idsem relation store and
   lineage query reproduce the positive and negative controls.
8. A positive control supplies an untracked but otherwise valid fixture and
   proves the gate refuses it before executing it.
9. A second positive control supplies a tracked noncanonical fixture and proves
   the gate refuses it before executing it.
10. GAP-103 remains open until origin, scope, lawset, and rename are reachable
    through the same source and graph authority. Closing this gate must not
    misclose that semantic reachability gap.
