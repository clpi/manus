# GAP-181 — value-of-information and semantic frontier

**Status:** OPEN · **Filed:** !2026-08-18T15:30:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/semantic_frontier.id, src/value_info.md

The compiler should choose not only code but which fact is worth learning. For
every region, expose:

- what is known
- what remains unknown
- which unknown blocks which realization candidate
- cost to resolve it
- potential payoff

Then optimizer and agent work targets the most valuable missing knowledge.

## Current measured boundary

`FRONTIER.md` records the canonical priority ladder and rung reach. There is no
machine-readable `semantic frontier` fact family that exposes missing knowledge
and its value.

**Crossed:**

- `unknown` is a recognized graph state.
- `demand` and `effect` facts already direct optimization.

**Still missing:**

- `frontier(region)` = `{ known facts, unknown facts, candidates, blocker map,
  resolution cost, payoff }`.
- Value-of-information estimate: `expected_optimization_gain - acquisition_cost`.
- Fact-acquisition options: static proof, runtime guard, sampling, profile,
  agent search, do not specialize.
- Integration with MCP/optimizer so agents query "what prevents this
  allocation?" and get a missing-fact response.
- Distinction between epistemic probability (compiler uncertainty) and semantic
  probability (program is random).

## Required order

1. Define `semantic frontier` as a graph region fact.
2. Attach `unknown` facts to the candidates they block.
3. Estimate payoff and acquisition cost for each missing fact.
4. Add `value_of_information` as an optimization objective alongside cost.
5. Expose the frontier through MCP as a queryable interface.

## Closure acceptance

Close when the optimizer can display, for any region, the missing fact with the
highest value-of-information and can choose whether to resolve it statically,
with a guard, a sample, a profile, or not at all.
