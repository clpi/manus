# GAP-050 — explicit realization evidence uses shared CWD state

**Status:** OPEN · **Filed:** 2026-08-08
**Priority:** P0 · **Kind:** evidence_gap
**Files:** src/main.zig,src/compile_semantic_cache.zig,src/persistent_semantic_state.zig

Normal `check` returns before realization-cache refresh. Production compile,
run, test, and bench no longer refresh the cache either: that discarded path
rebuilt a second graph from AST, reconstructed text-addressed realization
candidates, fingerprinted them, and mutated shared state without affecting
selection or emitted artifacts.

The explicit `realize` command still writes:

```text
.id/cache/semantic/state.json
```

relative to the current working directory. That command is an evidence query,
so its state must become private and revision/run-bound rather than a
process-global semantic cache. Concurrent requests must not overwrite one
another, and ordinary compilation must remain independent of this file.

## Current implementation audit

Commit `c3954e5` deletes the production refresh call and its ignored count
reporting. Static inspection shows that the removed branch rebuilt a graph from
AST, swallowed refresh failure, and did not feed backend selection or artifact
emission. The explicit `realize` entry point remains separately routed.

Those facts support the deletion but are not execution evidence. Byte identity,
cache absence, and retained query behavior have not yet been bound here to an
exact revision, dirty state, inner command, artifact, and positive control.
They remain unproved rather than implicitly green.

`scripts/capability_matrix.id` still describes `DUO_SEMANTIC_CACHE=0` as
load-bearing and exports it around a production compile. That projection is now
stale: the variable is ignored by the deleted compile path. Remove the claim
when that currently dirty file is reconciled; do not restore the discarded
refresh to make the old wording true.

## Required deletion proof

1. On parent `6fe1123`, execute a record-bearing production fixture in a private
   directory and positively prove that the enabled refresh path ran.
2. On that same parent, compare enabled and `DUO_SEMANTIC_CACHE=0` executable
   bytes and retain both inner outcomes and artifacts.
3. On `c3954e5` or a descendant containing only equivalent deletion, repeat the
   production compile in a new private directory, compare with the disabled
   baseline, and prove no cache file was created.
4. Positive-control the absence detector through explicit `realize` in another
   private directory: it must create evidence and publish a nonempty plan plus
   a fresh audit outcome.
5. Bind the focused result and serialized capability, unit, and aggregate gate
   outcomes to the exact tested tree. A wrapper exit without the inner outcome
   is not evidence.

Close this gap when `realize` consumes graph-owned facts and publishes private,
revision-bound evidence without shared CWD state. Missing or conflicting
evidence must remain an explicit incomplete/refused case.
