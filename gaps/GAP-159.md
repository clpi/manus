# GAP-159 — process.* namespace remains active despite world/run law

## State

Open.

## Problem

C0 `law.shell.run` and `law.run.algebra` say process execution reduces to
`run` with world, output demand, outcome, and evidence facts — not a
`process.*` namespace. The latest committed migration explicitly converted
`std.script.*` to `process.*` and called it canonicalization. This is
wrong destination architecture.

`process.capture`, `process.run`, `process.exit`, and `process.chomp`
are all live in `tools/mcp/shared.id` and gates.

## Evidence

```
tools/mcp/shared.id:109:    out = process.capture(...)
tools/mcp/shared.id:269:    rc = process.run(full)
tools/mcp/shared.id:133:    process.capture("git rev-parse HEAD ...")
gates/admission.id:45:      spell == "process.capture"
gates/admission.id:47:      spell == "process.run"
gates/admission.id:49:      spell == "process.exit"
gates/admission.id:51:      spell == "process.chomp"
```

## Required direction

```
run
  subject: command/work
  process world
  output demand
  outcome
  evidence
```

Not a `process.*` namespace.

## Specific issues

- `process.capture` should probably disappear: capture = run + output
  demanded as value/evidence (law.run.algebra)
- `process.exit` is suspect: likely collapses run outcome + continuation
  termination + foreign OS realization
- `process.chomp` is a conventional scripting helper, not a semantic
  relation
- `lib.process` import-by-assignment is module-like dispatch in disguise

## Deletion prerequisite

- `run` relation with world facts admitted
- Output demand modeled as ordinary value/evidence demand
- Outcome modeled as native semantic outcome, not OS status
