backend that has already decided not to declare a Lua runtime.

## Law

`docs/spec/constitution.md` §43 `law.brace` binds *"an ordinary callable uses
`name( … )`, never braces"* and fails on *"letting a callable use braces"*.
`apply.edge` keeps the two edges distinct: `apply(descriptor)(fieldpack)` vs
`apply(callable)(argpack)`. Resolution (§41) supplies *"ONE IDENTITY, OR A
DIAGNOSTIC"* — a callable subject with a braced face is a diagnostic, not a
fall-through to ordinary-call checking. The check gate is the fail-closed
boundary for this row; GAP-092 closure item 1 already requires ordinary call
recognition to "reject canonical postfix brace/string calls".

## Measured repro (current binary, HEAD d1b1c7a)

```id
point: { x: i64, y: i64 } = (x: i64, y: i64)
    { x = x, y = y }

main: i64 = ()
    p = point{ x = 3, y = 4 }
    p.x + p.y
```

`duo check` exits **0** (no diagnostic). `duo run` exits **1**, cc rejects
generated C:

```
/tmp/duo_callable_braces.c:145:50: error: call to undeclared function 'lua_to_num'
/tmp/duo_callable_braces.c:146:9:  error: use of undeclared identifier 'lua_Value'
/tmp/duo_callable_braces.c:147:9:  error: call to undeclared function 'lua_table_set_raw_lit'
```

The braced pack also passes a one-argument check against a two-parameter
callable, so the ordinary-call path is not type-checking the pack either.

## Bisection — the working rows are all descriptor-side

| shape | check | run |
|---|---|---|
| `d = { a = 3, b = 4 }` anonymous pack | pass | exit 7 |
| `point: { x: i64, y: i64 }` + `point{ x = 3, y = 4 }` descriptor subject | pass | exit 7 |
| `p: point = { x = 3, y = 4 }` + `q: point = point{ x = 5, y = 6 }` typed binding + braced apply | pass | exit 18 |
| **callable subject `point{ … }`** | **pass** | **exit 1, cc `lua_*`** |

Only the callable-subject row is broken, and it is the row the law forbids — so
the repair is a refusal, not a new construction path.

## Fail-open site

- `src/sema.zig:2644` `check_descriptor_application` returns null for the
  callable subject (`alias_defs` resolves `point` to a function, `is_record` is
  false), and the ordinary `.call` check then admits the braced pack.
- `src/codegen.zig:8154` `emit_descriptor_application` returns null for the
  same subject, so the ordinary `.call` prong at `src/codegen.zig:15735` falls
  to the boxed path and emits `lua_table_new_with_capacity` / `lua_to_num` /
  `lua_Value` — symbols with no declaration in a translation unit that decided
  not to declare a Lua runtime. The doc comment on `emit_descriptor_application`
  uses `point{ x = 3.0, y = 4.0 }` as its example, but that path only fires for
  record-alias and field-walk-descriptor subjects, never for a callable subject.

This is the same defect family as the native-gate precheck rows GAP-092 already
reported: native lowering chosen, boxed emission produced.

## Required controls

- `duo check` must refuse `name{ … }` when `name` resolves to an ordinary
  callable, with a diagnostic citing `law.brace` and naming the two homes
  consulted (descriptor space vs callable space) — the §41 "or a diagnostic"
  branch, never a silent fall-through.
- The refusal must fire on the source face (`form == .braced`) before any
  argument or parameter comparison, so a pack arity mismatch cannot mask it.
- The C backend must never emit `lua_*` helpers for canonical source. If the
  shape is ever legitimately admitted (an expected descriptor supplying the
  same descriptor fact), it must lower through `emit_record_initializer` with
  `pack.realized = .fields` — never through `lua_table_new_with_capacity`.
- Gate the row with a fixture pinned on the diagnostic substring, so the
  refusal cannot silently reopen. The pin lives in the sema unit suite
  (`zig build unit-test`), which is a blocking gate; the `.id` corpus row
  documents the shape.

Close only when check refuses the callable-subject row, a pinned fixture runs
in the blocking gate, and no canonical path emits `lua_*` helper calls.
