## The chain, reproduced out of repo

A probe linking `keyword_classify.c` and `lexer_tokenize.c` as `build.zig` does,
over the fixture `n = 8; r = 0; if (n > 3) …`:

```
PLACE CENSUS:  count=0  points=5   find("n")=false  find("r")=false
REGION CENSUS: count=3  points=5   subject=unknown  lower=unknown
```

`place.zig` `candidateShape` returns `.unknown` for a scalar initializer, so
`bindPlace`'s `if (shape == .unknown) return;` mints no row; `region.zig`
`placeOf` calls `ctx.places.find(name)`, gets null, and `domainOf` falls to an
all-default `Refinement`; the test reads `.at` on a `.unknown` bound and aborts.
The same null empties `collectCarried`, which is the `:815` failure.

`f5857e0a` (2026-08-19, +370/-1262 in one file) established "scalar values,
parameters and homes are not places". `region.zig` was authored in `0c51fc58`,
**306 commits earlier**, against a census that did mint them.

## Two proposals refuted before proposing a third

**Mint scalar places.** Measured in a full mirror: clears all six region rows and
breaks `place: scalar values, parameters and homes are not places` — the exact
invariant `f5857e0a` exists to establish. It also violates the stated intent of
`gate/semantic-graph-authority.sh`, which is in CI and `lacks`-guards
`break :blk .scalar` / `shape = .parameter` / `shape = .home`.

**Retype `Refinement.subject` to the "unused" `region.Site`.** Its premise is
false. `region.Site` is the type of `Region.parent` (`:155`), `Region.target`
(`:160`), `Ctx.loop` (`:219`) and the `parent` parameters of `walkBlock` /
`walkStmt` / `nested`. Its own doc says it exists so "a region id can never be
read as a graph entity id or a place id" — putting a subject id in it is the
conflation it was spelled to prevent. The proposal is also incomplete:
`Bound.place`, `Bound.under` and `Region.carried` carry place ids too, so
retyping `subject` alone fixes four rows of six.

**A graph fact instead.** Measured: none exists. Lifting the fixture through
`liftModuleWithCheckedCalls` yields two nodes, module and func, and
`places=0 origins=0`. `.local` nodes are minted only for `.record`/`.named` type
exprs or checked pack-adjustment binding, and every graph route to a named local
funnels through the same dead census.

## Measured fix: a binding census beside the place census

`place.zig` already visits every binder — `bindOrRebind` is called for scalars;
it is `bindPlace` that declines. Give it a sibling list of name bindings and have
region resolve subjects through that.

| variant | result | delta |
| --- | --- | --- |
| mirror baseline | 1651 pass, 12 fail, 3 crash | — |
| mint scalar places | 1656 pass, 10 fail, 0 crash | **+1 regression** |
| **binding census** | **1657 pass, 9 fail, 0 crash** | **-6 region, +0 regressions** |

In this repo that is **1658 pass, 8 fail, 0 crash / 1666 — all three crashes
gone.** `gate/semantic-graph-authority.sh` passes byte-identically on the
patched mirror.

Shape: `place.Binding {id, name, stmt, point}` plus a `bindings` list,
`bindingCount()`, `findBinding()` with the same backward shadowing rule as
`find`, `noteBinding()` called once at the top of `bindOrRebind`, and a
`place.BindingSite` union spelled separately from `Site`. Then two functional
lines in region: `subject: place.BindingSite` and `placeOf` calling
`findBinding`. The retype is load-bearing, not cosmetic — measured on
`s = (1,2,3); n = 8`, `s` is place id 0 AND binding id 0, so the two spaces
genuinely collide at index 0.

`semantic_graph.zig` compiles unchanged; only the JSON key `"place"` would
become `"binding"` for truthfulness. No gate or ledger pins that dump.
