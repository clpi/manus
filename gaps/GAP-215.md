# GAP-215 — file-scope loop closure changes a program's exit status

**Status:** OPEN · **Filed:** !2026-08-22T04:05:00Z
**Priority:** P0 · **Kind:** regression
**Filed by:** claude-gap145
**Files:** src/loop_closure.zig

Two spellings of one program. Identical stdout. **Different exit status.**

```id
a: i64 = 0                  a: i64 = 0
i: i64 = 0                  i: i64 = 0
while i < 5                 while i < 5
    a = a + 1                   t: i64 = a + 1
    i = i + 1                   a = t
print(a)                        i = i + 1
                            print(a)

stdout 5, exit 5            stdout 5, exit 0
```

| compiler | left form |
| --- | --- |
| `b64dc075` | `5`, **exit 0** |
| **`4cce7c93` (file-scope closure) onward** | `5`, **exit 5** |

Bisected. At 300 trips the left form exits **44** = `300 & 0xff`.

## Cause

The module exit rule — exit status is the low byte of the module's last
assignment — **pre-exists** and is not this transform's invention. Positive
controls: `a: i64 = 5` / `print(a)` exits 0; `a: i64 = 0` / `a = 5` /
`print(a)` exits **5** with no loop at all.

But file-scope closure replaces a `while` — which contributes **no**
assignment — with a `constantAssign`, which contributes one. So it changes
which statement is last-assigning, and therefore the program's exit status.

## Why the differential missed it, and this is the more important half

The 538-file corpus differential accompanying that change reported **0 exit
status differences**. Measured since:

> Of 538 corpus `.id` files, **10 contain a module-scope `while`**, and **9 of
> those 10 refuse to compile on the direct backend** — `pretty_trace`,
> `simd_mandelbrot`, `benchmark`, `pack/consume`, `boring/linecount`,
> `boring/list/linked`, `hash/agreement`, `layout/guard`, `boring/jsonparse`.
> Only `examples/boring/reverse.id` runs.

**The corpus covers this transform with one file.** A differential over 538
programs that exercises the changed path once is not evidence of safety, and it
read as though it were.

## Acceptance

Closure preserves exit status: either the rewrite does not become the last
assignment, or it restores the prior last-assignment value. Control both
directions — a module whose last statement *is* an assignment must keep its
exit status, and a module whose loop is closed must not acquire one.

**And the coverage must be raised before the admitted shape is widened.**
Widening `collectUpdates` to admit a body `local_decl` also requires widening
`entryValueIsDead`, which likewise walks only `.assign`. Three edits to a
transform with a known unfixed correctness hole, policed by one corpus row, is
the wrong order.
