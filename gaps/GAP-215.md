# GAP-215 — file-scope loop closure changes a program's exit status

**Status:** CLOSED · **Filed:** !2026-08-22T04:05:00Z
**Priority:** P0 · **Kind:** regression
**Filed by:** claude-gap145
**Files:** src/loop_closure.zig

Two spellings of one program. Identical stdout. **Different exit status.**

```id
a: i64 = 0                  a: i64 = 0
i: i64 = 0                  i: i64 = 0
while i < 5                 while i < 5
    a = a + 1                   t: i64 = a + 1
    i = i + 1                   a = t
print(a)                        i = i + 1
                            print(a)

stdout 5, exit 5            stdout 5, exit 0
```

| compiler | left form |
| --- | --- |
| `b64dc075` | `5`, **exit 0** |
| **`4cce7c93` (file-scope closure) onward** | `5`, **exit 5** |

Bisected. At 300 trips the left form exits **44** = `300 & 0xff`.

## Cause

The module exit rule — exit status is the low byte of the module's last
assignment — **pre-exists** and is not this transform's invention. Positive
controls: `a: i64 = 5` / `print(a)` exits 0; `a: i64 = 0` / `a = 5` /
`print(a)` exits **5** with no loop at all.

But file-scope closure replaces a `while` — which contributes **no**
assignment — with a `constantAssign`, which contributes one. So it changes
which statement is last-assigning, and therefore the program's exit status.

## Why the differential missed it, and this is the more important half

The 538-file corpus differential accompanying that change reported **0 exit
status differences**. Measured since:

> Of 538 corpus `.id` files, **10 contain a module-scope `while`**, and **9 of
> those 10 refuse to compile on the direct backend** — `pretty_trace`,
> `simd_mandelbrot`, `benchmark`, `pack/consume`, `boring/linecount`,
> `boring/list/linked`, `hash/agreement`, `layout/guard`, `boring/jsonparse`.
> Only `examples/boring/reverse.id` runs.

**The corpus covers this transform with one file.** A differential over 538
programs that exercises the changed path once is not evidence of safety, and it
read as though it were.

## CLOSED

`Stmt.assign` gains `closed_loop: bool = false` — a semantic fact about the
statement, not provenance: **the residue of a value-less statement is
value-less**. `tail_result_demand.tailStatementResult` answers `null` for it,
which is exactly what the `while` it replaced answered. `loop_closure`'s
`constantAssign` sets it, documented as obligation L6.

Declining instead would refuse the whole family the pass exists for — a
file-scope loop under a `print` *is* the last statement. Measured: a 2×10¹⁰-trip
loop still closes in 262 ms patched against 247 ms baseline.

| control | before | after |
| --- | --- | --- |
| `a = a + 1` in the body | `5`, exit **5** | `5`, exit **0** |
| `t: i64 = a + 1; a = t` | `5`, exit 0 | `5`, exit 0 |
| `a: i64 = 0; a = 5; print(a)` — no loop | exit **5** | exit **5** |
| `a: i64 = 5; print(a)` — declaration only | exit 0 | exit 0 |

The two spellings now **agree**, and both no-loop controls preserve the
pre-existing rule.

`zig build unit-test`: **1686 pass, 1 fail / 1687** — the +6 are new tests, and
the one failure is the same cwd-sensitive `git_preservation`. 538-example
corpus differential on compile status, exit status **and** stdout hash:
**0 differences, 538/538**.

## Refutation, reported first

Marking the store at **relation scope too** converts a program that used to
compile into a refusal (`DNB001 missing: unspecified`). The control is the
decisive part: **the other spelling already refused at baseline**. That shape
was never supported — it compiled only because the transform manufactured a
tail value, and the value it manufactured was the loop's answer, the same
defect one scope down. Refusing both spellings restores the
spelling-independence this gap asks for, and costs nothing on the corpus.

## The coverage was worse than this gap recorded

| | corpus at `d02cf682` |
| --- | --- |
| files scanned | 538 |
| **eligible** (module-scope `while`) | **10** |
| reach a runnable artifact | **1** (`examples/boring/reverse.id`) |
| **transformed** — loop actually closed | **0** |
| declined | 10 / 10 |
| tested on exit status | **0** |

**No corpus program exercises a closed file-scope loop at all.** `reverse.id`
is eligible and still declines — its entry values are strings and its body
applies `s:sub`, so `polyOfExpr` refuses. The 0-difference sweep is therefore
itself the measurement: this change alters behaviour only where a closed-loop
store becomes a block's value, and across 538 programs that happens zero times.

Two structural reasons the coverage cannot exist today, both measured:
`scripts/native_differential.id` — the runner that compares exit status — does
not compile on the direct backend (`DNB001 ret-type:any`), and
`--backend=c --emit exe` refuses for every program. And the one live corpus
oracle, `../idol-native/gate/expect.sh`, compares **stdout only** — its
`probe()` discards the status, so this gap's defect is invisible to it by
construction: both spellings print `5`.

**Coverage added** in `src/loop_closure.zig`: 6 tests, **16 programs**, each
read at both producers of the exit status and always as a differential between
the transformed and untransformed program, never against a hand-written
constant. 6 transformed, 8 declined across 7 distinct reasons — including body
`local_decl`, the exact shape this gap forbids widening `collectUpdates` into,
so the widening now has a row to answer to — and 2 no-loop positive controls,
without which a probe that always answered 0 would pass by accident. The
decline count is asserted so deleting a row fails rather than quietly shrinking.

## Acceptance

Closure preserves exit status: either the rewrite does not become the last
assignment, or it restores the prior last-assignment value. Control both
directions — a module whose last statement *is* an assignment must keep its
exit status, and a module whose loop is closed must not acquire one.

**And the coverage must be raised before the admitted shape is widened.**
Widening `collectUpdates` to admit a body `local_decl` also requires widening
`entryValueIsDead`, which likewise walks only `.assign`. Three edits to a
transform with a known unfixed correctness hole, policed by one corpus row, is
the wrong order.
