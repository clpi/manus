# GAP-164 — NO-C-BACKEND: generated C backend is bootstrap debt to delete

## State

Open.

## Problem

Per law.backend.c.zero, the generated C backend (`src/lexer_tokenize.c`,
codegen, all generated C artifacts) is bootstrap debt, not destination
architecture. The direct native backend is the sole realization path.

The C backend currently exists because the native backend cannot yet compile
the bootstrap subset (bytes, views, strings, arenas, vectors, maps, interning,
bitsets, source/span, filesystem read, diagnostic output).

No investment should improve the C backend. All investment should advance
native backend coverage to delete it.

## Current C artifacts

- src/lexer_tokenize.c (513KB, generated from lib/compiler/host.id)
- src/codegen.zig (the C code generator)
- build.zig C compilation steps
- All --backend=c code paths

## Deletion gate

Native backend coverage of the compiler-critical basis:
bytes, views, strings, arenas, vectors, maps, interning, bitsets,
source/span, filesystem read, diagnostic output.

## Rule

Do not improve the C backend. Invest in deleting it by advancing the native
backend to full coverage. Every C backend improvement is secondary to native
backend coverage advancement.
