# GAP-051 — Apple ARM64 passes a variadic tail on the STACK, not in x3

| # | directive |
|---|---|
| 1 | **Filed** 2026-08-08. **Status** CLOSED 2026-08-08. **Was blocking** `to(str)(n)` and `"x=" .. to(str)(n)` — the canonical way Pass 100 §7 says to build a string. |
| 2 | Both now lower natively and produce correct values. |

## What it actually was

| # | directive |
|---|---|
| 1 | `to(str)(n)` lowers as malloc(24) + snprintf(buf, 24, "%lld", n). |
| 2 | Staged as four `mov_arg` slots it assembled to code that reads as textbook-correct: |

| # | directive |
|---|---|
| 1 | mov x0, x9 ; buf mov x10, #24 / mov x1, x10 ; size adrp/add x10, Lduo_str_0 / mov x2, x10 |
| 2 | "%lld" mov x10, #42 / mov x3, x10 ; the value bl _snprintf |

| # | directive |
|---|---|
| 1 | and printed a ten-digit number. **snprintf never reads x3.** Apple's ARM64 ABI diverges from AAPCS64 for variadic functions: every argument past the last NAMED parameter is passed in the memory-argument area at sp, 8-byte aligned. x3 was ignored and the tail slot held whatever the save area had put at [sp]. |

## The bisect that found it — three named argument slots work

| # | directive |
|---|---|
| 1 | The earlier diagnosis ("the buffer pointer does not survive") was wrong, and the probe that produced it was one probe. |
| 2 | The decisive control was to hold the call shape fixed and vary ONLY the argument count: |

| # | directive |
|---|---|
| 1 | snprintf(buf, 24, "AB") 3 args, no tail |

      #s -> 2       s[0] -> 65 'A'     s[1] -> 66 'B'      ALL CORRECT
| # | directive |
|---|---|
| 1 | snprintf(buf, 24, "%lld", 42) 4 args, one tail |

      #s -> 10      s[0] -> 52 '4'     s[1] -> 51 '3'      WRONG

| # | directive |
|---|---|
| 1 | Three register arguments through `mov_arg` were never the problem. |
| 2 | "10 digits beginning 43" is an address in the loaded image, not a corrupted 42. |

| # | directive |
|---|---|
| 1 | Confirmed independently before touching the compiler, by hand-patching the emitted assembly to put the tail at [sp, #0] and reassembling with `xcrun cc`: `#s` went 10 -> 2. |

## The fix

* `dnir_lower.zig` marks the tail argument `mov_arg .field = "vararg"`, with
  `result` as the tail index rather than a parameter register.
* `native_backend.zig` collects those into `pending_varargs` and flushes them
  in `emitPushVarargs`, emitted AFTER `emitSaveCallerRegs` so the callee's
  memory-argument area begins exactly at sp; `emitPopVarargs` restores sp and
  releases any scratch register. Both are no-ops when no tail is staged, so
  every existing call emits byte-identical code.

| # | directive |
|---|---|
| 1 | Neither attempt recorded in the previous revision of this file was repeated. |
| 2 | Attempt 1 (copy a call's result out of the return register) was unnecessary: the integer arm of `call_extern` already does `mov dst, x0` after the branch, so the malloc result survives — the f64 arm deliberately does not, and that asymmetry is correct. |
| 3 | Attempt 2 (relocate a temp out of x0..x7 inside `mov_arg`) was neutral because register placement was never wrong. |

## Guard shipped with it

| # | directive |
|---|---|
| 1 | `"%lld"` is a constant the emitter assumes, so `exprIsIntegral` is a POSITIVE test and `to(str)` declines anything it cannot prove is an integer. |
| 2 | Before the guard, `to(str)(1.5)` printed 4378777232 and `to(str)("hi")` printed 4343729785 — each the operand's address, each indistinguishable from an answer. |

## Still open, deliberately out of scope

* The face-call spelling `n:to(str)` (Pass 100 §6) still bails: `faceAsCall`
  rewrites it to `to(n, str)`, which is not the shape this lowering matches.
* `print(s)` where `s` is a str LOCAL bails in the native-scalar precheck, with
  or without `to(str)` — `s = "hi"; print(s)` bails identically. That is
  codegen.zig, not this gap.
