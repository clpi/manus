# GAP-051 — a call's result register is x0, and `mov_arg` then aliases it

**Filed** 2026-08-08. **Status** open. **Blocks** `to(str)(n)`, and by extension
`"x=" .. to(str)(n)` — the canonical way Pass 100 §7 says to build a string.

## The attempt

`to(str)(n)` lowers cleanly as malloc(24) + snprintf(buf, 24, "%lld", n),
four arguments through `mov_arg`, which concat already proved works. Two
single-fact probes:

    to(str)(42)[0]   ->  52  ('4')   CORRECT — snprintf ran and wrote "42"
    #to(str)(42)     ->  11          WRONG   — should be 2

So the conversion works and the BUFFER POINTER does not survive.

## The mechanism

`call_extern`'s integer arm maps a call's result temp to **x0**
(`if (ins.result) |t| try temps.put(self.alloc, t, 0)`). So:

    bl _malloc            -> buf lives in x0
    mov_arg 0 = buf       -> a NO-OP; buf is already x0
    ...
    bl _snprintf          -> snprintf's RETURN VALUE lands in x0

and `buf` is gone. `s[0]` still read correctly because it was emitted before
the clobber; `#s` calls strlen afterwards and reads whatever snprintf returned.

## Why the obvious fix was already rejected once

Copying the result out of x0 after the call is the right shape, and the f64
version of exactly that change was reverted earlier tonight: **d0 IS the ARM64
return register**, so copying out broke the f64 return ABI and the unit test
"native backend lowers Pass 4 milestone with f64 return in d0" caught it.

The integer case may differ — x0 is also the return register, so the same
hazard applies. The safe form is probably not "always copy out" but "copy out
when the temp is LIVE ACROSS a later call", which needs liveness the backend
does not track.

## Cheaper alternative worth trying first

Have `mov_arg` refuse to be a no-op when the source register is also the
DESTINATION of a pending clobber — or simply materialize the argument through
a fresh register when `slot == reg`. That is local to `mov_arg` and needs no
liveness.

## Control to use

    to(str)(42)[0] == 52   and   #to(str)(42) == 2
Both must hold. The first alone passes with a corrupt pointer, which is exactly
how this got as far as it did.
