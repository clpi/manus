## Dominance contract (acceptance discipline — §98–§101)

| # | directive |
|---|---|
| 1 | The realization deliverable is not "faster than C" parity; it is the optimization-dominance contract now made law (`docs/spec/law.md` §98–§101 |
| 2 | C0 `law.ftcftw.dominance`, `law.optimization.open`, `law.optimization.validated`, `law.cost.closure`, `law.algorithm.realization`). |
| 3 | Every kernel and benchmark below is measured against `BEST KNOWN IMPLEMENTATION + SEMANTIC/PHYSICAL LOWER BOUND` — each named compiler/library is one oracle among many — and each cost dimension resolves to exactly one of: |

- **WIN** — strictly better than the best competitor with equivalence + confidence.
- **OPTIMAL** — equal the proven lower bound where no improvement is physically
  available (FTCFTW closure; fewer than the semantic minimum is impossible).
- **LOSS** — expose exact optimization debt: application id, extra physical cost,
  semantic cause, unresolved fact, lower bound, workstream. A loss without causal
  decomposition is itself a compiler defect.

| # | directive |
|---|---|
| 1 | Conflicting dimensions form a Pareto frontier under an explicit build-world policy/budget (§74, §98), never a scalar score. |
| 2 | The acceptance inequality is `IdolCost(P,T,W,Q) Pareto-dominates BestKnownCost(C,P,T,W,Q)` unless the competing point is already on a proven lower bound (then Idol must reach it). |
| 3 | A benchmark is CLOSED only when Idol dominates every compared implementation or reaches a proven lower bound; no win elsewhere and no geometric mean compensates for an open loss (§100). |
| 4 | Candidate realizations may originate from any source (rewrite, equality saturation, superoptimization, solver, autotuner, profile, hardware measurement, learned search, agent, competitor mining, or a method not yet invented) and are canonical only when observations are verified AND the cost frontier improves (§99). |
| 5 | There is no closed optimization taxonomy. |

## Vertical FTCFTW kernels (prove the architecture, in order)

1. **Scalarized record call** — known record → scalarize → application-specific
   call ABI → exact liveness → joint instruction/register decision → no spill →
   direct object.
2. **Fused table iteration** — iteration chain → effect/alias proof → fusion →
   vectorization → zero intermediate table (`law.buffer.demand`,
   `law.vector.one`).
3. **World-qualified I/O/text pipeline** — specialize world/witness → fuse
   formatting → zero temporary string → direct syscall or library realization.
4. **Numeric/array kernel** — layout choice → range/bounds proof → SIMD →
   three-layer measurement against Clang `-O3`/LTO and a Fortran-grade array
   compiler (`law.lower.bound`).

## Deletion conditions

1. Compiler B produces machine code for at least the four vertical kernels via
   `graph → demand → realization → instruction → object` with no reconstruction
   of application facts from spelling, AST, host types, or callee text.
2. Each kernel reports the `law.lower.bound` three-layer measurement
   (semantic minimum · best equivalent C/Fortran/LLVM · current Idol) with a
   current-subject revision (`law.evidence.subject`).
3. `src/native_backend.zig` spill behaviour is spill-last, not spill-all
   (`law.abi.internal`).
4. No second full IR world beside the graph; realization overlays only
   (`law.realization.late`).

| 2 | Verified inner loops: |

```text
kernel A (nonlinear recurrence) direct loop = 12 instr, ALL literals hoisted:
    cmp x11,x9 ; b.ge exit            # bound x9 hoisted in prologue
    mul x15,x10,x12 ; add x16,x15,x13 # C1=x12, C2=x13 hoisted; mul+add not madd
    mov x10,x16                       # home copy (residual)
    mul x15,x10,x10 ; add x16,x10,x15 # x + x*x
    mov x10,x16 ; add x15,x11,x14 ; mov x11,x15 ; b loop

kernel B (4 independent LCG lanes) direct loop: multiplier C hoisted to x15,
    addends hoisted to x16/x17/x19/x20; per lane `mul; add; mov` (not madd+coalesce).
```

| 1 | Rows A/B are at the shared multiply lower bound; the residual (madd fusion + 3 home-copy coalesces + down-count IV) is real but **not time-observable** — it retires in the multiply shadow, which is why the 12-vs-4 instruction gap is 0% wall-clock. |
| 2 | It may surface as energy (PMU unmeasured) or on a front-end-bound kernel; only then does it become a named time-debt. |

| # | directive |
|---|---|
| 1 | **The one genuine loss is kernel C, and it is NOT a peephole.** Every accumulator is affine (`final = init + N·stride`), so the program's sole observation (a compile-time-constant exit code) is closed-form in **O(1)**. clang's scalar evolution recognizes the affine induction, closes the loop, and emits the constant (inner loop has zero adds → 0.00 s). |
| 2 | The direct backend runs all 4e8 iterations. |
| 3 | This debt is a **semantic-graph / demand transformation** (recognize affine induction, demand only the closed-form result), on the ALGORITHM axis of §107 — not `madd`/copy. |
| 4 | Critically it does **not** apply to A/B: their recurrence is nonlinear and i64-wrapping, so *no* backend can close them, which is exactly why A/B are at parity and C is not. |

| # | directive |

| 1 | Corrected worklist sequencing (largest real debt first): |

1. **Affine scalar evolution / closed-form loop elimination** (kernel C, the only
   open loss; graph/demand layer; O(1) lower bound; oracle-gated).
2. **`madd` fusion** — DNIR is already expressive: `native_ir.Instr` carries a
   spare `third` operand; add BinOpTag `muladd`/`mulsub`, `emitMaddReg`

   front-end-bound or energy measurement justifying it.
3. **Copy coalescing** — compute a binop result into the local's home register
   instead of a fresh scratch + `mov`. Same non-observability caveat.
