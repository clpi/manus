# GAP-141 - generated runtime reserves a different temporary path than it uses

**Status:** OPEN · **Filed:** !2026-08-10 · **Priority:** P0 · **Kind:** security

## Observed defect

`src/codegen.zig` emits `duo_make_temp_path`, which calls `mkstemp` for
`/tmp/duo_ldXXXXXX`, closes and unlinks that file, then appends the requested
suffix. The returned `.err`, dynamic-library, or `.lua` path was never created
atomically. A local process can occupy or redirect that final path before the
generated runtime writes or invokes it.

The defect remains in current `main` at the filing point. Unmerged commit
`d6a1995` identified the same failure and switched the final path to
`mkstemps`, but its June branch predates the current constitution and must not
be merged wholesale.

## Required repair

Reserve the exact suffixed path atomically and retain ownership until its
consumer opens it. The bootstrap compatibility runtime may use the smallest
local `mkstemps` bridge, including a fail-closed WASI projection, only while
the generated C runtime owns this behavior. The deletion trigger is the Idsem
world-backed artifact/process realization replacing `duo_make_temp_path`.

Do not introduce a public `std.script`, filesystem, process, or temporary-path
relation to hide the bridge. Namespace reachability grants no authority.

## Acceptance

1. A positive control demonstrates that the current helper reserves only the
   unsuffixed path and leaves the returned suffixed path absent.
2. The repaired helper atomically creates the exact returned path.
3. Error capture, dynamic-library emission, and source loading still work.
4. WASI fails closed rather than returning an unreserved path.
5. The test consumes a private per-run directory and cannot overwrite another
   session's evidence.

## Current partial repair

On current `27e3d24` plus the owned `src/codegen.zig` worktree change:

- POSIX emitted C calls `mkstemps` on the exact suffixed path and retains the
  file until its consumer opens it;
- Windows uses `_mktemp_s` only to choose a candidate, restores the suffix, and
  atomically reserves that exact path with `O_CREAT | O_EXCL`;
- WASI's physical bridge returns failure for `mkstemps`;
- the generated application no longer mistakes its own executable for the
  compiler, which previously recursed through `compile --load-chunk` and
  crashed;
- an isolated current-tree compiler built successfully; its dynamic-source
  control printed `function` and exited 0; its emitted C compiled for
  `aarch64-macos`, `x86_64-windows-gnu`, and `wasm32-wasi`.

The focused Zig unit gate passes and pins the emitted helper shape. This gap
remains OPEN because that persistent control is structural rather than an
executed helper test, and the production helper still uses the shared `/tmp`
directory rather than proving the private per-run-directory requirement above.
Do not merge the old Jules branch: its direct `mkstemps` call does not compile
for the Windows target and it changes the pinned CI toolchain to `master`.
