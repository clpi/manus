# GAP-187 — relation mode and solution cardinality

**Status:** OPEN · **Filed:** !2026-08-18T16:10:00Z
**Priority:** P0 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/sema.zig, src/dnir_lower.zig, src/semantic_graph.zig

A relation is not only `subject × operands → result pack`. It has slots with
admissible directional modes, a solution cardinality law, and a failure/divergence
law. This absorbs Icon generators, Mercury determinism, optional results,
iterators, search, pattern matching, parser ambiguity, database queries,
constraints, logic relations and exceptions as one algebra.

## Current measured boundary

Application is modeled as a function-like call producing one result. `hex(b)`
versus `b:hex()` already reveals slot roles are under-determined by semantics.
There is no canonical mode/cardinailty fact family.

**Crossed:**

- `pack`, `cardinality`, `effect` and `demand` exist as graph facts.
- `law.application` and `law.relation` are specified in C0.

**Still missing:**

- `mode` per slot: `input`, `output`, `unique`, `unknown`.
- `solution` per relation: `exactly one`, `zero or one`, `one or more`,
  `zero or more`, `never returns`, `divergent`.
- `failure` law: `succeeds`, `fails`, `throws`, `blocks`.
- Demand can select `first`, `one`, `all`, `any`, `count`, `exists`.
- Reordering of goals/producers based on mode/dataflow.
- `b:hex()` and `hex(b)` converge to one relation with two admissible faces.

## Required order

1. Add `mode` and `solution` as graph facts on every relation declaration.
2. Make surface orientation (subject/operand) a provenance face, not a semantic
   authority.
3. Implement solution/demand interaction: `:first` stops at one, `:all` collects,
   `:has` checks existence, `:count` returns cardinality.
4. Derive generator/iterator/optional/search/parser/query from the same algebra.
5. Reorder applications by producer-consumer dataflow.

## Closure acceptance

Close when `hex(b)` and `b:hex()` are one relation with two admissible modes,
when `x:hex(b)` is rejected by mode arity, and when `users:find(.age > 18):first`,
`:all`, `:has`, and `:count` choose different realizations.
