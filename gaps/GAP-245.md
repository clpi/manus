## The defect, stated as one question with two answers

`dnir_lower.absentModulePlace` admits the module-place fold with exactly one
guard:

    if (place.residencyRefusal(p) != .none) return null;

`residencyRefusal` decides five PLACE facts — shape and value, mutation and
rebind, alias, escape, determinacy. Physical nonexistence is a REALIZATION
FREEDOM (`law.md` §104, `law.observation.minimum`), and the gate on a freedom is
`observation.permits(report, freedom)`, whose one gating class for `.existence`
is `allocation_identity`. Those are not the same question. A place can be
unwritten, unaliased, non-escaping and exactly determined while nothing has
proved that no demanded observer distinguishes it existing from it not
existing.

GAP-170's floor named this consumer, by name, and left it open:

> **WHAT THIS DOES NOT CLOSE.** Deletion condition 2 stands open … **no backend
> consults `permits`** … `dnir_lower.placeFold` already takes the `existence`
> freedom, and it takes it from `place.residencyRefusal` alone. That refusal
> never asks whether allocation identity is observed; it is fail-closed today
> only because a captured identity happens to drive `escape` to `unknown`
> through a different producer.

"Fail-closed because a different producer is conservative" is the shape
`gate/callfold.sh` already convicted for the two arms it deleted: *a guard that
permits a wrong answer and relies on someone upstream to never ask is fail-open
with a witness.*

## The witness, run rather than argued

Two programs, identical in every place fact the census publishes:

    t = { 10, 20, 30 }              t = { 10, 20, 30 }
    main: i64 = ()                  step: i64 = (x: i64)
        t[2]                            x + 1
                                    main: i64 = ()
                                        step(1)
                                        t[2]

`idol graph` on both publishes `escape:"no"`, `mutation:"no"`,
`immutability:"yes"`, `alias:"no"`, `determinacy:"exact"` for `t`. The five
place clauses answer `none` for both. The observation walk cannot prove `step`
boundary-local, so `allocation_identity` reads `unknown`, and the right-hand
program's existence freedom is **not** the compiler's to take. Before this
lane, the fold answered its `t[2]` as an immediate on evidence nobody had.

Reproduce:

    sh gate/place/existence.sh

## The seat

One producer, one census, one consumer, and the ruling travels on the row:

- `observation.analyzeScoped(…, .module)` — the same walk `analyze` already
  performs, over the MODULE census rather than the first relation's. Census
  region and walk region are then the same module, which is why the
  `relations > 1` refusal belongs to `.relation` scope and not to this one.
- `observation.ruledModuleCensus` — classifies each row and stamps
  `permits(&report, .existence)`. Ownership of the census transfers to the
  caller, because a ruling stamped from one census onto a different one is the
  two-producer defect this closes.
- `SemanticGraph.liftPlaces` — the one write site. The census and its ruling
  arrive together or not at all.
- `place.Place.existence` — the carried fact. Default `unasked`, which refuses.
- `place.residencyRefusal` — the clause, LAST, so every existing refusal keeps
  the reason it already published and a reader can tell a place fact from an
  observation ruling.
- `idol graph` v18 — `places[]` rows carry `existence`, so the whole six-clause
  decision is reproducible from an export. A v17 export answers a v18 question
  with a missing key, which is a reader told nothing rather than agreement.

`dnir_lower.zig` is unedited. The transfer reaches the fold through the guard it
already calls.

## What this costs, stated rather than hidden

An ordinary applied relation the walk does not recognize withdraws the freedom
for every module place. That is `unknown` read as `unknown`, and it is the
direction the law requires — but it is narrower than "any module collection
nothing writes". Widening it is a job for the walk's boundary recognizer, not
for the gate: a name wrongly recognized as boundary-local costs correctness,
while a name wrongly unrecognized costs a fold.

The storage decision is unaffected in the failing direction:
`dnir_lower.moduleBindingIsAbsentAggregate` admits on `residencyRefusal == .none`
OR `moduleConstTableKindGraph != null`, and a positional literal table still
takes the second route, so a refused existence ruling does not hand a table
literal a `__DATA` word it cannot initialize.
