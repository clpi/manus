| section |
|---|---|
| Why the mirror method exists, and what replaces it |

| # | directive |
|---|---|
| 1 | Mirrors exist to keep a measurement off the shared working tree, which here routinely carries several lanes' uncommitted work. |
| 2 | That requirement is real and is not in question. |

| # | directive |
|---|---|
| 1 | `git clone <repo> <mirror>` satisfies it identically — untracked files and caches do not come along, so cache cross-contamination is still prevented — while producing a tree with a real `.git`. |
| 2 | Verified: distinct binary hashes across archive-Debug, clone-Debug and clone-ReleaseFast builds, so no stale cache is shared. |
