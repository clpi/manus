# GAP-220 — `git archive` mirrors silently disarm 44 gates

**Priority:** P1 · **Kind:** evidence_gap

## Status
acceptance clauses 1 and 2 LANDED and controlled; clause 3 resolved by
measurement. See "Repair" below. The remaining open item is that `git archive`
still appears in agent instructions.

Originally filed: open — systemic. This invalidates an unknown fraction of every "gate passed"
claim made from a mirror, which is how essentially all agent measurement in
this repository is performed.

## The finding

The standard isolation method here is `git archive HEAD | tar -x -C mirror`.
That produces a tree with **no `.git`**. In such a tree:

    $ git ls-files
    fatal: not a git repository ...
    $ git ls-files | wc -l
    0

**44 files under `gate/`, `scripts/`, `tools/` and `.githooks/` enumerate
their subjects with `git ls-files`.** Exactly one of them (`gate/path.id`)
carries anything resembling a non-git guard. In a mirror the rest examine
ZERO SUBJECTS and report clean.

`law` already rules on this: a gate examining zero subjects must FAIL
(GAP-201). These do not fail; they pass.

## Measured instances

`scripts/public_safety_scan.id` is the proven case. Its body is
`git ls-files | xargs grep`. In an archive mirror it finds nothing and reads
as "no personal paths present". In a real checkout at the same commit it was
RED on two comments. So the mirror method concealed a live failure.

Measured on the same commit, `zig build test`:

    git archive mirror   14/28 steps, 12 failed, tests 1695/1/1696
    clean git clone      16/28 steps, 10 failed, tests 1697/1697

The mirror OVER-reported by two (`.githooks/pre-commit source-zero` and
`tools/node/dev/mcp-gate` both exit 128, "not a git repository") and
UNDER-reported by one (`public_safety_scan` passing vacuously). Two real
failures — `gate/defaults.sh` and `public_safety_scan` — are visible only in
a real checkout.

## The unit baseline everyone quotes is also an artifact

`zig build unit-test` is **1696/1696, exit 0** in a clean checkout. The
widely-quoted "1695 pass / 1 fail / 1696" is the mirror result: the single
failure is `git_preservation: buildPreservationReport runs read-only git and
frees cleanly`, which asserts `report.git_available` and whose own source
comment says "In this repo HEAD is always resolvable."

That figure has been carried through many reports in this session as a known
environment-sensitive failure. It is better described as a MEASUREMENT
ARTIFACT OF THE MIRROR, and its presence in a report is a reliable signal
that the report was taken in a non-git tree — and therefore that any
`git ls-files`-based gate in the same run was vacuous.

## Why the mirror method exists, and what replaces it

Mirrors exist to keep a measurement off the shared working tree, which here
routinely carries several lanes' uncommitted work. That requirement is real
and is not in question.

`git clone <repo> <mirror>` satisfies it identically — untracked files and
caches do not come along, so cache cross-contamination is still prevented —
while producing a tree with a real `.git`. Verified: distinct binary hashes
across archive-Debug, clone-Debug and clone-ReleaseFast builds, so no stale
cache is shared.

## Acceptance

1. `git clone` replaces `git archive` in agent instructions and in any gate
   or tool that builds a mirror.
2. Every subject enumerator asserts a non-empty subject set and FAILS when it
   is empty, per GAP-201. A shared helper is preferable to 44 open-coded
   checks.
3. `git_preservation` either passes in every supported measurement
   environment or is recorded as an exact expected failure with an identity,
   a reason, and an expiry — not carried indefinitely as "known".

## Repair

### `gate/subject.sh` — one owner for both rulings

    sh gate/subject.sh [pathspec...]        enumerate; ZERO is a FAILURE
    sh gate/subject.sh --any [pathspec...]  enumerate; empty is a lawful answer
    sh gate/subject.sh --tree               assert a real git work tree
    sh gate/subject.sh --selftest           both-direction controls

Exit 3 means the enumeration is not trustworthy; exit 1 is left to the calling
gate's own findings, so a reader can tell "ran and found something" from "never
ran". `--any` exists because a MEMBERSHIP PROBE — `is this forbidden artifact
tracked?` — has "no" as its lawful answer, and imposing a zero-subject failure
on it would be wrong; those callers keep the tree ruling and drop the count
ruling.

`--selftest` builds a scratch repository and runs twelve cases: lawful
pathspec, whole-tree, a zero-subject pathspec in a perfectly healthy tree, the
`--any` waiver, the bare tree assertion, then the SAME cases in a
`git archive | tar -x` mirror of that repository (all red, including `--tree`),
then in a `git clone` of it (green again). It refuses to certify itself in a
mirror it cannot prove is a mirror.

### A pipe destroys the helper's status, and that is the caller's problem

    sh gate/subject.sh '*.id' | xargs grep -c ... | awk ...

reports awk's status. Exiting 3 changes nothing about that pipeline's verdict;
the count simply comes out zero and reads clean. So a caller that consumes the
enumeration THROUGH A PIPE also asserts it separately, in one line, in the one
position where a status survives:

    if cap("sh gate/subject.sh '*.id' >/dev/null 2>&1; echo $?") != "0"

The ruling still lives in one file. Only the question is asked locally.
