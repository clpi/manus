| section |
|---|---|
| What landed |

| # | directive |
|---|---|
| 1 | `Node.scope` is the scope fact; `addChild(parent, node)` writes it and the `.contains` edge together, so the edge is a projection and the two cannot disagree. Twelve hand-written `addNode` + `addEdge(.contains)` pairs collapsed. |
| 2 | `stablePath` walks that chain: a parameter `n` of `scale` is `scale.n`. Module scope is skipped because `module_path` is already hashed separately, so no module-level identity changed. |
| 3 | `id_index` keys `StableId.hash → NodeId`. This is what a name-keyed index could not be — the earlier `name_index` was deleted (98bc13c) precisely because duplicate names panicked it, which is what forced `findByName` to a linear scan. `addNode` is its only writer; it is derivative of `nodes`, never an owner. |
| 4 | `findId(kind, path)` and `findFunc(name)` are O(1) and kind-exact. `findTableShape` / `findEnumShape` route through them — they used to fetch the first same-named node and return null if its kind was wrong, so a param called `Point` hid the shape called `Point`. |
| 5 | `scopedBindingName` is deleted. It spelled `func::binding` into the NAME to carry a scope; four sites then recovered the scope by searching the name for `"::"`. They ask `atModuleScope(node)` now. |
| 6 | `codegen.func_scope_base` marks where the current function body starts in `local_scopes`, so `is_func_local_name` can tell a function-body local (C local storage) from a module-top-level `local` (`duo_g_*` storage). That distinction is what previously limited shadowing to parameters alone (`is_param_name`, gap[027]) — the general rung is now in place. |
