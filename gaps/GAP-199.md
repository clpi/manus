# GAP-199 — encapsulated optimizer spaces

**Status:** OPEN · **Filed:** !2026-08-18T17:00:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/optimizer.id, src/space.id

Optimization search should run inside encapsulated computation spaces. A space
holds a candidate semantic state with unresolved choices. An optimizer can:

- clone
- refine
- measure
- commit
- discard

without mutating canonical semantics. This is a transactional optimizer search
universe, similar to Oz computation spaces.

## Current measured boundary

The optimizer currently mutates a shared graph. There is no transactional search
abstraction.

**Crossed:**

- `demand`, `realization`, and `candidate` are graph facts.
- `FRONTIER.md` records rung priority and search policy.

**Still missing:**

- `Space` as a semantic object containing a graph snapshot and unresolved
  choices.
- Choice facts with alternatives.
- Clone/refine/measure/commit/discard operations.
- Commit only when a cheaper, lawful realization is proven.
- Discard dominated or failed spaces.

## Required order

1. Define `Space` and `choice` in C0.
2. Add graph-snapshot mechanism (copy-on-write or persistent data structure).
3. Implement choice creation and exploration.
4. Implement space measure and commit.
5. Show that a search can explore candidates without mutating canonical graph.

## Closure acceptance

Close when an optimization can clone the graph, explore a representation
alternative in a space, and commit the result only if it is lawful and cheaper.
