# GAP-241 — `p:len()` on a pack answers 0 while `p.len` answers 3

**Status:** OPEN · **Filed:** !2026-09-06T06:30:00Z
**Priority:** P1 · **Kind:** correctness_gap
**Filed by:** named-claude-oracle-20260906T061533
**Files:** src/dnir_lower.zig, lib/table.id, examples/text/brace/hole.id

## The defect

One fact, two faces, two answers, at exit 0, on both realizations that execute
on this host. The canonical subject-first face is the wrong one.

    main: i64 = ()
        p = {10, 20, 30}
        a = p:len()
        print("{a}")
        0

| subject | `--backend=c` | `--backend=wasm` |
| --- | --- | --- |
| `p = {10, 20, 30}` ; `p:len()` | **0** | **0** |
| `p = {9}` ; `p:len()` | **0** | **0** |
| `p = { a = 1, b = 2 }` ; `p:len()` | refused `operation-not-in-c99-slice` | **0** |
| `p = {10, 20, 30}` ; `p.len` | 3 | 3 |
| `p = {10, 20, 30}` ; `p[2]` | 20 | 20 |
| `s = "abc"` ; `s:len()` | 3 | 3 |

The last three rows are the controls. `p[2]` answering 20 says the pack holds
the three members as written, so the 0 is not an empty pack. `p.len` answering
3 says the length is already a fact the compiler holds. `s:len()` answering 3
says `:len()` is not blind — it is right on text and wrong on a pack.

## The producer

`src/dnir_lower.zig:12736` — the `len` arm of the method-call lowering emits
`str_len` against whatever `lowerExpr` returned for the subject, with no
question asked about which descriptor that subject has:

    if (std.mem.eql(u8, mc.method, "len") and mc.args.len == 0) {
        ...
        try ctx.emit(.{ .op = .str_len, .result = t, .lhs = base });

`str_len` is a scan to the first NUL in both realizations. Run against a pack
slot it finds one immediately, which is where the 0 comes from and why both
backends agree on it — the wrongness is upstream of either.

Two places in the same file already hold the missing fact:

* `src/dnir_lower.zig:8193`, in the descriptor answer, states the rule this arm
  does not apply — *"The subject still must be text: `:len` on a table is a
  different relation owned elsewhere."*
* `src/dnir_lower.zig:13882`, `exprIsIntegral`, guards the identical method
  name with `exprIsStr(ctx, mc.obj)`.
* `staticTableLen` / `ctx.table_lens` (`src/dnir_lower.zig:9386` onward) already
  bind the length of a positional pack, and are what `p.len` reads to answer 3.

So this is not a missing capability. It is one arm of one dispatch that does
not consult a subject fact its own file computes, records and uses elsewhere —
`law.fact.producer.one`, and the same shape GAP-207 convicted for the byte
face: a face the arm does not name is admitted by default and answered wrong.

## Blast radius, measured not assumed

`lib/table.id:3` declares `len` over a table and its own append idiom is
`out[out:len() + 1] = k` (lines 11, 18). That idiom does **not** reach the
wrong answer today — it is refused before lowering:

    out = {}
    out[out:len() + 1] = 10        -> refused, graph-dnir-unsupported (both)

`p = {}` ; `p:len()` is refused too (`call_extern/extern:duo_hash_new`). The
reachable shape is the one at the top: a positional pack literal bound to a
name, `:len()` read into a value. That is what the corpus should not be able
to write again without a red row.

## The oracle that found it

`examples/text/brace/hole.id` declared `pack=3` for `{1, 2, 3}:len()` and no
realization ever produced it — the file was refused whole at
`binop-not-lowered:concat`, so its declared answer had never been compared.
The file now measures `p.len` (3) and `p[2]` (20) and names this gap for the
face that does not answer. It does **not** pin 0.

## Repair

Guard the `len` arm on the subject descriptor: text keeps `str_len`; a pack
answers from `table_lens`/`staticTableLen`, which is what `p.len` already does;
anything else refuses by name rather than falling through to a NUL scan. The
refusal must be named — an unnamed exit is the outcome `gate/byte/face.sh`
already refuses to call a refusal.

`src/dnir_lower.zig` was claimed by `claude-GAP-207-20260906T030713` when this
was filed, so no compiler code moved in the filing land.
