# GAP-082 — the conversion algebra has a semantic expansion ratio of 1

**Status:** MECHANISM LANDED, SCOPE OPEN · **Filed:** 2026-08-08 ·
**Measured again:** 2026-08-08
**Law:** Pass 100 §8 (relations, the trie, the algebra) · Pass 121 §9 (`to` is
the archetypal orientation fixture) · A3 ONE EDGE · A5 WITNESS
**Claim under test:** SER — semantic expansion ratio, *derived relationships per
authored relationship*. The design target for conversions is ~10,000x.

## The measurement

The compression thesis for conversions is that N descriptors need N primitive
canonical edges plus a small algebra, rather than N(N-1) pairwise conversions.
At 10,000 descriptors that is 10,002 authored facts standing in for 99,990,000
derived edges — **SER ≈ 9,997**.

Measured over tracked `.id`, 2026-08-08:

| | count |
|---|---:|
| `to(x)(y)` call sites | 1647 |
| **declared conversion edges** — `to(str)(u32) = digits` | **0** |
| distinct destination descriptors | **6** |
| `lib/std/relation.id` / `algebra.id` | **do not exist** |

**Zero.** The declaration face that the entire algebra rests on — Pass 121 §9's
own canonical example, `to(str)(u32) = digits` — appears nowhere in the tree.

The six destinations are the whole conversion universe:

```
1472  to(str)      175  to(i64)      37  to(f64)
   2  to(target)     1  to(int)       1  to(hex)
```

And `to` is not a relation at all. It is **hardcoded in the compiler** —
`src/codegen.zig` matches the literal string `"to"` at four sites (1898, 1916,
4871, 15944) and lowers it directly.

## Therefore SER = 1

Authored: 0 edges. Derived: 0 edges. Every one of the 1647 sites is a builtin
call, resolved by string comparison against `"to"` in the code generator. There
is no trie to enumerate, no algebra to compose, no primitive edge to derive
from, and nothing that could compose `a:to(canon)` with `canon:to(b)` to reach
`a:to(b)`.

**The architecture that would deliver 9,997x is not partially built. It is
absent, and a string comparison stands where it should be.**

This is the honest baseline, and it is worth more than the target: the target is
a hypothesis about an ecosystem that does not exist yet, while this is the
number the tree can be held to today.

## What that does NOT mean

It does not mean the thesis is wrong. It means the thesis is **untested**, and
that the first real test is small: two descriptors, one canonical edge each, and
one composition law that derives the pair conversion neither declared. If SER
moves from 1 to 2 on that fixture, the mechanism exists. If it cannot, the
mechanism is the gap and the 10,000x number is a projection of a projection.

Note the sharper reading of the six destinations: a corpus with 1647 conversions
over **six** destinations does not yet exercise an algebra at all. Even a
perfect implementation would show SER ≈ 1 here, because 6 descriptors admit only
30 pairwise conversions and 6 primitive edges — SER 5, not 9,997. **The ratio is
a function of ecosystem size, so publishing it requires publishing N.** A
headline SER computed on this corpus would be dishonest in either direction.

## Fix, in order

1. **`to` becomes a relation** with a declaration face, so `to(str)(u32) =
   digits` parses, lands in the trie, and is enumerable (`for src, conv in
   to[str]` — Pass 100 §8 writes this and it does not work today).
2. **One composition law**, witnessed: `a:to(canon)` ∘ `canon:to(b)` derives
   `a:to(b)`. A5 makes the witness mandatory, and this is the fixture that moves
   SER off 1.
3. **Conversion CLASSES as facts on the edge**, not separate systems: exact,
   lossless, checked, narrowing, view, consuming. Derived conversions must never
   silently compose into a lossy one — that is the failure mode that makes an
   algebra dangerous rather than merely absent.
4. **Retire the four `"to"` string comparisons in `codegen.zig`** once the trie
   answers. Until then they are `law.host.projection` debt and should carry the
   annotation: `projects = to`, `authority = false`, deletion gate = this gap.
5. **Publish SER with its N.** A ratio without its universe is not a
   measurement.

## MEASURED AGAIN 2026-08-08 — the mechanism exists; SER moved 1 -> 2

The smallest experiment that settles the biggest claim was run. It settles it in
the AFFIRMATIVE, and the honest reading is narrow.

| | before | after |
|---|---:|---:|
| declared conversion edges | 0 | declarable, and declared in a fixture |
| `to(str)(u32) = digits` parses AND lands | no | **yes** |
| `for src, conv in to[str]` enumerates | no | **yes** |
| a conversion nobody declared | impossible | **derived, witnessed** |
| SER on the fixture (N = 4) | 1.00 | **2.00** |

`examples/conversion/relation.id` declares 6 edges over 4 descriptors — `micron`
as canonical hub, `inch`/`milli`/`foot` as spokes — and the 6 spoke-to-spoke
conversions are answered by composition through the hub. **authored 6, derived
6, refused 0, N 4, SER 2.00**, and the fixture prints 189, which no degenerate
answer prints. The measurement is computed FROM THE TRIE (`DUO_SER=1`), not
declared, and it always prints its N.

**No new grammar** (A2 NNS-FIRST). `to(dest)(src) = conv` is an ordinary
assignment statement whose shape had no meaning; `conv@class` is the postfix
anchor, which already parsed to a field walk. The whole mechanism is a
recogniser plus `src/relation.zig`. Nothing was added to the surface.

### The baseline was worse than "absent" — it was a false green

`to(str)(u32) = digits` **passed `duo check`** and then died in the C backend on
`lua_to_str(tostring("u32")) = digits` — "expression is not assignable".
`to[str]` died on "use of undeclared identifier 'to'". A declaration face that
type-checks and cannot be lowered is the failure mode §3 MEASUREMENT HONESTY was
written about, and it is why the acceptance test had to be a RUN and not a check.

### The composition law, and what it refuses

`a:to(mid)` composed with `mid:to(b)` derives `a:to(b)`. One hop, deliberately:
a full transitive closure makes the answer depend on search order the moment two
paths exist, and G-TOTAL's ambiguity number is 0 — an ambiguous derivation is a
diagnostic, not a guess.

Classes ride on the edge (`exact` `lossless` `view` `checked` `narrowing`
`consuming`) and compose by MEET — a path is only as strong as its weakest hop.
**Silent derivation stops at `lossless`.** A route through a narrowing or
checked hop is FOUND, REPORTED with its weak hop named, and REFUSED:

```
error: no silent conversion inch -> milli: derived inch -> milli via micron:
stretch(inch) then shrivel(micron); class exact meet narrowing = narrowing;
REFUSED: silent composition stops at lossless
hint: declare the edge, or route the lossy hop by name
```

`examples/compile_fail/relation_lossy_compose.id` is the same six edges over
i64 instead of f64 — which makes each division narrowing — and it derives
**0 from 4 authored, with 2 refused**. That is the same law as the SER-2.00 row
and it is the more important half: an algebra that composes anything is not
safer than no algebra, it is more dangerous, because adding one descriptor could
quietly change an existing program's answer.

### Positive control

With `Relation.derive` short-circuited to `null` and nothing else changed, the
census reads `derived=0 ser=1.00` and the fixture **fails to compile** — the
three underived conversions fall through to a boxed table lookup on undeclared
identifiers. The fixture measures the composition law and nothing else.

### WHAT BLOCKS SCALING — the real finding, and it is not the algebra

**A user descriptor cannot be attached to a value.** `d: feet = 3.0` is rejected
by sema: *"variable 'd' declared as 'feet', but initializer has type 'f64'"* —
in both the `alias` and `type` spellings. So the trie can only be reached when
the call site SPELLS the source descriptor (`dest:from(src)(v)`, spec 2.6 gate
6), or when the source is a primitive.

This is the whole scaling story. The algebra composes; the descriptors have
nowhere to live. Until a nominal descriptor is a thing a binding can carry, the
canonical subject-first face `v:to(dest)` cannot resolve a user source, and
1647 call sites over six primitive destinations is the only universe there is.
**Nominal descriptors are the next gap, not more conversion machinery.**

Secondary, and smaller:

- **The refusal is a codegen veto, not a sema diagnostic.** `duo check` does not
  see it, so `examples/compile_fail/relation_lossy_compose.id` needed a
  compile-stage runner (`refuses` in `scripts/run_compile_fail_tests.id`). The
  class lattice belongs in sema. Until it moves, `duo check` is not authoritative
  about conversions — which is the same defect the baseline had.
- **One hop only.** `a -> b -> c -> d` is not derived. Longer paths need the
  ambiguity ruling first.
- **`lib/std` declares no edges.** The trie is empty for every real program in
  the tree, which is exactly why the four `codegen.zig` projections still stand.

### The four string comparisons: annotated, not removed

Per this gap's fix order they now carry, at each site:

```
law.host.projection { projects = to, authority = false }   -- gap[082] is the deletion gate
```

They survive because the primitive conversions are still taught to the code
generator by hand rather than written as edges in `lib/std`. The trie is
consulted FIRST (`emit_convert_edge_from`), so a declared edge already outranks
the projection — proven by the acceptance fixture, where `n:to(str)` on a `u32`
prints `<41>` and not `41`.

### SER, published with its N, and what it does not license

**SER 2.00 at N = 4.** That number is not evidence for 9,997. Six descriptors
admit 30 ordered pairs; a hub of k spokes authors 2k edges and derives k(k-1),
so SER is `1 + (k-1)/2` and reaching 9,997 needs k ≈ 20,000 descriptors that
share one canonical hub. What moved is not the ratio, it is the **category**:
derived conversions now exist at all, so 10,000x is a scaling question about
ecosystem size rather than a claim about a mechanism that was absent.
