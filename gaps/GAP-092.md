# GAP-092 — delimiter faces still survive as semantic call shape

**Status:** REOPENED 2026-08-10 · **Priority:** P0 · **Filed:** 2026-08-09

## 2026-08-10 delimiter closure correction

C0 now preserves useful source distinctions: parentheses are ordinary callable
application, braces are structured packs and descriptor application, and square
brackets are computed projection. These faces converge into shared application
and pack facts only after resolution. The former brace-call ruling below is
historical evidence, not current authority.

The implementation has not completed that correction:

- `src/ast.zig` still exposes `.braced` and `.parenless` as invocation forms;
- `src/parser.zig` still constructs ordinary call nodes from postfix braces and
  strings;
- `src/types.zig:CallShape.identityHash` includes the invocation form, so source
  punctuation changes semantic call-shape selection; and
- the closed `apply-one` gate proves the superseded brace-call behavior rather
  than the current delimiter law.

The source recognizer may retain brace, parenthesis, bracket, dot, colon, and
compatibility faces as syntax provenance. It may not turn them into relation,
subject, application, value, descriptor, demand, or realization identity.
Current closure requires all of the following:

1. ordinary call recognition accepts parentheses and rejects canonical postfix
   brace/string calls;
2. descriptor application retains structured-pack provenance without becoming
   an ordinary call category;
3. computed indexing remains projection/place syntax rather than callable
   application;
4. equivalent expected and explicit descriptor applications converge after
   resolution;
5. invocation punctuation contributes zero bits to semantic application or
   call-shape identity;
6. delimiter changes affect syntax provenance and diagnostics only; and
7. structured packs and computed projections introduce no allocation,
   materialization, boxing, or data-structure commitment without demand.

`src/ast.zig`, `src/parser.zig`, and the application producer are currently
claimed by the application-authority session. This gap is an integration
blocker for that claim: do not restore the historical closed status until the
production parser, resolver, formatter, and differential controls establish the
current law.

## What landed, and what it does not reach

c0 §43 gives the shared brace form three outcomes:

| subject | outcome | state 2026-08-09 |
|---|---|---|
| CALLABLE | ordinary application of a structured pack | **WORKS**, pinned by value |
| NEITHER | diagnostic, never a guess | **REFUSES**, wrong sentence |
| DESCRIPTOR | descriptor application, yields a value it describes | **OWED — this gap** |

The parser now emits ONE structural application node for every face and asks
nothing about what the subject denotes. That was the correct half to do first,
because gap[088]'s own closing section named it the root: *"The paren face
produces ONE application node. The brace face produces TWO disconnected
statements."* That statement was measured against `lib/compiler/parser.id`.
Measured against `src/parser.zig` the defect is different and worse in one
specific way, and it is the reason no downstream repair could have worked:

```
f{ x = 1 }        ->  call(f, [table{x=1}], form=parenless)
f({ x = 1 })      ->  call(f, [table{x=1}], form=parenthesized)  <- before: also parenless
```

**The two trees were byte-identical.** c0 §44a trap 2 is "braces as sugar", and
the tree had already applied that sugar and destroyed the evidence before sema
ran. No later consumer *could* have declined to allocate a table, because
nothing in the tree said a brace had ever been written in application position.
That is why the reverted codegen patch on gap[088] had to branch on
`record_aliases`: the fact it needed was gone, so it re-derived one.

## What is now in the tree for the resolving half to read

`src/ast.zig`:

- `InvocationForm.braced` — the brace face has a face of its own. It used to
  share `parenless` with the string face.
- `ast.Pack { applied, elided, home, realized }` on `Expr.table`, with
  `ast.Realization { undecided, table, fields }`.
- `TableLitField` **deleted** — a dead second spelling of `TableField.named`,
  declared with a doc-comment claiming sema used it, referenced nowhere.

The stances, which are stances of one form and not three mechanisms:

```
{ x = 1 }         anonymous structured value    applied=0 elided=0
point{ x = 1 }    the pack of an application    applied=1 elided=0
@{ x = 1 }        the same, subject elided      applied=1 elided=1  home=<descriptor>
```

`pack.realized` rests at `.undecided` and the parser may write nothing else —
`law.pack.shape` puts representation after semantic resolution, and a `{` in the
source is not a demand for a heap table.

Pinned by 9 unit tests in `src/parser.zig` (`apply-one: …`), by
`examples/apply_one_pack_proof.id` (values 3 4 7 7 9 1), by
`examples/compile_fail/apply_one_neither.id`, and by `zig build apply-one`.

## THE OWED WORK — three sites, all outside the parser

None is expressible in `src/parser.zig`. c0 §44 is explicit that the parser
"never resolves the edge", and `law.brace` holds at `.resolution`.

### 1 · `src/sema.zig` ~2758-2784 — the resolution, and the diagnostic

The neither-case refusal already lives here:

```zig
if (self.scope.lookup(callee) == null and
    !self.is_builtin_global(callee) and ...)
{
    self.err(c.func.name.loc, "call to undeclared function '{s}'", .{callee});
}
```

Two things are owed at this site.

**The resolution.** When `c.form == .braced` and the callee resolves to a record
descriptor, this is `apply(descriptor)(fieldpack)` — §44 `apply.edge` row 1 —
and the expression's type is the record, not the callee's return type. Today
sema falls through to `check_expr(c.func)`, gets the descriptor's type, does not
object, and codegen emits a call.

**The sentence.** `"call to undeclared function 'nosuch'"` is the right refusal
with the wrong words: it is the call path narrating its own unconditional win,
the exact framing §43 deletes, and it names one of the two homes the resolution
rule consults. Under APPLY-ONE the subject was looked for in descriptor space
AND callable space and found in neither. The text should say so, and the fixture
is pinned on the substring `nosuch` so it survives the rewording.

### 2 · `src/codegen.zig:15310` — the emission

`emit_expr`'s `.call` prong. When the resolved edge is descriptor application,
emit the compound literal instead of a call. The emitter already exists and is
already correct: `emit_record_initializer` (`src/codegen.zig:7776`) is what the
working typed binding uses at `codegen.zig:12188`, and it emits the designated
initializer body from a `.table`'s named and positional fields — exactly the
pack's own field list, in order.

**This is the ONE difference from the patch gap[088] reverted.** That patch
branched on `record_aliases` at the call site because the tree had no fact to
consult. This one reads `c.form == .braced` and `args[0].table.pack.applied`,
which the parser now states. Trap 1 is a consumer *deriving* the split; a
consumer *reading* a stated fact and selecting an edge is `law.brace` working.

### The table-allocation question, stated rather than claimed

`point{ x = 1, y = 2 }` **still allocates a table today.** Measured:

```c
lua_Value q = point(({
    lua_Value tmp = lua_table_new_with_capacity(0, 2);
    lua_table_set_raw_lit(tmp, "x", 4245442695, 1, lua_val_from_num((double)(3e0)));
    ...
```

The parser half removes the *reason it had to*: `pack.realized` is `.undecided`
and `pack.applied` is set, so the emitter is now free to choose fields over a
table. Nothing yet takes that freedom — `emit_expr`'s `.table` prong still
lowers every pack through `lua_table_new_with_capacity`. Setting
`pack.realized = .fields` at the site above and honouring it in the `.table`
prong is the ladder rung §44 `apply.ladder` calls scalar replacement.

### 3 · `src/pretty.zig:219` — the FORMATTER performs trap 2 on every round trip

Found by running `duo fmt` on the new fixture, which rewrote it in place:

```
first{ x = 7.0, y = 8.0 }     ->     first({ x = 7.0, y = 8.0 })
```

The `.call` printer writes `(` and `)` unconditionally:

```zig
.call => |x| {
    try self.printExpr(x.func, 0);
    try self.write("(");
```

So the canonical formatter is a **source-level implementation of "braces as
sugar"**: every `f{ … }` in the tree becomes `f({ … })` the moment anyone
formats the file. This is not new behaviour — but until this commit it was not
even a defect the printer could have avoided, because both faces recorded
`parenless` and the tree held nothing to distinguish them. It becomes fixable in
the same commit that makes it visible: the printer now has `x.form == .braced`
and `x.args[0].table.pack.applied` to read.

Two further things `fmt` did to the same file, noted because they are on §1's
deny list and a formatter is the last place they should be produced:

```
first(t: any): any    ->    fun first(t: any) -> any
point: @{ x: f64 }    ->    point: { x: f64 }
```

`fun` and `->` are both denied, and the compiler's own hint on the reformatted
output says so (*"'fun' is unnecessary here"*). Out of scope here; recorded
because the round trip is what surfaced it.

## FINDING, reported not repaired — `nn{ … }` is trap 1 in the arm APPLY-ONE fixes

`src/parser.zig:5842`:

```zig
if (e.* == .name and std.mem.eql(u8, e.name.ident, "nn")) {
    e = try self.parse_nn_block_desugar(tok.loc);
```

This is c0 §44a trap 1 verbatim — the parser asking what a name denotes to pick
a different production — sitting in the very arm this work repairs, and it is
worse than "is this a type" because it keys on one literal spelling. §3
MEASUREMENT HONESTY rule 1 forbids exactly this shape ("no recognizer may key on
a function name").

**Left standing, and measured rather than removed.** Real users: **one** —
`examples/ml_showcase.id:47`. The other six hits are prose, a comment in
`lib/ml/nn.id:74`, and two parser-proof rows about the *self-hosted*
parser. Deleting the hook changes what `ml_showcase` compiles to, and a
regression is not a fix. The repair is `std.ml.nn` accepting an ordinary applied
pack, at which point `nn{ … }` is `apply(callable)(argpack)` and the hook is
dead code.

## OTHER DUPLICATE SEMANTICS FOUND IN THE SAME AUDIT

Reported here because the owner asked for the inventory and because duplicate
construction paths grow back exactly where a dead one was left standing.

- **`ConstructorExpr` / `InitExpr` / `BraceCallExpr` / `RecordInit` /
  `DescInit` / `TableCtor` — ABSENT.** Repo-wide grep = 0. The AST never had two
  productions to collapse. The collision is that it has ONE and it is spelled
  `call`, which is why the fix is facts on that node and not a new node.
- **`AliasField` vs `RecordField`** (`ast.zig`) — two declaration-field shapes;
  `AliasField` is `RecordField` plus `is_private` and `default_val`. Not touched
  here: both are declaration-side and neither is on the application path.
- **Five brace readers in `src/parser.zig`**, now four produce a value through
  ONE of them: `parse_pack` (value stances), `parse_descriptor_table:3979`
  (declaration), `parse_table_destr_pattern:3817` (pattern),
  `parse_inline_caseset:662` (hoisted case-set), plus the `nn` hook above.
  `parse_table` is now a one-line call into `parse_pack` and the three value
  stances share a single reader.

## SEPARATE DEFECT, measured while writing the fixtures and NOT caused by this work

A module-scope typed record binding beside a `main()` mangles by one underscore:

```
point: @{ x: f64, y: f64 }
p: point = { x = 3.0, y = 4.0 }
main: void = ()
    print(p.x)
end
```

```
error: use of undeclared identifier 'duo_g__p'; did you mean 'duo_g_p'?
```

Reproduces with no brace face anywhere in the file, and with any module-scope
binding that is later assigned (it is why every runner in `scripts/` writes
`global`). Not filed separately because it is one symbol-mangling site, but it
is why `examples/apply_one_pack_proof.id` binds `p` inside `main`.

## Do not

Do not restore separate constructor and brace-call productions — §44 says a
repair that "fixes the collision" that way is a regression, not a fix. Do not
define `f{…}` as `f({…})`; that fixes the argument to one table before anything
is known, and it is the state this work just left. Do not branch on
`record_aliases` at the emit site to re-derive a fact the tree now states.
