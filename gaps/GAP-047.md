# GAP-047 — a method declaration disqualifies its whole module from native

| # | directive |
|---|---|
| 1 | **Filed** 2026-08-08. **Status** open. **Cost** 1 program today; the shape is canonical, so the cost grows as the corpus converges on Pass 100. |

## What

| # | directive |
|---|---|
| 1 | `native_scalar_precheck` refuses any module containing a function declaration whose path is more than one segment (`src/codegen.zig:3177`, `if (fd.path.len != 1) return nofit(@src())`). |
| 2 | A method declaration is exactly that: |

| # | directive |
|---|---|
| 1 | Person:greet = (other) "Hey " .. other -- path = { Person, greet } |

| # | directive |
|---|---|
| 1 | Isolated to one fact: a file containing only that line plus `main: i64 = () 0` bails at codegen.zig:3177. |
| 2 | Delete the line and the same file compiles natively. |

## Why it surfaced now

| # | directive |
|---|---|
| 1 | `examples/pass23_canonical_syntax.id` lowered natively earlier tonight and does not now — native coverage 90 -> 89. |
| 2 | The FILE is unchanged since a312382 and the RULE predates tonight, so neither moved. |

| # | directive |
|---|---|
| 1 | What moved is the PARSER. |
| 2 | That line previously did not reach the precheck as a `func_decl`; it does now. |
| 3 | So this is a parser becoming MORE correct and surfacing a native-subset limitation that was always there — not a regression to revert. |
| 4 | The honest number is 89. |

## Why it matters more than one program

| # | directive |
|---|---|
| 1 | Pass 100 §6 makes the receiver face the canonical call form, and §0 rule 4 puts construction on descriptors. |
| 2 | Method declarations are not a legacy shape the corpus is migrating away from; they are where it is migrating TO. |
| 3 | Every module that adopts one loses native lowering entirely — the precheck rejects the MODULE, not the function. |

## The repair

| # | directive |
|---|---|
| 1 | `fd.path.len != 1` is a proxy for "this is a method and the native subset has no receiver ABI". |
| 2 | The subset already lowers a receiver face at the CALL site — `faceAsCall` in dnir_lower normalizes `a:m(x)` to `m(a, x)` — so the missing half is the DECLARATION: bind `Person:greet = (other)` as a free function whose first parameter is the receiver, exactly the shape `faceAsCall` already emits against. |

| # | directive |
|---|---|
| 1 | That is the same normalize-at-the-lowering move that made `s[i]` and `string.char` work: give the backend one convention and translate at the edge. |
