# GAP-208 — record-argument lowering indexes a semantic operand array by a physical slot count

**Status:** OPEN · **Filed:** !2026-08-21T23:55:00Z
**Priority:** P0 · **Kind:** crash
**Filed by:** claude-gap145
**Files:** src/dnir_lower.zig

`src/dnir_lower.zig:7949`

```zig
if (!direct_gp) try stageCheckedScalarOperands(ctx, operands[0..staged.count], values[0..staged.count]);
```

`operands` is the **semantic** operand array — one entry per argument.
`staged.count` is the **physical** staged-slot count, which
`evaluateCheckedScalarOperands` inflates when a record operand expands into one
slot per field. Any call with a record argument of two or more resident fields
slices past the end.

## Reproduction — verified on `fd85e7b8`, default `zig build` (Debug)

```id
pt: { x: i64, y: i64 }
add: i64 = (a: pt, b: pt)
  return a.x + b.y
p: pt = { x = 1, y = 2 }
q: pt = { x = 10, y = 20 }
print(add(p, q))
```

## Exact rule, controlled both directions

`index` = sum of resident field slots across all operands.
`len` = number of semantic operands.
Panics **iff** some operand is a record with **two or more** resident fields.

| fixture | shape | `fd85e7b8` | `b64dc075` |
| --- | --- | --- | --- |
| two 2-field records | `add(p, q)` | `index 4, len 2` | `index 4, len 2` |
| record + i64 | `add(p, 3)` | `index 3, len 2` | `index 3, len 2` |
| one 2-field record | `add(p)` | `index 2, len 1` | `index 2, len 1` |
| **one 1-field record** | `id1(p)` | **ok, prints 7** | **ok, prints 7** |
| 3-field record | `s3(p)` | `index 3, len 1` | `index 3, len 1` |

No nested record, float field or mixed aggregate is needed — two fields is
enough. Brace and offside record construction behave identically. Subject face
(`p:add(q)`) and operation-first face (`add(p, q)`) behave identically, so it is
not a face bug. `idol compile` and `--target wasm32-wasi` are identical.
**`idol check` passes clean** — it never lowers, which is one way to miss this.

`direct_gp` requires `staged.count == 1`, and a record operand of N fields
forces `staged.count >= N`. So for any record of two or more fields `!direct_gp`
is true **by construction** and the overrun is unconditional.

## Optimize mode is the discriminator, not the program

| build | `cA` | `cD` | `cE` | `n1` | `n3` |
| --- | --- | --- | --- | --- | --- |
| Debug / ReleaseSafe | panic | panic | panic | ok 7 | panic |
| ReleaseFast | 21 | 4 | 3 | 7 | 6 |

`build.zig:100` names ReleaseFast as the vendored compiler artifact;
`b.standardOptimizeOption(.{})` defaults to Debug. A ReleaseFast `idol` does not
reproduce this, which is why it can be missed.

`operand_storage` is `[16]CheckedScalarOperand = undefined` and
`checkedScalarOperands` returns `storage[0..count]`, so indices past `count`
overrun the **slice** while staying inside the 16-element array — not a wild
pointer. `stageCheckedScalarOperands` reads only `.descriptor`, never
`.expression`, so nothing is dereferenced.

**Explicitly not claimed:** that safety-off miscompiles. The prediction that
undefined bytes would select the wrong register class was measured and did
**not** occur — every slot went GP, which is correct for `i64` fields, and the
ReleaseFast disassembly is correct (`p.x->x0, p.y->x1, q.x->x2, q.y->x3`,
`add` computes `x0 + x3`). Correct output from reading uninitialized memory is
an observed outcome, not a guarantee, and no wrong-codegen measurement exists.

## The tracked corpus contains the shape

`examples/native_record_params.id` has `alias_sum(p)` over a two-field record.
It is shadowed: line 1's `inline_y({ x = 3, y = 4 })` refuses first with DNB011
at `checkedScalarOperand()` (`dnir_lower.zig:7563`), so lowering stops before
reaching `:7949`. Delete that one call and the tracked example panics
`index 2, len 1`.

## The class, and why a bounds clamp is the wrong fix

No fact binds a physical argument slot back to the semantic operand it realizes,
so `:7949` reconstructs the operand for slot `i` by assuming `i` indexes
`operands` — and is wrong exactly when one operand realizes as several slots.

**Producer:** `evaluateCheckedScalarOperands` (`src/dnir_lower.zig`). It knows
the operand behind every slot it fills and returns only
`StagedOperands{count, floating}`.

The fix is **per-slot operand identity**, not a bounds clamp. Clamping to
`operands.len` would stage 2 of 4 values and turn a hard panic into a real
miscompile.
