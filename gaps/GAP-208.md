| Landed: per-slot operand identity, and the count is DELETED |

| # | directive |
|---|---|
| 1 | `StagedOperands{count, floating}` is replaced by `StagedSlot`, one per PHYSICAL slot: |

```zig
const StagedSlot = struct {
    operand: *const CheckedScalarOperand,  // which operand this slot realizes part of
    projection: []const u8,                // which field — EMPTY when the slot IS the operand
    descriptor: types.ResolvedType,        // what THIS SLOT carries, never the aggregate's
    value: dnir.Value,
};
```

| # | directive |
|---|---|
| 1 | `evaluateCheckedScalarOperands` returns `[]const StagedSlot`. `stageCheckedScalarOperands` takes only slots. **There is no longer a number a consumer could index the wrong array by** — the fix is the deletion of the count, not a bound on it. `floating` is deleted with it: consumer-zero under `law.md` §16, computed and never read. |

| # | directive |
|---|---|
| 1 | `direct_gp` is stated on the slot instead of on two counts agreeing: `slots.len == 1 and slots[0].projection.len == 0`. |
| 2 | Every operand contributes at least one slot or refuses, so `slots.len == 1` implies `operands.len == 1`; the pair `operands.len == 1 and staged.count == 1` was never carrying independent information. |

| # | directive |
|---|---|
| 1 | A record operand with an **f64 field** is now refused by name. `functionEligible` admits a record parameter by adding `r.fields.len` to `gp_slots`, so the callee homes every field out of x0..x7; staging a float field by its own descriptor would put it in v0 while the callee reads x1 — a wrong answer, not a refusal. |
| 2 | Nothing regresses: a mixed record has two or more fields by construction, so every such shape panicked before. |
