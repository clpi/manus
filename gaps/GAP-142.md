# GAP-142 - concurrent merge candidates lack one truthful admission boundary

**Status:** OPEN · **Filed:** !2026-08-10 · **Priority:** P0 · **Kind:** agent

## Observed defect

Current concurrent work contains useful changes, but the combined tree cannot
be admitted as one SHC advance. Three independent boundaries currently
contradict their evidence or ownership contract.

### Application ownership overclaim

The staged `GAP-137` wording says public machine-byte lineage is already owned
by `lib/compiler/application.duo`. That module explicitly says it preserves a
structural shape and does not observe identities. Its `application` descriptor
contains no instruction, byte-range, object, allocation, or transformation
projection. The unstaged wording correctly keeps public application-to-machine
lineage as a separate unowned requirement.

The staged wording must not merge. A schema is not production ownership, and
source-level application shape is not machine-byte lineage.

### Subject-authority integration collision

relations such as `observe(value)` or `observe(subject)` and invoke them through
a subject-call face. After Session 1 lands, those fixtures no longer prove the
subject-bearing checked path.

The combined merge must use an existing admitted descriptor-home subject
fixture for subject-bearing lineage and retain a separate subjectless ordinary
call fixture. No fallback subject inference may be added to make the tests pass.

### Value

The next in-flight checked-call expansion is not admissible in its observed
form. `appendCheckedRecordOperand` accepts a semantic argument only when its
source expression is a name, joins that binding spelling with each field
spelling, and queries `ctx.locals` for the resulting string. A value produced
by another application is then rejected because those host field locals do not
exist.

That rebuilds meaning from a source name instead of realizing a semantic value. It also
turns a structured value into a place merely because the earlier host lowerer
represented a local aggregate as separate field locals. More tests around the
bridge cannot make it authoritative.

The slice must instead consume graph-owned value projections or an explicit
realization slot map keyed by semantic value identity. Descriptor matching may
select a lawful layout, but binding and field spellings cannot identify its
physical values. If the graph does not yet expose those projections, this
structured-argument expansion is implementation blocked and must remain
unsupported rather than extending the text bridge.

### Subject

The in-flight application producer currently makes parse recognition supply
semantic subject authority. The parser creates a hidden `__duon_subject`
parameter for a descriptor-home relation and marks that parameter with the
subject role. Sema then reads the parser field as the resolved role.

The parser may retain the descriptor home and ambient invocation face as source
provenance. It may not decide the semantic subject or require a hidden source
binding to make that role exist. Sema and the graph must resolve the subject
from the admitted home and relation facts, then make the resolved value
available to the body without treating the synthetic spelling as identity.

The latest expansion deepens that ownership error. `ast.OperandRole` creates a
syntax-tree taxonomy for subject, level, operand, world, and demand; the parser
assigns `.subject`, and macro expansion copies the role. A bare ambient anchor
also falls back to a synthetic `"self"` name when no homed binding is present.
Those are semantic application roles, not parser or macro facts. Carrying them
farther through the host syntax tree does not make them authoritative.

The syntax projection may retain the descriptor home, declared parameter
shape, ambient face, and exact span. The semantic resolver must produce role
edges and the graph must own their identities. Macro expansion may preserve
syntax provenance, but it must neither copy nor invent semantic role facts.

The branch test claiming that subject role is independent of operand order
does not close this requirement: it mutates a parameter role directly in the
AST before Sema runs. That proves a consumer accepts an injected role, not that
production semantic authority creates it. The claim must remain partial until
an admitted producer supplies the role without parser ownership or test
mutation.

### Origin

The same producer currently admits `ApplicationConstant.nil` and publishes it
to graph constant facts without retaining the source language, origin, or law.
Native Duon does not admit bare `nil`; compatibility and foreign sources may
retain their own case only with exact provenance. The graph must either carry
that origin and law with the value or decline to publish it as a native
semantic constant.

### Pack

The application producer currently derives a two-slot result pack from the
parser field `ret_fallible`. Both slots cite the same application expression;
the second slot has no descriptor, label, constant, or independently resolved
failure value. The graph then mints two value incarnations from that fabricated
shape.

A syntax flag may preserve that a source face declared a failure alternative.
It cannot prove the cardinality, cases, correspondence, or values of the
semantic result pack. Native Duon requires a result union and an obligated
failure relation; an anonymous second slot is not that relation, and absence of
a descriptor is not a failure case.

The result pack must be projected from the resolved result descriptor and
failure semantics. Each produced value needs its own identity and case,
descriptor, position or label, provenance, and demand correspondence. Until
that producer exists, cardinality is unknown. It must not be guessed from
`ret_fallible`, tuple syntax, or return spelling.

### Realization

Commit `59d3e0e` removes symbol-first selection for the checked native slice,
but replaces it with one physical function per relation. The native validator
indexes functions by `function.semantic_identity`, rejects a second function
with the same relation as `function-identity-collision`, and selects linkage
from the application relation alone.

The application producer deliberately proves the opposite cardinality. Its
overload control gives the `i64` and `f64` implementations of `measure` one
relation identity, distinct selected target identities, and distinct result
descriptors. `applicationTarget` is already the graph projection of the exact
selected implementation. One relation may therefore have more than one lawful
target and realization.

The native map conflates semantic meaning with selected realization. It will
either refuse a valid second implementation or route an application to the
wrong linkage and ABI. A symbol map was not semantic authority, but a relation
map with one-value cardinality is not a valid replacement.

The checked path must carry and consume the selected target identity in
addition to relation, application, value, subject, operand, and descriptor
identity. Relation validates semantic meaning. Target selects a physical
implementation. Linkage and ABI are facts of that selected target. A link
symbol may validate the projection but may never select meaning or target.

The deletion gate is a graph-owned target projection carried through DNIR and
validated at machine emission. Two implementations sharing one relation must
remain distinct targets without a collision, and changing only their linkage
must preserve relation, application, and value lineage.

## Exact identity lookup

The active application producer correctly describes `StableId.hash` as a
collision-prone fingerprint, but its `id_index` still maps that fingerprint
directly to one `NodeId`. `findId` recomputes only the hash and returns the
indexed node without checking kind, scope-qualified path, generation, or any
other reversible identity material. `addNode` also keeps the first node on a
collision without reporting it.

That makes the API comment claiming an exact identity lookup false. A `NodeId`
is exact only after it has been selected by an exact join; wrapping a
hash-selected node in `NodeId` does not make the selection exact. Current shape
queries such as `findTableShape` and `findEnumShape` consume this path, and new
application descriptor publication may therefore inherit a wrong descriptor
node after a collision.

The hash may remain a lookup acceleration. The index must retain enough exact
material to verify the complete key before returning a node, or the producer
must use declaration-owned node joins where an exact declaration already
exists. A forced-collision control must prove that two distinct identities are
both retrievable or that publication fails closed; silently selecting the first
node is not admissible.

## Delimiter-derived identity

Current main still records `.braced` and `.parenless` invocation forms in the
AST, and `CallShape.identityHash` includes `invocation_form`. Under delimiter
closure, braces identify structured/descriptor source syntax and parentheses

The application producer owns the active parser/AST slice, so this is a merge

## Application identity root

The active producer correctly deletes `StableId`, `stable_id`, `id_index`, and
path/hash lookup from the graph. Its replacement then wraps every graph handle
in `SemanticIdentity { meaning, content, incarnation }`, where the first two
coordinates are usually unknown and the third contains the `NodeId`. That is a
second identity schema. Under the current root ruling, the graph entity is the
identity. Meaning, content, source continuity, and cross-snapshot
correspondence are facts or relations involving graph entities, not parallel
identity coordinates attached to each field.

The producer also lets a Sema `ApplicationCandidates` allocation survive
resolution as `fact.relation`. Candidate groups are initially indexed by source
name, the pointer is cast to an opaque relation witness, and graph
`RelationPlan` groups applications by that pointer to mint relation nodes.
Names are valid source-resolution input, but neither a source-name candidate
registry nor a host allocation address may become the resolved relation
identity. Sema must publish an admitted relation fact whose graph entity the
graph can retain directly; deleting the candidate allocation must not change
meaning.

This is independent of the valuable pack correspondence work in the same
branch. Pack slots, labels, positions, descriptors, constants, provenance, and
cardinality should remain graph facts while the parallel identity wrapper and
candidate-pointer witness are removed.

## Positive controls

- Changing only a checked call's callee spelling must fail before machine
  emission while its relation identity remains unchanged.
- Removing a subject edge from a subject-bearing application must fail; adding
  no subject to an admitted subjectless application must remain valid.
- A staged claim that `application.duo` owns machine bytes must fail review
  until an actual Duon projection can answer application to instruction and
  object byte ranges.
- The evidence-integrity patch must still prevent two concurrent runs from
  sharing scratch artifacts after all unrelated canonical rewrites are removed.
- A structured value produced by an application must remain eligible for the
  same checked call as an equivalent bound literal; changing its source binding
  spelling must not alter argument realization.
- Changing parser source-face metadata must not change a resolved subject role
  when the relation and home facts are unchanged. Removing the semantic role
  producer must fail closed rather than falling back to parser position.
- A compatibility `nil` value and any admitted native absence case must remain
  distinguishable after graph publication.
- Two implementations with one relation identity and different target
  identities must both link to the application that selected them. Removing
  target identity must fail closed rather than choosing by relation or symbol.
- A declared failure alternative with no resolved result case must leave pack
  cardinality unknown. Supplying resolved success and failure cases must create
  distinct value identities with preserved correspondence.
- Two deliberately colliding fingerprints with different exact identities must
  never resolve to the same node. The graph must preserve both or refuse the
  collision before publishing either as an exact relation, value, or
  descriptor identity.
- Destroying and recreating a graph at the same address must not make an old
  module, region or machine lineage valid against the new graph incarnation.
- Equivalent source faces that resolve to one relation, subject and operand
  pack must retain that semantic shape even when their delimiter provenance
  differs. Distinct occurrences still retain distinct application identities.
- Reallocating or deleting Sema candidate storage after resolution must not
  change relation identity. A graph lift that lacks the resolved relation fact
  must fail closed rather than grouping by candidate pointer or source name.

- postfix braces are still recognized as ordinary calls in the branch even
  though C0 now reserves braces for structured packs and descriptor

The latest worktree revision improves one part of this list: `CallShape` now
calls its derived hash a fingerprint, excludes invocation delimiter provenance
from that fingerprint, and verifies candidate equality with exact stored
facts. That is a valid collision-safe acceleration repair. It is not graph
identity closure:

- the exact comparison and fingerprint still contain callee and method source
  spellings, so host codegen specialization remains name-selected after
  resolution;
- codegen passes the fingerprint as both the input and output coordinates to
  `transform_engine.logProvenance`, whose public record contains only hashes;
  and
- no graph application, value, selected target, or transformation entity is
  retained by that log.

Calling the hash a fingerprint makes its physical role more honest, but a
fingerprint-only transform record is not semantic lineage. The deletion gate
is a graph-owned transformation projection carrying exact input application
and value entities, exact produced value or realization entities, and the
transformation entity. A fingerprint may accompany that projection for cache
lookup or integrity, but deleting every fingerprint must leave transformation
meaning and lineage unchanged.

The current producer must not widen into a parallel codegen provenance repair
to make its application claim pass. It may either leave this existing host
bridge explicitly classified and bounded, or consume an exact transformation
interface from the realization owner when that interface exists.

These are merge blockers, not follow-up style debt. A rebased producer must
prove relation selection survives deleting candidate storage, ambient subject
resolution survives without the hidden parser binding, and delimiter
provenance contributes zero bits to semantic identity.
