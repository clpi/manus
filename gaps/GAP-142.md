# GAP-142 - concurrent merge candidates lack one truthful admission boundary

**Status:** OPEN · **Filed:** !2026-08-10 · **Priority:** P0 · **Kind:** agent

## Observed defect

Current concurrent work contains useful changes, but the combined tree cannot
be admitted as one SHC advance. Three independent boundaries currently
contradict their evidence or ownership contract.

### Application ownership overclaim

The staged `GAP-137` wording says public machine-byte lineage is already owned
by `lib/compiler/application.duo`. That module explicitly says it preserves a
structural shape and does not observe identities. Its `application` descriptor
contains no instruction, byte-range, object, allocation, or transformation
projection. The unstaged wording correctly keeps public application-to-machine
lineage as a separate unowned requirement.

The staged wording must not merge. A schema is not production ownership, and
source-level application shape is not machine-byte lineage.

### Subject-authority integration collision

Session 1 correctly requires an admitted semantic subject role and refuses to
infer subject from parameter position, parameter spelling, or colon syntax.
Session 2 correctly consumes the graph subject without reconstructing it.
However, several in-flight Session 2 lineage fixtures still declare top-level
relations such as `observe(value)` or `observe(subject)` and invoke them through
a subject-call face. After Session 1 lands, those fixtures no longer prove the
subject-bearing checked path.

The combined merge must use an existing admitted descriptor-home subject
fixture for subject-bearing lineage and retain a separate subjectless ordinary
call fixture. No fallback subject inference may be added to make the tests pass.

The locked combined `zig build unit-test --summary all` run is currently red:
**1168/1175 passed, 7 failed**. Three failures are directly in the in-flight
checked-call expansion:

- `checked ordinary call reaches regions and machine lineage` passes
  `ordinary-object` to an API accepting only the real `native-object` or
  `native-mach-o` targets, so the claimed object-lineage proof never runs;
- `checked call result descriptor does not select argument ABI` is refused by
  `lowerModuleFromGraph`, so its intended ABI invariant is unproved;
- `discarded checked calls do not retain return registers` reports 28 branch
  instructions where the lineage helper requires exactly one, exposing
  overlapping or over-wide machine ranges for repeated calls.

These are merge blockers. A newly added test that fails before its asserted
boundary is not evidence, and a lineage range containing unrelated calls is
not exact machine provenance.

A later exact locked run against the current dirty tree reports **1171/1178
passed, 7 failed**. The count moved as concurrent tests were added, but the
admission result did not change. The ordinary and record lineage controls still
use target spellings the real object API rejects, and the descriptor/argument
control is still refused before its intended invariant. Physical target
validation also still begins with `instruction.callee` through
`functions_by_symbol`; therefore the checked slice has not yet eliminated name
selection at that boundary. The other four failures are the interpolation
index, register-spill, root-relation projection, and relation-family controls.
This exact result supersedes any current dirty-tree ledger claim of a passing
unit gate.

### Evidence-integrity change contains unrelated canonical migration

The claimed GAP-115 slice is private per-run evidence storage and provenance.
Its dirty diff also performs broad identifier and callable-face rewrites across
many gates and adds new `std.script` authority such as `runid`, `provenance`,
`fs_tmpdir`, `getenv`, `run`, `capture`, and `status` usage. The additions retain
namespace authority, sentinel absence, command concatenation, and historical
`end` forms. They are not justified by private temporary-directory ownership
and do not satisfy the current canonical Duon preflight.

The private-path repair is valuable, but it must be separated from the broad
canonical rewrite. No new public `std.script` vocabulary or use site may be
counted as Duon convergence. The deletion gate is a world-backed Duon
filesystem/process/environment realization, not a larger compatibility home.

The required exact-diff preflight was run across the claimed GAP-115 and LSP
files. `scripts/idiomgate.duo` reported **125 findings on added lines** with all
20 positive controls passing. Findings include `law.authority.home`,
`law.lua.hosted`, `law.subject.one`, output materialization, underscore-bearing
identities, and deleted `end`. The current diff therefore fails its own merge
gate independently of this review.

The separately synthesized diff for every untracked `.duo` candidate reports
**149 additional findings**, again with all 20 controls passing. These include
deleted block closure, underscore and uppercase identities, Lua `nil` and
`require`, capability homes, and output materialization. Untracked state is not
an exemption: each file must reach zero findings before it is staged as
canonical repository Duon.

## Unmerged branch admission

The following branches predate current C0 grammar or duplicate superseded
compiler architecture and must not be merged wholesale:

- `evalmerge` and `pass104-evaluator`: a large parser-projection evaluator with
  historical `end` syntax and a parallel evaluation model;
- `pass108-grammar`: an obsolete grammar authority plus independent
  conformance/fuzz tables;
- `gap083-mangle`: broad C-codegen ownership and historical script vocabulary;
- `gap065-for-effect`: useful differential cases mixed with old DNIR/codegen
  changes and historical harness vocabulary;
- `audit-ownership-ab5f51c`: a historical gap report plus a codegen patch;
- `native-runtime-globals` and `untyped-bails`: findings may be reconciled, but
  their old branch state is not merge authority.
- `claude/wasm-wasi-compat-perf-HhvNU`: useful Wast cases are mixed with a
  737-line host-codegen diff, 567 lines of new shell test drivers, broad
  distribution changes, Lua examples, and a tracked `zig-out/bin/duo` binary;
  this is the opposite of the current Duon-owned Wasm and compiler boundary;
- `claude/test-coverage-analysis-AYYVb`: its compile-fail runner repair is mixed
  with a historical shell implementation and broad host `main`/codegen edits.

Individual evidence or tests may be re-derived against current main and C0.
Branch existence is not evidence that its implementation remains admissible.

## Admission requirements

1. `GAP-137` must distinguish the Duon application schema from observed
   production graph facts and from machine/object lineage.
2. Session 1 and Session 2 must pass together with no parameter/name/colon
   subject inference and no callee-text semantic fallback.
3. Subject-bearing fixtures must obtain subject identity from admitted semantic
   authority; subjectless fixtures must preserve authoritative absence.
4. GAP-115 must land only its claimed evidence-integrity behavior or explicitly
   re-scope and pass current canonical gates on every touched Duon line.
5. Added canonical Duon must introduce zero `std.script` authority, sentinel
   absence, output concatenation plumbing, uppercase/underscore identifiers,
   or historical block ceremony.
6. Every stale branch must be re-derived as a bounded current-main patch. No
   wholesale merge is admissible.
7. The combined tree must run focused Session 1/2 tests followed by the locked
   unit gate. A green result from either branch in isolation is insufficient.

## Positive controls

- Changing only a checked call's callee spelling must fail before machine
  emission while its relation identity remains unchanged.
- Removing a subject edge from a subject-bearing application must fail; adding
  no subject to an admitted subjectless application must remain valid.
- A staged claim that `application.duo` owns machine bytes must fail review
  until an actual Duon projection can answer application to instruction and
  object byte ranges.
- The evidence-integrity patch must still prevent two concurrent runs from
  sharing scratch artifacts after all unrelated canonical rewrites are removed.

## Closure

Close only after the conflicting owners have landed together on current main,
the mixed GAP-115 diff has been split or repaired, and the stale branches are
either explicitly rejected or reduced to independently validated current-law
patches.
