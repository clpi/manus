# GAP-148 — value locations and fixed-frame register spilling

**Status:** OPEN · **Filed:** !2026-08-10T13:08:38Z
**Priority:** P0 · **Kind:** native_lowering_gap
**Filed by:** codex-root-continuation-20260810
**Files:** src/native_backend.zig, build.zig, docs/performance.md
**Migration fixtures to replace/delete:** examples/pass11_spill_proof.id, scripts/pass11_spill_smoke.id (deleted with the retired catalog apparatus)

The GP spiller keys state by physical register while DNIR values and local homes still point at that register. Reusing a spilled register therefore creates two owners and has a proven silent-miscompile history; the current guard correctly fails closed. Dynamic inline stack growth is also unsafe because existing record/table slots use fixed SP-relative offsets, and compiler spill state is not an authoritative value realization. WP-03 is false evidence: v1..v20 are unread, so its required STR/LDR canonizes storage that semantic demand does not require. Current bounded backend repair omits only unlineaged unread i64 immediate stores, proves exact assembly/object equality to the equivalent two-binding program, and retains a genuine 20-live-value RegisterExhausted control. Closure requires Idol to assign authoritative graph values to `register` or `frame` realization facts before emission, with CFG/backedge-aware liveness, a prologue-reserved frame, materialization returning the actual register, per-function state reset, value differentials under calls/branches/records, and replacement of the stale spill proof projections. Zig may project that assignment only as a bounded bootstrap bridge with an explicit deletion gate.

## The reclaim abandoned an owner and kept its records

Measured on `0365b107` plus this change, in

reloaded the value. That hazard is this gap's and is unchanged here. What the
drop did NOT do was clear the two OTHER records the abandoned owner held, and
each is a defect in the opposite direction — against the live value the reclaim
just handed the register to:

- `gp_reg_owner[reg]` still named the abandoned owner. That owner is normally

repair above turns on. One frame slot then entered the free pool twice, and two

## The reload put the value back and left the register free

Measured on `33f2f82e` plus this change, in
`/home/clp/src/idol/.worktrees/named-gap148-20260901`.

`spillReg` performs two halves of one act: it moves the value out of the register
— `str`, then `spilled_regs.put` — and it stops the register standing for that
value, `used_regs[victim] = false`. `ensureRegLive` is the exact inverse, the
`ldr` back into THAT SAME register, and it undid only the first half.

So the value returned to a register that read as free. Worse, the one fact that
had been substituting for the claim left in the same breath: both free scans in
`allocRegExcluding` skip a register `spilled_regs` contains, which is the
fail-closed guard that made a spilled register unallocatable, and the reload's
own `spilled_regs.remove` is what ends that. Between the reload and the next
`sweepGpLive` the register is in neither set, so the next allocation of any kind
returns a register holding a live value whose owner still names it, and the
second owner's first write is a silent wrong answer for the first.

Restoring the claim returns the register to the state it held before the spill,
and cannot leak for the same reason: `spillReg` never cleared
`gp_reg_owner[victim]`, so `sweepGpLive` releases this claim on the same owner
record, at the same index, as it would have had the register never spilled.

Bounded to gate transport with the rest of this gap. `spillReg` is reached only
from `allocRegExcluding`, which refuses above its spill loops unless
`gate_transport`, so `spilled_regs` is empty elsewhere and `ensureRegLive` is a
no-op there. Distinct from both reclaim facts above: those are
`reclaimSpilledReg` and `ensureRegLiveRemap`, the paths that move a value to a
DIFFERENT register; this is the path that puts it back in the same one.

## The reclaim ignored the one register the allocation excluded

`allocRegExcluding(exclude)` makes exactly one promise, and every path in it
kept that promise but the last. Both free scans skip `exclude`; all three spill
passes skip `exclude`, which is also why this call can never be what puts
`exclude` into `spilled_regs`. Then the bottom handed the whole decision to
`reclaimSpilledReg`, which took no `exclude` at all and walked the map in hash

could be handed back the register it had just named as holding a value it was
still using.

The exclusion is not a preference. `emitBinopFlooredConstDivisor` states the
reason at its own call: `dst` is claimed by the caller and a plain `allocReg`
could spill it, leaving `dst` mapped to a slot holding the value it had BEFORE
the sequence. The reclaim is worse than that spill, because it drops the
`spilled_regs` entry as well — the caller's value is abandoned in the frame with
nothing able to read it back, the caller writes its second value into the same
register, and both reads are wrong with no diagnostic.

The excluded register has to have been spilled BEFORE the call, and those
windows are ordinary. `emitIfConverted` reads the binding into `old`, then
evaluates both operands — each of which allocates, and can therefore spill `old`

the then-arm's `rt` across the whole else arm and then asks for

filled with every allocatable register; when it is genuinely the last one, the

## The release dropped the entry and kept the slot

Measured on `359fa064` plus this change, in
`/home/clp/src/idol/.worktrees/named-gap148-20260901`.

Four paths take a register out of `spilled_regs`, and taking the entry out is
what makes the frame slot behind it unreadable: `ensureRegLive` and
`ensureRegLiveRemap` are that slot's only readers and both key on the entry.
The removal is therefore the moment the slot becomes dead, and three of the four
hand it straight back to `free_spill_slots` on exactly that removal —
`sweepGpLive` and `reclaimSpilledReg` for a register they take from its owner,
both reloads for a value they move out of the frame. `releaseReg` was the fourth
and kept it.

A slot nothing can ever read again then stayed reserved for the rest of the
function. `spillReg` takes `free_spill_slots` first and otherwise steps
`gate_spill_cursor`, so every leaked slot moves the cursor one step closer to
`gate_spill_end` and the refusal there is a spill the pre-reserved area still had
room for. That refusal is not inert: it is the exact condition that propagates
out of the `allocRegExcluding` cascade into `ensureRegLiveRemap`'s exhaustion arm
and into the `reclaimSpilledReg` at the cascade's bottom — the two paths this
gap's open hazard lives on. The leak spends the reserved area on dead storage and
then hands the allocator the state where it has to abandon an owner.

Reached by ordinary scratch, not by a corner. `releaseReg` returns above every
record an owner holds, so only an UNOWNED register gets past that guard — which
is the ordinary state of a register `allocReg` handed out for one instruction's
operands, and it is exactly what the spill passes take first, since they require
`used_regs[victim]` and skip homes. `emitFlooredDivRem` holds `q` across two more
`allocRegExcluding(dst)` calls, either of which can spill it, and releases it at
the end of the sequence.

Releasing it is safe because the storage is dead in both directions at once: no
owner record names the register, or this body is not reached at all, and the
entry that was the slot's only reader is gone on the line above. This is the
argument `reclaimSpilledReg` already makes for the slot of the owner it abandons,
where the owner at least still exists.

The append belongs to the removal that actually took the entry, because the
removal is idempotent and a release is not. The emit paths release one register
more than once — `releaseReg(addr)` beside `releaseReg(base)` where both resolved
to the same register — and one offset in `free_spill_slots` twice is two later
spills storing two live values at one offset. `sweepGpLive` already spells it
this way; this makes the third path agree with it.

## A spilled home moved and the pin that names it did not

Measured on `109072c9` plus this change, in
`/home/clp/src/idol/.worktrees/named-gap148-20260901`.

`evalDnirValue` reads a `.local` through `pinned` FIRST and `temps` second.
`ensureRegLiveRemap` rewrites `temps` and cannot reach `pinned` — the map is not
passed to it — nor `imm_hoist`, which names a hoisted immediate's register the
same way. Relocating a home's value to a fresh register therefore left both of
those naming the register the value LEFT, and that register is free after the
move: `spillReg` cleared `used_regs`, the remap removed the `spilled_regs` entry,
and `markGpHome` had already nulled `gp_reg_owner`. The pool hands it to the next
allocation, and the next read of that local answers with whatever landed there.

`gp_call_home_regs` states this failure and its measurement — `sha.id` answered 0
instead of 16 across every NIST digest word, and `native.id` fell from 210
agreements to 128 — and buys the CALLING function out of it by refusing to spill
a callee-bank home, which costs nothing because `probeFunctionPlan` steps its
ladder down. It says in the same breath that a LEAF's home remains a spill victim
and carries the hazard unrepaired, because a leaf has no ladder and taking its
victims away would refuse programs that compile today. The second spill pass in
`allocRegExcluding` skips only `gp_call_home_regs`, and a leaf sets no bit there,
so a leaf home is reached whenever pressure walks x28 down past the unhomed
registers.

The repair takes no victim away: the home still spills, and it comes back to the
register every map already names. Reloading into `reg` is available for the
reason the exhaustion arm above states at length — a register in `spilled_regs`
holds nothing, because both free scans in `allocRegExcluding` skip that map and
all three of its spill passes require `used_regs`, which `spillReg` cleared — and
`ensureRegLive` is already exactly that reload, entry removal, single slot
release, and claim. Nothing below the branch applies to a home: `temps` names
`reg` and still should, `gp_reg_owner[reg]` is null, and `sweepGpLive` and
`releaseReg` both return above a home rather than freeing one. Bounded to gate
transport with the rest of this gap, since `allocRegExcluding` refuses above its
spill passes otherwise and no home is ever a victim elsewhere. Not the closure —
closure is still authoritative `register`/`frame` assignment before emission, per
the record above, under which a home's location is a fact the assignment carries
rather than one four maps restate.

## The reclaim bid for a home, and nothing can give a home back

Measured on `185a7dc8` plus this change, in
`/home/clp/src/idol/.worktrees/named-gap148-20260901`.

`reclaimSpilledReg` iterated `spilled_regs` in hash order with no home check.
Taking a home is wrong in two independent directions at once, and only the first
is this gap's already-recorded hazard:

- against the HOME, the dropped entry is the only thing that would have reloaded
  it, so the next read reaches `ensureRegLiveRemap`, finds no entry, and returns
  the register unchanged — now holding the reclaimer's value. That is the exact
  failure the home-reload arm repaired on the read path, reached through the
  reclaim instead;
- against the value the reclaim hands the register TO, which is new.
  `markGpHome` sets `gp_home_regs[reg]` and nothing clears it for the rest of the
  function: `sweepGpLive` skips a home, `releaseReg` returns above one, and only
  the hoist unwind or the per-function reset touches the array. So the returned
  register arrives still flagged as somebody's home, no release path can take it
  back, and the pool shrinks by one for the rest of the function — on the one
  path whose whole job is to relieve register pressure. `ensureRegLiveRemap`
  compounds it from the other side: it refuses to write `gp_reg_owner` for a home
  destination, so a value later relocated there lives under a null owner the
  sweep also skips.

Only a LEAF's home reaches the map. The first spill pass in `allocRegExcluding`
skips every home and the second skips `gp_call_home_regs`, which a calling
function sets for its whole bank and a leaf never sets — the leaf victim
`gp_call_home_regs` names and leaves unrepaired. The reload path answers that
victim by returning the home to the register every map already names; this path
has no such answer, because the value it is asked for is not the home's, so the
answer is to pass over the entry. The cost is the `exclude` skip's cost, one
candidate out of a map the cascade filled with every allocatable register.

`reclaimSpilledReg`'s remaining hazard against a TEMP is unchanged and still
bounded to gate transport. This is not the closure — closure is still
authoritative `register`/`frame` assignment before emission, per the record
above, under which a home's location is carried by the assignment and is not a
register the reclaim can bid for.
