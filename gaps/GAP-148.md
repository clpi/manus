The GP spiller keys state by physical register while DNIR values and local homes still point at that register. Reusing a spilled register therefore creates two owners and has a proven silent-miscompile history; the current guard correctly fails closed. Dynamic inline stack growth is also unsafe because existing record/table slots use fixed SP-relative offsets, and compiler spill state is not an authoritative value realization. WP-03 is false evidence: v1..v20 are unread, so its required STR/LDR canonizes storage that semantic demand does not require. Current bounded backend repair omits only unlineaged unread i64 immediate stores, proves exact assembly/object equality to the equivalent two-binding program, and retains a genuine 20-live-value RegisterExhausted control. Closure requires Idol to assign authoritative graph values to `register` or `frame` realization facts before emission, with CFG/backedge-aware liveness, a prologue-reserved frame, materialization returning the actual register, per-function state reset, value differentials under calls/branches/records, and replacement of the stale spill proof projections. Zig may project that assignment only as a bounded bootstrap bridge with an explicit deletion gate.

## The reclaim arm returned a destination as if it were the value

Measured on `0c753bd4d` plus this change, in
`/home/clp/src/idol/.worktrees/named-gap148-20260901`.

`ensureRegLiveRemap` is the read path for a `.local`/`.temp` whose register has
been spilled — `evalDnirValue` hands its result straight back as THE register
holding that value. Its gate-transport exhaustion arm returned
`reclaimSpilledReg()` directly, above the single `ldr` that is the only
instruction moving the value out of the frame, and so also above the
`spilled_regs` removal, the slot release, and the temp remap. The caller
therefore received a register nothing had loaded; a register reaches
`spilled_regs` because something else needed it, so when the reclaim returns the
same register it holds that something else. A wrong value with no diagnostic, on
the one path whose whole job is to make a spilled value readable again.

Reached whenever the pre-reserved gate spill area is full at a read of a spilled
value, which is the condition that puts `allocRegExcluding` into the reclaim in
the first place: `spillReg` refuses once `gate_spill_cursor + 16 >
gate_spill_end`, that refusal propagates out of the cascade, and this arm catches
it. The arm now supplies the reload destination and the rest of the function runs
as written.

`reclaimSpilledReg`'s own hazard is unchanged and still bounded to gate
transport: it drops the `spilled_regs` entry that would have reloaded the
register it hands back, abandoning that register's previous owner. Remapping this
value's owner onto the same register adds a reader to an owner already abandoned
by that drop, so no owner is broken that the reclaim had not already broken, and
one guaranteed wrong read is removed. This is not the closure — closure is still
authoritative `register`/`frame` assignment before emission, per the record
above.
