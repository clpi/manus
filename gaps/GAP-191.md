# GAP-191 — automatic universal rank lifting and cell composition

**Status:** OPEN · **Filed:** !2026-08-18T16:35:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/table.id, src/vector.id

Incorporate J/APL rank semantics into Idol's core relation model: any scalar or
structured relation naturally applies over cells of a designated rank across
multidimensional arrays and tables, eliminating the need for dedicated collection
mapping/iteration combinators and enabling universal loop/kernel fusion.

## Current measured boundary

Array operations require explicit loops or collection combinators. There is no
compiler-level rank lifting over multidimensional table shapes.

**Crossed:**

- Dense array shapes and rank/extent facts exist in the descriptor model.
- SIMD and vector instructions recognized in backend.

**Still missing:**

- `rank` as a formal relation descriptor attribute (e.g. scalar rank 0, vector rank 1).
- Automatic lifting theorem: relation $f: \tau_1 \to \tau_2$ applied to array $[\dots]\tau_1$
  lifts automatically across leading shape dimensions.
- Fusion of adjacent lifted relations into single-pass SIMD / GPU compute kernels.
- Elimination of intermediate array allocations between chained rank-lifted operations.

## Required order

1. Add rank descriptors to relation and shape fact families in C0.
2. Formulate lifting rules over arbitrary tensor/table ranks.
3. Build loop and kernel fusion optimizer for lifted relation chains.
4. Lower fused lifted operations directly to NEON/AVX SIMD vector instructions.
5. Benchmark against manual vector loops.

## Closure acceptance

Close when scalar relations automatically apply over arrays/tensors with zero-cost
vectorization and cross-relation kernel fusion without explicit map combinators.
