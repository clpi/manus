# GAP-034 — `sh`/`proc` do not exist, so `std.script` cannot be retired

**Status:** open · **Filed:** 2026-08-07 · **Frequency:** every script in `scripts/`
**Blocks:** Pass 94 §3 — the junk-drawer decomposition
**Sites:** `scripts/census/contract.duo` (P94-1..P94-4), and every census in
`scripts/census/` (each cites `-- gap[34]` at its `capture` use)

## The defect

Pass 94 deletes `std.script` as a junk drawer — a namespace bundled by *activity*
(writing a script) rather than by *subject* — and decomposes its contents:

```
capture(cmd)  →  sh(cmd).out        consuming .out IS the capture (demand)
                 sh(cmd).code       status only; nothing buffered
                 sh "duo build"     effects only
chomp(s)      →  dissolved          numeric edges tolerate lexical noise
```

Measured, **none of the process surface resolves**:

| Row | Form | State |
| --- | --- | --- |
| `P94-1` | `sh` as a binding | MISSING |
| `P94-2` | `sh(cmd).out` | MISSING |
| `P94-3` | `sh(cmd).code` | MISSING |
| `P94-4` | `sh "cmd"` parenless | MISSING |

So the drawer is denied and its replacement is absent. Every Duo script that
runs a command — which is every gate in `scripts/` — has no conforming spelling
available.

## What IS repairable today, and was

The `chomp` half of the ruling lands immediately, and has been applied:
`to(i64)("42\n")` returns `42` (P94-5), so the numeric edge already tolerates
surrounding whitespace and `chomp` was, exactly as the ruling says, "a workaround
for a conversion edge that didn't exist yet, wearing a function's name". Both
call sites in `scripts/census/identifiers.duo` dropped it.

The import canon also lands: `{ capture } = std.script` at the top, bare
`capture(cmd)` in the bodies, so the bodies stop reading like a filesystem.

What cannot land is the namespace's removal, because `sh` is not there to
receive it.

## Note on the demand claim

`sh(cmd).out` is not merely a rename of `capture`. The ruling is that
**consumption is the capture** — `.out` observed means stdout is buffered,
`.err` unobserved means stderr never is, `.code` alone means nothing is
captured. That is a demand-driven realization, not a record with three eager
fields, so implementing it as a plain record returning all three would satisfy
the spelling and miss the ruling. Worth stating because the cheap version is
tempting and would be wrong.
