# GAP-162 — Compound/abbreviated std names need semantic admission

## State

Open.

## Problem

C0 `law.path.name` and LAW-ONE forbid compound names and abbreviations
that evade semantic decomposition. Several `lib/std/` file names violate
this.

## Evidence

```
lib/std/mproc.id     — "multi-process" abbreviated to mproc
lib/std/datetime.id  — compound: date + time
lib/std/strconv.id   — Go-style abbreviation for string conversion
lib/std/strings.id   — plural namespace (mirrors Go's strings package)
```

## Required

Each name needs semantic admission. The question is not "is it short"
but "does one irreducible semantic concept remain after decomposition."

- `mproc`: abbreviation to avoid compound. Decompose into process
  relations over genuine subjects.
- `datetime`: compound of two semantic concepts (date, time). Each
  may be a separate relation or descriptor.
- `strconv`: a Go API mirror. Conversions are `to` relations, not a
  conversion API package.
- `strings`: plural namespace. String operations are relations over
  text subjects.

## Rule

Abbreviation does not evade LAW-ONE. A shorter compound is still a
compound.
