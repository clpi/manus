| title | GAP-162 — Compound/abbreviated std names need semantic admission |

| section |
|---|---|
| State |

| # | directive |
|---|---|

| section |
|---|---|
| Problem |

| # | directive |
|---|---|
| 1 | C0 `law.path.name` and LAW-ONE forbid compound names and abbreviations that evade semantic decomposition. |
| 2 | Several `lib/` file names violate this. |

| section |
|---|---|
| Evidence |

```
lib/mproc.id     — "multi-process" abbreviated to mproc
lib/datetime.id  — compound: date + time
lib/strconv.id   — Go-style abbreviation for string conversion
lib/strings.id   — plural namespace (mirrors Go's strings package)
```

| section |
|---|---|
| Required |

| # | directive |
|---|---|
| 1 | Each name needs semantic admission. |
| 2 | The question is not "is it short" but "does one irreducible semantic concept remain after decomposition." |

| # | directive |
|---|---|
| 1 | `mproc`: abbreviation to avoid compound. Decompose into process relations over genuine subjects. |
| 2 | `datetime`: compound of two semantic concepts (date, time). Each may be a separate relation or descriptor. |
| 3 | `strconv`: a Go API mirror. Conversions are `to` relations, not a conversion API package. |
| 4 | `strings`: plural namespace. String operations are relations over text subjects. |

| section |
|---|---|
| Rule |

| # | directive |
|---|---|
| 1 | Abbreviation does not evade LAW-ONE. |
| 2 | A shorter compound is still a compound. |
