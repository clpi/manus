# GAP-077 — `a, b = b, a` assigns left-to-right and silently corrupts data

**Status:** CLOSED 2026-08-09 · **Filed:** 2026-08-08 · **Severity:** SILENT WRONG ANSWER
**Fixture:** `examples/simultaneous_assign_proof.id` · **Gate:** `zig build semantics-gate` (tier-0, under `agent-smoke`)

## CLOSED — measured before and after, both backends

Re-run of the repro 2026-08-09 confirmed it was NOT stale: `{3,7}` swapped
printed `7 7` and `a=1,b=2` swapped printed `2 2`, on `--backend=direct` AND
`--backend=c`. Two backends agreeing on a wrong answer is why no differential
had convicted it.

| row | before | after (direct) | after (c) |
|---|---|---|---|
| `t[1], t[2] = t[2], t[1]` over `{3,7}` | `7 7` | **`7 3`** | **`7 3`** |
| `a, b = b, a` with `a=1 b=2` | `2 2` | **`2 1`** | **`2 1`** |
| `t[i], t[j] = t[j], t[i]` | `7 7` | **`3 7`** | **`3 7`** |
| `v, w = two(4)` — the pack, must not regress | `8 12` | `8 12` | `8 12` |
| `p, q = 8, 9` — negative twin, no overlap | `8 9` | `8 9` | `8 9` |
| side-effecting indices, `calls` | — | **`2`** | **`2`** |

The last row is the one the gap asked for by name: a key expression is
evaluated ONCE, so a naive temp rewrite (which reads `4`) is also convicted.

### Where the repair went, and why there

`src/parser.zig` — the statement is rewritten into the sequence that already
means it: read the PLACES (so a computed key is evaluated once, before any
write), stage the VALUES, then write. The staging lives inside a `do` block, so
the places cannot escape and no block parser has to drain a hoist list — three
of the four statement-list builders do not drain one.

Fixing it here rather than in a lowerer is what makes the answer the same on
both backends: `codegen.zig` and `dnir_lower.zig` each wrote the targets in a
plain left-to-right loop, and both are other agents' files.

**It fires only on a real conflict** — a target whose storage a LATER value
reads — so the AST every other front end reads is unchanged for the ordinary
case. `v, err = f(x)` is a one-value pack (`values.len == 1`) and never reaches
the rewrite at all, which is why the pack row above is untouched rather than
merely unbroken.

Multiple assignment is not simultaneous. The right-hand side is not evaluated
into temporaries before any target is written, so the canonical swap destroys
one of its own operands.

## Repro

```duo
main(): i64
    t = { 3, 7 }
    t[1], t[2] = t[2], t[1]
    print(t[1])
    print(t[2])
    return 0
end
```

```
prints   7 7        correct is 7 3
```

Verified under `--backend=c`. `t[1]` is written from `t[2]` first, and then
`t[2]` is written from the ALREADY-OVERWRITTEN `t[1]`.

## Why this one is nastier than most

`a, b = b, a` is the swap every programmer reaches for, in every language that
has multiple assignment, and it is correct in all of them — Lua included, which
matters because Duo is a Lua superset and this is the reflex a Lua reader brings.
The FAMILIARITY LAW (Pass 115) says every surface must explain itself through
reflexes the reader already has. This surface uses the reflex and then violates
it.

It also fails silently and plausibly: `{7,7}` looks like a swap that half
worked, not like a language defect, so the natural reaction is to doubt the
surrounding code.

Found during the Pass 119 semicolon migration, where one-line swaps
(`tmp = a[i]; a[i] = a[j]; a[j] = tmp`, 30 of them) were the largest population
of code semicolons. The obvious de-glued rewrite is `a[i], a[j] = a[j], a[i]` —
which would have introduced this corruption into thirty call sites. Every
migrated swap kept its temp instead.

## What the fix must preserve

Pass 100 B-9 and the pack machinery mean the right-hand side is already a pack
in the general case (`v, err = f(x)`). The rule is that **all right-hand values
are realized before any target is written** — which is what makes the failure
pack correct too, and is presumably why the pack case works while the
element-assignment case does not.

Check both when fixing:

```duo
t[1], t[2] = t[2], t[1]        -- must give 7 3
a, b       = b, a              -- plain locals, same requirement
v, err     = f(x)              -- must not regress
t[i], t[j] = t[j], t[i]        -- computed indices, both evaluated once
```

The last row matters: if the fix introduces temporaries, the INDEX expressions
must be evaluated once each, not twice, or a swap with side-effecting indices
changes meaning.

## Verify

Print the values; do not return them. Exit codes are 8-bit and a two-element
swap is easy to misread through a status.

## VERIFIED FIXED — and the repair costs NATIVE LOWERING, which is not recorded above

Re-measured independently after the repair landed:

```duo
a: i64 = 1 · b: i64 = 2 · a, b = b, a · print(a) · print(b)
```

| backend | before | after |
|---|---|---|
| `--backend=c` | `2 2` **corrupt** | **`2 1` correct** |
| `--backend=direct` | `2 2` **corrupt** | **refuses the program** |

Direct now answers:

```
hint: refused with: UnsupportedProgram
hint: bail site: lowerStmt() at dnir_lower.zig:1202
```

The repair reads places, stages values, then writes — **inside a `do` block**,
because three of the four block parsers do not drain a hoist list. `lowerStmt`
has no `.do_block` arm, so it falls to `else => return bail(@src())` and the
whole enclosing program leaves the direct backend.

**This is the correct trade and it is still a cost.** Priority order is
correctness above performance, and a refusal is honest where `2 2` was not — the
old behaviour was a silent wrong answer on BOTH backends, which is why no
differential ever caught it. But every program containing a swap now compiles
through C, and that is a native-coverage regression the census cannot see
because no census fixture performs a swap.

`native-census` reads 128 either way. That is not evidence of no regression; it
is evidence the corpus has no swap in it.

## What closes this properly

Teach `lowerStmt` a `.do_block` arm — the block is an ordinary scope and its
statements lower in order. Then the swap keeps its correct answer AND stays
native. Positive control: this exact fixture must compile `--backend=direct` and
print `2 1`, and a swap with side-effecting indices must still evaluate each
index ONCE (`calls = 2`, where a naive temp rewrite reads 4).

Until then, add a swap to the native corpus so the gap is visible to the gate
rather than only to whoever reads this file.
