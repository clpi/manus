# GAP-203 — the injection half of the world algebra has no graph fact

**Status:** OPEN · **Filed:** !2026-08-21T17:40:00Z
**Priority:** P0 · **Kind:** expressiveness_gap
**Filed by:** claude-gap145
**Files:** src/semantic_graph.zig,src/ast.zig,src/parser.zig,src/sema.zig,docs/spec/world.md

`docs/spec/world.md` §30-34 states one surface, and `law.injection.only` — the
GAP-110 reconciliation of 2026-08-13 — rules that `@{ … }` derives a world.
Measured against the compiler that ships that spec, two of the five faces do not
compile and a third derives nothing.

## Measured 2026-08-21 (subject 4c95b497)

| face | spec | parser | graph |
| --- | --- | --- | --- |
| `@x` access | select one exact fact | accepts | reaches ambient world |
| `@{ k = v }` inject | derive a closed world | accepts | **derives NO world** |
| `thing@world` qualify | evaluate under world | accepts (name glued only) | anchored `.field`, i.e. retrieval |
| `thing@{ k = v }` interject | evaluate under injected world | **refuses** | none |
| `@k = v` mutate | world member as place | **refuses** | none |

The spec's own examples do not compile. `world.md:67`
(`sale.quote@{ tax = (sum) 0 }(100)`) and the `world.md:107` block containing
`@fee = 0` are both rejected.

`w = @{ clock = fake }` type-checks and exports `"worlds":[]`. A program that
merely reaches `os` exports a populated row, so the world column is live — the
empty result is the derivation producing no fact, not absent machinery.

## The missing fact

`semantic_graph.WorldFact` is `{ world, home, reach, members }` — a
module-REACHES-world fact, with `Draw` keyed by application occurrence. There is
no `parent` and no fact-delta range, so a derived world is unrepresentable. There
is also no AST node for qualification or interjection: `grep -nE
'qualif|interject|world_expr' src/ast.zig` is empty.

`thing@world` is not qualification today. `src/parser.zig` builds an anchored
`.field` node and its own comment says RETRIEVAL, NEVER INVOCATION — it retrieves
a member at an anchored home rather than evaluating under a world.

## Why interjection could not parse

`src/parser.zig:5481` maps `.at => .matmul`. The escape hatch
`at_is_glued_anchor` admits only a name-like token glued to the sigil, so a
glued `{` fell through to matmul and died in sema as "matmul over non-tensor
operands" — whose repair hint is "close the space", advice the spec's example has
already taken. `world.md:64`'s exact reduction `thing@(@{ k = v })` failed the
same way, so this was never missing sugar: qualification by any non-name
expression is unimplemented.

Crossed 2026-08-21: `at_is_glued_world_face` now refuses both glued faces where
the shape is known and names the missing fact. Spaced `a @ b` remains matmul and
`X@rel` is unchanged; suite held at 11 failures + 3 crashes over 1666.
That is a diagnostic repair. It closes nothing.

## Why `@k = v` cannot parse (measured 2026-08-21)

Not a routing problem, and an attempted parser-only repair is recorded here so
the next agent does not spend the same hours.

`@name` at statement start is an ATTRIBUTE (`@hot`, `@export`, `@build.*`), so
`@fee = 0` entered attribute dispatch and met `=` where a declaration belonged.
Routing the shape away from attributes before dispatch is correct and was
verified reaching `parse_expr_stmt` with an instrumented predicate observing
`kind=name text='fee'` then `kind=assign`. It still fails, one layer down:

- `parse_expr_stmt` builds its target with `parse_suffixed_expr`, which handles
  names, literals, calls and field access. `@fee` is none of those.
- Routing the target through a bounded `parse_prec(2)` instead — bounded because
  the assignment family is precedence 1 right-associative and full expression
  parsing would swallow the `= v` — reaches the primary `.at` arm.
- That arm recognises the bare anchor and otherwise falls through to
  `parse_macro_call_expr`, which expects `@name( … )`. Bare `@fee` dies there
  demanding `(`, which is the original error at its true origin.

So the world place has no expression form in statement-target position, and
would still need to survive `check_assign_target` and reach a place in
lowering. `@k = v` is blocked on the same missing fact as interjection: there is
no world place. It is not a parser bug with a parser fix.

## The sigil is OCCUPIED, not merely unimplemented (measured 2026-08-21)

This is the finding that changes the shape of the work, and it was missed by
reading the spec instead of the parser.

`@{ … }` in expression position is not unimplemented. `parse_macro_call_expr`
routes it to `parse_pack` under a `.compile` staging wrapper — it is the
descriptor/pack face, and its own comment says the measured `= @{ … }` sites in
the tree "are frozen constant tables that depend on the staging".

Those sites are live. `grep -rn '= *@{' --include='*.id'` over lib, examples,
scripts, tools and gate finds 11, and they are keywordless enum descriptors:

```id
kind = @{ eof = 0, ident = 1 }
Kind = @{ eof = 0, ident = 1, number = 2, punct = 3 }
```

`parse_expr_stmt` names this face directly: "`Color: @{ Red, Green, Blue }`
keywordless enum descriptor".

So GAP-110's ruling — that the `@{}` collision is "resolved decisively in favor
of world injection only", with a descriptor being an ordinary table `{ … }`
carrying no sigil — was RECORDED BUT NEVER IMPLEMENTED. The descriptor meaning
still holds the sigil.

This explains every measurement above without appealing to missing features:
`@{ k = v }` type-checks because it parses as a descriptor; it derives no world
because a descriptor is not a world; and `thing@{ … }` refuses because the
postfix position has no descriptor reading at all.

**Consequence for closure: this is a breaking migration of an occupied sigil,
not the addition of an absent one.** A derived-world fact cannot simply be
published from `@{ … }` while 11 corpus sites read the same spelling as a frozen
constant table. The migration must come first, or the two meanings must be
separated by position with an executable control proving which face each site
took.

## The law's literal words break; the copula does not

`law.injection.only` says a descriptor is an ordinary table `{ … }` with no
sigil. Taken literally for the bind form, `Kind = { eof = 0, ident = 1 }` passes
`check` and then the direct backend REFUSES with
`DNB001 … keyed-table-export` — because the descriptor became a materialized
table (`places: []` for `@{}` against one runtime record place with
`extent {exact: 4}` for `{}`).

The copula case-set `Kind: { eof, ident, number, punct }` is exit-identical AND
strictly better: it produces a real `enum_shape` with variant children and
`member` edges, and a `duo:enum:kind` with `layout_completeness: complete`. The
`= @{ … }` form exports NOTHING — zero nodes, zero edges. All four corpus enums
are dense `0..n-1` in order, so implicit ordinals match exactly.

Full corpus differential, 83 programs migrated: **zero divergences**. Every
`ok compile` held, every exit code matched, and every pre-existing refusal kept
its exact code.

## `idol fmt` is already on the law's side

Formatting `Base: @{ x: i64 }` emits `Base: { x: i64 }`. The canonical formatter
performs the migration today; the parser is what still accepts the retired form.
That also means leaving `pretty.zig`'s `@{` reprint in place after the parser
stops accepting it would make formatting a legal file produce an illegal one.

## The parser cites an authority that no longer exists

`parse_macro_call_expr`'s comment justifies the descriptor reading with
"c0 §43 `anchor.brace`". `grep -n 'anchor\.' docs/spec/constitution.md` returns
only `anchor.recover` and `anchor.apply`, and both say the opposite: `@{ … }`
derives a world by injection, descriptor construction is `name{ … }` or plain
`{ … }`. The cited authority was replaced by its own negation.

## A live law violation, measured

        construction face (law.injection.only)"

## Position-disambiguation is foreclosed

`constitution.md:2761` binds `@{ … }` as **exclusively** world
derivation/injection, and `:2199` adds it is NOT name-elided descriptor
construction. Keeping the descriptor meaning in copula position and giving
worlds the expression position is a second meaning for the sigil, which
`exclusively` forecloses — and it would preserve the one spelling `:2884` denies
by name. It is also unnecessary: every corpus site has a sigil-free spelling
that already compiles.

## Re-measured 2026-08-23 (lane/worldstage) — `@x` ACCESS CLOSES

**One of the five faces now compiles, runs, and is held by a gate.** The table
in the previous section read `error: write `(` at this token edge` for `@x`,
because `@name` was the directive reader and its `expect(.lparen)` was
unconditional. It no longer is.

    sh gate/world/access.sh

is the authority for what closed, in six sections, each proved non-vacuous.
What the face now does, and none of it is inferred from a parse:

- `@x` resolves against the LAUNCH WORLDS and never the lexical scope, which is
  the whole capability. `world.md` rules that a bare lexical name wins for the
  bare spelling and that `@x` accesses the world member explicitly, so the
  disagreement case is the test: `env = (k) "shadowed"` followed by
  `@env("IDOLWORLDACCESSPROBE")` runs and answers the ENVIRONMENT, while bare
  `env(k)` in the same shape still answers the relation. §3 holds both halves.
- A member the current world does not have FAILS CLOSED and by name. There is
  no parent-directory, other-world, global-registry, library, or
  default-namespace fallback, and `k = 7` then `@k` still refuses — a lexical
  binding is not a world member.
- The graph DRAWS the world at the occurrence, including under the shadow.
  Three producers were each publishing a fact that contradicted the machine and
  all three are repaired: `Sema` selected a module relation by SPELLING from
  `callable_defs`, so the graph exported `relation: <env decl>` over a site
  realized as `getenv`; `semantic_graph.worldOfApplication` let `findFunc` claim
  the same occurrence; and `table_apply.bareMember` declined the world ingress
  whenever any binding shared the spelling, which made the program PRINT the
  relation's answer. Measured before the repair: `env = (k) 99` +
  `@env("HOME")` compiled, ran, and printed `99`.
- The printer writes the sigil back. Dropping it is a worse failure than
  gap[223]'s: the reprint still compiles and means something else. §5 asserts
  the reprint's ANSWER, not its bytes.
- The production EXPANDS WHAT IT RETURNS. `@x(args)` is decided in the macro
  expander, so its arguments go back through the same hygiene clone every other
  arm uses; handing them over untouched left a nested access as an unexpanded
  `.macro_call` that sema refused. §6 pins it with an indirection
  (`@env(@env(OUTER))` answers the value `OUTER` names, which only an evaluated
  inner access can produce) and controls it against an absent member inside an
  argument, which must still refuse by name.

**What did NOT close, measured rather than assumed.** The DOTTED face `@x.y`
is still the directive path: `@os.env("HOME")` does not check. The parser
consumes the whole dotted path before any world question is asked, and it must
keep doing so while `@c.type(…)`, `@c.call(…)` and `@c.export` are live —
`c` is a declared world NAME, so a rule turning `@world.member` into an access
would take those spellings with it. The dotted face closes with the directive
catalog, not before it. `gate/world/access.sh` §1 holds that fact and FAILS if
`@os.env(…)` starts checking, so the row cannot go stale silently.

Corpus control for the whole change: every tracked `.id` subject (1014) checked
before and after, comparing exit code AND first diagnostic. **Zero
divergences.**

Items 2-6 below are untouched. Item 1 — the derived-world fact — is untouched.

## Closure

1. A derived-world fact: parent world id plus exact fact deltas, with empty
   injection identity and same-fact idempotence as executable properties.
2. An AST face for qualification and interjection that is not `.field`.
3. `Draw` records which world — ambient or derived — each application drew from.
4. `@k = v` yields a place only where projection actually yields one.
5. A derived world may not read a parent fact missing at formation.
6. `thing@{ k = v }` proved exactly equivalent to qualification under the
   derived world, per `world.md:64`.

Close only when the spec's own examples compile and execute under the world they
name, and when the algebra's identities are executable property tests rather
than prose.
