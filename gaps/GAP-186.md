# GAP-186 — bidirectional semantic graph

**Status:** OPEN · **Filed:** !2026-08-18T16:00:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/source.id, src/graph.id

Support not only `source → graph`, but `graph delta ↔ source delta` and
`view delta ↔ semantic delta`. This unifies IDE refactors, semantic MCP edits,
source generation, database lenses, UI bindings, and generated-code provenance.

## Current measured boundary

Parsing is unidirectional. Source changes are re-parsed. There is no graph-edit
source-delta operation.

**Crossed:**

- `source → graph` is the production pipeline.
- `law.change.delta` exists.

**Still missing:**

- Delta of graph → delta of source.
- Delta of view → delta of semantic graph.
- Bijective or near-bijective source mapping for round-trip edits.
- Source-preservation constraints (names, formatting, trivia) as semantic facts.
- Generated-code provenance: each target fragment maps back to semantic ids.

## Required order

1. Add source-span and provenance facts to every semantic identity.
2. Define `edit_graph` as a delta operation.
3. Implement `graph_delta → source_delta` for a constrained class of edits.
4. Implement `view_delta → graph_delta` for lenses/database views.
5. Verify round-trip for a corpus of canonical source.

## Closure acceptance

Close when a graph edit can be projected back to a minimal source delta with the
same meaning, and when a view delta can update the source through the semantic
graph.

## C0 alignment

Instance of the schema in `gaps/RESEARCH-SPINE.md`; `tools/node/dev/gapc0` fails
closed without it.

- **constitutional owners:** relation (delta relations, GAP-177) · place · provenance (source-span mapping)
- **kind delta:** 0
- **registry delta:** 0
- **source syntax delta:** 0
- **semantic invariant:** `graph_delta → source_delta` and `view_delta → semantic_delta` are witnessed change relations; source-preservation constraints (names, formatting, trivia) are facts.
- **physical mechanism:** source-span/provenance mapping; constrained-class edit projection; round-trip verification over a canonical corpus.
- **prerequisites:** GAP-177.
- **foreign implication:** IDE refactors, semantic MCP edits, lenses, and UI bindings over foreign views are one mechanism.
- **world implication:** edits apply under a world; generated-code provenance maps every target fragment back to semantic ids.
- **projection implication:** bidirectional projection pairs `source → view` with `Δview → Δsource` where lawful — lenses are the projection algebra run backward.
- **demand implication:** only the demanded slice of the graph needs a source mapping.
- **realization implication:** minimal source delta for a graph edit; no full reparse for tooling edits.
- **evidence:** round-trip verification over a corpus of canonical source.
- **deletion witness:** one-way reparse machinery behind every tooling edit.
