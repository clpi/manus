# GAP-128 — Runtime benchmark invokes Duon WASM with obsolete WARD environment contract

**Files:** scripts/runtime_bench.duo,tools/wasm/src/engine.duo,build.zig,docs/performance.md,gaps/GAP-072.md

scripts/runtime_bench.duo invocation() exports WARD_WASM and WARD_INVOKE, but tools/wasm/src/engine.duo intentionally requires DUO_WASM_MODULE and reads DUO_WASM_INVOKE. The engine has no fallback and exits nonzero when DUO_WASM_MODULE is absent. Therefore every Duon-runtime cell in the release comparison is invalid and current faster/slower claims cannot be reproduced through this gate. Do not merely rename the environment variables while preserving std.script/process namespace authority: the harness is also blocked on the canonical process/world/result vocabulary. First add a positive control proving the exact engine contract and nonzero/result parsing, then migrate invocation through the admitted world relation, then rerun value-checked performance against pinned wasmtime. Preserve std.script removal and 100% Duon direction.
