### The guard cannot admit anything

`moduleFieldWord` (`src/dnir_lower.zig:827`) admits the module's field word only
when both hold:

```zig
const base_binding = ctx.graph.bindingNamedIn(relation, base) orelse return null;
const base_node = ctx.graph.get(base_binding) orelse return null;
if (base_node.scope != ctx.graph.module_root) return null;
```

**Those two conditions are mutually exclusive.** `bindingNamedIn`
(`src/semantic_graph.zig:4352`) skips every node whose `enclosingCallable` is
not the relation it was asked about, so it can never answer with a module-scope
binding; and anything it does answer with is scoped inside the relation, so its
scope is never `module_root`. Both arms take the same `return null`.
`moduleFieldStorageBase` carries the identical shape.

The consequence is the complement of the filing, from the same line. The
original defect was the SHADOW's write reaching the module's word. This one is
the module's word becoming unreachable from the body that genuinely owns it:
with `moduleFieldWord` null, `lowerFieldAssignTarget` falls through to the
fresh-local fallback its own comment calls "the defect" — it mints a frame slot
named `M.x`, so the write the module can see never happens and every later
reader answers the literal.

### What the repair owes

Restoring the module's word is one sign flip in the query — absence of a
body-local binding is what MEANS the module's binding is reached — but the
distinction the deleted `bodyDeclaresBinding` carried has to come back with it,
from the graph rather than from a spelling: a bare `M = { … }` in a relation
ASSIGNS the module binding and is not a shadow, while `M: cell = { … }` and a
parameter are. `place.BindOrigin` is the published fact for that.

**The "it may not even reach here" escape does not hold, and this much is now
read rather than assumed.** The hope was that `registerTableFieldGlobals`
declines storage for the assignment case before `moduleFieldWord` is consulted.
It declines on `moduleAssignCount(mod, name) > 1` (`src/dnir_lower.zig:1615`) —
STRICTLY more than one — and `moduleAssignCount`
(`src/dnir_lower.zig:589`) counts bare `.assign` targets while its
`.local_decl, .const_decl, .global_decl => {}` arm counts declarations as ZERO.
So a module that introduces `M` by DECLARATION and is assigned bare exactly once
inside a relation body scores 1, not >1, and is not declined. The assignment
case reaches `moduleFieldWord`, and the `BindOrigin` distinction is genuinely
owed rather than incidentally covered. The in-tree comment at
`src/dnir_lower.zig:1684` — "a bare `M = { x = 5 }` inside the relation is an
assignment to the module binding, not a shadow of it, and it is declined earlier
by `moduleAssignCount`" — is therefore true only for the >1 case and must not be
read as general.

This is a READING of three functions, not an execution, and it is labelled as
one. What still needs the parse GAP-145 owns is the answer, not this structure.

**Nothing here is landed unrun again.** A repair to `moduleFieldWord` whose
acceptance cannot be executed is the same act as `4a0b2eef`, and it is what
produced this state.

## Why the neighbouring fix does not cover it

`examples/shadow.id` covers the case where the module's table is written by
NOBODY. That was repaired by teaching the field-write scan not to descend
into scopes that rebind the base name, so the module's table is no longer
granted storage it does not own.

This case is the complement: the module's table genuinely DOES own storage,
because `poke` really writes it. The scan is right to grant it. The defect
is downstream — `lowerRecordLiteralFields` and `lowerRecordLiteralAssign`
resolve a field write against `ctx.module_globals` BY SPELLING, so the
shadow's `bank.x = 99` finds the module's word and stores into it.

## The missing fact

`LowerCtx` carries no per-body binding identity. It can answer "is there a
module global spelled `bank.x`" and cannot answer "does the `bank` in scope
at THIS point denote the module binding". Those are different questions and
only the second is semantic.

This is the same frontier the aggregate-projection lane reached from the
other side: `AggregateFact.place` is `.one(site)` and `boundAggregateAtPlace`
returns null when two aggregates share a place, so the graph can name THE
COLLECTION AT SITE s but not WHICH BINDING A READ RESOLVES TO, nor ITS
CONTENTS BETWEEN WRITE w_i AND w_{i+1}. Two independent consumers, one
missing fact.

## Deletion witness for the eventual repair
Whatever supplies the per-body binding fact must DELETE the by-spelling
`ctx.module_globals` consults in `lowerRecordLiteralFields` and
`lowerRecordLiteralAssign`. A patch that adds binding identity while leaving
the spelling lookups in place leaves two stores that can disagree — which is
this defect, not its repair.
