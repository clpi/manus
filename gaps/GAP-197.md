# GAP-197 — CHR-style fact saturation engine

**Status:** OPEN · **Filed:** !2026-08-18T16:40:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/semantic_graph.zig, src/sema.zig

Replace hand-ordered compiler passes with multi-headed rules over the semantic
graph. Rules monotonically add, refine, or invalidate facts. The compiler is a
CHR-style saturation engine, not a pipeline of passes.

## Current measured boundary

Compiler passes are still ordered by hand. Analyses invalidate one another.
There is no unified rule language for graph facts.

**Crossed:**

- `law.fact.producer.one` and `law.coordination.fact` exist.
- `demand`, `effect`, `shape`, `range` are graph facts.

**Still missing:**

- An inference rule is an ORDINARY RELATION applicable when head facts hold, whose guard is a demanded obligation, and whose application publishes or refines body facts — no `rule` semantic kind.
- Rule application: match head, check guard, publish body.
- Saturation: apply rules until fixed point.
- Rule examples:
  - `unique(x), lastuse(x)` ⇒ `movable(x)`.
  - `movable(x), shape(x, S)` ⇒ `candidate(inplace, x)`.
  - `constant(x), demanded(x, none)` ⇒ `unrealized(x)`.
- No pass order: scheduler uses rule dependencies.

## Required order

1. Express inference rules as ordinary relations over graph facts; `saturation` is the scheduler's fixed-point law, not a new semantic kind.
2. Add a rule matcher over the semantic graph.
3. Express existing analyses as rules.
4. Implement saturation scheduler: dependencies and cost.
5. Show that hand-ordered pass pipeline is replaced by rule-driven saturation.

## Closure acceptance

Close when `range`, `effect`, `shape`, `ownership`, `demand`, and `world` are
expressed as rules, and the compiler reaches a fixed point by rule saturation
rather than a hand-ordered pass pipeline.

## C0 alignment

Instance of the schema in `gaps/RESEARCH-SPINE.md`; `tools/node/dev/gapc0` fails
closed without it.

- **constitutional owners:** relation (an inference rule is a relation) · demand · obligation (the guard)
- **kind delta:** 0
- **registry delta:** 0
- **source syntax delta:** 0
- **semantic invariant:** facts ↓ applicable inference relations ↓ new/refined facts ↓ fixed point — `unique(x) ∧ lastuse(x) ⇒ movable(x)` is an ordinary relation application, and the compiler is a physical saturation scheduler over ordinary semantic relations.
- **physical mechanism:** rule matcher + saturation scheduler driven by rule dependencies and cost; no pass order.
- **prerequisites:** GAP-196.
- **foreign implication:** foreign inference results enter as trust-labelled facts from the same relation face.
- **world implication:** rule applicability is world-qualified.
- **projection implication:** rule discovery is graph projection.
- **demand implication:** only demanded facts saturate — undemanded inference does not run.
- **realization implication:** deterministic refinement runs to saturation before any search (feeds GAP-198); hand-ordered pass pipelines disappear into rule dependencies.
- **evidence:** the same fact set reached by rule-driven saturation as by the hand-ordered pipeline, with the pass-order machinery deleted.
- **deletion witness:** hand-ordered pass pipelines, `rule` languages, CHR as a separate engine.
