# GAP-197 — CHR-style fact saturation engine

**Status:** OPEN · **Filed:** !2026-08-18T16:40:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/compiler_rules.id, src/graph.zig

Replace hand-ordered compiler passes with multi-headed rules over the semantic
graph. Rules monotonically add, refine, or invalidate facts. The compiler is a
CHR-style saturation engine, not a pipeline of passes.

## Current measured boundary

Compiler passes are still ordered by hand. Analyses invalidate one another.
There is no unified rule language for graph facts.

**Crossed:**

- `law.fact.producer.one` and `law.coordination.fact` exist.
- `demand`, `effect`, `shape`, `range` are graph facts.

**Still missing:**

- `rule` = `head facts + guard + body facts` over the graph.
- Rule application: match head, check guard, publish body.
- Saturation: apply rules until fixed point.
- Rule examples:
  - `unique(x), lastuse(x)` ⇒ `movable(x)`.
  - `movable(x), shape(x, S)` ⇒ `candidate(inplace, x)`.
  - `constant(x), demanded(x, none)` ⇒ `unrealized(x)`.
- No pass order: scheduler uses rule dependencies.

## Required order

1. Define `rule` and `saturation` in C0.
2. Add a rule matcher over the semantic graph.
3. Express existing analyses as rules.
4. Implement saturation scheduler: dependencies and cost.
5. Show that hand-ordered pass pipeline is replaced by rule-driven saturation.

## Closure acceptance

Close when `range`, `effect`, `shape`, `ownership`, `demand`, and `world` are
expressed as rules, and the compiler reaches a fixed point by rule saturation
rather than a hand-ordered pass pipeline.
