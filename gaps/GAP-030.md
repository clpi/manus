| section |
|---|---|
| How to measure it correctly |

| # | directive |
|---|---|
| 1 | Library modules: `--emit obj`, never `--emit exe` (no entry point by design). |
| 2 | Exclude `examples/compile_fail/**` — those must fail. |
| 3 | Count only `DNB*` and `error: direct backend ...` as native bails. |
| 4 | `DUO_DNIR_TRACE=1` names the bail site once a real one is isolated. |

| # | directive |
|---|---|
| 1 | The bail codes are DNB000..DNB010 |
| 2 | DNB001 is the general "outside the direct subset" refusal and is the one worth ranking by cause. |

| section |
|---|---|
| The existing trace mechanism CANNOT recover DNB001's site — measured |

| # | directive |
|---|---|
| 1 | `src/main.zig:3186` already tries: on `DUO_DNIR_TRACE=1` it dumps Zig's error return trace, and its comment says that names which of "~57 `return error.UnsupportedConstruct` sites fired". |
| 2 | It does not work here: |

| # | directive |
|---|---|
| 1 | hint: DUO_DNIR_TRACE: lowering bailed at — (empty stack trace) |

| # | directive |
|---|---|
| 1 | The comment attributes empty traces to ReleaseFast. |
| 2 | That is not the cause — `build.zig` uses `standardOptimizeOption`, which defaults to **Debug**, and this binary is the plain `zig build` output. |
| 3 | So the trace is being lost some other way: the error is caught and re-raised (or crosses a boundary that drops it) before reaching the reporter. |

| # | directive |
|---|---|
| 1 | **So DNB001 needs EXPLICIT instrumentation, not a build-mode change.** Each `return error.UnsupportedConstruct` site should record its construct — a small enum or a string set beside the error — because the ambient mechanism has been tried, is already wired, and yields nothing. |

| # | directive |
|---|---|
| 1 | That is worth knowing before anyone spends a rebuild on `-Doptimize=Debug` expecting the histogram to appear. |

| section |
|---|---|
| The blocker on finer resolution |

| # | directive |
|---|---|
| 1 | DNB001 is **83% of all native bails** and is the GENERIC code — it names no construct. `DUO_DNIR_TRACE=1` does not resolve it either: over 25 DNB001 files the trace reports the bail site as literally `—`, with only two files naming anything (`UnsupportedConstruct`). |

| # | directive |
|---|---|
| 1 | **That is the thing to fix first for "native 100%", ahead of any individual construct.** 60 bails share one undifferentiated code, so there is no worklist to work: every attempt would be a guess at which construct to support next. |
| 2 | Give DNB001 a construct-level reason (or make the trace name its site) and the 60 become a ranked histogram — at which point the actual lowering work can be ordered by frequency instead of by hunch. |

| # | directive |
|---|---|
| 1 | DNB007 (10) and DNB002 (2) are already specific and are the only rows actionable today. |
