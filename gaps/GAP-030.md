# GAP-030 — the native-coverage map (measure before optimizing "native 100%")

**Status:** open (measurement, not a defect) · **Filed:** 2026-08-07

## Why this exists

"Native 100%" needs a denominator before it needs work. A naive sweep produces a
number that is almost entirely wrong:

    lib/std, --backend=direct --emit exe    OK 0 / 60      <- MEANINGLESS
    examples,  --backend=direct --emit exe  OK 1 / 60      <- ALSO MEANINGLESS

Both are dominated by causes that have nothing to do with native lowering.
Ranked over 40 examples:

    19  error: no linker entry        modules and fixtures with no `main` —
                                      not programs, cannot be --emit exe
    14  error: expected ...           compile-fail fixtures; they exist TO fail
     4  error: direct backend         <- the ONLY real native-subset bails
     1  macro expansion error
     1  expected expression

So the actual native gap in that sample is **4 of 40**, not 59 of 60. Anyone
optimizing against the raw count would spend their effort on entry points and
negative fixtures.

## How to measure it correctly

- Library modules: `--emit obj`, never `--emit exe` (no entry point by design).
- Exclude `examples/compile_fail/**` — those must fail.
- Count only `DNB*` and `error: direct backend ...` as native bails.
- `DUO_DNIR_TRACE=1` names the bail site once a real one is isolated.

The bail codes are DNB000..DNB010; DNB001 is the general "outside the direct
subset" refusal and is the one worth ranking by cause.

## Next step

Build this as a gate beside `language_census` — a `native_census` reporting the
DNB histogram over a correctly-filtered corpus. That converts "native 100%" from
a slogan into a ranked worklist, the same way the language census converted the
monoglot goal into twelve named files (and then two).

Known real hole closed today for reference: `s:byte(i)` had no native lowering
and emitted `duo_fatal("unlowered native string method")` — see gap[025]. The
other surviving fatal is `"unlowered native call"`; only two such stubs exist in
codegen, so the fatal-stub route is NOT how native coverage is bounded. DNB is.
