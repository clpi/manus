# GAP-103 — the relation store has stable semantic ids; nothing in a `.duo` file can reach them

**Status:** OPEN · **Filed:** 2026-08-09
**Law:** constitution §21 `law.identity.three` + `law.dedup` · §22 lawsets ·
§37 `law.distribution` clause 3 ("a package namespace is not a substitute for
relation identity") · §0h PACKAGES ARE INERT GRAPH FRAGMENTS
**Answers:** owner priority #4 — *"stable semantic identity, replacing
strings"* — **half.** The store layer is done and proven. The front end is not.

## What landed

`src/relation.zig` keyed every edge on a descriptor's TEXT. It now keys on a
stable semantic `Id`, minted by an interner (`Names`) from a key carrying
everything that makes two names different things:

| the key carries | discriminates |
|---|---|
| `kind` | a descriptor `to` from a callable `to` from the relation `to` |
| spelling | the ordinary case |
| `origin` = package + version | a@1's `micron` from b@1's from a@2's |
| `scope` = exported + owner | one module's private `scratch` from another's |
| `lawset` = duon \| lua \| c \| wasm | a Lua `number` from a duon `number` |

`Id` holds **no text**, deliberately: a copy cannot go stale across a rename
and cannot be byte-compared by accident. All three identities of §21 are
present and separate:

- **semantic** — `Id` for a descriptor/callable/relation, `EdgeId` =
  (relation, src, dest) for a relationship. Survives a rename and survives a
  redeclaration that swaps the realization.
- **content** — `Fact.content`, a hash of (endpoints, realization, facts) and
  **not** of the family, so two families holding the same conversion SHARE
  content while keeping distinct `EdgeId`s. That is `law.dedup` exactly: share
  content nodes, never collapse semantic identity.
- **incarnation** — `Record.incarnation` per minting, `Fact.incarnation` per
  declaration. Bumped by a redeclaration that changes nothing, because an
  incarnation that held still would not be one.

The string survives only as rendering and lookup: `Edge`, `Path` and
`Relation.name` are the rendered face of `Fact`, `Route` and `Relation.id`, and
`Names.find` is the single quarantined site where comparing bytes is correct.
`zig build relation-id` measures the quarantine and positive-controls its zero.

**SER is unchanged at 2.00** (n=4, authored=6, derived=6, refused=0), verified
by running the compiler over `examples/spec100/relation.duo`, and the control
still fires: with `routeBy` stubbed to `null` the same fixture reads `ser=1.00`
and the run exits 1.

## What did NOT land — the gap

**Every discrimination above is unreachable from a `.duo` file.** The front end
(`codegen.zig:populate_relation_edges`) interns through `Store.descriptor` /
`Store.callable`, which supply the DEFAULT origin, scope and lawset. So today:

| failure mode | store layer | reachable from source |
|---|---|---|
| packages | **fixed** — two packages' `micron` are two descriptors and do not compose through a shared hub | no — there is no package surface |
| versions | **fixed** — a@1 and a@2 coexist | no — same reason |
| private descriptors | **fixed** — owner participates in identity | no — the front end interns everything exported |
| renames | **fixed** — `Store.rename` moves the spelling, edges untouched, SER unchanged, the old spelling stops resolving, a rename onto an occupied spelling is REFUSED | no — there is no rename operation in the language, and no LSP path to one |
| lua firewall | **fixed** at the identity layer | no — one lawset reaches the store |

Calling any of the first four "fixed" without this table would be the exact
dishonesty §3 MEASUREMENT HONESTY was written against. They are **unblocked**:
the mechanism exists, is tested with a negative twin each, and needs a caller.

## The next three, in order

1. **A second origin through the front end.** Nothing needs a package manager
   for this — `use()` anchoring a value (§0h) is enough for the store to see
   two origins, and the first thing it buys is that a package may declare
   `to(micron)(inch)` without colliding with the prelude's.
2. **`Store.rename` behind the LSP rename.** The LSP is a protocol front end
   over the graph service (§0f); a rename that edits spellings and leaves every
   edge intact is the whole point of an id, and it is currently reachable only
   from a Zig test.
3. **Lawset at the boundary.** Lua source entering the shared substrate must
   intern with `lawset = .lua`, or the firewall is a comment. This is the one
   that gets *harder* the longer it waits, because every edge minted under the
   default lawset today is an edge that will need re-minting.

## Also still open, unchanged by this work

Two of the file's other three debts are untouched and are not this gap:
class legality is still refused at CODEGEN rather than in SEMA, and the `to`
CALL face is still reached by family NAME in `codegen.zig`. The third —
`derive` being ONE HOP — is not a debt: longer paths need a path-selection law
and adding BFS/DFS instead would be architecturally wrong.

## Do not

Do not close this by widening `Store.descriptor`'s defaults, and do not add a
`text` field back to `Id` "for convenience". Both restore the text key with an
id-shaped wrapper, and both would pass every test in `src/relation.zig` — a
single-origin single-lawset compilation unit cannot tell the two keys apart.
Only `zig build relation-id`'s quarantine scan can, which is why it exists and
why its zero carries a positive control.
