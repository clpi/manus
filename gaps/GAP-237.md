# GAP-237 — a method applied directly to an indexed element segfaults through the generated-C bridge

**Status:** OPEN · **Filed:** !2026-08-25T09:20:00Z
**Priority:** P1 · **Kind:** wrong_answer
**Filed by:** gap133-alignment
**Files:** src/codegen.zig

Tree `fc48acea`, executed path `idol dump-c` + cc (the direct backend answers
DNB004 on this host). `rows[i]:relation()` — a method applied in the same face
as the computed projection that produced its subject — compiles without
diagnostic and the emitted binary dies with SIGSEGV before any output:

```id
main: i64 = ()
    t: str = "  hello law  "
    rows = t:split(" ")
    v: str = rows[3]:trim()   # SIGSEGV at runtime; no compile diagnostic
    print("c [{v}]")
    0
```

Binding the element first is correct on the identical input:

```id
    r: str = rows[3]
    v: str = r:trim()         # prints as expected
```

The class, not the specimen: the subject of the method arrives from a computed
projection and is still boxed/unnarrowed when the method lowering selects its
receiver face. `:trim` is the measured specimen; whether every string relation
on an indexed receiver dies the same way is unmeasured — the fixture below
must sweep the family rather than pin one method.
`scripts/alignment_emit.id` was the discovery site and now binds every indexed
element before applying a relation, and says why. This is the
GAP-114 family — a boxed receiver reaching a representation-specific intrinsic
— but the outcome is memory-unsafe rather than a plausible wrong value, so
`idol check` green plus a segfault is the entire observable.

What closes this: the lowering either narrows the indexed element like an
annotated binding would, or refuses the unprovable receiver at compile time
with a DNB diagnostic. A fixture must assert the VALUE of a
`table[index]:method()` chain through the generated-C bridge, control
(pre-bound) first. Generated-C evidence only; not direct-native or wasm
evidence.

Adjacent measured limits on the same bridge, recorded here so the next reader
does not rediscover them: `os.env(name)` and `os.args` refuse honestly at
codegen (unrealized callee / unrepresentable binding) — diagnosed, so merely
missing, not silent; scripts executed through the bridge take configuration
from the working directory instead (see `scripts/alignment_emit.id`).
