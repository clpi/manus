# GAP-108 — Semantic Reconstruction Count: seven facts, four measured owners each, and one live wrong answer

**Status:** OPEN · **Filed:** 2026-08-09
**Law:** §0f ONE GRAPH SERVICE ("no backend decision outside canonical
representation selection") · §3 MEASUREMENT HONESTY ("no recognizer may key on a
function name, a literal") · owner rule: **for every major semantic fact there
must be exactly ONE authoritative writer; downstream systems consume it.
Target SRC = 1.**

**Answers:** the owner's immediate-order item 3 — whether `src/relation.zig`,
`src/realization.zig` and `src/semantic_algebra.zig` are becoming competing
semantic authorities rather than distinct projections of one substrate.

## Method, and why it is not a code review

Every claim below was produced by constructing an input where two owners COULD
disagree and running it. Nothing here rests on two functions having similar
names. Three probes were written, run, and are reproduced in full at the bottom
so they can be re-run; each carries a CONTROL row that must come out `agree`,
because a probe that can only report disagreement is not measuring anything.

A duplication that could not be made to disagree is reported as a PROJECTION and
is explicitly allowed.

## Headline

The three files are **NOT** the problem the order suspected. Their split is
largely honest:

- `realization.zig` defines **no** cost algebra — it imports
  `semantic_algebra.CostVector` / `DominanceVerdict` / `Objective`. Correct.
- `realization.funcLowersNative` delegates to `semantic_algebra.lowersToNativeC`.
  Correct.
- `EffectSet` / `EffectAtom` exist in exactly one file and enter through exactly

The duplication is **not between the three files. It is between each of them and
`codegen.zig`**, which reconstructs every fact they own. Three of the four
measured duplications have `codegen.zig` on one side.

### 2.2 descriptor identity — **SRC = 4** on a layer the law says must not conflate

`src/pass26_descriptor_identity.zig:7` enumerates four identity layers and states
they "must never conflate". Two mechanisms independently occupy **layer 2,
declaration_identity**:

| # | owner | file:line | key |
|---|---|---|---|
| P | `pass26_descriptor_intern.declarationIdentityHash` | `src/pass26_descriptor_intern.zig:40` | module + name + **line/col** |
| R | `relation.Names.intern` | `src/relation.zig:381` | kind + text + package + version + exported + owner + **lawset** |

Neither key is a subset of the other. Probe `identityprobe.zig`, control held,
**5 of 5 questions disagree**:

```
agree     pass26=same      relation=same       [CONTROL] identical declaration twice
DISAGREE  pass26=distinct  relation=same       Q1 same name, different line/col
DISAGREE  pass26=same      relation=distinct   Q2 same spelling, lawset duon vs lua
```

**Q4 is the one that matters.** `relation.zig`'s entire stable-identity design
(its `STABLE SEMANTIC IDENTITY` block, `src/relation.zig:404`) rests on "a rename
is a harmless edit — the identity does not move, only its spelling does".
`declarationIdentityHash` hashes the name, so under P a rename **destroys** the
declaration identity. Two files, one layer, opposite laws.

**Q2/Q3 are the Lua Firewall.** `relation` discriminates lawset and package
version; `pass26` cannot see either. A Lua `number` and a duon `f64` are the same
declaration identity under P.

The other two owners of *descriptor identity* are different LAYERS and are
therefore legitimate: `semantic_algebra.descriptorStructuralHash`
(`src/semantic_algebra.zig:203`, layer 1) and `semantic_fingerprint.compute`
(`src/semantic_fingerprint.zig:19`). Those are projections, not duplicates.

### 2.4 tail-slot selection — **SRC = 3, and it produces a LIVE WRONG ANSWER**

| # | owner | file:line |
|---|---|---|
| 1 | `tail_result_demand.blockTailResultWithDemand` | `src/tail_result_demand.zig:54` |
| 2 | `codegen.emit_block_stmts` `BlockTailMode` | `src/codegen.zig:10987` |
| 3 | the direct/native backend's own tail handling | reached via `--backend=direct` |

Owner 1 is consumed by `sema.zig:1978`, `dnir_lower.zig:962` and
`semantic_graph.zig:505` — correct. **`codegen.zig` never calls it.**

`src/tail_result_demand.zig:63-72` already records a past sema-vs-codegen
disagreement in its own comment. A live one is worse. Minimal repro:

```duo
f(): i64
  print(111)
  222
print(f())
```

| backend | stdout | exit |
|---|---|---|
| `--backend=c` | `111` `222` | 0 — **correct** |
| `--backend=direct` | `111` | **222** |

The direct backend treated the module's tail expression `print(f())` as the
module's **implicit return value** where the C backend treated it as a
statement — so `222` became the process exit status instead of being printed.
The generated C is correct (`printf("%lld\n", f());`), which rules out codegen
and localizes the defect to owner 3. Adding any preceding top-level statement
masks it entirely: the same file with `print(999)` inserted before `print(f())`
answers correctly. That masking is why this survived — the shape only appears
when the call is the module's sole top-level statement.

**This is the highest-value item in this gap. It is a silent wrong answer under
the backend that §0b calls "not an alternative backend, it IS the path".**

**GAP-102 is the same fact with a different trigger.** It is filed as "a
descriptor-application binding is taken as the tail, so DEMAND-RETURN returns
the wrong statement" and it surfaces as `explain: FAIL` in `agent-smoke`. Same
question — *which slot is the tail?* — same three owners, different input. They
should be closed together by R1: GAP-102 is the sema-side symptom and §2.4 is
the backend-side symptom of one missing single owner.

## 4 · `path legality` — reported as NOT a duplication

but take different subjects: a *conversion path* versus a *physical candidate
under target and knowledge*. I could not construct an input where they answer the

The real finding in this neighbourhood is one of PLACEMENT, not duplication:
`relation.zig` owns a composition algebra — `meet` (`:135`), `derivable`
(`:149`), the six-class bijection (`:158`, `:230`). By the owner's stated split
("semantic algebra: lawful composition · implication · meet/join · coherence

## 6 · Ranked collapse plan — delete > derive > project > generalize > port

**R1 · tail-slot in the direct backend — FIX, do not collapse yet.**
A live silent wrong answer under the shipping backend. Make owner 3 consume
`tail_result_demand.blockTailResultWithDemand` instead of deciding for itself,
which is *project* and simultaneously fixes the bug. Add the repro above to the
native differential. **Unblocks:** trusting `--backend=direct` results at all;
every native-census row is currently a number produced by a backend that can
disagree with C about what a module returns.

**R2 · descriptor identity — DELETE one of the two layer-2 owners.**
`relation.Names` is the strictly better key: it carries lawset and package
version (which `pass26` cannot see) and it survives a rename (which `pass26`
cannot). Make `pass26_descriptor_intern` take its `declaration_identity` from
`relation.Names.intern` and delete `declarationIdentityHash`
(`pass26_descriptor_intern.zig:40`, 14 lines). **Unblocks:** the Lua Firewall at
the identity layer, and gap[103]'s "front end hands the store one origin" — the
two are the same work item once there is one interner.

**R3 · native-scalar — DERIVE B and C from A.**
Four owners, seven contradictions. `is_native()` (A) is the only one with no
lattice pretension and the only one every backend already respects. Redefine
`lowersToNativeC` as `rt.is_native()` and replace
`type_expr_is_native_scalar`'s hand-written tag list with the same call. This
IS a behaviour change (the seven rows above flip) and must ship with the native
census, `bench` and the differential, so it is R3 and not R1. **Unblocks:**
~40 lines deleted, and the GAP-092 class of bug — "two spellings of one value on
opposite sides of the native gate" — stops being constructible.

**R4 · candidate selection — DELETE `static_cost`.**
`Candidate` should carry one cost. `static_cost` + `optionality_retained` are a
pre-§47 scalar that `CostVector` subsumes; port the ~6 `appendCandidate` call
sites to `setFact(..., .estimated)` and delete `selectDeterministic`
(`realization.zig:320`, 48 lines) in favour of `selectAgainstFloor`. Note
`realization.zig:232` already flags a related gated-number hazard for the
`lowering` list; read it before moving. **Unblocks:** one selection law, so
`why(skip)` answers the same thing regardless of entry point.

**R5 · conversion legality — GENERALIZE.**
Move `meet` / `derivable` / the class bijection out of `relation.zig` into
`semantic_algebra.zig` (§4), then make `emit_convert_edge_from` consult the fact
set instead of matching target spellings. The primitive edges become authored
store edges with real `Properties`, and `f64 -> i8` starts diagnosing as
narrowing. This is the largest of the five and the "500 lines become 50" one:
the ladder is a table of edges pretending to be control flow.

**R6 · world — decide the owner before writing the second one.**

## 7 · What was collapsed safely in this worktree, and its proof

**One divergence removed: `type_expr_is_native_scalar` no longer calls a boxed
dynamic table "native scalar".**

`src/codegen.zig:5052` — one line, the `.table_type` arm made storage-class-aware
so it agrees with the two other owners on the row that split three ways:

```zig
-            rt == .table_type or rt == .pointer;
+            (rt == .table_type and rt.table_type.storage_class != .dynamic) or rt == .pointer;
```

This is the **`.dynamic` row of §2.1** — the one where `C` said native and both
`A` and `B` said boxed. It is exactly the GAP-092 failure shape, and it was the
only one of the seven splits that could be closed without changing any measured
number.

Proof it is safe — every gate re-run, before and after:

| gate | baseline | after | exit |
|---|---|---|---|
| `zig build` | ok | ok | **0** |
| `zig build unit-test` | 1161 pass / 1 fail | 1161 pass / 1 fail | 1 (pre-existing) |
| `zig build native-census` | native **127** · bail 67 · reachable 194 | native **127** · bail 67 · reachable 194 | **0** |
| `zig build lsp-gate` | FAIL (legend re-derives) | FAIL (legend re-derives) | 1 (pre-existing) |

**The stated baseline for `agent-smoke` was stale and this work corrects it.**
The order recorded it as "RED on GAP-102 only". At `6598f50` it is **also RED on
`lsp-gate`**:

```
FAIL the committed legend re-derives from docs/spec/roles.md —
     regenerating changed the block — commit the regeneration, do not hand-edit it
lsp-gate: FAIL — 1 check(s) failed
```

Proven pre-existing by single-variable test, not by argument: the one-line
codegen change was reverted with `git checkout -- src/codegen.zig`, the tree

`tools/lsp/src/server.duo`. Note the gate REWRITES that file when it runs, so a
session that runs `agent-smoke` and then commits broadly will sweep the

The single unit-test failure is `relation.test.an eq family composes

**Native census did not move**, which is the number that would have caught a

remaining six splits in §2.1 all DO change behaviour and are deliberately left

are supposed to delete, and a test that pins a defect in place is the wrong
artifact. They should be re-added, inverted to assert AGREEMENT, as the closing
