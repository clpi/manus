# GAP-108 — the native backend has no module storage: a file-scope binding is per-function

**Status:** OPEN (P0, silent wrong answer) · **Filed:** 2026-08-09
**Law:** §3 MEASUREMENT HONESTY · backend-independent semantic contracts
**Found by:** the constant-branch lane, reproduced here on the branch tip.

## Reproduced

```duo
total = 5

show(): i64
    total

main(): i64
    total = 8
    a: i64 = total
    b: i64 = show()
    print(a)
    print(b)
```

```
--backend=direct   ok compile   8|5|
--backend=c                     8|8|
```

**C is right.** A file-scope binding is one storage location; writing 8 in
`main` must be visible in `show`. The direct backend answers with the
INITIALIZER.

## Cause

There is no module-level storage in the native path at all:

```
grep -nE "global"  src/native_backend.zig   -> one comment, no storage
grep -nE "global|module_scope|file_scope"  src/dnir_lower.zig
                                            -> unrelated ("runtime global by name")
```

A file-scope binding is lowered as an ordinary LOCAL, per function, each
re-materialized from its initializer. So `main` and `show` hold two different
`total`s, and neither write nor read crosses. Writes are invisible in both
directions — `show` writing would be equally lost.

## Why this is worse than its size

**It is silent and it is shape-independent.** No bail, no diagnostic, `ok
compile`. Any program with a mutable file-scope binding read in more than one
function answers wrongly on the native path and correctly through C, so:

- the two backends disagree on a basic semantic contract;
- the disagreement is invisible to any test asserting only one backend;
- and it was masked further because `--backend=c` could not compile a mutable
  file-scope scalar AT ALL until earlier today, so the differential that would
  have caught it did not run.

Two defects hid each other. That is the argument for backend differentials being
a gate rather than a convenience.

## The repair, and the interim

**Real repair:** module storage — a data section (or frame-independent slot)
with one address per file-scope binding, loaded and stored rather than
re-initialized. That is a backend capability, and it is also what a self-hosted
compiler needs for its own globals, so it is on the SHC spine rather than beside
it.

**Interim, if the real repair is not immediate:** REFUSE. If a file-scope
mutable binding is assigned anywhere outside its initializer, decline to lower
natively any function that reads it. A bail is a correct answer through C; the
current behaviour is a wrong answer. Same trade as the spiller refusal shipped
today, and it should be measured the same way — name the native-census cost
rather than asserting it is small.

**Not attempted here** because the cost is unmeasured and the conservative rule
("any module with a written file-scope binding") could be broad. Whoever takes
it should measure the census delta first and report it, per the spiller
precedent.

## Do not

**Do not fix this by making the initializer run in every function.** That makes
reads agree and leaves writes lost, which converts a visible disagreement into a
subtler one.

**Do not assume `const` is unaffected.** An immutable file-scope binding
re-materialized per function is only accidentally correct — it answers the same
value because nothing writes it. The storage defect is identical; only the
symptom is absent.
