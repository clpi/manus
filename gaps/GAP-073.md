# GAP-073 — the role taxonomy is not implementable as written

**Status:** OPEN (a finding about the LAW, not the code) · **Filed:** 2026-08-08
**Law:** H-2 "the 18-role taxonomy is CLOSED" · H-4 (hue = semantic space) ·
Pass 117 §0g "FINE SPLITS ARE LAW" · G-TOTAL

Building the G-TOTAL instrument produced an instrument that correctly reports
**exit 1**, and the reason it cannot reach green is that the law it enforces does
not close.

## H-2 says 18. Seventeen are derivable, and the count cannot close at 18 anyway

Passes 113-119 have **no document in `docs/spec/`** — `CLAUDE.md` §0d and §0g
are the entire surviving text. Every role H-4 actually names, by hue:

| hue | roles | n |
|---|---|---|
| red — law | `keyword`, `copula` | 2 |
| orange — descriptor | `descriptor`, `anchor`, `union` | 3 |
| purple — callable | `callable`, `invoke`, `action`, `opcode`, `mnemonic` | 5 |
| blue — value at rest | `number`, `case`, `literal`, `register` | 4 |
| green — data flow | `walk`, `pipe`, `witness` | 3 |

**17.** The 18th is unnamed; `comment` and `name` are the candidates and neither
is derivable from the text, so neither was invented.

But 18 is not reachable in the other direction either. §0g's **"fine splits are
law"** requires distinct roles for at least twelve more constructs — `=` bind /
`+=` update / `==` relation / level parens / parameter parens / grouping /
descriptor braces / comma / `[space walk]` / unit `*` / dnir `=` and `->` /
`bor` — and H-4 gives none of them a hue. The list then ends open, with
"per-language leftover roles".

Reading the fine splits as sub-role *modifiers* would rescue the number, and
that reading was considered and **rejected**: H-1 says the `:` and `|` splits are
"two roles, two colors", and §0g lists `=`/`+=`/`==` in exactly that register.

## The largest hole is not a fine split: ordinary names have no hue

H-4's blue is "numbers, `.cases`, literals, `%values`, registers". A plain
binding — `x`, `total`, `lx` — is none of those, and it is **the most common
token class in any real file**. H-6 says the role function is TOTAL and every
character has a role. Those two cannot both hold today.

This is why coverage measures **20%** and not something close to 100: the
instrument is honest about a hue that was never assigned.

## §0d's spacing rule is not the decider for `:`, and grammar.md already says so

§0d: *"canonical layout makes L1 lexical: copula `:` is spaced (`x: f64`),
invoke `:` is tight (`lx:read`)."*

`docs/spec/grammar.md` R1 gives the real rule: **IS never takes an argument
group; INVOKE always does.** Spacing is a corollary of canonical layout, not the
discriminator. They disagree on `count:u32` — spacing calls it invoke, R1 calls
it a copula, and R1 is right. That spelling is in the corpus.

Two law documents I landed today disagree; grammar.md wins on the merits and
§0d's sentence should be demoted to "canonical layout renders this
distinguishable" rather than "decides it".

## Seven of the seventeen are unimplementable today

`action` needs the world graph · `opcode` / `mnemonic` / `register` need dnir and
ISA surfaces that have no grammar in the tree · `case` is a SEMANTIC decision by
grammar.md R2, not a lexical one · `pipe` is inseparable from `bor` without the
graph · `witness` has no surface at all (gap[064]: `why` is an undeclared
function).

## The instrument, and why it does not ratchet

`scripts/role_scan.duo` + `zig build role-scan`:

```
coverage    20%   44 of 219 bytes carry one of the closed 17 roles
ambiguity   12    spans with two candidates and no deciding rule
mismatch     0    scan agrees with the hand-written sidecars
            exit 1
```

**Deliberately no ratchet.** A budget here would convert an unwritten rule into a
satisfied number — the exact failure this repo has been correcting all day. Both
numbers close by WRITING LAW, not by tuning a threshold.

The gate is proven able to go green (control C below), which matters: without
it, a red gate is indistinguishable from one hard-coded to fail.

## Controls

| control | exit | result |
|---|---|---|
| A — mislabel one span in a copy | 1 | `mismatch 1`, exact span named |
| B — delete a span row | 1 | `mismatch 12` — deletion cascades; a short list cannot pass |
| C — synthetic all-hued corpus | **0** | `coverage 100%`, PASS — **the gate can go green** |
| D — one byte's role moved outside the 17 | 1 | coverage 100% → 66% |

Plus five per-run: population; **tiling** (spans must tile each file in order,
non-overlapping, in bounds, gaps whitespace-only — this is what makes the
denominator real); comparator both halves; coverage counted twice by different
paths then cross-checked by striking the largest role; sidecar reader accepts a
span row and rejects prose.

A false green was caught by the harness's own control: the first scoring script
returned a confident `TOTAL 0` because this shell is fish and `$FILES` did not
word-split.

## What closes this

1. **Name the 18th role, or admit the set is open.** "Closed at 18" is currently
   neither true nor reachable.
2. **Give ordinary names a hue.** Nothing else moves coverage materially.
3. **Assign hues to the §0g fine splits**, or restate them as modifiers — but
   then H-1's "two roles, two colors" needs amending to match.
4. **Demote §0d's spacing sentence** in favour of grammar.md R1.

Sidecars are `<fixture>.roles.duo`, not `*.roles`: §0d asks for `*.roles`, §1's
last deny row is "any non-`.duo` file", and `audit100`'s `nonduo` budget has zero
slack. The epoch-2 protocol resolves it — the sidecar is both, holding an
ordinary Duo table.
