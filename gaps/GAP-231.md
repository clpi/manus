| Why it is a law defect and not a C bug |

| # | directive |
|---|---|
| 1 | `docs/spec/law.md` §5: "`()` is ordinary application. |
| 2 | It never means table indexing." `CLAUDE.md` says the same from the source side — "Computed or indexed aggregate access uses projection: `table[key]` and `row[1]`. |
| 3 | Ordinary `value(args)` remains application and never table indexing." |

| # | directive |
|---|---|
| 1 | So the source wrote a projection, and the C realizer emitted an APPLICATION. |
| 2 | The two faces `law.paren.one` keeps separate were collapsed at the realization boundary, and C — which also separates them — refused the result. |
| 3 | The defect is that the projection fact did not survive to the emitter, not that C is strict. |
