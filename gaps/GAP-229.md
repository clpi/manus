## Why it is not a wrong answer TODAY, and why that is not a reason to leave it

| # | directive |
|---|---|
| 1 | `effect: none` licenses CSE, hoisting, whole-relation folding and speculation. |
| 2 | Two consumers read it, and neither can reach this shape: |

- `comptime.foldRelationBody` binds module-scope initializers into the fold's
  scope and refuses one whose binding is written (`moduleBindingConstant`,
  GAP-225), and it never bound a `global` declaration at all. So a body reading
  `_pos` fails closed on the unbound name.
- `native_backend.ifConvArmOpAdmissibleTwoSided` admits only single-cycle
  integer ALU work, so a `call_direct` is refused by SHAPE.

| # | directive |
|---|---|
| 1 | Both are accidents of coverage rather than of the card. |
| 2 | The reduction that would convict it is a consumer that hoists an effect-free call out of a loop that also mutates, and the tree does not have one yet. |

| 2 | The rows are RAW: whether a read is an observation is not stored, because that depends on the write column, and the two license opposite decisions. |
| 3 | Projected in the graph export as `reads`, beside `mutations`, at schema v15. |

| # | directive |
|---|---|
| 1 | **One producer.** The same lexical lift that owns the write half. |
| 2 | The bindings walk (`liftBindingsInStmts` → `liftBindingsAtScope`) now carries the whole `ast.Block` — the tail expression was invisible to it before, and `_at`'s entire observation sits in tail position — and walks every statement's expressions (`noteExprReads`, mirroring `place.reachExpr` member for member) against the shadow roster AS IT STANDS: an initializer is read before its name binds, loop bounds before the loop variable, a `repeat` condition inside the body's extent. |

## Acceptance, measured

1. The same jq over `lib/compiler/comptime.id` now prints
   `["_hex_val", "_is_digit"]`. `_at` moved and carries
   `effect: {card: "one", id: <_src>}` — grounded at the exact binding read
   (`groundRow`'s lowest-entity tie-break picks `_src` of the two; both rows
   `_at → _pos` and `_at → _src` are in `reads`). The closed-function pair did
   not move.
2. `gate/effect.sh` records the movement in GAP-225's shape (the third ledger
   row), and `one` names the binding read. The live census is the runner's:
   `sh gate/effect.sh --census-only` prints the current partition, and the
   gate's own `MIN_*` floors are where the numbers live. Direction of the
   movement at this close, stated without pinning a value here: every moved
   card paid `none` → `one` and `unknown` did not move — the `none`s that
   moved were not proofs (the GAP-225 argument applies verbatim), so the
   floors were raised to the measured values IN THE GATE.
3. The control in the other direction holds, at the specimen this record
   misnamed as `lib/compiler/native.id` — it is `explore/native.id`, `ring =
   2147483647`. That module has ZERO mutation rows, `ring` is read by
   `affine`, `binom3`, `doloop`, `expr` and more, and its `effect: none`
   population is unmoved: the write column is the discriminant, so a module
   binding nothing writes stays a constant. The unit test pins the same shape
   ("reading a mutated module binding is an observation; a constant read is
   not"): `peek` reading written `cursor` → application effect
   `one(cursor)` with mutation card `none` (a read is not a write); `still`
   reading never-written `fixed` → effect `none`; both raw rows present and
   sparse.
