# GAP-229 — reading a mutated module binding is not published as an observation

**Status:** CLOSED · **Closed:** !2026-08-25T00:00:00Z
**Priority:** P2 · **Kind:** missing_fact
**Filed by:** claude-mutation
**Files:** src/semantic_graph.zig,src/graph_query.zig,gate/effect.sh

## The defect

`gaps/GAP-225.md` gave the graph the WRITE half: a relation whose body assigns
a module-scope binding names that binding (`SemanticGraph.binding_mutations`), the
mutation column publishes the closure, and `publishApplicationEffects` refuses
to call such a relation unobservable.

The READ half is unpublished. `_at` in `lib/compiler/comptime.id` reads `_pos`
and `_src` — two `global`s that `_skip_ws`, `_eat`, `_number` and `_prim` all
advance — and still publishes `effect: none`:

    zig-out/bin/idol graph lib/compiler/comptime.id \
      | jq -r '(reduce .nodes[] as $n ({}; .[$n.id|tostring]=$n.name)) as $nm
               | [.applications[] | select(.effect.card=="none") | $nm[.relation|tostring]] | unique'

    ["_at", "_hex_val", "_is_digit"]

`_hex_val` and `_is_digit` are honest — they are closed functions of their
operands. `_at` is not: its answer depends on when it is called.

## Why it is not a wrong answer TODAY, and why that is not a reason to leave it

`effect: none` licenses CSE, hoisting, whole-relation folding and speculation.
Two consumers read it, and neither can reach this shape:

- `comptime.foldRelationBody` binds module-scope initializers into the fold's
  scope and refuses one whose binding is written (`moduleBindingConstant`,
  GAP-225), and it never bound a `global` declaration at all. So a body reading
  `_pos` fails closed on the unbound name.
- `native_backend.ifConvArmOpAdmissibleTwoSided` admits only single-cycle
  integer ALU work, so a `call_direct` is refused by SHAPE.

Both are accidents of coverage rather than of the card. The reduction that
would convict it is a consumer that hoists an effect-free call out of a loop
that also mutates, and the tree does not have one yet.

## What landed

**The fact family.** `SemanticGraph.BindingObservation { relation, binding }` —
one relation reads one exact module-scope binding — stored in
`SemanticGraph.binding_reads`, sparse (repeated reads are one row), accessor
`bindingReads()`. The rows are RAW: whether a read is an observation is not
stored, because that depends on the write column, and the two license opposite
decisions. Projected in the graph export as `reads`, beside `mutations`, at
schema v15.

**One producer.** The same lexical lift that owns the write half. The bindings
walk (`liftBindingsInStmts` → `liftBindingsAtScope`) now carries the whole
`ast.Block` — the tail expression was invisible to it before, and `_at`'s
entire observation sits in tail position — and walks every statement's
expressions (`noteExprReads`, mirroring `place.reachExpr` member for member)
against the shadow roster AS IT STANDS: an initializer is read before its name
binds, loop bounds before the loop variable, a `repeat` condition inside the
body's extent. The resolution is `moduleBindingNamed`, factored OUT of
`noteModuleWrite` so the read half and the write half adjudicate shadows
identically — one resolution, two fact producers (`publishBindingMutation`,
`publishBindingRead`), each validating the entity exactly as the other does.
`@x` (world-face names) are excluded: they read the current world, never a
lexical binding.

**The derivation, and it is a join.** `publishApplicationEffects` blocks AND
grounds a relation whose read row names a binding SOME `binding_mutations` row
writes — the observation is `read × written`, derived at the one producer that
already derives the write consequence, never stored as a judgment on the read
row. It sits under `IDOL_MUTATION_SEVER` with the two write loops,
necessarily: the observation is derived FROM the write column, and a sever
that emptied the write consequence while leaving this join standing would let
`gate/speculation.sh` attribute surviving refusals to a column it had just
severed. Measured: with the column severed, `_at` (and everything else in
`comptime.id`) returns to `effect: none`; the raw `reads` rows stay published,
exactly as the raw `mutations` rows do.

**No new consumer.** The fact is the deliverable. `comptime.foldRelationBody`
still refuses this shape by coverage (it binds no `global` declaration, so a
body reading `_pos` fails closed on the unbound name), and
`native_backend.ifConvArmOpAdmissibleTwoSided` still refuses by shape; both
accidents now have the exact fact standing in front of them. GAP-202's
speculation work is where a consumer reads it deliberately. Convergence noted,
not refactored: `dnir_lower.collectModuleGlobals` asks `moduleBindingWritten`
for STORAGE, a physical requirement on the write side only — reads change no
storage decision and that query is untouched.

**Bounded coverage, recorded.** `noteExprReads` does not descend into
`func_expr`, `list_comp`, `match_expr`, `quote`/`unquote`, `macro_call`, and
the statement walk has no `.match_stmt` arm — the same set the WRITE walk does
not model. A read inside one publishes no row, which under-blocks: the same
missing-fact class this column shrinks, one seam narrower now, and the
exhaustive switches break the build when the AST grows a face.

## Acceptance, measured

1. The same jq over `lib/compiler/comptime.id` now prints
   `["_hex_val", "_is_digit"]`. `_at` moved and carries
   `effect: {card: "one", id: <_src>}` — grounded at the exact binding read
   (`groundRow`'s lowest-entity tie-break picks `_src` of the two; both rows
   `_at → _pos` and `_at → _src` are in `reads`). The closed-function pair did
   not move.
2. `gate/effect.sh` records the movement in GAP-225's shape (the third ledger
   row), and `one` names the binding read. Census, `--census-only`, this tree:

       examples       before  none 1058   one 169   unknown 151
                      after   none 1057   one 170   unknown 151
       examples lib   before  none 3716   one 380   unknown 1033
                      after   none 3702   one 394   unknown 1033

   Every moved card paid `none` → `one`; `unknown` untouched. `MIN_ONE` is
   pinned at the measured 170; `MIN_NONE` stays 1019 (the GAP-225 argument —
   these `none`s were not proofs — applies verbatim).
3. The control in the other direction holds, at the specimen this record
   misnamed as `lib/compiler/native.id` — it is `explore/native.id`, `ring =
   2147483647`. That module has ZERO mutation rows, `ring` is read by
   `affine`, `binom3`, `doloop`, `expr` and more, and its `effect: none`
   population is unmoved: the write column is the discriminant, so a module
   binding nothing writes stays a constant. The unit test pins the same shape
   ("reading a mutated module binding is an observation; a constant read is
   not"): `peek` reading written `cursor` → application effect
   `one(cursor)` with mutation card `none` (a read is not a write); `still`
   reading never-written `fixed` → effect `none`; both raw rows present and
   sparse.

Order (read-before-write vs write-before-read within one binding) is still not
carried — the column is flow-insensitive, like the write half. That is the
known remainder for a consumer that wants to commute two pure readers.
