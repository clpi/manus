## Obligation

The direct native backend (`idol run`, `emitArm64ModuleWithGraph`) silently
miscompiles several nested-control-flow shapes: it compiles and runs, but
produces wrong results with no diagnostic. Silent wrong-answer lowering violates
`law.fallback.zero` (no silent fallback) and blocks every self-hosted control flow
richer than a single flat loop — including an exploratory pure-`.id` compiler
(`explore/native.id`), which had to route ALL nesting through function recursion
and flat/`for` loops to stay correct.

These are wrong-answer defects, not "outside the subset" refusals (which the
backend already reports cleanly as DNB00x). A refusal is acceptable at S0; a
silent wrong answer is not.

## Reproductions (each compiled OK and returned the wrong value)

1. **Sibling `while` after a nested loop is skipped.** A `while` at the same
   indent immediately after an outer `while` that contains a nested loop does
   not execute its body (loop variable observed unchanged afterward). Replacing
   it with a `for` executes correctly.

2. **`while` whose condition calls a function is mis-evaluated.** A shunting-yard
   pop-loop `while ot > 0 and ops[ot] != 40 and prec(ops[ot]) >= prec(c)`
   collapsed to left-to-right (the condition behaved as always-true). Moving the
   precedence into a parallel array (no call in the condition) fixed it.

3. **Value reductions inside a nested `while` are dropped.** Inlined stack
   reductions (`val[vt] = apply(o, a, b)` with `vt -= 1`) inside the operator
   pop-`while` produced wrong sums for 3+ operators, while the identical
   reduction inside a `for` flush produced correct results.

Positive controls that DO work: single flat `while`/`for`, `while` inside an
`if` (not inside another `while`), function recursion (mutual + self-recursion), method
calls in the body, `for`-loop bodies with reductions.

## Notes

Discovered while building `explore/native.id`, a from-scratch pure-Idol
expression compiler that lowers to the semantic/physical floor (`movz/movk
x0,#k ; ret`) via compile-time evaluation + closed-form recurrence solving. The
workarounds (recursion for nesting, flat/`for` loops, no calls in loop
conditions, parallel-array precedence) are load-bearing evidence of the exact
shapes that miscompile.

**Those workarounds are now stale documentation, and they are load-bearing in
the wrong direction.** Two sites still instruct every later reader to avoid the
shapes:

    explore/native.id:31   "NESTED `while` bodies are miscompiled. So nesting is
                            expressed only through function recursion, every
                            loop is flat and flag-controlled"
    idol-native/sha.id:7   "Compression is ONE flat loop (S0 miscompiles nested
                            `while`)"

Both were re-run for this measurement: `idol-native/sha.id` answers 16 under
`--backend direct`, the number `gate/all.sh` pins, and every shape its comment
says to avoid is proven correct by `gate/nest.id` beside it. A comment that
names a defect is what every later reader PLANS AROUND, so it outlives the
defect by exactly as long as nobody re-runs it — the failure `AGENTS.md` records
under "numbers live in exactly one place, and that place runs", here in its most
expensive form, because the thing that decayed was a whole compiler's
architecture. Correcting the two comments is a source change with its own
before/after and belongs to whoever next touches those files, not to this note.

**The instrument, not the verdict, is the transferable part.** Every defect
found in this pass was found by DIFFERENCING TWO REALIZATIONS OF ONE PROGRAM
against a truth computed outside both — never by reading lowering code, and
never by a unit test asserting that instructions are present. The one live
wrong answer this pass found (GAP-174) was in the backend nobody was
suspecting, and it was three lines long.
