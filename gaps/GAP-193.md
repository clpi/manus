# GAP-193 — semantic threaded execution and generated superinstruction tiering

**Status:** OPEN · **Filed:** !2026-08-18T16:45:00Z
**Priority:** P1 · **Kind:** research_gap
**Filed by:** devin-semantic-20260818
**Files:** docs/spec/constitution.md, docs/spec/law.md, src/eval.zig, src/threaded.zig

Establish an ultra-fast baseline execution tier based on semantic threaded code
and mechanically generated superinstructions. Forth and Gforth prove that threaded
chains of primitive execution tokens provide near-instant startup; Deegen proves that
superinstruction selection, quickening, and tiering transitions can be mechanically
synthesized from language semantics rather than handwritten.

## Current measured boundary

Idol compiles directly to machine code via `dnir_lower.zig` and `native_backend.zig`.
Small or cold relations pay the full machine compilation latency.

**Crossed:**

- Direct native backend compiles in milliseconds.
- Copy-and-patch and stencil compilation evaluated.

**Still missing:**

- Semantic threaded realization tier: application IDs -> primitive execution tokens.
- Dynamic superinstruction fusion: frequent semantic sequences (e.g. `read -> add -> store`)
  automatically fused into single-dispatch execution tokens.
- Multi-tier realization progression:
  1. Semantic threaded execution (zero compilation delay, instant startup)
  2. Generated superinstructions (quickened hot paths)
  3. Copy-and-patch native stencils (sub-millisecond native emit)
  4. Fully optimized native realization (full microarchitectural optimization)
- Deegen-style mechanical generation of the baseline VM from C0 relation semantics.

## Required order

1. Define threaded execution and stencil token models in C0.
2. Build mechanical superinstruction generator from semantic graph patterns.
3. Wire execution tiering transitions based on call/loop execution frequency.
4. Measure and optimize cold relation startup latency.
5. Prove identical observable behavior across all execution tiers.

## Closure acceptance

Close when short-lived or cold scripts start in microseconds via semantic threaded
execution and hot loops seamlessly transition to optimized native code without
handwritten VM interpreter code.
