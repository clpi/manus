**Priority:** P0 · **Kind:** regression

| compiler | result |

Bisected across three compilers built from those exact subjects. **This is a

## The exact shape

A module-scope binding **declared with an explicit type**, reassigned from an
expression that **mentions itself**, then **interpolated**.

| source | result |
| --- | --- |
| `t: i64 = 0` / `t = t + 5` / `stdout:write("{t}\n")` | **REFUSED** |
| `t: i64 = 0` / `t = t + 5` / `s: str = "{t}"` / `print(s)` | **REFUSED** |
| `t: i64 = 0` / `t = t + 5` / `print(t)` | compiles, `5` |
| `t: i64 = 0` / `t = 5` / `stdout:write("{t}\n")` | compiles, `5` |
| `u: i64 = 1` / `t: i64 = 0` / `t = u + 5` / `stdout:write("{t}\n")` | compiles, `6` |
| `t = 0` (untyped) / `t = t + 5` / `stdout:write("{t}\n")` | compiles, `5` |
| the same body inside `main: i64 = ()` | compiles, `5` |

Not `stdout:write` — interpolation into a `str` binding refuses too. Not the
loop — no loop is needed. Not reassignment alone.

## Why

GAP-209's fix correctly drops `t` from `ModuleConsts` (it is rewritten, so the
recorded initializer is stale) and grants it module storage instead. The
interpolation hole's operand then has to resolve its type through the module
global rather than a constant — and `exprIsStr` does not resolve it, so the
concat chain is not taken and `.concat` falls to the `else => bailWith` at
`src/dnir_lower.zig:9438`.

**The hole in `exprIsStr` pre-existed.** GAP-209's fix exposed it by moving this
shape from the constant path onto the storage path.

## The trade, stated plainly

GAP-209's fix turns a class of **silent wrong answers** into correct answers
(`42 43` where the oracle says `42 43`, previously `42 1`). It also turns this
class of **working programs** into refusals. Refusing beats answering wrong, so
the fix should not be reverted — but the cost was measured as zero and was not.

## Why the corpus missed it

809 files, 179 both compiled and ran, 0 status differences. The corpus contains
no program with a typed module binding, self-referential reassignment, and
interpolation of that binding. As with GAP-207 and GAP-209, **only a
hand-written program in the neighbouring shape finds it.**

## Acceptance

The graph publishes the checked interpolation-hole value with its exact
descriptor and value → module-binding edge. `exprIsStr` and the
integral/float/pointer siblings consume that graph route. `ModuleGlobals.types`
remains only a transitional fallback for occurrences outside the producer's
declared domain; damaging the published binding edge must make this occurrence
fail closed rather than reconstructing its type from the name. Then this
program compiles again **and** GAP-209's oracle rows still hold. Both controls
are required in the same run.

## Closure

The checked-name producer now owns name occurrences inside application operand
expression trees.  It publishes one value id carrying Sema's exact descriptor
and the exact value → binding edge.  Immediate operands of resolved
applications remain owned by the existing application-pack producer; nested
function and block bodies are explicitly outside this producer domain and stay
unvisited until their scope-owned producer admits them.

DNIR distinguishes four states for the exact occurrence:

- `known`: the graph descriptor decides the scalar class;
- `unknown`: the producer resolved the binding but Sema did not prove a
  descriptor, so transitional physical facts may still answer;
- `invalid`: the producer visited the occurrence but its binding route is
  absent or contradictory, so module-name reconstruction is forbidden;
- `unvisited`: the occurrence is outside this bounded producer domain.

This closes the reported interpolation refusal without pretending the
bootstrap `stdout:write` call has a resolved `ApplicationFact`.  General
projection/application publication, including `xs[1]` and foreign-field result
identity, remains open.

## Executed evidence

- the semantic-graph positive proves exactly one nested `t` value, descriptor
  `i64`, and `Card.one(module_binding)` under the honest bootstrap call;
- the DNIR damage control removes that value's binding edge and requires the
  named `concat` refusal, proving `ModuleGlobals.types` cannot mask damage;
- the focused Zig suite passes `1693/1693` tests;
- Debug direct, ReleaseFast direct, and wasm32-wasi/Wasmtime each print `5`;
- GAP-209's linear control still prints `42` then `43`, and its loop control
  still prints `10` then `11`;
- the 211 previously direct-lowerable corpus subjects, excluding the
  deliberately cwd-sensitive fixture, have identical stdout and status.

The coverage census records the acquisition cost rather than calling it a
performance win: application publication stays `4992/14932` and blockers stay
`4655`, while graph size grows from `80719` to `87960` nodes and `15566` to
`22127` edges (`44270` to `51511` values).  The new facts have a real DNIR
consumer, but packed storage and broader application continuity remain required
before this is a closed optimization route.
