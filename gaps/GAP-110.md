> **Reconciled 2026-08-13:** `AT-APPLY` (`@{ … }` as ambient-descriptor
> application) is **RETIRED**. The `@{}` collision is resolved decisively in
> favor of world injection only (`law.injection.only`): `@{ … }` derives a world
> by injection; a descriptor is an ordinary table `{ … }` with no sigil. The
> ladder below is now two rungs; the `@{ x, y }` row is historical only.

## The ruling

Two source projections of ONE application relation, most explicit to most
inferred:

```duo
point{ x, y }        -- descriptor stated
{ x, y }             -- descriptor = expected descriptor
```

with `{…}` remaining **semantically neutral** — a structured pack, not a hidden
second constructor — and demand supplying the omitted subject
(`expected point + pack{x,y} -> apply(point, pack)`). The canonicalizer then
drops whatever is uniquely implied (OMIT-DERIVABLE).

## Measured — the hierarchy is upside down

```
point{ 1.0, 2.0 }              APPLY-ONE        prints 1          WORKS
p: point = { 1.0, 2.0 }        EXPECT-APPLY     broken C on READ
make: point = (a, b) { a, b }  CALLABLE-DEMAND  undeclared 'make'
@{ 1.0, 2.0 }                  AT-APPLY         expected expression
```

**Only the form that states everything works.** Every form the ruling wants
canonical source to shrink toward is unimplemented, and none of them
DIAGNOSES — each fails as a C compile error or a parse error.

### EXPECT-APPLY, isolated

```duo
p: point = { 1.0, 2.0 }
print("built")        -- prints `built`: construction is fine
print(p.x)            -- error: call to undeclared function 'lua_table_get_str_num'
```

and the control:

```duo
p = point{ 1.0, 2.0 }
q: point = p          -- annotation on an ALREADY-APPLIED value
print(q.y)            -- prints 2
```

So the annotation is not the problem and the pack is not the problem. **The pack
is never applied to `point`** — it stays a bare pack exactly as PACK says it
should, and demand does not supply the descriptor. Reading `.x` from a bare pack
takes the dynamic path, which emits a helper the module never declared.

That is the law working correctly at rung 1 (`{…}` stays neutral) and missing
entirely at rung 2 (demand supplies the subject).

## This is the same shape as the `@` finding, and that makes it a pattern

gap[107] measured the identical inversion on the ambient dyad: the `@` that
PREFIX-ZERO abolishes is the only `@` that functions, and the `@` that AT-ONE
reserves the sigil for does not parse.

Both `@{…}` and `{…}`-under-demand fail; `point{…}` works. So across two
independent consolidations the law asks for, **the implementation supports the
explicit spelling and not the inferred one.** The consolidations are exactly the
work that has not been done, which is worth stating plainly because the rulings
read as descriptions of the language and are currently descriptions of its
target.

## Order

1. **EXPECT-APPLY** is the highest-value rung and the smallest: a binding with a
   descriptor annotation whose RHS is a bare pack should apply that descriptor.
   The construction path already works and the annotated-value path already
   works — what is missing is the join. It also removes the current failure mode,
   which is a C compile error from a dynamic read.
2. **CALLABLE-DEMAND** next. `make: point = (a, b)` does not even bind `make`,
   so the annotated-callable form is not parsed as a callable binding at all.
   The ruling is explicit that this is a CONTEXTUAL PROJECTION — annotation +
   callable RHS -> result descriptor — and not a function-return-type grammar,
   so it should land as resolution, not as syntax.
3. **AT-APPLY** last, and only compositionally. gap[107] records the trap: do not
   implement `@{…}` as a descriptor-literal to make it parse, because that gives
   `@` the construction semantics AT-ONE exists to deny.

## Do not

**Do not make `{…}` mean "construct the expected descriptor".** PACK is explicit
that a bare pack stays a pack; the descriptor arrives from demand at the
application site. Collapsing them would create the second constructor mechanism
APPLY-ONE exists to prevent, and `a = { x, y }` would stop being an ordinary
positional value.

**Do not add a diagnostic that fires on a bare pack.** `a = { x, y }` with no
demand is legal and common. The diagnostic belongs where a descriptor IS
demanded and the pack cannot satisfy it.
