# GAP-022 — token text must be a slice into the SOURCE, not a copy

**Status:** open · **Filed:** 2026-08-07 · **Frequency:** 1
**Blocks:** SH-03 `tokenizeAuthority() == .duo_native` (the last step)

## The defect

A host `lexer.Token.text` is a slice **into the source buffer**, and the parser
relies on that: it does pointer arithmetic against `tok.text.ptr` to recover
absolute offsets.

`duo_lexer_tokenize_full` copies each token's bytes into a caller-provided text
arena and reports `text_off`/`text_len` **into that arena**. Tokens rebuilt from
it therefore point somewhere unrelated to the source, and the arithmetic yields
garbage.

## Repro

With `tokenizeAuthority()` returning `.duo_native`:

```
$ duo check examples/layout_attrs_test.duo
thread panic: index out of bounds: index 26286, len 188
  src/parser.zig:1073 parse_attribute_args
  src/parser.zig:1014 parse_one_attribute
```

188 is the file's length; 26286 is an arena pointer minus a source pointer.

Two compile-fail rows regress under the flip and no others:
`examples/layout_attrs_test.duo` and the `dump-c` case. Everything else is
byte-identical to the host-authority baseline.

## The fix

Publish each token's **absolute source offset**. The Duo lexer already has it —
its token text is `strm.sub(self.src, start, self.pos - 1)`, a substring of the
source — so `start` exists and is simply not exported. Replacing the arena
offset with the source offset lets the host slice the real source, after which
every existing pointer relationship holds and the text arena disappears
entirely (a copy nobody needed).

That is an ABI change to `duo_lexer_tokenize_full`, not a flag flip, which is
why the flip was reverted rather than patched around.

## Established before the revert

- The routing in `src/main.zig` genuinely drives the parser: corrupting the Duo
  stream by one token made the compiler fail to parse, proving dispatch was live
  rather than silently falling back.
- The Duo and host token streams agree **field for field** — kind, line, col,
  text, int_val, float_val (`src/duo_lexer_dispatch.zig` differential).
- Unit tests showed no new failure under the flip; the only delta was the
  git-dependent `git_preservation` test.

So the disagreement is not about token CONTENT. It is entirely about where the
text bytes live.
