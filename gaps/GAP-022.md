# GAP-022 — `#.src` parses as ruled and lowers to `strlen(<closure>)`

**Status:** open · **Filed:** 2026-08-07 · **Frequency:** 1 (every use)
**Blocks:** Pass 81 §0 — the `len` operator over an anchored-scope lens
**Sites:** `scripts/family_registry_census.duo` (LENS-1)

## The defect

Pass 81 §0 rules `#.src` canonical: the `len` operator applied to the applied
lens — `#(.src)`, "the length of *my* `src`". Operators compose with
anchored-scope lenses like any primary expression, and there is no ambiguity —
`.src` cannot be a numeral, since numbers need a leading digit.

**The parse is exactly as ruled. The lowering is not.** `.src` becomes a closure,
and `#` is then applied to *the closure itself* rather than composed into a lens
`(x) => #x.src`. The backend emits `strlen` against a `lua_Value` closure and the
C compiler rejects the type.

## Minimal repro

```duo
f(p: any): i64
    #.src
end
main(): void
    print(f({ src = "abc" }))
end
```

```
/tmp/duo_g22_lens.c:5706:19: error: passing 'lua_Value' to parameter of
    incompatible type 'const char *'
 5706 |     return strlen(lua_val_from_closure((lua_Closure*)duo_make_closure_0()));
```

The emitted line is the whole diagnosis: the closure is constructed
(`duo_make_closure_0()`), and then `strlen` is applied to it directly. Nothing
composes the operator into the lens body.

Control — the same length on a named subject works:

```duo
main(): void
    p = { src = "abc" }
    print(#p.src)      -- 3
end
```

## Severity

This is the **honest** failure of the three registry lowering bugs: it does not
compile, so nobody ships a wrong answer. Compare `PLACE-3` (`t:get(k)` returns
nil) and `LV-4` (`t:push(v)` drops the element), which are the same family of
"canonical form, no realization" but fail silently. Recorded at normal priority
for that reason.

Passing the lens where a lens is expected fails the same way, one layer out:

```duo
print(#vs:map(#.src))
```
```
error: call to undeclared function 'duo_make_closure_0'
```

## The fix

`#` over a lens must produce a lens, not a value: the operator composes into the
closure body rather than being applied to the closure. Every operator root in
§2.8 has the same shape, so a fix should be checked against at least one more
(`-.x`, `#.a.b`) rather than special-cased to `len`.
