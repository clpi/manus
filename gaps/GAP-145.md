## Required order

1. Add distinct Idol-owned token identities and compatibility/lawset status for
   text, bytes, Lua long text, canonical comment, Lua comments, shebang, and
   reserved backtick.
2. Generate compact grammar roles from the constitutional grammar owner. Parser
   consumers must use identities/roles, never delimiter text.
3. Add canonical and compatibility lexer differentials, including unchanged
   spelling with changed identity and changed spelling with preserved role.
4. Implement canonical multiline text normalization exactly once: omit the
   opening and closing structural newlines, remove the closing-delimiter indent
   from every nonblank content line, and diagnose insufficient indentation.
5. Preserve single-quoted Lua text under compatibility provenance and migrate
   it to double-quoted text before native Idol interpretation. Native single
   quotes then produce byte-sequence semantics; Unicode escapes remain rejected
   pending separate admission.
6. Make hash comment-only in canonical Idol and migrate length to the admitted
   subject-oriented `len` relation. Compatibility `#value` remains provenance,
   not a second native relation.
7. Project the same authority into parser, formatter, canonicalizer,
   Tree-sitter, LSP, MCP, generators, documentation, and corpus ratchets.
8. Migrate canonical source only after exact rewrites exist. Never replace
   historical single quotes or long strings textually without a semantic
   equivalence witness.

## Required controls

- Double-quoted text, single-quoted bytes, compatibility single-quoted text,
  and Lua long text have distinct token identity/provenance.
- One-byte demand can scalarize a byte sequence without changing its semantic
  literal identity.
- Canonical hash comments are trivia; canonical `#value` is rejected; Lua hash
  length is compatibility-only and resolves to canonical `len` semantics only
  through a witnessed projection.
- Backtick cannot reach process execution and is rejected in canonical source.
- A byte-zero shebang is distinct from an ordinary hash comment by source
  position fact.
- Parser classification changes with token identity, not delimiter text.
- Removing comments changes only trivia provenance, not semantic graph facts.
- Generators and Tree-sitter consume the authority projection rather than local
  spelling lists.

Passing the lexer differential is necessary but not sufficient. Close when:

- `KIND_STRING_LIT` and host `TokenKind.string_lit` are **deleted**, not a hole

  survive only as a collapsed arm name

The test is **literal zero on the old identity**, not “new kinds exist beside
legacy members.”
