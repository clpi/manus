## O3 first direct parser consumer (2026-08-30, base `61e0e951` + diff)

Callable-header classification is now the first production parser decision to
leave Zig. `src/parser.zig` projects each producer token once into a compact
physical fact (owner ordinal, line, column), then `lib/compiler/parser.id`
`header_signal_lx` answers typed/call/offside/condition/empty/nested header cases through
the same `token.grammarrole.*` owner. The 209-line Zig `headerSignal` and

### The consolidation

**The P0 in `GAP-207` and the O5 quote collapse are the same defect at two
depths, and the O5 census could not see the deeper one.**

`s = 'abc' ; print(s .. "Z")` printed `4308223088Z` at exit 0 with no
diagnostic on the pristine mirror of the base — a fresh ASLR'd address every
run. The mechanism: `exprIsStr` correctly answers "not text" for the byte
face, `concatOperandOk` read that as permission to ask `exprIsIntegral`, and
that predicate's `.name` tail admits any slot which is not f64 / str / ptr —
a NEGATIVE test sitting directly beneath a doc comment explaining that the
predicate is positive on purpose. `planConcat` then chose `%lld` for a
`const char*`.

So a face added anywhere in the compiler became a wrong answer HERE by
default. That is why the two are one subject: GAP-145 adds faces, and this
predicate answered for every face nobody had told it about.

### What is closed

`LowerCtx.byteseq_slots` is the third arm `GAP-207` asked for. It records the
byte face at the same store that records the text face; membership is the
descriptor the semantic graph already published for the quote
(`publishSourceQuote` -> `types.quotedLiteralType`), never `expr.quoted.quote`
off the AST; `types.isQuotedByteSequence` owns the shape so no consumer
restates `elem == .u8 and size == null`. `concatOperandOk` and the
`exprIsIntegral` `.name` tail now ask the positive question.

Three collapse sites are closed with it:

- `src/comptime.zig` folded a byte sequence into `.string`, a `Value` kingdom
  with no member for it. It declines now, which every caller of `eval`
  already handles as "fail closed, leave the body lowered".
- `src/codegen.zig` `known_lua_type_name_without_eval` answered the Lua

### The census instrument was structurally blind, and this is what it missed

`planConcat` is written `if (p.* == .quoted)` — a TAG TEST. The O5 number
that has been carried in this gap since it was first taken greps for a SWITCH
ARM, `^\s*(\.[a-z_, .]*)?\.quoted =>`, and cannot match a tag test at all.

    grep -h '^[[:space:]]*\(\.[a-z_, .]*\)\?\.quoted =>' src/*.zig | wc -l
    grep -h '== \.quoted\b' src/*.zig | wc -l

The second form is the larger surface by a factor of two and a half, it had
never been counted, and one of its members carried a wrong answer. One fact
had two answers decided only by whether the operand had a name:

    print('abc' .. "Z")            abcZ      folded in planConcat
    x = 'abc' .. "Z" ; print(x)    refused   lowerBinop

`gate/gap-145-consumer.sh` now counts it. It counts the SURFACE and says
plainly that it does not judge each member: most of those sites read a
literal as a NAME — a concept name, an `__emit` template, a field spelling —
where no text/byte law is observable, and no grep decides that line-locally.
A ceiling on a surface that was invisible is worth more than a blind count
that is wrong.

### The same defect at the egress relation, found by following the hint

`src/parser.zig` carries a hint on a real diagnostic telling people that "a
payload that is all braces and no holes — JSON, a C body, an awk program —
belongs in the byte face `'…'`". Following the compiler's own advice reaches
`stdout:write`, and `lowerWrite` ends in the same `else .i64` that
`exprIsIntegral` did:

    stdout:write('{"a":1}')            {"a":1}
    j = '{"a":1}' ; stdout:write(j)    4371891320     exit 0, no diagnostic

Both spellings reproduce on the pristine base. The literal one answered only
because it lowers to a `.str` value that `holds` recognises; the bound one
fell through. So the recommended idiom was the broken one, and the two
spellings of one fact disagreed again.

Here the answer is not a refusal. **Writing bytes to a byte stream needs no
textual law**, so the byte face belongs on the `.str` side of that selection —
which is also what makes the literal spelling right. `print` is deliberately
NOT changed with it: it is line-oriented text egress and already refuses a
byte sequence at the native-scalar precheck for both spellings.

### Ordered-work item 1: the obvious `read` substitution is a trap, measured

`scripts/treesitter_emit.id` `slurp` is `io.open` / `f:read("a")` / `f:close()`,

compat-face spelling standing in front of `split`, and `split` returns a list,
