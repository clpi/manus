## 6. World, home, reach, subject, place

| # | law |
|---|---|
| 1 | A world is the closed semantic table under which meaning is resolved. |
| 2 | It may carry bindings, descriptors, relations, facts, stage/target facts, authority, requirements, witnesses, and observer demand. |
| 3 | Authority is a fact in a world; world is not synonymous with authority. |
| 4 | Never conflate: |
| 5 | Absolute: |
| 6 | A place exists only when mutation, alias, address, lifetime, persistence, volatile/device behavior, or an ABI boundary makes location observable. |
| 7 | Scalars, parameters, homes, and immutable determined values are not places merely because a compiler implementation stores them. |
| 8 | `@` is the current world. `@member` accesses an exact current-world member; `@{ k = v }` derives a closed world with an exact fact delta; `thing@world` evaluates/qualifies `thing` under that world. |
| 9 | Injection does not mutate its source world and cannot manufacture authority from a boolean/string label. |
| 10 | Stage is a fact a world carries, so evaluation at a stage is evaluation under a world. `@(expr)` is the current world applied to an expression — `expr` resolved under the world resolving it, whose stage fact is the compile stage — and is therefore exactly `expr@{ stage = compile }`. |
| 11 | It is not a compiler directive and not a fourth use of the sigil; prefix `@` keeps its one meaning. |
| 12 | It follows that an operation whose whole content is "do this at compile time" is an ordinary relation applied under a stage-delta world, that a value absent at that stage is absent from that world rather than specially diagnosed, and that stage participates in world identity wherever it changes lawful realizations. |
| 13 | A local binding wins over an ambient projection. |
| 14 | Ambiguity fails closed—never first/last/load/path/hash order. |
