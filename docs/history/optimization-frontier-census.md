# Optimization frontier census — coverage map (research projection)

**Disposition:** research / audit projection — **not** semantic law, not a
workstream checklist, not an obligation register. Authority chain:
`docs/spec/law.md` → `docs/spec/constitution.md` → `gaps/GAP-*.md` →
`evidence/*` → this file.

**Purpose:** reconcile an external "nothing important may remain invisible"
compiler-capability census (875 numbered rows across 79 families, 2026-08) with
Idol's executed law, gaps, and evidence. Rows are **indexed**, not adopted as
875 independent tasks.

**Unifying criterion (Idol-native):** any optimization or capability belongs in
the one semantic graph when expressible as relations, facts, observations,
demands, laws, witnesses, transformations, worlds, or realizations. It must not
become another IR or subsystem unless irreducibility is proved
(`law.projection.one`, `law.fact.producer.one`, GAP-172 five-graph machinery).

**Structural completeness, not enumerative completeness:** new capability
enriches an identity (GAP-171 `I0`/`I1`/`I2`, relation-law algebra, candidate
provider protocol) — it does not mint a parallel optimizer kingdom
(`law.optimization.open`, `docs/demand-projection.md`).

## Five-graph index (census → machinery)

Every census family routes through GAP-172 graphs:

```text

Mechanical loop (`law.cost.closure`): measure → largest weighted debt → classify
`E.cause` → implement → validate (`law.optimization.validated`) → ratchet.

```

## Twelve-factor optimization state (census supplement, 2026-08-20)

The original census indexed six visible axes (identity, facts, demand, laws,
candidate, realization). The supplement argues the universal optimization state
should be **twelve interoperable algebras** over the same identities — not twelve
subsystems:

| factor | role |
|---|---|
| **identity** | what semantic thing is this? |
| **facts** | what is known? |
| **observations** | what differences can matter? |
| **demand** | which portions/qualities are required? |
| **laws** | what transformations/compositions are valid? |
| **change** | how do facts/outputs respond to input changes? |
| **correspondence** | what is equivalent across transformations/incarnations? |
| **search** | what alternative solutions are discoverable? |
| **proof** | which alternatives are actually lawful? |
| **cost** | what physical resources does each consume? |
| **world** | under what target/authority/deployment constraints? |
| **realization** | which lawful physical choice wins? |

**Architectural bet (supplement closing):** relational composition, observation
projection, world injection, demand propagation, change propagation,
equivalence, and realization selection are **queries over one graph** — not
separate compiler / query planner / DI / PE / incremental / AD / synthesis /
placement / foreign-adaptation kingdoms.

**Highest-leverage supplement differentiators for Idol today:**

1. **Minimal sufficient semantics** (rows 706–708, 779) — extends measured
   quotient-demand work (`docs/demand-projection.md`); find minimal input
   projection for demanded observation.
2. **Supercompilation as region protocol** (688) — unfold → propagate →
   generalize → fold → residualize; demand-aware equivalence (`≡_demand`).
3. **Relational solving modes** (690) — directionality as solving mode over one
   relation, not a second relation identity.
4. **Trusted-core + proof-carrying plugins** (693, 694, 759) — eBPF/Kops pattern:
   untrusted candidate → witness → small checker; plugins propose realization,
   never meaning.
5. **Boundary contraction / composition-driven fusion** (770–771) — generic
   `g ∘ f` when intermediate observation absent; cancellation/adjoint pairs.
6. **Semantic memoization & cross-build cache** (703–705) — key by relation +
   demanded facts + world; quotient by observer.

## Information frontier (census supplement 3, 2026-08-20)

Beyond recognizable compiler categories, the remaining frontier is **forms of
information about a computation** Idol does not yet model — and the physical work
that becomes removable once that information exists.

**Guiding question:**

> What information about a computation exists that Idol still does not model,
> and what physical work becomes removable once that information is available?

**Fact-value lattice (extends status legend):**

| value | meaning |
|---|---|
| **unknown** | no fact yet |
| **absent** | proven not to hold / not applicable |
| **possible** | finite exclusion set remains |
| **exact** | definite positive or negative fact |
| **contradictory** | conjunction impossible → region unreachable |

Negative knowledge, exclusion sets, and contradiction are first-class — not
rediscovered on every pass (rows 826–828).

**Generalize ↑ / specialize ↓** (row 800) joins refinement as a fundamental
bidirectional compiler operation: anti-unification discovers shared semantic
skeletons; re-generalization controls specialization explosion (801–802).

**Compiler graph liveness** (851–858): facts, proofs, and provenance have
lifetimes analogous to value liveness — dead semantic facts can be evicted from
compiler memory; the compiler itself gets store/recompute/compress economics.

**Highest-leverage information-frontier differentiators:**

1. **Anti-unification / semantic generalization** (800) — shared skeleton +
   varying facts; re-generalize to control code explosion.
2. **Minimum-description factoring** (801) — common meaning + small deltas;
   reduces compiler retained state.
3. **Negative knowledge & contradiction** (826–828) — explicit cannot-facts;
   unreachable regions deleted; unsat cores for diagnostics.
4. **Explanation-minimal diagnostics / why-not** (830–831) — smallest
   missing/conflicting fact set; optimization refusal minimization.
5. **Fact liveness & compiler memory hierarchy** (852, 856–857) — evict dead
   facts; hot/cold/compressed/recomputable compiler state.
6. **Group-action quotienting** (815) — observation-invariant group actions
   collapse search/state spaces (extends quotient-demand philosophy).
7. **Guard algebra** (832–837) — minimal guard synthesis, sharing, implication,
   profile/world sealing elimination.
8. **Distributed untrusted compilation** (873–875) — proof-carrying workers,
   optimization marketplace, vendor semantic providers (FTC-012 endgame).
