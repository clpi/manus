# Idol metaprogramming architecture

This page is a current projection, not a directive catalog. The sole semantic
law is [`docs/spec/constitution.md`](spec/constitution.md), and canonical
source uses `.id`.

Idol metaprogramming operates on graph-owned identities, relations, facts,
dependencies, demands, laws, worlds, provenance, and transformations. It does
not require an independent macro language, AST kingdom, directive namespace,
or string-dispatched compiler API.

## Semantic amplification

One authoritative relation, descriptor, or law may project validated:

- implementations and realization candidates;
- documentation and completion;
- diagnostics and canonicalization;
- tests, fuzz cases, and benchmarks;
- foreign mappings and ABI evidence;
- MCP and LSP views;
- invalidation and regeneration dependencies.

Generation is useful only when every projection traces back to the same facts,
regenerates completely, and preserves semantic identity. Generated volume is
not the objective; duplicated authority and manual obligations must decrease.

Transformations retain causal lineage from original application and values to
derived values, realization, machine instruction, and object range where the
production boundary supports it. Hashes may accelerate lookup but never replace
identity or lineage.

Compile-time discovery and candidate selection must compile away for sealed
programs. Metaprogramming must not impose a runtime registry, reflection object,
package traversal, boxing, or generic dispatch unless runtime openness is
actually demanded.

Candidate applicability, capability, proof, and profitability remain facts,
demand, and evidence. Do not collapse them into `can`, `supports`, `valid`, or
`should` booleans that hide unknowns or make realization policy semantic
identity.

No compiler-directive syntax is admitted. If an irreducible operation is
missing, use `SEMANTIC-VOCABULARY-BLOCKED` and establish its owner instead of
inventing a directive.
