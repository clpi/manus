# The demand quotient as a lattice — three identities, and what falls out of them

| # | directive |
|---|---|
| 1 | Companion to `src/demand_projection.zig`. |
| 2 | GAP-171 asks for the *smallest* set of identities from which the optimization classes in `docs/performance.md` are instances, and insists that completeness be **structural, not enumerative**: a new capability must enrich an identity, never mint a parallel algebra. |
| 3 | This file states the identities, derives named classes from them, and — the part that makes it a claim rather than a slogan — records which derivations are MEASURED, which are DERIVED but blocked from measurement, and by exactly what. |

---

## 1. The identities

| # | directive |
|---|---|
| 1 | Let `L` be a region that maintains state `σ` by repeated application of an update relation `u`, and let `h` be the projection through which a demanded observer reads `L`'s live-out. |
| 2 | The realization set for `L` is generated by ONE test — *can `h(σ)` still change?* — which yields exactly four candidates. |

| # | directive |
|---|---|
| 1 | I0 h = ⊥ -> R_empty no demanded observer distinguishes any two states of σ. |

| # | directive |
|---|---|
| 1 | I1 h(σ) has entered a class closed -> R_truncate under u stop; the remaining work computes a distinction nobody demands. |

| # | directive |
|---|---|
| 1 | I2 h ∘ f = g ∘ h for cheaper g -> R_project (a homomorphism) maintain h(σ), never σ. |

| # | directive |
|---|---|
| 1 | I∞ otherwise -> R_keep always lawful, never deleted. |

| # | directive |
|---|---|
| 1 | `I0` is the bottom of `I1` (the empty class is entered before the first step) and `I2` is what makes `h` computable at all, so the three are not independent axioms; they are one question asked at three points. **That is the structural completeness claim.** `src/demand.zig` implements `I0`. `src/demand_projection.zig` implements `I1` over the projection lattice `none ⊏ {nonzero, low_bits k} ⊏ whole` and implements `I2` as `projectionOfName`, the demand derivative that computes `h` in the first place. |

| # | directive |
|---|---|
| 1 | Three supporting algebras decide the test, and each has one producer: |

| algebra | question it answers | producer |
|---|---|---|
| `law.demand.derivative` | which projection of each input suffices for `h` of the output | `projectionOfName` |
| `law.relation.property` | which laws `u` carries (bit-local, ring-hom mod 2^k, can-produce-zero, absorbing) | `lawsOf` / `composeLaws` |
| `law.uncertainty.algebra` | what interval `σ` is confined to, and whether that is a fact, an unknown, or a contradiction | `Domain` |

| # | directive |
|---|---|
| 1 | **Every rule in the demand derivative is an instance of `h(f(x)) = g(h(x))` and nothing else is admitted.** A rule may be added only by naming the homomorphism that licenses it. |
| 2 | Where no homomorphism exists the answer is `whole`, which costs candidates and never costs correctness. |
| 3 | That discipline is what stops the derivative from silently becoming a peephole table with an algebraic name. |

## 2. Derived class: existence-only demand on a count — MEASURED

| # | directive |
|---|---|
| 1 | `filter(xs, p):len() != 0` → `exists(xs, p)`. |
| 2 | GAP-171 algebra 2's "existential/`any`/`count`/membership" row. |

| # | directive |
|---|---|
| 1 | hits = 0 while i < N if p(i) hits += 1 i += 1 hits != 0 |

| # | directive |
|---|---|
| 1 | **Derivation, with no new mechanism.** |

1. `projectionOfName(whole, "hits != 0", hits)` = `nonzero`. The rule is the
   comparison-against-zero homomorphism: the value of `x != 0` is a function of
   `h(x) = (x != 0)`, not of `x`. `I2`.
2. `u` is `hits = hits + 1`. `lawsOf(.add)` says `+` is a ring homomorphism mod
   2^k, is monotone on the non-negative domain, and CAN produce zero from a
   nonzero operand — so no law-only argument is available.
3. The uncertainty algebra supplies the missing half. `hits` starts at a proven
   literal `0`; the trip count is proven `T = 2e9`; therefore after the first
   write `hits ∈ [1, 2e9]`, an interval that both excludes 0 and stays inside
   i64. `h(hits) = 1` from the first write to the exit. `I1`.
4. `R_truncate` is emitted: `break` after the write.

| # | directive |
|---|---|
| 1 | **MEASURED**, `--backend=direct`, Apple Silicon, best-of-2, answers checked against an offline Python observer (never a checksum inside the measured program — `HPLS.md` §68): |

| | idol 2843fad3 | + this change | answer |
|---|---|---|---|
| `hits != 0` (h = nonzero) | 1.4121 s | **0.0022 s** | 1 |
| `hits & 255` (h = low_bits 8) | 1.3770 s | 1.3566 s | 101 |
| no-witness control (h = nonzero) | 1.2599 s | 1.2138 s | 0 |
| start at `-1` (interval fails) | 1.4213 s | 1.3516 s | 1 |

| # | directive |
|---|---|
| 1 | 642×, and it is a complexity-class change: 2,000,000,000 iterations → 733. |
| 2 | The three controls are what make it evidence. |
| 3 | The second is the *same loop over the same data* with a wider observer and it must not move. |
| 4 | The third is the same observer with nothing to find and it must not move — that is what separates early exit from elimination. |
| 5 | The fourth changes one literal, which breaks the interval proof, and the transform correctly refuses; had it fired it would have answered 0 where the answer is 1. |

|---|---|
| 1 | `HPLS.md` §13's "one-bit / range-class / width narrowing" row, and §16's demand entropy. |

| # | directive |
|---|---|
| 1 | flag = 1 while i < N if p(i) flag = 16 flag = 32 i += 1 flag & 15 |

| # | directive |
|---|---|

## 6. Derived class: `sort:first()` → selection — DERIVED, NOT MEASURED

| # | directive |
|---|---|
| 1 | **The derivation is complete and adds no mechanism.** |

| # | directive |
|---|---|
| 1 | `first` is the rank-0 order statistic. `sort` is a producer whose only contribution is ORDER: its output is a permutation of its input, so the element MULTISET is invariant under it. |

| # | directive |
|---|---|
| 1 | h = rank_0 f = sort h(f(xs)) = min(xs) = g(xs) with g = fold(min) |

| # | directive |
|---|---|
| 1 | which is `I2` verbatim: a homomorphism from the sorted sequence's rank-0 projection to a fold over the unsorted multiset. `g` is Θ(n) comparisons against Θ(n log n) for `f`; the win is asymptotic and it is a `law.lower.bound` F3 (algorithmic) improvement, not an F8 instruction-count one. |

| # | directive |
|---|---|
| 1 | `I1` then applies ON TOP of `g`: if the element domain has a proven infimum `a` (e.g. `& 1023` gives `[0, 1023]`) then `min` is absorbing at `a`, so the fold truncates at the first element equal to `a` and the class drops again, from Θ(n) to Θ(index of the first minimum). |

| # | directive |
|---|---|
| 1 | **Why it is not measured, precisely.** Two independent blockers, both outside this module: |

1. `:sort()` does not reach machine code on the surface where demand runs. The
   direct backend refuses it at the scalar precheck —
   `method-unresolved:sort`, DNB001 — so the *program* cannot be compiled, let
   alone optimized.
2. The `I1`-on-`g` half needs a GUARDED truncation (`break` only when the fold
   reaches `a`), and `demand.Plan` carries an unconditional `break_after` set and
   nothing else. Realising it needs a `break_when` map on `demand.Plan` plus the
   matching arm in `demand.prune` — both in a held file. See the lane report for
   the exact anchor and the projected gain.

| # | directive |
|---|---|
| 1 | Recording this as DERIVED-not-MEASURED is the whole discipline. `HPLS.md` §4: never infer capability from a derivation. |

## 7. Derived class: `map:sum()` → no materialization — DERIVED, NOT MEASURED

| # | directive |
|---|---|
| 1 | sum(map(g, xs)) = fold(+, 0, map(g, xs)) = foldl(λ a x. a + g(x), 0, xs) |

| # | directive |
|---|---|
| 1 | `h = sum` is a monoid homomorphism from the list monoid to `(Z, +)`, and `map g` is a monoid homomorphism too, so their composite is one: `I2` again. |
| 2 | The intermediate sequence is never a demanded observation, so `I0` deletes it — `HPLS.md` §31, absence is a representation. |
| 3 | The win is asymptotic in SPACE (Θ(n) → Θ(1)) and neutral in time. |

| # | directive |
|---|---|
| 1 | **Why it is not measured, precisely.** The direct backend refuses an indexed store: `lowerIndexAssignTarget()` at `dnir_lower.zig:4534`, DNB001 `graph-dnir-unsupported`. |
| 2 | A program that materializes a table and then folds it cannot be compiled on this surface, so the "before" side of the measurement does not exist. |
| 3 | Measuring the "after" alone and calling the difference a win would be manufacturing a baseline. |

| # | directive |
|---|---|
| 1 | **One half of it IS already implemented elsewhere and has no consumer.** `src/recurrence.zig`'s alternative B is exactly `h(x) = x mod 2^k` maintained through `g` instead of `x` through `f` — `closeWhileByOrbit`, whose own header states the identity in these words. |
| 2 | It is unreachable: `recurrence.zig`'s closure engine has **zero non-test consumers** in this tree, measured by `gate/recurrence.sh`, which reports `closure absent, quotient absent` and 21 "a loop survived" violations out of 26 cases. |
| 3 | The missing input is precisely the fact this module produces — the demanded projection `h` — and the missing wiring is a call site. |
| 4 | That is the highest-value single item this derivation exposes and it is written up in the lane report rather than acted on here, because `recurrence.zig` is held. |

## 8. What the identity set does NOT yet cover

| # | directive |
|---|---|
| 1 | Stated so the completeness claim is falsifiable rather than decorative. |

- **`law.change.delta`** (GAP-171 algebra 4). A semantic derivative
  `Δf(x, Δx)` is `I2` with `h = Δ`, and nothing here computes it. Not
  implemented, not claimed.
- **Guarded truncation.** `I1` is implemented only where the absorbing class is
  entered by EVERY write. Where only some writes enter it — `min`, `top-k`,
  threshold counts — the candidate is derived and refused. See §6.
- **Hyperproperties.** Every check in this module and in `gate/quotient.sh` is
  SINGLE-TRACE. `I1` changes the iteration count, which a timing observer
  distinguishes, so no amount of per-trace evidence authorizes it under a
  determinism, noninterference, serializability or linearizability demand.
  **This one IS a mechanism**: `observationRefusal` asks
  `observation.World.demandsHyperproperty()` first and refuses the whole module
  with its own distinct reason, and it refuses again unless the observer roster
  computed by `observation.World.observers()` is exactly
  `{program, deployment, failure_recovery}` — the three that provably cannot
  distinguish an iteration count. Nine world facts each delete every candidate
  on their own; `--emit obj`/`dylib` delete them by not closing the world.
- **The per-place observation ruling is NOT consulted, and that is the real
  hole.** `observation.permits(&Program.report(place), .schedule)` is the finer
  instrument GAP-171 deletion condition 2 names, and it cannot answer here:
  `observation.zig` indexes evidence by `place.zig`'s census, which records a
  place only where a binding's value is a `.table` literal. MEASURED on the §2
  fixture: 7 program points walked, **0 places produced**, `report("hits", …)`
  null. Permitting where no report exists would treat an absent authority as a
  permissive one. The gap is in `place.zig`'s census, not in the observation
  model.
- **Order-statistic projections** are in the lattice as a derivation only;
  `Projection` has no `rank_k` constructor because nothing could consume one.
  Adding one before a consumer exists would be `HPLS.md` §7 scenery.
